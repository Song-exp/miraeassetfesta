## 2. Part A — 콘솔 작업 (본인, 약 15분)

제가 못 들어가는 구간입니다. 로그인 세션도 결제 권한도 없습니다.

> 📖 **클릭 순서·입력값은 `docs/NCP_CONSOLE.md` 에 화면별로 정리해 뒀습니다.**
> 아래는 체크리스트만 봅니다. 콘솔을 띄워 놓고 하실 거면 그 문서를 여세요.

### 2.1 네트워크 — 무료

- [ ] **VPC** 생성 (Classic 말고 **VPC**) — `192.168.0.0/16`
- [ ] **Subnet** 생성 — `192.168.1.0/24` · 🔴 **Internet Gateway 전용 = Y** (Public)
- [ ] **ACG 인바운드 3개**

| 프로토콜 | 접근 소스 | 포트 | 용도 |
| :--- | :--- | :--- | :--- |
| TCP | **내 IP/32** | 22 | SSH. `0.0.0.0/0` 로 열지 마세요 |
| TCP | `0.0.0.0/0` | 80 | 🔴 **막으면 인증서 발급 실패** (HTTP-01 챌린지) |
| TCP | `0.0.0.0/0` | 443 | 실제 평가 트래픽 |

> 📌 **8000 은 열지 않습니다.** 지시서엔 "API 포트 인바운드"라고 되어 있지만
> Caddy 가 컨테이너 네트워크 안에서 프록시합니다. 열면 HTTP 평문 우회 경로가 생깁니다.

### 2.2 서버 — 🔴 여기서 과금 시작

- [ ] **Server 생성** — Ubuntu Server **24.04 LTS** / **2vCPU·4GB** / 스토리지 **50GB**
      (22.04 든 24.04 든 무관합니다. 앱은 컨테이너 안에서 돕니다)
      (주최측 권장은 SSD 20GB. 평가 기간엔 정지 불가 = 증설 창구가 없어 올려 잡습니다)
- [ ] **요금제 = 시간 요금제** — 절감이 아니라 정지 기간 제한에 묶이지 않기 위해서
- [ ] **인증키 신규 생성 → `.pem` 다운로드**
      🔴 **재발급 불가.** 잃으면 서버를 다시 만들어야 합니다. 받는 즉시 저장하세요.
- [ ] **공인 IP 할당** — 이게 있어야 `nip.io` 가 성립합니다
- [ ] 🔴 **ACG 는 기본값 말고 2.1 의 3개 규칙** — 기본 예시는 22를 `0.0.0.0/0` 로 엽니다
- [ ] **관리자 비밀번호 확인** — 콘솔에 `.pem` 을 올려 root 비밀번호를 받습니다
      (NCP 는 `.pem` 으로 직접 SSH 하지 않습니다. 비밀번호 조회용입니다)

### 2.3 결제 안전장치

- [ ] 결제관리 → **한도 알림 설정** (크레딧 잔액 임계치)
- [ ] **크레딧 잔액 확인** — 9/20 평가 종료까지 버틸 양인지 판단해야 합니다

## 5. 통과 기준 — 이게 다 되면 끝

- [ ] `docker compose up -d --build` 빌드 성공
- [ ] `docker compose logs caddy` 에 **`certificate obtained successfully`**
- [ ] 밖에서 `https://<IP>.nip.io/health` → `{"status":"ok","agent_ready":false,...}`
- [ ] 밖에서 `https://<IP>.nip.io/answer` → **5필드 JSON**
- [ ] **한글 질의 왕복 무손상** (`question` 에코가 안 깨질 것)
- [ ] `question` 파라미터 누락 시에도 **200 + 5필드** (폴백 작동)
- [ ] **서버 재부팅 후 자동 복구** (`restart: unless-stopped`)

> 마지막 항목까지 봅니다. 평가 당일 인스턴스가 한 번 튀어도 알아서 살아나야 합니다.

기대 응답:

```json
{
  "question_id": "Q-001",
  "question": "국내 상장 ETF 중 최근 1년 수익률이 가장 높은 채권형 ETF 3개를 알려줘.",
  "retrieved_context": "",
  "think_trace": "1. [Normalize] 질의 정규화 완료\n2. [Ground] ...",
  "answer": "현재 시스템 구축 중으로 답변을 제공할 수 없습니다."
}
```

## 6. 🔴 하면 안 되는 것

| 하지 말 것 | 왜 |
| :--- | :--- |
| **서버 끄기 / 정지** | 채점기 호출 시점이 미상입니다. 꺼져 있을 때 들어오면 **40점이 0점** |
| `docker compose down -v` | `-v` 가 `caddy_data` 볼륨을 지웁니다 → **인증서 소멸 + 재발급 한도 소모** |
| ACG 22 를 `0.0.0.0/0` 으로 | SSH 전면 개방 |
| 8000 포트 인바운드 개방 | HTTPS 우회 경로가 생깁니다 |
| 원인 모른 채 재빌드 반복 | 주간 5회 한도를 태웁니다 |
| `.env` 커밋 | 자격증명 유출. `.gitignore:35` 로 막혀 있지만 강제 추가하지 마세요 |

### 서버를 끄면 안 되는 이유 — 조금 더

기술적으로는 껐다 켜도 됩니다. 공인 IP 는 유지되고 인증서는 볼륨에 남습니다.
**그런데 아껴 봐야 실익이 없습니다.**

```
정지해도 디스크 요금은 계속 → 컴퓨트분만 절약
아낀 크레딧은 9/30 소멸    → 쓸 데가 없음
거는 것은 배점 40점
```

숫자로 확인했습니다 (`PROJECT.md` §4 — 권장 스펙 월 5~7만 원 · 크레딧 총 30만 원):

```
8/16 개설 ~ 9/20 평가 종료 = 35일 ≈ 1.17개월
상시 가동  1.17 × 6만 원 ≈ 70,000원  /  크레딧 300,000원  →  사용률 23%
```

**상시 가동해도 크레딧의 1/4도 안 씁니다.** 정지로 아끼는 2.5만 원은 어차피 9/30 소멸분이고,
대신 정지→기동 왕복 리스크(공인 IP 유지·컨테이너 자동 기동·인증서 볼륨)를 떠안게 됩니다.
켜 두는 편이 "2주 방치 생존"(`PROJECT.md` §2) 검증까지 덤으로 줍니다.
