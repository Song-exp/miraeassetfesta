   근거 컬럼이 없으면 **결과를 버리고**(R09), 라벨이 없으면 **행을 빠뜨린다**(038).
   같은 결핍이 환각·오거절·누락 세 얼굴로 나타났다. → 근거 컬럼을 SELECT 에 기계 주입하는 것이 처방.
3. **"플래그 하나로 부재를 단정하지 말 것"** — `hdge_fd_yn=0행` 을 근거로 "공모 헤지펀드 없음" 을
   규칙에 박았는데 실제로는 66행/14펀드가 있었다(`ext_fund_page` 미확인). 마스터 45컬럼만 보고 만든
   reject 문항 4건이 전부 오설계. **리드 세션과 밤 세션이 독립적으로 같은 실수를 했다.**

### 5-2. 개별 함정 (해당 세션에서 실제로 밟았던 것)

| 무엇 | 교훈 |
| :-- | :-- |
| `.env` 를 `set -a; source` 로 읽어 안의 ssh 메모가 실행됨 | .env 는 파서(dotenv)로만 읽는다 — 설정을 실행하지 않는다 |
| 헬퍼 함수를 `def load_context` 바로 위에 삽입 → `@lru_cache` 가 새 함수에 붙음 | def 앞 삽입은 데코레이터까지 앵커에 포함 |
| paired v1 "24%" 를 실력으로 읽을 뻔 | 이상하게 낮은 수치는 채점기부터 의심 — 같은 채점기의 **상대 비교**(R-2)는 절대치가 무효여도 산다 |
| 스캐너 상방 5건을 그대로 예외 후보로 보고 | 병든 클래스가 다수면 중앙값이 끌려간다 — 자동 탐지→사람 검증 없이 배제 금지(방향 오탐 4/5) |
| 성분 alias 를 자동 경로에만 걸어 816행 최대 건 누락 | "제외 후 처리" 구조에서 제외된 쪽은 다른 경로에 있다 — 전 갈래 순회 + 전체 지표로 검증 |
| 병렬 세션이 같은 yaml 에 블록을 추가 → 나중-키-우선으로 리드 결정이 조용히 무효화 | **커밋 전 dupkeys 를 게이트로** (§4-4) |
| 새 최상위 yaml 키를 규칙북 화이트리스트에 안 넣어 렌더 누락 | 생성기 `DOMAIN_RULE_KEYS` 확인 (§1-1) |
| 브랜치 구본을 기계 병합할 뻔 | 수동 이식된 main 선별본이 최신일 수 있다 — 충돌 시 계보 먼저 (§4-5) |
