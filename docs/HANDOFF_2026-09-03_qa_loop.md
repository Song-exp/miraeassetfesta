## 4. 🔴 gold 파일은 고치지 않는다 (리드 결정 2026-09-03)

gold 를 서버 답에 맞춰 고치면 **그 gold 로 서버를 채점하는 것이 순환**이 된다. 계측기를 피측정 대상에 맞추면 측정이 사라진다.
결함 8문항은 `docs/gold_defects_2026-09-03.md` 에 근거와 함께 분리했고 **판정 보류**(집계 분모에서 제외)로 둔다.

- 랭킹 결과에 같은 펀드 중복 5: `FND-003`·`FND-004`·`FND-009`·`OFFICIAL-002`·`UNANS-006`
  (`gold_sql` GROUP BY 가 `or_co+mtco` 축 — mtco 는 398 rptt 그룹/2,686 클래스행에서 **클래스 단위 발급**.
   `FND-009` 는 1위·4위가 같은 펀드라 "상위 5개"가 실제 4개 펀드)
- `FND-008`: `LIKE '%채권%'` 가 혼합형 974행(50.1%) 오염 — gold 상위 5건 중 4건이 혼합형
- `OFFICIAL-NA-003` 자기모순 · `OFFICIAL-001` 모수 15,806→15,792

**규칙**: gold 수정 근거로 "서버 답과 일치" 를 쓰지 않는다. 근거는 **질문 문언·도메인 정본·DB 실측** 셋뿐.
단 **그 문항에서 본 서버 결함은 정상적으로 수정안에 올린다**(gold 가 못 쓴다고 서버 결함까지 덮지 않는다).

## 5. 🔴 판정 대기 안건

   실측: 미래에셋 주식형만 **69,336억/142펀드**(현 서버, Y7 ✅) vs 주식형+해외주식형 **114,227억/480펀드**.
   포함 근거 3 — `ontology/enums/public_funds.yaml:949` 의 `자산군_주식형: IN ('주식형','해외주식형')`(플래너가 싣는 우리 규칙) · 리드 `gold_sql FND-009` 도 같은 `IN` · gold 심사관이 `FND-008` 에서 "서버가 해외채권형을 빼는 것이 결함" 판정.
   제외 근거 1 — 재검 심사관 10R §③-4.
   🔴 **지금 `Y7` 의 ✅ 가 틀린 기준 위에 서 있을 수 있다.** 15R 채점에 판정을 맡겼다. 채권형과 대칭이어야 한다.
2. **펀드 정의 이원화** — 모수 집계 3,040(`or_co`+`mtco`) vs 랭킹·개수 1,809(`rptt`). 12R 에서 축을 나눠 집행했고 `COUNT(DISTINCT 펀드키)=3,040` 은 테스트로 고정. 기존 리드 안건(펀드키 규약)의 연장.
3. **FND 랭킹 gold 의 묶기 축** — rptt 로 옮기면 서버 축과 같아져 자기 채점이 된다. §4 참조.
4. `Z16` 키움 2코드(`Org_00040013`·`Org_00080052` 가 둘 다 `label_official='키움투자자산운용'` — 전체 유일 중복) · `Idx_NASDAQ100` alias — 둘 다 런타임으로 우회됨, 온톨로지 보고 항목.

## 7. 이 구간의 교훈

1. **자체 생성 질문에 과적합된다.** 7라운드 동안 자체 문항으로 ✅56/93 을 만들었는데, 한 번도 안 던진 gold 37문항에서는 15/37 이었다. **주최 규격에 가까운 문항을 일찍 던져야 한다.**
2. **가드를 늘릴수록 조합에서 깨진다.** 실패 5변종이 전부 "개별 가드는 옳고 조합에서 깨짐" 이었다. 12R 의 확정식 원자성·체인 끝 사후조건이 구조적 처방.
3. **조건이 살아 있는지를 봐야 한다.** `Z19` 가 1,160(ETF 전수)을 답했는데 값만 보면 그럴듯했다. 채점 지시에 **"최종 SQL 에 사용자 조건이 살아 있는지 트레이스로 확인"** 을 넣었다.
4. **심사관 보고를 그대로 믿지 않는다.** "이름 하드코딩" 오진(실제로는 DB 실측 렌더), `label_official` 만 보고 "KG 미수록" 오판, A 의 `LIKE 'Samsung%'` 가 별개 법인 25행 합산 — 전부 원본·DB 재확인에서 걸렸다. 반대로 심사관이 A 의 보류 사유를 실측으로 반증한 것도 3건.
5. **계획서와 구현을 일치시켜야 한다.** 12R 계획서에 "보류" 로 적힌 항목이 배포돼 17문항에 회귀를 냈다.
6. **`git add -A` 금지.** A 가 두 번, 동시 실행 중이던 오케스트레이터 산출물을 함께 커밋했다. 손실은 없었으나 경로 명시가 원칙.
