## 1. 오늘(9/3) 확정된 것 — 되돌리지 말 것

### 1-1. 설계 철학 (정본 `docs/기술제안서/08_설계철학.md`)
- **KG는 상품이 아니라 조건의 값을 담는다.** 값 접지는 그래프, 행 선택은 SQL. 데이터에 대한 사실은 선언에, 선언을 다루는 방법은 코드에. **모델은 복사만 한다.**
- 편입 기준: "질문의 어휘가 **값·지표·단위·범위**로 이어지는가"(9/3 이전엔 "값"만).
- 원칙 5: 값은 사전에서 ✅ · 축도 사전에서 🔶 · 없는 것은 구조가 안다 ✅ · **선언은 실리고 또 강제된다** 🔶 · 그래프를 걷지 않는다 ✅.
- 용어 규율: Federated·그래프 탐색·추론 금지. "펀드"는 운용단위 `(or_co, mtco)` vs KG Fund 노드(rptt) 두 뜻 — 절마다 표기.
- 온톨로지(스키마: 개체 종류·관계 종류·부재·범위, ttl+yaml 선언부) ≠ KG(인스턴스: kg_node 41,580·alias 66,592·closure·edge). 그래프 탐색기 페이지는 **온톨로지** 그림이다.
- 선언 vs 규칙의 경계: `kg_entity`·shared 노드/alias/계층/edge·`absent_*`·`range_by_table` → ttl+KG. `query_rules(text/enforce)`·결측 판정·normalization·clarify·answer_rules·gate_constants → 프롬프트·게이트·적용기. "모든 규칙을 yaml 로"가 아니다.

## 6. 이 구간의 교훈
1. 목차는 시스템 구조가 아니라 채점 구조를 따른다(60절 → 22절).
2. "도메인별로 나눠 쓴다" ≠ "온톨로지가 셋". 도메인 그림은 통합 그림의 스포크 확대.
3. "규칙이 실려도 무시된다"는 실림 여부만 본 진단이었다 — 미주입·모순·과량을 재지 않은 채 코드로 갔다. 루프 경계가 yaml 을 통째로 막은 것이 코드 편중의 원인.
4. 코드 규칙은 SQL 모양에 묶여 전이되지 않고 수렴하지 않는다. 선언 + 적용기가 UNION 가지를 닫았다(17R 축 11→6).
5. 섀도 없이 전환했으면 슬롯 결함 4건이 배포 후에 났다. 측정 방법을 먼저 자기검증(15R vs 13R)한 것이 맞았다.
6. 생성 문서(NUMBERS)는 재생성 시점이 다르면 어긋난다. 조판 직전 한 번의 재생성을 절차로.
