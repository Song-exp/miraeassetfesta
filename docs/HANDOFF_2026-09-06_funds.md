### 기술 정의서에 쓸 만한 정량 사실 (재확인 후 인용)

- 회차별 ✅: 48 → 53 → 57 → 66 → 68 → 69 → (7차 반영) 77. 2차는 회수 10/회귀 9 로 제자리, 3차부터 회귀 0~3 — **수리를 프롬프트에서 결정층으로 옮긴 시점과 일치**.
- HCX 호출 수별 오답률(18R 인계): 0회 ❌0% · 1회 ❌10% · 2회 ❌53%.
- 같은 질문의 HCX 원문이 회차마다 다른 모양으로 나온 실측: U14(ORDER BY 3 → ORDER BY 없음 → 축 컬럼 없음), KG-005(코드 오컬럼 → 이름 LIKE → 목록형), OFFICIAL-002(거절 → 환각 컬럼 둘). 결정층은 **원문 형태별**로 닫아야 했다.
- KG 구조: 노드 40,845 · 별칭 66,603 · 엣지 5,704(술어 3종, Fund 관계 0) — 값 사전이지 관계 그래프가 아니다(`funds_structural_causes`).
- 보유종목 JOIN 사각: JOIN 하나로 랭킹·대표행·보수 가드 전부가 꺼져 SUM 보수 1,677% · 행 뻥튀기. 처방은 가드 추가가 아니라 **입력을 단일 테이블로 환원**.

## 5. 운영 절차 (채점 당일)

1. 틀린 문항 → 서버 로그 `qid=… raw=` 에서 **가드 적용 전 원문** 확보.
2. 원문을 가짜 플래너로 로컬 재생(트레이스 SQL 로 재생하면 재현 안 됨 — R13 ③).
3. 부류 규칙 + 테스트 → 전체 스위트 → `bash deploy/deploy.sh --code-only` → 같은 문항 서버 2회.
4. 팀원 커밋이 먼저 있으면 `origin/main` 워크트리에 체리픽해 푸시(다른 세션의 미커밋 문서 보호). 온톨로지 `shared/`·`codebooks/`·`*.ttl`·빌드 스크립트가 바뀌었으면 `build_ontology.py` 후 전체 배포.
