## 1. 전체 아키텍처 개요

외부 인터넷과 통신 가능한 독립된 가상 사설망(VPC)을 구축하고, 방화벽(ACG)을 적용한 단일 리눅스
서버(Ubuntu)를 띄운 뒤, 그 위에 **컨테이너 2개**로 API 서비스를 구동합니다.

# Part 1. 클라우드 인프라

## 2. 가상 사설 네트워크 (VPC)

클라우드 내에 우리 프로젝트 전용으로 생성한 독립된 가상 네트워크 공간입니다. 다른 클라우드
사용자와 완전히 격리되어 보안을 보장합니다.

- **VPC 이름 (`mirae-vpc`):** 리소스 식별을 위한 논리적 이름
- **IP 주소 범위 (`192.168.0.0/16`):** 사설 IP 대역(RFC 1918). 총 65,536개의 사설 IP를 가질 수 있는 네트워크 틀
- **유형 (`Normal`):** 일반적인 단일 프로젝트 구성을 위한 표준 VPC

## 3. 서브넷 (Subnet)

VPC 네트워크를 목적에 맞게 쪼갠 세부 네트워크 구역입니다.

- **Subnet 이름 (`mirae-subnet`):** 서브넷 식별 이름
- **IP 주소 범위 (`192.168.1.0/24`):** 256개의 IP(`192.168.1.0`~`192.168.1.255`)를 할당받는 구역
- **가용 Zone (`KR-1`):** 네이버 클라우드의 물리적 데이터센터 위치. **서버와 서브넷의 Zone이 일치해야** 통신 가능
- **Internet Gateway 전용 여부 (`Y - Public`):** 외부 인터넷과 직접 통신 가능한 Public Subnet 설정
  (**서버에 공인 IP를 할당하기 위한 필수 조건.** 여기서 `N`을 고르면 공인 IP도 HTTPS도 성립하지 않습니다)
- **용도 (`일반`):** 일반 서버 배치용

## 4. 방화벽 규칙 (ACG)

서버 앞단에서 비인가 트래픽을 차단하는 가상 방화벽입니다. **상태 저장(stateful)** 방식이라,
허용된 연결의 응답 패킷은 반대 방향 규칙 없이도 통과합니다.

### Inbound — 들어오는 연결

- **22번 포트 (`내 PC IP/32`):** SSH 관리용 포트. 무차별 대입 공격 방지를 위해 관리자 IP로만 접근 제한
- **80번 포트 (`0.0.0.0/0`):** HTTP 포트. Caddy가 SSL 인증서(Let's Encrypt) 자동 발급/갱신 검증
  트래픽을 받기 위해 전체 개방. **막으면 인증서 발급이 실패합니다**
- **443번 포트 (`0.0.0.0/0`):** HTTPS 보안 포트. 평가단 및 외부 API 호출 수신용 전체 개방
- **8000번 / 3389번 미개방:** 8000번(FastAPI 직접 노출)은 Caddy 내부 프록시를 통하므로 닫고,
  3389번(Windows RDP)은 불필요하여 제외

### Outbound — 나가는 연결

- **TCP `0.0.0.0/0` `1-65535` (전체 개방):** Docker 이미지 다운로드, pip 패키지 설치, git clone,
  Let's Encrypt 인증서 발급, LLM API 호출에 필요

> 🔴 **실제로 여기서 한 번 막혔습니다.** 새로 만든 ACG는 아웃바운드가 **비어 있습니다.**
> 인바운드만 넣고 넘어가면 서버가 인터넷으로 나가지 못합니다.
>
> 진단이 까다로웠던 이유 — 두 개의 "정상" 신호가 오진을 유도합니다.
>
> | 신호 | 상태 | 실제로 증명하는 것 |
> | :--- | :--- | :--- |
> | SSH 접속 | ✅ 됨 | ACG가 stateful이라 **들어온 연결의 응답**만 나감. 아웃바운드와 무관 |
> | DNS 이름 해석 | ✅ 됨 | NCP **내부 resolver**(`169.254.169.53`) 사용. 인터넷 불필요 |
> | 아웃바운드 TCP | 🔴 차단 | 443·80 전부 300초 타임아웃 |
>
> "접속도 되고 이름도 풀리는데 왜 안 되지"로 보이지만, `docker` 설치·`git clone`·`pip install`·
> 인증서 발급이 전부 막힌 상태였습니다.

## 5. 가상 서버 인스턴스 (Server)

애플리케이션 코드가 실행되는 가상 머신(VM)입니다.

- **OS 이미지 (`Ubuntu Server 24.04 LTS` / KVM):** 안정적인 장기 지원 버전의 리눅스 배포판 및 최신
  KVM 가상화 기반. **호스트 OS 버전은 우리 스택에 영향이 없습니다** — 앱은 컨테이너 안에서 돌고,
  호스트가 하는 일은 Docker·git·ssh 셋뿐입니다
- **서버 스펙 (`c2-g3a` — 2vCPU / 4GB):** High-CPU 사양. 주최측 권장 스펙과 동일
- **요금제 (`시간 요금제`):** 서버 정지(Stop) 시 컴퓨팅 요금이 중단되어 크레딧 절약 가능.
  월 요금제는 할인 대신 정지 기간 제한(1회 90일)이 붙습니다
- **사설 IP (`192.168.1.101`):** Subnet 내부 고정 사설 IP
- **공인 IP (`49.50.134.229`):** `nip.io` 도메인 연결 및 SSL 인증서 발급에 사용되는 고유 공인 IP
- **스토리지 (`CB1 50GB`):** 기본 블록 스토리지. 주최측 권장은 20GB지만 상향했습니다 —
  평가 기간(9/7~9/20)은 정지 불가 구간이라 **증설 창구가 없기** 때문입니다 (§11 참조)
- **인증키 (`mirae-api-key.pem`):** 관리자(root) 비밀번호 **복호화용** 비대칭 암호화 키

### 왜 이 사양으로 충분한가

- **CPU 바운드 구간이 없습니다.** LLM 호출 2회는 전부 네트워크 대기이고, 판단은 코드가 합니다.
  SQLite는 최대 테이블이 95,619행이라 풀스캔해도 수십 ms. 실측 응답 시간 **7~9ms**
- **메모리 실사용 ~830MB / 4GB** (uvicorn 2 workers 300MB + Caddy 30MB + Docker 100MB + OS 400MB)
- **디스크 실사용 5.7GB / 50GB (12%)**

# Part 2. 서버 내부 구성

## 6. 접속 체계 — 키가 두 종류입니다

NCP는 AWS와 달리 **`.pem` 으로 직접 SSH하지 않습니다.** 헷갈리기 쉬운 지점입니다.

| 키 | 용도 | 위치 |
| :--- | :--- | :--- |
| `mirae-api-key.pem` | NCP **콘솔에서 root 비밀번호를 복호화**하는 용도. SSH 접속키가 아님 | `secrets/` |
| `deploy_key` (ed25519) | **실제 SSH 접속용.** 배포 작업 전용으로 새로 생성해 서버에 설치 | `secrets/` |

- **왜 별도 키를 만들었나:** 비밀번호를 명령마다 반복해 흘리지 않기 위해서입니다. 최초 1회만
  비밀번호로 접속해 공개키를 `~/.ssh/authorized_keys` 에 심었고, 이후 모든 작업은 키 인증입니다
- **🔴 `.gitignore` 로 차단:** `secrets/` · `*.pem` · `*.key` · `*.ppk` · `id_rsa` · `id_ed25519`
  (`.gitignore:41`). 개인키가 커밋되면 서버가 통째로 넘어가고, **NCP 인증키는 재발급이 불가능**합니다
- **⚠️ 로컬 백업 필수:** `secrets/` 는 git에 안 올라가므로 PC가 죽으면 같이 사라집니다

## 7. 컨테이너 런타임 (Docker)

- **Docker Engine (`29.7.2`):** 컨테이너 실행 엔진. `curl -fsSL https://get.docker.com | sh` 로 설치
- **Docker Compose (`v5.4.0`):** 여러 컨테이너를 하나의 파일로 정의·기동하는 도구
- **`systemctl is-enabled docker` = `enabled`:** 🔴 **재부팅 시 Docker 데몬이 자동 기동됩니다.**
  이게 없으면 컨테이너의 `restart` 정책도 무의미합니다

### 왜 컨테이너인가

```
컨테이너 없이            컨테이너로
  서버에 python 설치       이미지 안에 python 3.12 고정
  서버에 의존성 설치       requirements.txt 가 이미지에 박힘
  "내 PC에선 되는데"       로컬·서버가 같은 이미지를 실행
```

제출 규격(`PROJECT.md` §6-4)이 **Dockerfile 재현성**을 소스코드 배점에 포함합니다.

## 8. 컨테이너 구성 — 2개

```
mirae-caddy-1   caddy:2-alpine (88.7MB)   0.0.0.0:80->80, 0.0.0.0:443->443
mirae-api-1     mirae-api:latest (452MB)  8000/tcp  ← 호스트에 노출 안 함
```

### ① `api` — FastAPI 애플리케이션

- **베이스 이미지 (`python:3.12-slim`):** 호스트 OS와 무관하게 파이썬 버전을 고정
- **실행 명령 (`uvicorn src.api.main:app --workers 2`):** 2vCPU에 맞춘 워커 수
- **포트 (`expose: 8000`):** 🔴 **`ports`가 아니라 `expose`입니다.** 컨테이너 네트워크 안에서만
  보이고 호스트에는 열리지 않습니다. 외부에서 8000으로 직접 접근할 경로 자체가 없습니다
- **헬스체크:** 30초마다 `/health` 를 찔러 "죽지는 않았는데 응답 못 하는" 상태를 잡아냅니다
- **재시작 정책 (`restart: unless-stopped`):** 크래시·재부팅 시 자동 기동. 사람이 명시적으로
  `stop` 한 경우에만 안 올라옵니다

### ② `caddy` — TLS 종료 및 리버스 프록시

- **역할:** 외부의 HTTPS 요청을 받아 복호화한 뒤, 내부 `api:8000` 으로 평문 전달
- **Let's Encrypt 자동 발급·갱신:** 인증서를 사람이 관리하지 않습니다
- **`reverse_proxy api:8000`:** `api` 는 Docker 내부 DNS가 해석하는 **서비스 이름**입니다
- **액세스 로그:** JSON 형식, `10MiB × 5개` 로테이션. 평가 후 재현·소명용
- **외부에 노출되는 유일한 컨테이너**입니다

## 9. 스토리지 — 볼륨과 바인드 마운트

두 방식의 차이를 구분하는 것이 중요합니다.

| 이름 | 방식 | 무엇이 들어있나 |
| :--- | :--- | :--- |
| `mirae_caddy_data` | named volume | 🔴 **발급받은 인증서.** 절대 삭제 금지 |
| `mirae_caddy_config` | named volume | Caddy 내부 설정 상태 |
| `mirae_caddy_logs` | named volume | 액세스 로그 |
| `./data:/app/data:ro` | bind mount | **금융 DB** (호스트 디렉터리를 직접 연결) |

- **named volume:** Docker가 관리하는 저장 공간. 컨테이너를 지우고 다시 만들어도 남습니다
- **bind mount:** 호스트의 특정 경로를 컨테이너 안에 그대로 붙입니다. DB처럼 **호스트에서 직접
  교체하고 싶은 파일**에 적합합니다
- **🔴 `:ro` (read-only) 인 이유:** 에이전트는 조회만 합니다. DB가 `journal_mode=delete` 라서
  읽기 전용에서도 SELECT가 정상 동작합니다. **WAL 모드였다면 `-wal`·`-shm` 파일을 만들지 못해
  조회 자체가 막혔을 것**입니다 — `build_db.py` 를 고칠 때 journal_mode를 바꾸면 안 됩니다

# Part 3. HTTPS는 어떻게 성립하는가

도메인을 사지 않고 HTTPS를 붙인 구조라, 원리를 알아두면 장애 대응이 쉬워집니다.

## 11. `nip.io` + Let's Encrypt

Let's Encrypt는 **공인 DNS 이름**에만 인증서를 발급합니다. IP 주소로는 안 됩니다.
`nip.io` 는 `<IP>.nip.io` 를 그 IP로 해석해 주는 공개 와일드카드 DNS입니다.

```
49.50.134.229.nip.io  ──DNS 조회──▶  49.50.134.229
     (공인 DNS 이름)                    (우리 서버)
```

발급 절차(HTTP-01 챌린지):

```
① Caddy → Let's Encrypt : "49.50.134.229.nip.io 인증서 주세요"
② Let's Encrypt → 80번 포트 : "이 토큰을 그 주소에 띄워봐"     ← 🔴 80이 열려 있어야 함
③ Caddy가 토큰 응답 → 검증 통과
④ 인증서 발급 → mirae_caddy_data 볼륨에 저장
```

- **발급 결과:** 2026-08-16 **첫 시도 성공**. 유효기간 **2026-08-16 ~ 2026-11-14**
- **갱신 시점:** 만료 30일 전(10월 중순). **평가 기간 9/7~9/20 이후**라 평가 중에 ACME 트래픽이
  끼어들지 않습니다
- **🔴 주간 5회 발급 한도:** 도메인당 주 5회. 원인을 모른 채 재시도를 반복하면 한도를 태우고
  그 주 내내 HTTPS가 막힙니다. 인증서는 볼륨에 있으므로 **재빌드해도 재발급되지 않습니다**

## 13. 정지·기동 절차

**🔴 기동 후 반드시 확인할 3가지:**

| # | 확인 | 왜 |
| :--- | :--- | :--- |
| ① | **공인 IP가 그대로인가** | 바뀌면 `SITE_ADDRESS`·제출 URL·인증서가 **전부 무효** |
| ② | 컨테이너가 자동 기동했나 | `docker compose ps` — `unless-stopped` 정책 확인 |
| ③ | 인증서 재발급을 시도했나 | 로그에 ACME 트래픽이 뜨면 볼륨이 안 붙은 것. 주간 한도 소모 |

**재기동 데드라인 — 8/30 권장, 늦어도 9/5.**

## 14. 비용 — 무엇이 멈추고 무엇이 계속되나

| :--- | ---: |
| 현재 크레딧 잔액 | 199,030원 |

| **미신청 웰컴 크레딧** | **+100,000원** |

- 정지로 아끼는 22,000원보다 **웰컴 크레딧 10만 원 신청이 4.5배 큽니다.** 리스크도 없습니다
- 정확한 단가는 **결제관리 → 이용 내역**에서 Server / CLOVA Studio 항목별로 확인 가능합니다
