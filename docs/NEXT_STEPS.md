### 이번 단계 3원칙

**1. 값을 고치지 말고 배제하세요.**
`0`을 `NULL`로 바꾸거나 결측을 채우면 안 됩니다. **판정하고 `query_rules`로 걸러냅니다.**

`du_last_aum`은 국내가 원, 해외가 USD입니다. 그냥 정렬하면 순위가 뒤집힙니다.

#### ① `ontology/enums/domestic_bonds.yaml` 신규 작성 — 최우선

**노트 §B.2에 결측 7유형이 이미 정리돼 있습니다. 그걸 yaml로 옮기는 작업입니다.**
형식은 `ontology/enums/domestic_etfs.yaml`을 그대로 따라 하세요.

```yaml
domain: domestic_bonds

columns:
  BUY_YIELD:
    korean_name: 매수수익률
    missing_reason: not_applicable        # 매수 가능 종목만 수록 — 결측이 아님
    answer_policy: "'수익률 높은 채권' 질의는 모수 881건(2.1%) 명시 필수."
    note: BUYABLE_QUANTITY 와 엇갈림 0건 → 완벽 대응. 881건 중 556건이 수량 0 → 실질 325
    unit: percent
  CRD_GRD:
    korean_name: 신용등급
    missing_reason: not_applicable        # 국채·지방채는 등급을 안 매김
    answer_policy: "'확인할 수 없음' ❌ → '국채라 신용등급이 부여되지 않습니다' ✅"
  AVG_ANNUAL_TAX_YIELD:
    korean_name: 연평균 과세수익률
    missing_reason: missing
    answer_policy: "'데이터 미제공'. 전량 0이라 사용 불가."

query_rules:
  수익률정상:   APPLIED_YIELD > 0                    # =0 이 1,289건 (가격은 정상인데 수익률 0)
  듀레이션정상: DUR IS NOT NULL AND DUR != 99         # 99 는 센티넬 2건
  익일값금지:   "NDY_* 사용 금지"                      # 미산출을 0으로 채움 — 8,503건
  매수가능:     BUYABLE_QUANTITY > 0                 # 881건 중 556건이 0
  특수구조제외: "추천·랭킹 질의 기본 제외 (15,306건, 36.1%)"
```

**반드시 넣을 `query_rules`** (전부 노트 §D에 근거가 있습니다):

| 규칙 | 근거 |
| :--- | :--- |
| `APPLIED_YIELD > 0` | `=0` 1,289건 → *"수익률 낮은 채권"* 공동 1위 오염 |
| `NDY_*` 사용 금지 | 미산출을 `0`으로 채움. 원본>0인데 `NDY_=0` 이 **8,503건** |
| `AVG_ANNUAL_TAX_YIELD` 사용 금지 | 전량 `0` |
| `DUR != 99` | 센티넬 2건. 이론 위반 1,035건도 별도 플래그 |
| `TRIM()` 전면 | `BD_KND='일반회사채'` 188건 vs `TRIM()` **13,998건** |
| 특수구조 8종 | 15,306건(36.1%) — 콜옵션부 12,119·CB 2,337·후순위 1,210·FRN 643·영구채 450·EB 391·코코본드 96 |
| 만기 4상태 | 만기 도래분 16,180건. **삭제 금지, 상태 구분** |

> ⚠️ **공백 문자열 주의.** `PD_ABRV_NM` 은 `NULL` 69건인데 `TRIM` 후 빈 문자열이 **296건**입니다.
> `IS NULL` 로만 세면 80%를 놓칩니다.

## 3. 산출물 규격

### 3.1 `ontology/enums/<domain>.yaml` — 이번 단계의 주 산출물

**완료 판정 기준입니다.** *"EDA 마무리"* 는 판정이 안 되지만 파일 4개는 됩니다.

```yaml
domain: <table_name>

columns:                          # ① 결측·0값의 의미
  <column>:
    korean_name: ...
    missing_reason: not_applicable | missing | mixed
    answer_policy: "이 컬럼이 결측일 때 뭐라고 답할지"    # ← §6 답변 매트릭스의 원료
    note: "판정 근거 (건수 포함)"
    unit: percent | krw | usd | days | ...              # ← 층위. 반드시 명시

query_rules:                      # ② 모든 질의에 항상 붙는 필터 (예외 처리가 아님)
  <규칙명>: <SQL 조건>

axis_derivation:                  # ③ 축 유도 — 파생 컬럼이 아니라 규칙으로
  confirmed:
    <축>: { accuracy: N/100, rule: "..." }
  pending_workshop:
    <축>: { accuracy: N/100, issue: "..." }
```

> 🔴 **`answer_policy` 를 비우지 마세요.** 이게 *"확인할 수 없음"* 과
> *"국채라 신용등급이 부여되지 않습니다"* 를 가르는 유일한 근거입니다.
> 뒤쪽이 훨씬 높은 점수를 받습니다.

## 4. 하면 안 되는 것

| ❌ | 왜 |
| :--- | :--- |
| 결측 채우기 (평균·중앙값 대치) | **환각.** 없는 값을 만드는 것 |
| 센티넬 삭제 (`-100`·`해당없음`·더미) | 지우면 **"왜 없는지"를 못 답함** |
| 이상치 제거 (수익률 2,738%) | 실제 값으로 검증 완료 |
| 행 삭제 (만기도래 16,180 · ETN 591 · 사모 102) | 이력·질의 대응 가치. **구분만, 삭제 금지** |
| 파생 컬럼 추가 | 판정이 워크샵에서 바뀜 → DB 재빌드. **yaml 규칙으로** |
| Holdings 지금 수집 | 범위가 워크샵에서 정해짐 |
| 원본 DB에 쓰기 | 노트북 첫 셀의 `mode=ro` 를 반드시 복사해 쓰세요 |
