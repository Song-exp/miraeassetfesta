## A-2. 결측의 의미 — 4분류를 다시 세운다

`missing_reason` 은 **왜 비었는가**를 선언하는 축이고, 답변 문장이 여기서 갈린다.

| 값 | 뜻 | 답변 문장 |
| :-- | :-- | :-- |
| `not_applicable` | 그 상품엔 해당 개념이 없음 | "해당 사항이 없습니다" (❌ "모릅니다" 아님) |
| `missing` | 있어야 하는데 미수록 | "데이터가 제공되지 않았습니다" |
| `present` | 결측 없음 | 그대로 답변 |
| `mixed` | 행마다 이유가 다름 | `missing_semantics` 로 값별 분해 필수 |

**핵심 함정 — "결측"과 "0"과 "위장결측"은 다르다.**

- **위장결측**: 값이 있는데 의미 없음. 예 — 펀드 대표코드 더미 `000000000000`, `pd_lstg_dt` 0(날짜), 채권 `dur = 99`
- **센티넬**: 오류·부재 표식. 예 — 수익률 `-100`, 해외 기초지수 `'Index is not provided by...'` 2,920건(`IS NULL` 로 안 잡힘)
- **0**: 2026-08-26 주최 답변으로 규칙 확정 — *"수익률·총보수 같은 컬럼을 질의했을 때 그 컬럼의 값이 0 인 행들은 아예 포함하지 않는 게 맞다 (값이 0 이니 당연히 기준이 없음)"*

> **8/26 반영 완료**: `zero_is_value` 예외 19 → **10건**. 남는 예외는 0 이 랭킹 축이 아닌 것만 — 분류 코드 `bdbns_abl_chnl_tcd` · 목록 길이 `prfd_attr_cnt` · 자산군 미편입 `zrin_*` 7종 · **총보수 합산 성분** `ofwk_trus_rwrd_r`.
>
> 마지막 항목이 판단의 본보기다: 0 을 빼면 사무관리회사를 두지 않는 펀드 4,866건이 총보수 질의에서 통째로 사라진다. **0 제외는 합산 성분이 아니라 합산된 값에 적용한다.**
>
> → 검토 시 매 컬럼에 물을 것: **"이 컬럼이 질의의 주제(랭킹 축)인가, 아니면 다른 값의 재료인가?"**

# 트랙 B — 온톨로지/KG 구현 상태 점검

> 🆕 규칙이 **왜** 그렇게 생겼는지는 **`ontology_rules/`** (규칙 12종 · 규칙당 문서 1개 · 검토 체크리스트 60항목) 에 정리돼 있다.
> 컬럼 하나하나의 의미·결측 판정은 **`data_dictionary/`**.

## B-0. 구조부터 (여기를 모르면 나머지가 안 읽힌다)

**2층 구조** (`ONTOLOGY_BUILD_PLAN.md` §2.2~2.5)

```
ontology/enums/<domain>.yaml     담당자가 쓰는 도메인 판정
                                 (컬럼 의미 · 결측 · 함정 · query_rules)
        │  kg_entity: <개체>      ← 두 층을 잇는 단 한 줄
        ▼
ontology/shared/<entity>.yaml    횡단 공유 개체 (노드 · alias · edge · parent)
        │
        ▼   scripts/build_ontology.py   (검증 → 생성)
ontology.ttl  +  kg_node / kg_alias / kg_edge / kg_closure
                                 ← 전부 생성물. 손으로 고치지 않는다
```

**yaml 이 유일한 진실의 원천**이고 ttl·`kg_*` 는 매 빌드마다 `drop table` 후 재생성(멱등)된다. → **KG 를 고치려면 yaml 을 고친다.**

## B-2. 관계 설계 점검 — 이번 트랙의 핵심 질문

**① 무엇이 `kg_edge` 이고 무엇이 아닌가**
상품→종목(`holds`)은 **`kg_edge` 가 아니다.** 행 100만 규모라 `ext_*` 테이블 자체를 edge 로 간주하고, 플래너가 `kg_alias` 를 키로 조인한다 (`scripts/build_ontology.py:52` 주석). → 제안서에서 **"왜 그렇게 설계했나"** 를 설명해야 하는 지점(재현성 · 60초 예산 · SQLite 단일 엔진).

**② edge 는 전부 `source: rule`**
7,345건이 규칙 유도다. 사람이 본 것은 상위 150 + override 37 뿐. → 답변에 **"추정" 병기**로 방어 중. 미검수 ~3,000 중 상품 연결 수 상위 200 추가 검수가 안건 §3-3.

**③ 계층은 `parent` → `kg_closure` 로 전개**
Region 43종 국가/권역, CreditGrade 21(rank·투자/투기 밴드), Index 패밀리. 조상 전부를 빌드 타임에 풀어 둔다.

**④ alias 의 `status: pending` 은 KG 에 들어가지 않는다**
리포트에만 표시된다 (`build_ontology.py` `emit_kg()`). → **pending 이 몇 건이고 왜 pending 인지**가 커버리지 공백의 실체다.

**⑤ 축 × 도메인 연결 현황** — `graph_sources_review_2026-08-25.md` §0 표가 그대로 점검표다.

- §1 채권 — 재료는 풍부한데 **관계가 미연결**
- §2 국내ETF — 지수는 됐고 운용사·종목이 남음
- §3 해외ETF — **운용사 382종이 통째로 비어 있음**
- §4 펀드 — 상품 간 관계 재료가 가장 많은데 **전부 미사용**

- §6 우선순위 6단계

## B-3. 검증기가 보장하는 것 / 보지 않는 것

`scripts/build_ontology.py` 의 `validate()` — 통과해야 산출물이 생성된다.

| 검증 | 무엇을 잡나 |
| :-- | :-- |
| V5+V1 | 테이블·컬럼 실존 → raw 값 실존 (**죽은 alias** 검출) |
| V2 | 한 raw 값이 두 노드에 매달림 (판정 충돌) |
| V3 | `enums` 의 `kg_entity` 포인터가 `shared` 에 실존하는가 |
| V4 | 코드북 규정 — `source`·`as_of`(≤ 기준일) 필수 |
| V6 | `absent_in` 선언인데 실제로는 컬럼이 있는 경우 |

**보지 않는 것 = 사람이 봐야 하는 것**

- 노드 **라벨이 옳은가** (답변에 그대로 노출된다). Security 이름 폴백 744건, Fund 라벨 접미 제거 오작동, 동명이인 노드
- edge **규칙이 옳은가** — V 검사는 참조 무결성만 본다
- **빠진 노드** — 편입비중 상위 50 밖 종목은 노드가 없고 `ext_*` 조인으로만 조회된다
- `answer_policy` 같은 **평문 필드의 내용** — A-1 의 중복 키 사고가 바로 이 사각지대에서 났다
