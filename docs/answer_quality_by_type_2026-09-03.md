## 1. 🟢 잘 맞추는 유형

### 1-1. 개별 조회 — 정답률 90%
상품 이름을 주고 속성 하나를 묻는 질의. 이름 매칭·클래스 묶기·단위·기준일 표기가 모두 자리 잡았다.

**`T14` "한국투자베트남그로스 펀드 순자산 알려줘"** ✅
```
'한국투자베트남그로스' 이름의 공모펀드 2개가 조회됐습니다
(기준일 2026-08-24, 펀드 = 대표예탁원번호 기준·클래스 = 판매 단위).

- 한국투자베트남그로스증권자투자신탁(주식): 순자산 2,528억원 (클래스 합계) · 클래스 7개(전부 판매중)
- 한국투자베트남그로스증권자투자신탁UH(주식): 순자산 767억원 (클래스 합계) · 클래스 7개(전부 판매중)
```
잘된 지점: ① 같은 이름의 별개 펀드 2개를 **분리** ② 클래스를 합쳐 펀드 단위로 제시 ③ **무엇을 기준으로 셌는지 머리줄에 고지** ④ 판매중 여부 병기.
> 이 문항은 6R 에 **"212억원"** 한 줄이었다. 묶기 가드가 HCX 의 `AVG()` 때문에 비켜갔던 자리다.

**`V4` "KB중국본토A주증권자투자신탁 위험등급 알려줘"** ✅
```
- KB중국본토A주증권자투자신탁(주식): 위험등급 2등급(높은 위험) · 클래스 14개(전부 판매중)
```
등급 숫자에 **방향 라벨**(높은 위험)을 붙인다. 숫자만 주면 1등급이 안전한지 위험한지 알 수 없다.

### 1-2. 단일 축 집계 — 정답


## 2. 🔴 못 맞추는 유형

### 2-1. 교차질의 "A와 B는 각각" — 정답률 33% · ❌ 최대 덩어리
`❌ 30건 중 16건`이 이 얼굴이다.

**`KG-025` "삼성자산운용이 운용하는 공모펀드와 국내 ETF는 각각 몇 개야?"** ❌
```
답변:  삼성자산운용이 운용하는 공모펀드는 850개, 국내 ETF는 240개입니다.
gold:  공모펀드 207개(클래스 850개) · 국내 ETF 240개
```
**ETF 240 은 맞고 펀드만 틀렸다.** 850 은 펀드 수가 아니라 **클래스 수**다.

**`X9` "미래에셋자산운용이 운용하는 공모펀드와 국내 ETF는 각각 몇 개야?"** ❌
```
답변:  공모펀드는 2,066개, 국내 ETF는 230개입니다.
gold:  공모펀드 823개(클래스 2,066개) · 국내 ETF 230개
```
같은 형태. `S8`("KB자산운용… 몇 개야")은 `129개(클래스 625개)`로 정확한데, **"~와 ~는 각각"이 붙는 순간 클래스 수가 펀드 수로 나간다.**

**원인(코드로 확정)** — 펀드단위 집계 교체 가드가 `SELECT 목록 전체가 COUNT(*)`일 때만 발동하는데, 교차질의 가지는 항상 `SELECT '공모펀드' AS 구분, COUNT(*) …` 라 **라벨 리터럴에 막혀 한 번도 발동하지 않는다.** 단일 상품군에서 닫힌 확정식이 UNION 문장엔 안 붙는다.

### 2-2. 랭킹의 정렬 축 — 값은 맞는데 순서가 틀림

**`KG-008` "공모펀드를 가장 많이 수탁하는 수탁사 상위 3개 알려줘"** ❌
```
답변:  1. 국민은행(00020004): 1656개    2. 홍콩상하이은행 서울지점: 1827개    3. 한국씨티은행: 1466개
gold:  1. 홍콩상하이은행 714      2. 국민은행 516      3. 한국씨티은행 465
```
🔴 **1위(1,656)가 2위(1,827)보다 작다** — 개수를 물었는데 **수탁 금액 순**으로 정렬하고, 숫자는 **클래스 수**를 실었다. 축이 두 번 어긋났다.
> SQL 자체는 gold 순서를 돌려준다. HCX 가 만든 `COUNT(*) as 펀드수` 별칭이 안 지워져 **답변기가 그쪽을 읽는다.**

**`FND-R03` "기준가가 높은 순서로 좋은 펀드 알려줘"** ❌
```
답변:  조회 결과 5행입니다 (기준일 2026-08-24).
       - 종목명 우리다같이국공채법인달러MMF1호(USD)ClassC-e · 펀드 기준가/수익률 기준일자 20260821
       - 종목명 Plus 신종 법인용 MMF1호 종류C · 펀드 기준가/수익률 기준일자 20260821  …
```
🔴 **기준가가 아니라 기준가의 "기준일자"로 정렬**했다(5행 전부 20260821 동일). 게다가 원시 컬럼명이 그대로 노출되고, "기준가는 펀드 간 비교 지표가 아니다"라는 규칙이 답변에 반영되지 않았다.

### 2-3. 기준이 없는 추천·되묻기 — 되물어야 할 때 답해버린다

**`FND-C01` "규모가 큰 펀드 추천해줘"** ❌
```
답변:  순자산 상위 5개 공모펀드입니다 … 1. 삼성MMF법인제1호: 124,295억원 …
gold:  clarify (기준을 되물어야 함)
```
**값 자체는 정확하다.** 문제는 "규모"가 순자산인지 설정액인지, 개인용인지 법인용인지 안 물어보고 임의로 정한 것. 결과가 **법인 전용 MMF 일색**이라 개인 투자자에겐 무의미한 답이 된다.

**반대 방향의 실패 — `AA2` "KB중국본토A주 펀드 A클래스 기준가 얼마야?"** ❌
```
답변:  요청하신 상품은 제공된 데이터에 없습니다. 혹시 다음 상품을 말씀하신 건가요?
       — KB중국본토A주증권자투자신탁[주식]A / …
```
🔴 **되묻기 후보의 첫 줄이 정답이다.** 찾아놓고 못 찾았다고 답했다. 2-3 의 반대편 — 답할 수 있는데 되묻는다.

### 2-4. 답을 못 냄 (거절·무응답) — ❌ 30건 중 10건

**`CROSS-002` "S&P500을 추종하는 국내 ETF와 해외 ETF의 총보수를 비교해줘"** ❌
```
답변:  조건에 해당하는 상품이 데이터에서 확인되지 않습니다.
실측:  국내 순수추종 24건 실재
```
지수명 확정식이 **JOIN 이 있으면 즉시 반환**하도록 돼 있어 교차질의에선 개입하지 않는다. 그래서 `ref_base_index LIKE '%S&P500%'`(공백 없는 표기)가 0행이 되고, DB 실제 값은 `'S&P 500 CR'`(공백 있음)이다. **띄어쓰기 하나로 24건이 0건이 된다.**

### 2-5. 목록이 원시 덤프로 새는 것

**`Z18` "ETF로 자산배분하는 공모펀드 알려줘"** ❌
```
답변:  조회 결과 30행입니다 (기준일 2026-08-24).
       - 대표_itm_no KR5116601006 · 종목명 ㅊ · 클래스수 1 · 판매중클래스수 0 · 운용속성구분코드 설명 주식형
       - 대표_itm_no OS5501400003 · 종목명 젬스 리커버리 · …
gold:  9펀드 / 71클래스
```
🔴 SQL 이 주식형 전수라 무관 행이 나오고, 조립기를 못 거쳐 **컬럼명·내부 식별자가 그대로 노출**된다. 종목명이 `ㅊ` 인 행까지 실려 나간다.

### 2-6. 같은 문형인데 답 형태가 갈리는 것

**`KG-031` "피델리티가 운용하는 공모펀드는 역외펀드까지 포함하면 몇 개야?"** ❌
```
답변:  106개(클래스 246개)입니다. … 역외펀드 47개는 별도 법인이라 이 수에 포함하지 않았습니다.
gold:  153개(클래스 293개)   ← 질문이 "포함하면" 이라고 명시했다
```
**질문이 포함하라고 했는데 제외하고, 제외했다고 고지했다.** 고지는 정직하지만 요구를 안 따랐다.
형제 문항 `X12`(슈로더, 같은 문형)는 **합산으로 정답**이다 — 같은 문형에 답 형태가 두 가지다.

## 3. 오답 30건의 성질

| 성질 | 건수 | 뜻 |
| :-- | --: | :-- |
| **② 값을 냈는데 축이 틀림** | **16** | 펀드↔클래스, 개수↔금액. 숫자는 DB 에서 나왔지만 **무엇을 센 숫자인지**가 어긋난다 |

## 4. 한 문장 진단

> **질문이 축을 명시하지 않았을 때 결정층이 축을 확정하지 못한다.**

- 축이 하나뿐인 질의(개별 조회) → **90%**
- 축이 둘 이상 얽히는 질의(교차·랭킹의 정렬축·개수 단위) → **33~69%**
- 축을 사용자가 안 정해준 질의(추천) → 임의로 정하고 답해버린다

값 계산·이름 매칭·환각 방지는 이미 신뢰할 수준이다. 남은 일은 **"무엇을 세고 무엇으로 정렬하는가"를 기계가 확정하고, 확정 못 하면 되묻게 하는 것**이다.
