## 1. 🔴 확답 ① — 해외 ISIN 을 조인키로 금지하는 규칙, 어디에 넣을지

**A-2-03 으로 ⚠️ 남겨 뒀던 건데, 이번에 실제 오답 사례로 증명됨.**

| | |
| :-- | :-- |
| 상품 | `FILL.K` — iShares MSCI **Global Energy Producers** ETF (글로벌 에너지) |
| ISIN 조인 결과 | 69행이 붙음 |
| 그런데 그 69행은 | `POWR` — iShares **US Power Infrastructure** ETF (미국 전력) 의 구성종목 |

같은 ISIN 이 두 상품에 걸려 있는데 외부 데이터는 **한쪽 티커 것만** 갖고 있어서 생김.
*"글로벌 에너지 ETF에 뭐 들었냐"* 에 **전혀 다른 ETF 종목**을 답하게 됨.

같은 방식 오배정 **8건** — `CCMG.K` `STXF.K` `SIXG.O` `GSWO.K` `FILL.K` `FIBR.K` `IEQ` **`SPLG.K`**(SPDR S&P500).

### 내가 한 조치

`overseas_etfs.yaml` 에 `external_join` 블록 신설, 조인키를 티커로 교체함.

```sql
ext_ovs_etf_holdings.etf_ticker
  = replace(replace(overseas_etfs.pd_itm_no, '.K', ''), '.O', '')
```

→ **1,358 상품 · 오배정 0건.** yaml 에 적은 키를 DB 에 그대로 실행해 수치까지 확인함.

### ❓ 물어볼 것

`pd_isin_cd` 를 **단독 조인키로 쓰지 말라**는 규칙 자체는 확정으로 봐도 될 듯한데, **어디에 둘지**를 못 정하겠음.

- ⓐ `overseas_etfs.yaml` `query_rules` 에 넣기 (지금 `external_join` 에만 있음)
- ⓑ B-2(판정 상속) 로 승격
- ⓒ D절(관계) 로 승격 — 조인은 관계 문제니까

> 해외ETF 유일 키는 `pd_itm_no` **뿐**임 (행 6,037 vs ISIN distinct 5,962 · NULL 12 + 중복).
> `_identifier_dup` 에 기록은 돼 있는데 **강제하는 규칙이 없음.**

## 2. 🔴 확답 ② — `security_alias_manual.csv` 에 103종 내가 채워도 되는지

*"NVIDIA 담은 ETF"* 질의가 **어느 노드를 잡느냐에 따라 56 / 155 / 211 개**가 나감. 전부 합치면 **442개**.
챗봇은 빠뜨린 줄 모르고 답함 — *"확인할 수 없음"* 보다 나쁨.

`News Corp` 도 같음. 국내 ETF 34개가 담고 있고 **철자가 해외와 완전히 동일**한데(`News Corp`, 국내 rank 18) 국내쪽 alias 가 아예 등록 안 돼 있음.

### 이건 버그가 아니라 형이 정한 설계인 걸 확인함

`gen_security_auto.py` 주석에 이미 적혀 있었음.

> *"병합: 동일 키(티커/cusip/LEI)만 자동. **이름 동일은 병합하지 않는다 (삼성전자 ≠ 삼성전기).**
> 한↔영 교차는 **수동 코드북 parent 로만.**"*

**근본 원인은 식별자 체계가 달라서임** — 국내는 블룸버그식(`NWSA US` · `2015 HK`, 공백포함 3,517종), 해외는 CUSIP/LEI. 겹치는 키가 없어서 자동 병합이 **원리적으로 불가능**함.

### 규모 — 생각보다 작음 (103종)

처음엔 1,219종으로 셌는데 **내가 과대추정한 거였음.** 생성기가 `TOP_RANK = 50`(편입비중 상위 50위까지만 노드화)이라 51위 이하는 누락이 아니라 **설계상 제외**임(국내 4,401종 · 해외 67,671종). 조건 넣고 다시 세니:

| | 종수 | 국내ETF 연결 |
| :-- | --: | --: |
| **진짜 누락** | **103** | **213건** |
| ⓐ KG 에 노드 자체가 없음 | 60 | 122건 |
| ⓑ 노드는 있는데 국내 alias 만 없음 | 43 | 91건 |

> `Zhongji Innolight` 은 어떤 국내 ETF 에서 **편입 2위**인데 노드가 아예 없음.

### ❓ 물어볼 것

형이 만들어 둔 통로(`ontology/codebooks/security_alias_manual.csv` 에 parent 넣기)를 그대로 쓰면 **생성기·자동 yaml 안 건드리고** 해결됨.

**103종을 내가 채워도 되는지?** 코드북은 손으로 쓰는 파일이라 내 영역인 것 같은데, **채권·펀드 노드에도 영향**이 가서 혼자 정하기가 그럼.

> 오병합 위험은 낮게 잡았음 — 103종은 **철자가 완전히 동일**하고 국내 TOP50 안에 든 것만 추린 거라
> `삼성전자 / 삼성전기` 같은 케이스가 아님. 그래도 **전건 눈으로 확인**하고 넣을 생각임.

## 5. 참고 — 확답 없이도 넘어가는 것들 (공유만)

### 5-1. 국내ETF 듀레이션 3종 + 분배금이 통째로 비어 있음

| 컬럼 | 유효 | 영향 |
| :-- | --: | :-- |
| `fn_average_maturity` (평균만기) | **0 / 1,780** | |
| `fn_effective_duration` (유효듀레이션) | **0 / 1,780** | *"금리위험 낮은 채권형 ETF"* → **답변 불가** |
| `fn_modified_duration` (수정듀레이션) | **0 / 1,780** | |
| `pd_dvid_inc_dist` (분배금) | **0 / 1,780** | *"분배금 많이 주는 ETF"* · *"배당수익률"* → **답변 불가** |

*"모른다"* 가 아니라 *"이 데이터셋에 수록되지 않았다"* 로 답하게 해 뒀음.

### 5-2. 해외 구성종목 기준일이 **2~10개월 낡음**

`report_date` 가 2025-10-31 ~ 2026-06-30. 마스터 기준일(2026-08-22) 대비 최대 10개월 전.
SEC N-PORT 분기공시 주기라 **구조적이고 개선 불가**.
→ 상품별 `report_date` 병기 필수로 해 뒀음. 국내(1일 전)와 달리 *"현재 구성"* 이라 하면 오답.

### 5-3. 인버스 판별 규칙 새로 만듦 (183 → 191건)

`cu_inverse_short_yn` 플래그만 믿으면 **8건 놓침** — 플래그 NULL 인데 배수 `-2.0` 인 확정 인버스 3건(SSPC·SKDD·SPCQ) 등.
플래그 OR 음수배수 OR 상품명 병행으로 바꿈. 기존 `Y` 183건 누락 0 · 오탐 0 검증.

> ⚠️ 이름만 보면 함정 있음 — `Short Duration`·`UltraShort + Bond/Treasury` 는 **만기가 짧다**는 뜻이지 인버스 아님(안 빼면 103건 오탐).
> `BullBear`(WBI 3종)도 양방향이 아니라 **하락장 방어 얹은 상승 추종 액티브 주식펀드**임(전략 원문·자산군 Equity 로 확인).

### 5-4. 결측이 한 가지가 아니라는 걸 3갈래로 나눠 뒀음

| 결측의 정체 | 국내 | 해외 | 답변 문장 |
| :-- | --: | --: | :-- |
| 판매종료라 시세 갱신 멈춤 | 182건 | — | *"판매종료된 상품이라 최신 시세가 없습니다"* |
| 마스터 수록이 껍데기 | — | 14건 | *"이 상품은 데이터가 등록되지 않았습니다"* |
| 애초에 해당 없는 개념 | ETN 545건 | 3,630건 | *"이 상품엔 그 개념이 없습니다"* |

전부 `present` 로 두면 챗봇이 셋 다 *"데이터가 누락되었습니다"* 로 뭉뚱그려 답함.

### 5-5. 국내 구성종목 커버리지는 **답변 대상 기준 100%**

*"1,160 / 1,780 = 65.2%"* 는 오해를 부르는 모수임.
안 붙는 620건 = **ETN 545**(구성종목 개념이 없는 상품) + **판매종료 ETF 75**.
**판매중 ETF 1,160건은 미수집 0건.**

### 5-6. `pd_lstg_dt` 에 센티넬 섞여 있음

`10001231`(서기 1000년) 같은 값이 있어서 **상장 기간 계산 전에 `상장일유효` 필터를 반드시 걸어야** 함.
안 걸면 *"상장 6개월 이상"* 필터에 껍데기 상품이 잘못 들어옴.
