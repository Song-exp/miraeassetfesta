## 3. 수리 항목 (P0 ~ P9) — 일반 규칙으로만

각 항목: **소속 부류** → **일반화된 규칙** → **과적합 점검** → **회귀(형제 질문)**. 사례 표가 아니라 규칙 표다.

### P0. 개발자 사유의 기준일 어휘 (yaml 한 줄)
- `absent_properties.hasYieldHistory.why` "기준일(2026-08-22)" → "데이터 산출 시점(8/21 스냅샷) 한 시점". 고객 `answer` 는 그대로.

### P1. KG 빌드 — 정본 법인(Sec_m) ↔ 채권 발행사(Org_issuer) 를 같은 법인 키로 잇는다
- **부류**: `scripts/gen_security_auto.py` 정본 targets(kr_ticker·isin·cusip·lei 와 같은 열). 해외는 이미 `Sec_lei_*` 로 "정본 → 주식·회사채·LEI" 가 열린다. 국내는 그 자리가 비어 있다.
- **규칙**: 정본 `name_ko` 를 발행사 병합과 **같은 법인 키**(`(주)`·`주식회사`·공백 제거, `gen_shared_auto.py` 의 키)로 정규화해 `Org_issuer_*` 라벨과 일치하면 closure 후손으로 잇는다(`Sec_m_x → Org_issuer_y`). 수동 컬럼 추가 없음 — 빌드 산출물이다. V1~V7 검증 그대로(V2 "한 raw 값이 두 노드" 는 alias 가 아니라 closure 라 안 걸린다).
- **실측**: 정본 30 중 채권 발행사 법인 키 일치 **2**(에코프로 · 에코프로비엠). 나머지 28 은 국내 채권 발행이 없거나(캠브리콘·엔비디아 등 해외) 국내 종목이 아니다 → 영향 범위가 작고 셀 수 있다.
- **구현 자리(재점검으로 확정)**: `gen_shared_auto.py` 459행이 `Org_issuer_*` 노드를 만든다. 여기서 수동 코드북 `security_alias_manual.csv` 의 `name_ko` 를 같은 법인 키로 비교해 일치하면 `parent: Sec_m_<slug>` 를 적는다. `build_ontology.py` 의 closure 전개(352~376행)는 파일마다 `parents={}` 를 새로 잡지만 `(parent, child)` 첫 단은 **부모가 다른 파일에 있어도 넣는다** — `Sec_m_*` 는 부모가 없으므로 한 단으로 충분하다. 채권 경로는 `cross=False` 고정(9100행 "채권엔 ext_* 가 없다")이라 Security 정본이 접지돼도 ext 조인 가드는 돌지 않고, `_mapping_block` 은 `target_aliases` 로 대상 테이블 alias 만 싣는다 → `tests/test_closure.py::test_etf_subsidiary_expansion` 의 `"pd_pbcm" not in grounding`(ETF 대상) 단언은 그대로 성립.
- **효과**: Ground '에코프로' → `Sec_m_ecopro`(members 에 채권 alias 가 생겨 `_in_target` 통과, 같은 길이 라벨이면 값 많은 정본 우선) → `relations` → `Sec_m_ecopro_bm` → closure → `Org_issuer_에코프로비엠` → `pd_pbcm='(주)에코프로비엠'`.
- **과적합 점검**: 에코프로만 잇는 게 아니라 30 정본 전부에 같은 키 규칙. ttl 에 `subsidiaryOf` 도메인이 Security 로 남는 문제는 **안 건드린다**(온톨로지 훼손 금지) — closure 로 발행사 노드를 정본 아래 두는 것이지 관계 정의를 옮기는 게 아니다.
- **회귀**: ETF-D-022 · OFFICIAL-005(ETF 경로 불변) · "한국전력 채권"(정본 없음 → 종전 경로) · "삼성전자 채권"(정본 있고 채권 발행 0 → 0행 사유가 "발행사 미수록" 으로) · `tests/test_kg_build*` V1~V7.

### P2. Ground — '○○의 자회사' 는 자회사만 (모회사 본체 제외) ★리드 결정
- **부류**: `expand_node(relations=True)` seeds.
- **규칙**: `_SUBSIDIARY_HINT` 가 잡히고 자회사 edge 가 1건 이상이면 seeds 에서 **자기 자신을 뺀다**. 자회사 edge 가 0 이면 종전대로 자신(그리고 답변에 "자회사 정보 미수록, 본체 기준" 고지 — P7 의 must_say).
- **근거**: ETF gold 두 건이 이미 본체 제외다. 런타임만 포함하고 있었다.
- **과적합 점검**: 개체 특정 없음. 어휘는 기존 `_SUBSIDIARY_HINT`(자회사|계열사|계열회사|종속회사) 그대로.
- **회귀**: ETF-D-022(KODEX 200 · 에코프로머티 0.039% — 본체 빼도 1위 불변, 실측으로 확인) · FIN-20.
- **리드 결정 필요**: "에코프로 자회사 편입 ETF" 에서 에코프로 본체 편입분을 목록에 남길지. 권고는 **제외 + 고지**(gold 와 일치).

### P3. Gate — 업종·테마·섹터 ABSENT 선언 (`hasIndustrySector`)
- **부류**: `absent_properties`(등급 이력·수익률 이력과 같은 부류) + ttl ABSENT(빌드 V6 가 "컬럼 실재하면 거부" 를 검사 — 업종 컬럼은 없다).
- **vocab(문형만, 명사 열거 금지)**: `(?:업종|산업|섹터|테마)(?:[이은을의별로])?` · `관련\s*(?:발행사|기업|회사|종목|채권)` · `(?:분야|계열)\s*(?:발행사|기업|회사)`. 우주항공·반도체 같은 **테마 명사는 넣지 않는다** — 열거하면 다음 명사에서 다시 새고(과적합), 발행사 이름에 든 낱말('한화에어로스페이스')과 충돌한다.
- **answer(결론→이유→대안)**: "발행사의 업종이나 테마로는 찾을 수 없습니다. 제공된 채권 데이터에는 발행사 이름·종류·등급은 있지만 업종·테마 분류가 없습니다. 발행사 이름을 말해 주시면 그 발행사가 최근 6개월에 발행한 채권으로 찾아드리겠습니다." (예시 발행사명은 적지 않는다 — 업종 추론 자체가 환각)
- **불개입 조건(두 단계)**: ① `업종|산업|섹터|테마` 는 **없는 축의 이름 자체**라 접지와 무관하게 발동("은행 업종 채권" 도 — answer 의 대안 문장이 "종류(은행채·회사채…)나 발행사 이름으로" 를 안내하므로 되묻기로 충분). ② `관련 발행사/기업/회사` 문형은 Ground 가 발행사 노드에 접지되면 발행사 조회다("한화에어로스페이스 관련 채권") → 이 문형만 `hits` 가 비었을 때 발동. 구현: `gate.check(q, ctx, tables)` 는 지금 hits 를 받지 않는다(9151행, `_ground` 는 9109행에서 먼저 돈다) → 선택 인자 `grounded: bool = False` 하나 추가, 선언 항목엔 `only_ungrounded: true` 플래그. 다른 ABSENT 항목(등급 이력·수익률 이력)은 플래그 없음 = 종전 동작.
- **과적합 점검**: ETF 의 `섹터테마질의` 트리거 목록을 복사하지 않는다(그건 우회 3축이 있는 도메인의 규칙). 채권은 축이 없으므로 ABSENT 가 맞고, 리드 09-05 결정(업종축 3-hop 미선언)과 일치.
- **회귀**: gold 채권 문항 중 업종/테마/관련 어휘 **0건** → 기존 gold 무영향. 형제: "반도체 회사채 알려줘"(명사만, 문형 없음 → P4 로 감) · "은행 업종 채권"(은행채는 `bd_knd` 종류다 — `종류확정식` 이 먼저 잡히는지 순서 확인 필요 · 회귀에 포함) · "한화에어로스페이스 채권"(불개입).

### P4. Guard — LIKE 리터럴 출처 검사 (`ensure_like_literal_provenance`)
- **부류**: `forbidden_literal_use` · 값 사전 대조 옆(값 검사 부류). 지금은 "실재하는 값" 만 본다 — 실재해도 **질문에 없는 값**은 날조다(#2 `'000'` 사고와 같은 뿌리).
- **규칙**: `pd_nm LIKE '%X%'` 의 X 가 ① 질문 정규화 문자열에 없고 ② yaml 선언 리터럴 집합(`name_encoding.esg_labels`·`구조표시` CASE·`신용보강`·규칙 text 안의 LIKE 조각)에도 없으면 그 가지를 **걷어내고**(OR 가지면 결과 보존적 — `prune_dead_in_literals` 와 같은 논리) 남는 조건이 없으면 기각·재생성 사유 "질문에 없는 이름 조각 'Space'".
- **선언 리터럴 집합의 크기**: gold 채권 SQL 의 `pd_nm LIKE` 리터럴 중 질문 밖 108건 → **종류 22개**, 전부 yaml 선언(녹/사/지 4형 · 후/전환/풋 4형 · 신종·영구·물가·분리채권·유동화·콜·콜마·(정부보증)). 화이트리스트는 yaml 파싱으로 만들고 손 목록을 두지 않는다.
- **동일 부류 확장 (등급)**: `crd_grd IN (…)`·`=` 리터럴이 질문에 등급 토큰(서열표 20 + 'A등급' 통칭)이 하나도 없을 때 나오면 절을 제거 — `strip_fabricated_risk_filter`(위험등급) 의 신용등급판 `strip_fabricated_grade_filter`. 불개입 4종을 그대로 계승(질문에 등급·신용 어휘 있음 / OR 그룹 / 최상위 AND 아님 / 가드 주입분).
- **과적합 점검**: 'Space'·'우주항공' 을 적지 않는다. 검사는 "질문 ∪ 선언" 의 여집합.
- **회귀**: gold 채권 38개 전건(LIKE 리터럴 108건이 전부 화이트리스트 통과해야 함) · BND-D-019(전환사채 CASE) · "정부 보증 채권"(신용보강 A~D 층) · "ESG 채권"(4형).

### P5. Guard — 신용등급을 1차 정렬 축으로 (`ensure_grade_rank_sort` 신설, 정렬축 부류)
- **부류**: 규칙 `정렬축` + `_grade_rank_case()`(서열은 선언 `loader.grade_scale`). ⚠️ 재점검 정정 — `_SORT_AXES` 행 추가로는 안 된다. 그 가드는 ORDER BY 의 **혼동쌍 컬럼**을 정본으로 바꾸는 구조라 `ORDER BY crd_grd` 처럼 축 컬럼이 이미 맞는 경우엔 손대지 않는다. 별도 가드로 `ORDER BY [MIN|MAX](crd_grd)` 를 `ORDER BY [MIN](CASE 서열) ` 로 바꾼다(HEAD 체인은 대표행 가드가 `MIN(crd_grd)` 로 감싸므로 집계 래퍼 안쪽을 고친다).
- **발동 어휘는 `신용\s*등급` 명시일 때만.** 맨 '등급' 은 건드리지 않는다 — gold **BND-C-016 "등급 낮은 채권 알려줘" 는 되묻기**(신용등급/위험등급 다의)가 정답이고, 그 경로(`clarify.다의어.등급`)가 먼저 잡아야 한다. 이 가드는 되묻기 판정 뒤, 실제 SQL 이 나온 뒤에만 돈다.

### P8. Answer — 위험요인 재료 선언과 기계 조립 (`answer_rules.위험요인재료` + `_bond_risk_profile`)
- **부류**: ETF 최종점검 20번의 "위험요인 재료(위험등급·배수·변동성) 서술" 과 같은 자리의 **채권판 선언**. 도메인마다 재료 표 하나 — 코드는 표를 읽어 조립한다.
- **트리거**: `위험\s*요인|리스크\s*요인|위험\s*요소|주의(?:할|해야\s*할)\s*점|어떤\s*위험`. ⚠️ 재점검 정정 — '리스크'·'위험성'·'위험도' 단독은 넣지 않는다. "위험도 낮은 채권 5개" 같은 랭킹 질문에 문단 5개가 붙어 답이 부풀고, `risk_ambiguity_clarify`(가장 위험한 채권 되묻기)의 `_RISK_CUE` 와 겹친다. 위험요인 트리거가 `_RISKY_Q`·`_RISK_CUE` 어느 쪽과도 교집합이 없음을 테스트로 고정.

- **답변 측(종목당 한 문단, 데이터 값만)**: ① 투자위험등급 문구(`pd_risk_nm`) ② 신용등급 + 서열표 밴드 위치("투자적격 최하단 BBB-"/"투기등급"/"무등급 — 국공채는 평가 대상 아님·회사채는 미수록", 밴드는 코드북 `credit_grade_scale.csv` 의 밴드 2) ③ 금리위험: 듀레이션·잔존일수(`듀레이션정상` 규칙 — 0·99 는 "미산출") ④ 구조: 영구채 → "만기일 = 콜 개시일" · 후순위·전환·풋 한 단어(`구조표시` 규칙 문구 재사용) ⑤ 사모 표기 ⑥ 이자유형(할인·변동은 표면금리 해석 주석). 데이터에 없는 것(발행사 재무·업황·전망)은 **쓰지 않고** "발행사 재무·업황은 데이터에 없어 다루지 않았습니다" 한 문장으로 닫는다.

- **과적합 점검**: 에코프로·SK 를 적지 않는다. 재료 표는 컬럼·규칙 참조만. #5 처럼 30행 목록이면 문단이 30개 — 길이 상한은 "상위 5행까지 문단, 나머지는 열 값으로" 를 표에 선언(수치 근거: 기존 상한 30·답변 길이).

### P10. 0행 진단 문구 — 이름 LIKE 조건의 한국어화
- **부류**: `guard._humanize_cond`. `col LIKE '%x%'`(OR 묶음 포함) → "종목명에 'x' 표기가 든". 그러면 #3 류는 "수록된 데이터에는 종목명에 '우주항공' 표기가 든 상품 자체가 없습니다" 가 되어 "상품 자체가 없다" 왜곡이 사라진다(P3 가 앞에서 끊으면 이 경로는 다른 문형에서만 남는다).
