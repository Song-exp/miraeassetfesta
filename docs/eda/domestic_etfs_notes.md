## A. 데이터 구조 — 행 하나가 무엇인가

### A.1 식별자

| 컬럼 | distinct | 판정 |
| :--- | ---: | :--- |
| `pd_itm_no` | 1,734 | ✅ **PK** (표준코드 `KR7305080004`, 행 수 = distinct) |
| `pd_itm_no_ma` | 1,734 | ✅ 미래에셋 내부코드 (`A305080`) — 보조키 |
| `pd_nm` | 1,734 | 상품 정식명 ⚠️ 패딩 있음 → `TRIM` 필수 |
| `pd_abrv_nm` | 1,727 | 약어명 (`TIGER 200`) — 7건 중복 |

> ✅ 공모펀드와 달리 **PK 중복 없음.** 행 하나 = 상품 하나. 집계 시 `GROUP BY` 불필요.

### A.2 🔴 행에 ETF가 아닌 것이 섞여 있다 — ETN 30.7%

```sql
SELECT pd_grp_no, COUNT(*) FROM domestic_etfs GROUP BY 1;
-- ▶ ETF 1,202 / ETN 532
```

**"국내ETF마스터"인데 ETN이 532건(30.7%) 혼입.** ETN은 오타가 아니라 **다른 상품**입니다:
- ETF = 자산운용사가 운용하는 **펀드** (실물 자산 보유)
- ETN = 증권사가 발행하는 **파생결합증권** (발행사 신용위험, 만기 존재)

구분 컬럼: `pd_grp_no` (`'ETF'` / `'ETN'`).

> 🔴 **실제 오답 확인:** *"1년 수익률 높은 채권형 ETF Top3"* 를 자산군 필터만으로 조회하면
> Top3가 전부 **메리츠 인버스 국채 ETN**으로 나옵니다 (채권형 261건 중 30%가 ETN).
> → 온톨로지 `ETF owl:disjointWith ETN` 이 **실제 필터**로 동작해야 함.
> → 단 *"ETN도 알려줘"* 질의 대비, **삭제하지 말고 구분만.**

### A.3 컬럼 접두사 = 데이터 소스 & 갱신주기 (구조 발견)

컬럼명 접두사가 **데이터 출처와 갱신 주기**를 나타냅니다. 갱신일자 컬럼으로 확증:

| 접두사 | 의미 | 갱신주기 | 갱신일자 컬럼 |
| :--- | :--- | :--- | :--- |
| `pd_` | 상품 기본정보 | 정적 | — |
| `cu_` | 설정·운용 정보 | 변동 시 | `cu_upt_dt` (변동갱신일자) |
| `du_` | 일간 시세 | 매일 | `du_upt_dt` (일간갱신일자) |

## B. axis_* 유도 규칙 검증 (샘플 100건)

주최 측 schema 엑셀 `Sheet2_Sample` 의 `axis_*` 7축 정답 100건으로 채점.
`Sheet2_Sample` 에는 **`legacy_leaf`** 라는 4계층 분류 문자열도 있어 유도 근거로 활용.

`legacy_leaf` 계층 구조:
```
depth1: 패시브 / 액티브                          → strategy
depth2: 정방향1배 / 레버리지 / 인버스 / 인버스레버리지  → leverageType
depth3: 주식형 / 채권형 / 원자재형 / 통화형 / 금리현금성 / 멀티에셋 / 부동산리츠인프라
depth4: 시장대표 / 테마 / 섹터 / 스타일팩터 / 규모 / 국채 / 해외채권 …
```

| 축 | 유도 규칙 | 정확도 | 상태 |
| :--- | :--- | :---: | :--- |
| `axis_strategy` | `cu_strtegy=='액티브'`→Active, else Passive | ✅ **100/100** | 확정 |
| `axis_leverageType` | `cu_lev_fector` 값매핑 (1→Std, 2→Lev2X, -1→Inv1X, -2→Inv2X) | ✅ **100/100** | 확정 |
| `axis_distributionType` | 상품명에 `TR`/`Total Return`→TotalReturn, else Distributing | ✅ **100/100** | 확정 |
| `axis_replicationMethod` | `cu_strtegy` 실물복제→Physical / 합성복제→Synthetic | ✅ **99/100** | 확정 |
| `axis_region` | `wu_inv_rgn=='국내'`→Domestic, else Overseas (+통화선물 보정) | 🔶 **94/100** | 양호 |
| `axis_assetType` | `wu_inv_ast_type` 매핑 + 상품명 보강 | 🔶 **92/100** | ⚠️ 안건 |
| `axis_underlyingScope` | 상품명 기초자산 키워드(대표지수/단일종목/섹터) | ⚠️ **87/100** | ⚠️ 안건 |

### B.1 발견 — 5축은 DB 컬럼 하나로 유도 가능

`strategy`·`leverageType`·`distributionType`·`replicationMethod`·`region` 은
`cu_strtegy`·`cu_lev_fector`·`pd_nm`·`wu_inv_rgn` 만으로 90%+ 재현됩니다.

### B.2 ⚠️ `assetType` — 주최 기준이 우리 데이터와 상충

정답이 `wu_inv_ast_type` 과도, `legacy_leaf` 와도 안 맞는 케이스:
```
국고채10년/30년 ETF  → 데이터=채권, leaf=채권형, 그러나 정답 = Equity (?!)
머니마켓/CD금리/KOFR   → 정답 = MoneyMarket
미국달러선물인버스     → 정답 = Currency
```
> 🔴 특히 **"국고채 ETF를 Equity로 분류"** 는 상식과 반대. 주최 측 `assetType` 은
> 우리가 아는 자산군 기준과 **다른 로직**입니다. → **워크샵 안건 (F-2).**

### B.3 ⚠️ `underlyingScope` — 독립 축, 상품명 기초자산으로 결정

`legacy_leaf` 계층 위치로는 안 나옵니다 (파싱 시 오히려 76%로 하락).
정답 패턴:
```
반도체TOP10 / 200IT / 나스닥100 / S&P500 → MarketRepresentative
삼성전자단일종목 / 테슬라밸류체인          → SingleStock
그 외 테마·섹터                        → SectorTheme
```
> `assetType`·`leverageType` 과 **직교하는 독립 축.** 상품명 기초자산 규칙이 최선(87%).
>
> 🔴 **시도했으나 실패한 규칙들 (규칙으로 유도 불가 확인):**
> - `legacy_leaf` 계층 위치 → 76% (하락)
> - `pd_sect_cd=8`(단일종목ETF)을 SingleStock 으로 → **83%로 하락**. 코드8인데 정답 SectorTheme
>   (예: `KODEX SK하이닉스단일종목레버리지`), 코드2인데 정답 SingleStock(예: `테슬라밸류체인`)이 다수.
> - → **주최 기준이 상품명·코드·계층 어느 것과도 일관되지 않음.** 사람 손 주관 분류로 추정.
>   규칙 하나로 87% 천장. **워크샵에서 유도규칙 or 자체정의 결정 (F-3).**

### D.5 `cu_strtegy='C'` 409건 = ETN 전용값 (미해독 아님)

```sql
SELECT cu_strtegy, pd_grp_no, COUNT(*) FROM domestic_etfs GROUP BY 1,2;
-- ▶ 실물복제·액티브·합성복제 = 전부 ETF / 'C' 409건 = 전부 ETN
```
ETN은 발행사가 지수 수익률을 계약으로 지급하는 구조라 **"실물/합성복제" 같은 운용전략 개념이 없습니다.**
그래서 전략값이 `C`(미분류/Certificate 추정)로 통일된 것. → **미해독이 아니라 "ETN이라 전략 부재".**
`cu_strtegy='C'` 는 `pd_grp_no='ETN'` 과 함께 **ETN 판별 보조 신호**로 쓸 수 있습니다.
> 단 ETN 532건 중 `C` 409 + NULL 123 → `pd_grp_no` 가 여전히 1차 기준.

### D.2 총보수 0값 = 미입력 확정

```sql
SELECT COUNT(*) FROM domestic_etfs WHERE pd_grp_no='ETF' AND cu_charge_rt > 0;   -- ▶ 67
SELECT COUNT(*) FROM domestic_etfs WHERE pd_grp_no='ETF' AND cu_charge_rt = 0;   -- ▶ 150
```
**근거:** 상품명에 `배당`·`커버드콜`·`고배당` 포함된 명백한 배당형 ETF 113건이 배당금/보수 전부 0.
진짜 무보수·무배당이면 이름에 안 붙임 → **미입력.** ETN 532건은 총보수 **전부 NULL** (ETN은 보수 개념 다름).
> → 답변정책: "보수 낮은 ETF" 질의는 `>0` 필터 + **유효 모수 67건 명시**.

### D.6 전일NAV·전일등락금액 컬럼 깨짐 🔴 (1,137건 전부)

```sql
SELECT du_last_nav, du_nav_yday, du_nav_rnf_amt FROM domestic_etfs WHERE TRIM(pd_abrv_nm)='KODEX 200';
-- ▶ 129938.89 / 129938.89 / -129938.89
```
`du_nav_rnf_amt`(전일NAV등락금액)이 `실제 등락(오늘−어제)`인 종목 **0건**, `−전일NAV`인 종목 **1,137건(전부)**.
원인 추정: **`du_nav_yday`(전일NAV)에 오늘 NAV 값이 복사**되고, `du_nav_rnf_amt`은 `0 − NAV`로 잘못 계산됨.
→ **"어제 대비 NAV 등락" 질의에 이 두 컬럼 사용 금지.** 일간 등락은 `du_er_1d`(정상, -12~14% 범위) 사용.
> `du_last_nav`(최종NAV) 자체는 정상.

### D.7 운용사에 상품명 통째 오염 — 54건

```sql
SELECT COUNT(*) FROM domestic_etfs
WHERE pd_grp_no='ETF' AND (cu_fund_mgmt_co LIKE '%상장지수%' OR cu_fund_mgmt_co LIKE '%투자신탁%');
-- ▶ 54
```
`cu_fund_mgmt_co`(운용사) 자리에 `삼성KODEX철강증권상장지수투자신탁[주식]` 같은 **상품 전체명**이 들어감.
정상 운용사 약칭은 32종인데, 오염 54건이 각각 distinct로 세어져 `DISTINCT cu_fund_mgmt_co`가 부풀려짐(97종).
→ 운용사 목록/집계 시 **상품명 오염 행 제외 필터** 필요. 워크샵 §F-4(운용사 정규화)에 포함.

### D.8 종가(du_clpr)=0 종목 50건

만기형 채권 ETF(`KODEX 25-12 은행채` 등)·신규 상장 미거래 종목. AUM은 있으나 종가 0.
→ "종가 높은/낮은 ETF", 가격 기반 Top-N 질의 시 `du_clpr > 0` 필터로 제외.

### D.9 ✅ 수익률 250%는 오염 아님 — 실제 폭등 (검증 완료)

초기에 KODEX 200 등의 1년수익률 250%를 데이터 오류로 의심했으나 **정상 확인**:
- **같은 지수 추종 5개 운용사 ETF가 250.6~251.6%로 일치** (오염이면 불가능한 일관성)
- **기간 정합**: 1일5.4%→1개월16%→3개월67%→6개월136%→1년250% (매끄러운 우상향)
- 코스닥150은 46%로 다름 → 지수별 실제 성과 차이 반영
> ⚠️ **함의:** "수익률 높은 ETF Top-N"에 레버리지·IT/반도체가 상위 도배(실제 현상).
> `-100` 센티넬(34건)만 제외하면 값은 신뢰 가능. 레버리지 구분 노출은 워크샵 판단.
