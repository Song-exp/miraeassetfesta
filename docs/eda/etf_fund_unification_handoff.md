# 🤝 ETF ↔ 펀드 통일 제안 (펀드팀 전달용)

> **작성:** ETF 담당 · **수신:** 펀드 담당(리드)
> **결정:** 워크샵에서 **기초지수/벤치마크 = 독립 개체(B안)** 확정.
> ETF와 펀드가 **같은 개체·같은 스키마**를 쓰면 상품군 교차질의가 가능해집니다.
> 아래 2가지를 펀드쪽 구조와 맞춰주시면 됩니다.

---

## 1. 기초지수 / 벤치마크 → 독립 개체 통일 (B안)

ETF의 `기초지수`와 펀드의 `벤치마크`는 **사실상 같은 것**(추종/비교 기준 지수)입니다.
이걸 **하나의 `Benchmark` 노드**로 합치자는 제안입니다.

### 컬럼 매핑

| | ETF (`domestic_etfs`) | 펀드 (`public_funds`) | 통일 개체 |
| :--- | :--- | :--- | :--- |
| 지수명 | `cu_base_index` | `bmrk_nm` (391) | **`Benchmark`** |
| 영문명 | (해외ETF에 있음) | `bmrk_eng_nm` (388) | Benchmark.engName |
| 관계 | ETF -`tracks`→ Benchmark | FundClass -`benchmarkedTo`→ Benchmark | 공통 노드 |

> 펀드 entity map §221 "Benchmark 를 독립 개체로 세울지" 안건 = **B안으로 확정**.

### 통일하면 가능해지는 질의 (핵심 가치)

- *"S&P500 추종하는 ETF랑 그 지수 벤치마크로 쓰는 펀드 다 보여줘"*
- *"코스피200 추종 상품 (ETF+펀드) 수익률 비교"*

→ 하나의 지수 노드에 ETF·펀드가 같이 매달리므로 **한 번의 질의로 상품군을 넘나듦**.

### ⚠️ 통일 시 맞춰야 할 것 (표기 정규화)

같은 지수를 ETF·펀드가 다르게 적을 수 있어서, **지수명 표기를 통일**해야 합쳐집니다.

| 문제 | 예시 | 해결 |
| :--- | :--- | :--- |
| 표기 차이 | `KOSPI200` vs `코스피200` vs `코스피 200` | 정규화 규칙 필요 |
| ETF 결측 89% | `cu_base_index` 대부분 빈값 | ETF는 **상품명에서 지수 유추** (예: "TIGER 미국S&P500" → S&P500) |

> 👉 **부탁:** 펀드 `bmrk_nm`의 distinct 391개 표기 목록을 공유해주시면,
> ETF쪽 지수명과 대조해서 **공통 지수 매핑표**를 만들겠습니다.

## 2. 구성종목(Holding) 스키마 통일

### 현황: ETF·펀드 **둘 다 마스터에 구성종목 없음** → 외부수집 필요

- ETF: 마스터에 구성종목 컬럼 자체가 없음 → **FunETF 공개 API로 외부수집** (7/10 기준, 테스트 20종 완료)
- 펀드: `itm_no`는 **판매클래스(ShareClass)**지 편입종목이 아님 → 펀드도 편입종목은 외부수집 대상

→ **같은 외부수집이니 저장 스키마를 처음부터 통일**하면 KG에서 한 테이블처럼 조인됩니다.

### 제안 스키마 (ETF·펀드 공통)

```
product_code   상품코드 (ETF 종목코드 / 펀드 종목번호)
product_type   ETF | FUND        ← 상품군 구분
ticker         편입종목 코드 (예: 005930)
constituent    편입종목명 (예: 삼성전자)
weight_pct     비중(%)
quantity       구성수량 (없으면 공란)
as_of          기준일 (2026-07-10)
```

> ETF쪽 실제 저장 예시 (`data/external/holdings/`):
> ```
> KR7069500007, KODEX 200, 005930, 삼성전자, 32.96, 6978, 2026-07-10
> ```
> 여기에 `product_type` 컬럼만 추가하면 펀드와 공용 테이블이 됩니다.

### 통일하면 가능해지는 질의

- *"삼성전자를 편입한 상품 (ETF·펀드 전부) 비중순으로"*
- *"에코프로 담고 있는 ETF와 펀드"*
