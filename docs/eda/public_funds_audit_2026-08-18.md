## 3. yaml 반영 내역 (4건)

### 반영 ① 위험등급 저장형태 판정 정정 — `numeric_string_columns`

| | 이전 판정 | 실측 (현행 DB) |
| :--- | :--- | :--- |
| 저장형태 | 문자열 '1.0'~'6.0' | **REAL** (typeof 실측) |
| `= '6'` | 0건 | **2,397행** (REAL 친화 변환으로 매칭) |
| `= '6.0'` | 338건 | 2,397행 — **338 은 행이 아니라 종목 수**였다 |

- 이전 판정은 구 dtype=str 빌드 DB 기준. 현행 `build_db.py` 는 이 컬럼을 REAL 로 적재한다.
- **CAST(... AS INTEGER) 규칙은 두 저장형태 모두에서 동일 결과** → 규칙 유지, 근거·검증 문구만 정정.
- 수정 위치: `columns.zrin_fd_ivst_risk_gcd.layer.scale` · 동 `answer_policy` · `normalization.numeric_string_columns`

### 반영 ② `query_rules.수익률정상` 개정

이전: `fd_yr1_ern_r > -100 AND fd_yr3_ern_r > -100` (고정 2컬럼)
개정: **질의 대상 기간 컬럼에 `> -100 AND IS NOT NULL`** (ETF 규칙과 같은 단일 컬럼형)

근거 2가지 (실측):
1. **NULL 함정** — 5년 수익률은 있는데 1년/3년이 NULL 인 종목 74개. SQL 에서 `NULL > -100` 은 행을 탈락시키므로 5년 Top-N 에서 74종목이 부당 탈락한다.
2. 오류값(<-100)은 mm18·yr2·yr3·yr5 4개 컬럼에 존재 (전부 KCGI베트남 KR515303001M 1종목, 최저 -4,381%). 고정 2컬럼으로는 커버 의도가 불투명하다.

### 반영 ③ `row_grain` 블록 신설 — 행 구조의 완전 증명 (A급 승격)

```
95,619행 = 종목(itm_no) 11,139 × 속성태그(prfd_attr_cd)
(itm_no, prfd_attr_cd) 조합 수 = 정확히 95,619 (완전 일치)
종목 안에서 값이 갈리는 컬럼 = 45개 중 prfd_attr_cd 단 하나 (전수 검사)
```

- 이 테이블은 종목 마스터가 아니라 **종목×속성태그 롱 포맷**이다. 8.6배 행 중복의 정체.
- 기존 `query_rules.종목단위` 가 경험칙이었다면 이제 수학적 증명이 붙었다.
- 파생 규칙 명문화: prfd_attr_cd 질의가 아니면 **COUNT(\*) 금지 → COUNT(DISTINCT itm_no)**, SUM/AVG 는 종목 축약 선행.
- 이 yaml 에서 반복 정정된 '행 기준 vs 종목 기준' 수치 혼동(§반영① 338 사건 포함)의 뿌리가 이 구조다.

### 반영 ④ `columns.int_dvd_desc` 판정 신설

- '배당' 99.99% vs **'이자' 10행 = 단 2종목** (G4한바구니장기 · 칸서스국공채MMF법인1호, 둘 다 판매완료)
- 준상수 — 필터 축으로 쓰지 말 것. '이자 지급형' 질의는 모수 2종목(판매완료) 명시.

## 4. 🔴 워크샵 안건 (팀 결정 필요)

### 안건 1 — 정본 DB 확인: 배포 서버 DB 와 재빌드 DB 의 dtype 이 다를 수 있다

- 배포 서버의 `financial_products.db`(dd9b482, md5 `29767df7…` 확인본)는 **dtype=str 빌드**로 추정된다
  (yaml 의 구 판정 "= '6' → 0건" 이 그 DB 에서는 참이었을 것).
- 로컬 재빌드 DB 는 현행 `build_db.py` 기준 — zrin·frc_bpr·hdge·ofsfd 가 **REAL** 이다.
- CAST 비교 규칙 덕에 런타임 결과는 같지만, **문자열 정확일치를 쓰는 코드가 어딘가 생기면 두 DB 에서 결과가 갈라진다.**
- 결정할 것: ① 정본을 어느 쪽으로 못 박을지 ② 서버 재기동(8/30 데드라인) 시 DB 를 재반입할지 ③ `build_db.py` 에 dtype 명세를 고정할지.

### 안건 2 — 수익률정상 규칙의 런타임 반영 방식

- 개정 규칙은 "질의 대상 컬럼에 건다" 는 **매개변수형**이라, 고정 문자열 주입이던 기존 런타임 설계와 형태가 다르다.
- 결정할 것: SQL 생성기가 정렬/필터 컬럼을 인식해 조건을 끼워 넣는 방식 확정 (ETF `du_er_1y` 규칙도 동일 구조로 통일 가능).

### (참고) 기존 pending 안건과의 관계
