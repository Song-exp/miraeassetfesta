## 1. 무엇을 하는 중인가

공모펀드 EDA를 **1차(`public_funds_eda.ipynb`)와 무관하게 처음부터** 다시 하고 있습니다.
현재 주제는 **"1. 코드별 매칭"** — 같은 종목을 여러 코드로 지칭하는 관계를 밝히고,
NaN이 **미부여**인지 **결측**인지 판단하는 것입니다.

재작업 이유: **DB가 `dtype=str`로 재구축되어 선행 0이 복구**되었습니다.
`or_co_xtn_itt_cd`가 `40010.0` → `'00040010'`이 되면서 앞 4자리 기관종별이 살아났고,
1차 EDA의 코드 구조 분석은 전부 무효입니다. (`data/financial_products.pre_dtype.db`가 구버전)

최종 목적은 **금융상품 Agent**입니다. 식별자 분석이 거기서 하는 일:
집계 시 행 단위 오류 방지 · 사용자가 어떤 코드로 물어도 같은 종목에 도달 ·
`미부여`("해당 없음")와 `결측`("제공되지 않음")을 다른 문장으로 답하기.

## 4. 확정된 결론

### 4.1 행 구조와 키

```
행 95,619 = 종목 11,139 × 속성태그 (평균 8.6배)
PK: (itm_no, prfd_attr_cd)  ← 검증 완료, 중복 0건
종목 안에서 코드 9종은 전부 값이 하나로 고정 (축약 안전)
```

### 4.2 모펀드의 진짜 키는 합성키

`mtco_itm_no`는 **운용사 내부** 번호라 전역 유일이 아닙니다.

```
mtco 단독 distinct 4,573  vs  (or_co, mtco) 합성 4,643
65종의 mtco 값이 최대 3개 운용사에 걸침 → 단독 키로 조인하면 남의 펀드와 뭉침
```

### 4.3 기관별 코드 구조

| 기관 | 발견 |
| :--- | :--- |
| 운용사·수탁사 | 8자리 = 종별(4) + 번호(4). 운용사 종별 `0004`/`0008`, 수탁사 `0002`(대부분)/`0005`/`0016` |
| 금감원 `fss` | `앞7(운용사 식별부) + C + 뒤4(일련)`. 앞 7자리 81종 중 **75종이 운용사 1개에 대응** |
| 예탁원 `rptt` | `앞5(운용사 식별부) + 뒤7`. 접두 69종 중 **66종이 운용사 1개에 대응** |
| 협회 `kofia` | 20자리. 같은 펀드 안에서 6·10·11번째 자리가 갈림 → **클래스 수준 분류** (모펀드의 45.9%가 갈림) |

### 4.4 도메인 불변식 성립

**펀드당 수탁사 1개** (자본시장법의 운용/보관 분리): 모펀드 4,643개 중 위반 **9개(0.19%)**뿐.
위반 9건은 수탁사 이관 이력 또는 오염 후보 — 개별 확인 대상.

### 4.5 두 기관의 "펀드" 경계가 다름

```
예탁원 대표 묶음 2,610개  vs  운용사 모펀드 묶음 4,225개
두 묶음이 완전히 같은 종목 68.0% · 예탁원 묶음 1개에 모펀드 2개 이상인 경우 560개
```
어느 쪽이 틀린 게 아니라 **묶는 기준이 다른 것**입니다.

### 4.6 모자형 — 모펀드는 이 테이블에 없다

```
자투자신탁 7,191 + 자투자회사 29 = 7,220종목 (64.8%)
모투자신탁 0 · 모투자회사 0
```

도메인상 타당합니다. 모펀드의 집합투자증권은 **자펀드만 취득 가능**해 투자자에게 팔 수 없고,
이 테이블은 판매 상품 마스터(`sale_yn`, `thco_sale_yn`, 클래스, 위험등급)입니다.
→ **자펀드의 실제 편입자산은 이 테이블 밖에 있습니다.** 포트폴리오 질의는 구조적으로 답 불가.

`(or_co, mtco)` 묶음은 **모자형이 아니라 한 펀드의 클래스 묶음**입니다
(기본명 1종 80.9%, 나머지는 `K-1` vs `K-1호` 표기 변형 · 자/일반 혼재 17개뿐).

### 4.7 실질 결측 — 코드별 (종목 11,139 기준)

```
fss_itm_no    3,023 (27.1%)   대부분 '000000000000' 더미
kofia_fd_ccd  2,891 (26.0%)   '0'×20 더미

동시 결측 패턴에서 `RFC`가 함께 비는 437종목은 **전원 판매완료 + 평가데이터 부재** —
비어있음이 무작위가 아니라 한 그룹을 가리킵니다.

### 4.8 더미·오염 유형 (`eff_empty` 정의에 반영됨)

```
잡음: NULL · 공백 · 0패딩 (KR)?0+ · 한 문자 반복 (.)\1+  ('9999999999' '11' 'PP')

## 5. 가설 — 미확정 (도메인 근거 없음)

### 5.1 `M109` / `kofia` 5번째 자리 = 모자형 인코딩?

종목명의 `자` 마커를 정답으로 놓고 후보를 전수 채점한 **순수 데이터 유도** 결과입니다.

| 규칙 | 정확도 | 기준선(68.0%) 대비 |
| :--- | ---: | ---: |
| `prfd_attr_cd`에 `M109` 있으면 자펀드 | 95.9% | +27.9%p |
| `kofia_fd_ccd[5] == '3'`이면 자펀드 | 93.9% | +25.9%p |

두 신호가 **서로 96.0% 일치**해 같은 무언가를 인코딩하는 것은 유력하지만,
**그게 정확히 모자형인지는 미확정**입니다. 주의점:

- 정답 라벨(이름 마커) 자체가 프록시 — **프록시 대 프록시 상관**
- 528건 적용은 **외삽** — 검증은 이름 있는 종목에서만 했는데, 528건은 명명 규칙이 깨진 집단
- `prfd_attr_cd` M축·`kofia` 자리별 의미는 기존 EDA에서도 **미해독**

**확정 방법:** `1.금융상품/PRFD01N001_공모펀드마스터_schema.xlsx`에 `prfd_attr_cd` 코드
설명이 있는지, 또는 금투협 표준코드 정의표를 구할 수 있는지. **아직 안 뒤져봤습니다.**

### 5.2 기타 미해결

- `rptt` 꼬리 7자리 == 그룹 대표의 mtco → 86.7%. 나머지 13.3% 중 95.5%는 대표가 이 테이블 밖
  (사모인지 청산인지 **구분 불가** — 사모 마스터 없음)
- `fss` 공유 25종 중 3종은 서로 다른 모펀드 간 공유 → 오염 후보, 미확인
- 수탁사 불변식 위반 9건 미확인
- `kofia` 6·10·11번째 자리가 클래스의 **무엇을** 인코딩하는지 미해독
