## A. 데이터 구조 — 행 하나가 무엇인가

### A.1 3단 계층

```
mtco_itm_no (운용사종목번호)   4,660  ← 운용 단위 = 모펀드
   └ itm_no (종목번호)        11,139  ← 클래스 = 판매 단위
        └ prfd_attr_cd          228종  ← 속성 태그 → 95,619 행
```

**행 = (클래스 × 속성태그)** 이고, 종목당 태그가 4~16개라 평균 8.6배로 부풀어 있습니다.
이름·수익률·순자산 등 나머지 컬럼은 모든 행에서 동일합니다.

```sql
SELECT COUNT(*), COUNT(DISTINCT itm_no) FROM public_funds;
-- ▶ 95,619 / 11,139
```

계층 검증 — `삼성MMF법인제1호` 4개 클래스가 같은 `mtco_itm_no` 공유:

```sql
SELECT trim(itm_nm), itm_no, mtco_itm_no FROM public_funds
WHERE itm_nm LIKE '삼성MMF법인%제1호%' GROUP BY itm_no;
-- ▶ C / Cp / Ce / Cpe  →  mtco_itm_no 전부 '0123604'
```

### D.9 `해당없음` 을 결측으로 본 것은 오판 — 정정

처음에 `prvo_fd_desc='해당없음'` 95,451건과 `pers_corp_desc='해당없음'` 73,054건을
센티넬(위장 결측)로 분류했습니다. **틀렸습니다.**

```sql
SELECT trim(prvo_fd_desc), trim(prvo_pbff_desc), COUNT(*)
FROM public_funds GROUP BY 1,2;
-- ▶ ('해당없음','공모') 95,451 / ('일반사모(2015년전)','사모') 102   ← 1:1 완전 대응
```

`'해당없음'` 은 **"공모라서 사모 세부구분이 없다"는 정보**입니다.
`pers_corp_desc='해당없음'` 도 "개인/법인 전용이 아닌 일반 펀드"라는 정보입니다.

이 오판으로 결측률이 **99.9% / 76.5%** 로 부풀려져 있었습니다. 실제는 각각 **0.1%** 입니다.

→ `ontology/enums/public_funds.yaml` 에 `not_applicable` 로 선언 완료.
→ 프로파일러의 `SENTINEL_PATTERNS` 도 `not_provided` / `not_applicable` 두 갈래로 분리했습니다.

**교훈:** `Not Provided`(제공 안 됨 = 결측)와 `Not Applicable`(해당 없음 = 정보)은 다릅니다.
한국 금융 데이터의 `해당없음` 은 대개 후자입니다.
