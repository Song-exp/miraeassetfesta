## 0. 읽는 법

### 0.1 근거 등급 — 값의 뜻마다 붙습니다

| 등급 | 뜻 | 답변에서 할 수 있는 것 |
| :-: | :--- | :--- |
| **A** | 도메인 법·구조 근거 + 데이터 정합 | **이유를 말해도 된다** |
| **B** | 독립 지표 여러 개가 일치 | **조건부로 말해도 된다** |
| **C** | 관측만. 인과 아님 | **사실만 병렬 서술. 이유 금지** |
| **❌** | 뜻을 모른다 | **값을 그대로 노출하지 말 것** → §4 |

### 0.2 이 문서의 규칙

- **관측과 판정을 섞지 않습니다.** 건수·비율은 실측이고, "뜻" 칸은 판정이며 등급이 붙습니다.
- **뜻을 모르면 모른다고 씁니다.** 그럴싸한 추정을 뜻 칸에 넣지 않고 §4로 보냅니다.
  🔴 값의 뜻을 모르는 컬럼은 **필터로도 쓰지 않습니다** — 코드값을 그대로 답변에 내보내면
  *"펀드설정유형은 20입니다"* 같은 문장이 나옵니다.
- 여기서 확정된 뜻은 `ontology/enums/public_funds.yaml` 의 **`value_semantics`** 블록으로
  그대로 옮깁니다 (§5). 현재 그 필드는 **45컬럼 전부 비어 있습니다.**

### 7.7 🔴 부수 발견 — 순자산 집계 함정 (`SUM` 이 3.31배 과대계상)

결측 프로파일을 만들다 드러난, **결측과 무관하지만 더 위험한** 문제입니다.

```
삼성MMF법인제1호  C 클래스  12,440,162,407,400 원
                 Cp 클래스 12,440,162,407,400 원   ← 같은 값이 반복된다 (분할이 아니다)

다클래스 펀드 1,513개 중 전 클래스 순자산이 동일한 펀드 1,144개 (75.6%)
   → 0 을 결측으로 정규화하면 1,234/1,502 (82.2%) 로 올라간다

전체 SUM      1,545조 8,239억 원
펀드별 MAX 합   466조 7,214억 원      🔴 SUM 이 3.31 배 과대계상
```

> 🔴 **`yaml` 의 `fd_nast_suma.answer_policy` 가 "GROUP BY mtco_itm_no 필요"라고만 적혀 있어
> 집계 함수를 명시하지 않았습니다.** `SUM` 을 쓰면 3.31배 틀립니다.
> **`MAX`**(또는 펀드당 1행 선택)를 써야 합니다.
> ⚠️ 0 배제 후에도 값이 갈리는 다클래스 펀드가 **268개** 남습니다 — 이 펀드들은 `MAX` 도 근사값이며
> 클래스별 순자산인지 기록 시점 차이인지 미확정입니다. 펀드 단위 순자산 질의에 이 한계를 붙이세요.

### 7.11 ✅ 수익률 결측 4갈래 재검증 — 기존 판정은 유효, 근거의 순서를 바꿉니다

기존 판정은 **`NULL` 만 결측으로 보고** 만든 것이었습니다. §7.3.2의 `0.00` 위장결측을 반영해
11,130종목을 두 정의로 전수 재분류했습니다.

#### 7.11.1 결과 — 판정은 유효하고, 오염 배제로 미세 조정됩니다

| 갈래 | 기존 기재 | 재산출 (오염 배제) | 확정규칙 적용 후 | 판정 |
| :--- | ---: | ---: | ---: | :--- |
| 완전 | 5,482 | 5,482 | **5,413** | 해당없음 |
| 접미결측 | 1,994 | 1,994 | 1,994 | `not_applicable` |
| 구멍 | 127 | **126** | 126 | 데이터 오류 후보 |
| 전무 | 3,536 | **3,528** | **3,597** | `missing` |
| 합계 | 11,139 | **11,130** | 11,130 | |

```
오염 배제분  구멍 −1 · 전무 −8  (오염 9종목이 이 두 갈래에 있었다)
확정규칙     zero_as_missing.수익률_9기간전부0 (69종목) → 완전에서 전무로 이동
             🔵 이 69종목이 '완전 → 전무' 이동분과 정확히 일치했다 — 규칙과 분류가 서로 검증됨
```

#### 7.11.2 🔴 `0.00` 을 전면 결측으로 보면 안 됩니다

| 갈래 | 기존 정의 (`NULL`만) | 신 정의 (`NULL`+`0.00`) | 변화 |
| :--- | ---: | ---: | :--- |
| 완전 | 5,482 | 5,170 | −312 |
| 접미결측 | 1,994 | 1,934 | −60 |
| **구멍** | **126** | **408** | 🔴 **3.2배** |
| 전무 | 3,528 | 3,618 | +90 |

**이동 372종목(3.34%)** — 완전→구멍 243 · 완전→전무 69 · 접미결측→구멍 39 · 접미결측→전무 21

구멍 408종목을 쪼개면 성질이 다른 두 집단입니다:

```
좌측결측       194종목   패턴 '·······OO' 63 · '········O' 40 …
                        = 최근 단기 수익률이 0.00. §7.3.2의 '5기간 0 + 장기 비영' 군과 같은 집단
진짜 중간구멍   214종목   = 운용기간으로 설명되지 않는 데이터 오류 후보
```

> 🔴 **두 종류를 한 갈래로 뭉치면 "구멍 = 데이터 오류" 라는 판정 자체가 오염됩니다.**
> 확정 규칙(9기간 전부 0 = 69종목)만 적용하고, 개별 `0` 은 값으로 둡니다.

#### 7.11.3 🔴 접미결측 근거의 순서를 바꿉니다

기존 `yaml` 이 근거로 나란히 적어둔 두 지표가 **강도가 전혀 다릅니다.**

| 근거 | 기존 정의 | 신 정의 | 판정 |
| :--- | :--- | :--- | :--- |
| **형제 클래스 대조** (형제가 더 긴 이력) | 32.7% (653) | **32.5%** (629) | ✅ **정의와 무관하게 견고 → 주근거** |
| 우측결측 vs 구멍 비율 | 94.1% : 5.9% | **82.6% : 17.4%** | 🔴 **정의 의존 → 단독 인용 금지** |

> 판정(`not_applicable`)이 뒤집히지는 않습니다. 다만 *"무작위 적재 누락이면 구멍이 더 많아야
> 한다"* 는 논거는 **결측 정의를 바꾸면 3배 흔들리므로** 보조 근거로 내려야 합니다.
> `evidence_grade: B+` 를 지탱하는 것은 형제 대조입니다.

#### 7.11.4 ★ 새 발견 — 순자산 결측과 수익률 전무는 사실상 같은 사건

```
순자산이 결측이거나 0 인 2,142종목 중 2,141 (99.95%) 이 수익률 전무 그룹
역방향: 수익률 전무 3,528종목 중 순자산 결측·0 은 2,141 (60.7%)
```

> 🔑 *"평가 데이터 소스가 통째로 없다"* 는 전무 그룹 판정을 **강하게 뒷받침합니다** —
> 순자산과 수익률이 한 소스에서 함께 들어오지 않은 것으로 보입니다.
> ⚠️ **단방향입니다.** 순자산이 있어도 수익률이 전무인 종목이 1,387개(39.3%) 있습니다.
> 인과로 서술하지 마세요.

#### 7.11.5 전무 그룹 판별 지표 — 하나가 틀렸습니다

| 지표 | `yaml` 기재 | 재현값 | 판정 |
| :--- | ---: | ---: | :--- |
| 위험등급 보유 | 27.3% | 27.4% | ✅ 재현 |
| 판매중 비율 | 26.2% | 26.2% | ✅ 정확 일치 |
| **순자산 보유** | **47.7%** | 47.6% (`NULL`만) / **39.3%** (`0` 포함) | 🔴 **`NULL` 만 센 수치** |

그리고 **완전·접미결측·구멍 세 그룹은 위험등급·순자산이 모두 100%** 입니다 — 이 지표들은
*"전무 그룹과 다르다"* 만 말하고, 나머지 세 갈래를 서로 가르지는 못합니다(판별력 0).
