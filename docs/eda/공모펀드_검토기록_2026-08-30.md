## 0. 이 회차가 무슨 작업인가 (쉬운 말)

**③이 핵심인 이유** — 규칙을 아무 컬럼에나 걸면 **정상값이 통째로 사라진다.** 이번에 그 반례를 두 개 실측으로 잡았다(§3). yaml 의 `🔴_화이트리스트_필수` 경고가 옳다는 것이 수치로 확인됐다.

## 2. 규칙 층위 지도 — `dummy_as_missing` 은 **공모펀드에만 있다**

4개 도메인 yaml 의 `normalization` 을 전부 열었다.

| 도메인 | 결측을 만들어내는 규칙 |
| :-- | :-- |
| **`public_funds`** | `dummy_as_missing` · `zero_as_missing`(기본 + **보수_3종전부0** + **센티넬 `fd_last_dstb_r = -100`** 73행) · `value_variants`(표기 변형 → 정확일치 조회 시 누락) · `contaminated_rows`(2차 0건) · `invalid_values`(2차 0건) |
| `domestic_bonds` | `zero_as_missing` (기본 · `zero_is_value` · `zero_as_missing_columns`) |
| `domestic_etfs` | `zero_as_missing_default` · `zero_is_value_columns` |
| `overseas_etfs` | **없음** (`trim_columns` · `language_note` 뿐) |

**읽는 법**

- 결측은 **한 가지 규칙에서만 나오지 않는다.** 공모펀드만 해도 ⓐ NULL ⓑ 더미 ⓒ 0 ⓓ 센티넬(-100) ⓔ 보수 3종 동시 0 ⓕ 표기 변형 — **여섯 갈래**다. `missing_reason` 한 글자가 이 전부를 대표하지 못한다.
- **위장결측(더미) 규칙을 가진 도메인은 공모펀드 하나**다. 이것이 이번 스캔의 출발점이었다.

```sql
(C IS NULL                                                    -- ① 물리 NULL
 OR trim(C)=''                                                -- ② 공백/빈 문자열
 OR replace(replace(trim(C),'KR',''),'0','')=''               -- ③ KR·0 만 남으면 빈값

     AND replace(trim(C), substr(trim(C),1,1), '')=''))       -- ④ 첫 글자가 전부 반복 ← 이걸 빼먹어 왔다
```
