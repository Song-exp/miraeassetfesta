## 4. 오늘 결정층에 들어간 규칙 (2026-09-05 밤 ~ 06 새벽, R12~R14)

- 확정식이 축을 심었으면 남은 환각 컬럼 절을 걷는다 — OR 가지만, 성한 컬럼 보존
- 집계 GROUP BY 위치 표기 제거 · 조건부 집계 0 에 실제 값(수탁사 KG 이름) 병기
- 랭킹 축 컬럼이 SELECT 에 없으면 덧붙이고 정렬 · 질문이 명시한 개수 → LIMIT · 고유키 묶음의 HAVING COUNT 제거
- 접지 코드 컬럼 교정 · 부재 속성 컬럼 교정 · 보수 0 제외 · 대표행 MIN(MIN) 이중 감싸기 수정 · 이름 LIKE → 접지 코드 등호
- 존재 질의 → 개수 집계 + 예/아니오 · 역외 포함 합산 · 연환산 부재 즉답에 누적값 병기
- SELECT 에만 있는 환각 컬럼은 항목만 걷기 · 유일 근사 치환의 별칭 처리 · 재생성 실패 뒤 실재 상품은 수록 항목 조회
- **개요 조회 확정식**(HCX 0회) · 위험등급 방향 · 목록 판정 확장 · 이름순 ORDER BY 는 목록 묶기가 걷기
- **보유종목 JOIN → 펀드 키 IN-부질의** · 확정 랭킹/목록 형태 · 전용 조립기 · 유형 축의 국가 확장

## 7. 팀에 넘기는 진단 하나

**외부표 JOIN 이 들어오면 도메인 가드가 한꺼번에 꺼지는 사각.** 펀드에서 보유종목 JOIN 이 랭킹·대표행·보수 가드를 전부 비켜갔고, 처방은 JOIN 을 키 IN-부질의로 바꿔 바깥 문장을 단일 테이블로 되돌리는 것이었다. 공식 예시 ETF 상 문항(에코프로 자회사 편입 ETF 순자산 큰 상품의 위험요인)이 KODEX 200 한 줄로 떨어진 것은 같은 구조의 증상으로 보인다. `eval/probe_official8_2026-09-06.json` 에 원문 실측이 있다.
