## 2. 단계 2 — `absent_properties` 에 `hasInvestmentStrategy` (`OFFICIAL-002`❌)

보고서 §🔧① 이 "한 줄 추가" 로 제안한 항목이다. 방향은 맞지만 **그대로 넣으면 안 된다.**

게이트는 질문 단위 전부-아니면-전무다(`gate.check` ①-0 은 즉시 return). `OFFICIAL-002` 의 질문은
"국민성장펀드의 **구조와** 투자전략 동향 등" — 복합 질문이다. `투자전략` 어휘로 통째 게이트하면
기대 답변이 요구한 **구조·보수·환매(모두 `ext_fund_page` 에 실재)를 못 답하게 된다.**
통과 조건("전략을 서술하지 않는다")은 만족하지만 답변 품질은 내려간다.

**2단 구성으로 간다:**

1. `absent_properties` — 순수 전략 질의만. 앵커 부정선행으로 답할 수 있는 축이 같이 물린 질문은 뺀다.
   ```yaml
     - property: hasInvestmentStrategy
       why: "펀드의 운용 전략·투자 전략 서술은 마스터에도 설명서 수집분(ext_fund_page 20컬럼)에도 없어 답할 수 없습니다."
       vocab: ["^(?!.*(?:구조|보수|수수료|환매|설정일|클래스|모펀드)).*(?:투자[ ]?전략|운용[ ]?전략|운용[ ]?방침|전략[ ]?동향)"]
       substitute: {column: "zrin_btyp_nm·or_attr_desc·prfd_attr_cds", note: "펀드 유형(주식형·채권형…)·약관 분류(재간접·파생상품)·속성 태그(투자 국가·지수)는 안내할 수 있습니다."}
   ```
2. `answer_rules` 한 줄 — 복합 질문이라 SQL 이 도는 경로를 잡는다.
   > "조회 결과에 없는 항목을 **서술하지 않는다** — 특히 운용 전략·투자 방침·시장 전망은 어느 컬럼에도
   > 없다. 부인 문장('확인할 수 없습니다')을 쓴 뒤에 같은 답변에서 그 항목을 단정하는 것은 환각이다
   > (2026-09-04 `OFFICIAL-002` 실측: '전략은 확인 불가' 라고 쓰고 바로 앞줄에서 '국내 주식·채권 분산 투자'
   > 라고 단정)."

`substitute` 는 **있는 컬럼만** 적는다(좌수 환각 때의 규칙 그대로).

**닫히는 문항: ❌1.** 위험 — 부정선행 정규식은 게이트 어휘 중 처음 쓰는 형태다. 형제 질문
"미래에셋코어테크 펀드의 투자전략 알려줘"(게이트 발동) / "…의 구조와 보수 알려줘"(미발동) 두 개로 검증.

## 3. 단계 3 — `query_rules` 에 **SELECT 별칭 규약** (‰→%) 🔴 두 번째로 중요

`FND-005` 의 ‰→% 10배 오류는 `answer_rules` 에 이미 규칙이 있는데 지켜지지 않았다. 문장을 더 쓰는 건
같은 실패를 반복하는 일이다. **이 저장소에는 이미 작동하는 대안이 있다** — `순자산_억원` 별칭.
`answer_rules` 의 "순자산은 결과의 순자산_억원 값을 그대로 옮겨 말한다" 는 실측에서 지켜지고 있다
(`Y2`·`V5`·`FND-C01` 전부 억원 표기 정확). **값 변환은 문장이 아니라 SQL 이 하게 한다.**

`query_rules` 에 추가:

```yaml
  보수단위:
    triggers: [보수, 총보수, 수수료, 비용, 저렴, 낮은 보수]
    text: >-
      🔴 마스터 보수 4종(or_co_rwrd_r·sale_co_rwrd_r·trusc_rwrd_r·ofwk_trus_rwrd_r)은 **‰(천분율)** 이다.
      보수를 SELECT 할 때는 반드시 % 환산 별칭을 함께 낸다 — 답변기가 단위를 바꾸지 않게 하는 유일한 방법이다:
        ROUND((or_co_rwrd_r + sale_co_rwrd_r + trusc_rwrd_r + ofwk_trus_rwrd_r) / 10.0, 4) || '%' AS "총보수_퍼센트"
      (순자산_억원 별칭과 같은 규약이다.) 설명서 보수(ext_fund_page.total_fee_pct)는 이미 % 라 환산하지 않는다 —
      두 출처를 한 답변에 섞을 때는 어느 쪽인지 밝힌다.
```

+ `answer_rules` 한 줄: "보수는 결과의 `총보수_퍼센트` 값을 그대로 옮겨 말한다 — 원값(‰)을 % 기호와 함께
적지 않는다."

**닫히는 문항: `FND-005`❌ 의 단위 결함 + `DOM-06`❌ 의 절반.**
(`FND-005` 의 목록 붕괴 '2.3.4.' 와 클래스 수 불일치는 조립기 결함 — §6 참조. 이 단계로는 안 닫힌다.)

계획에서 빼는 게 아니라 **다른 트랙 항목**임을 못박는다. 이걸 yaml 로 시도하면 프롬프트만 비대해진다.

| 층 | 문항 | 무슨 일 |
| :-- | :-- | :-- |

넣을지는 게이트가 정규식뿐이라 위험하다 — **리드 판단 대상**으로 올린다.

## 7. 실행 순서와 검증

```
단계 1 (gate_constants 4)   ─┐ yaml 단독 · HCX 0회 · 코드 0줄
단계 2 (absent 1 + answer 1) ─┤ 프리즈 전 최대 위험(환각) 차단
단계 3 (보수 별칭)           ─┤ 값 변환을 문장에서 SQL 로 내림
단계 4 (answer_rules 6)      ─┤ 죽은 블록 이관 · 준수율 측정 대상
단계 5 (query_rules 4)       ─┘ 플래너 SQL 결함
   ↓
python scripts/build_ontology.py        # ttl 재사영 (absent_properties → # ABSENT:)
python scripts/build_ontology.py --check # 검증만 — 죽은 alias·깨진 포인터
   ↓
eval/probe_funds_2026-09-04_core.txt 78문항 재측정 + 형제 검증 질문 9개
```

**단계마다 지킬 것**

1. 한 단계 = 한 커밋. 단계 1의 4개 게이트도 항목별로 형제 질문을 붙인다.
2. **회귀 우선.** 새로 닫는 문항보다 지금 ✅ 48건이 유지되는지가 먼저다 — 게이트 오발동은
   답변 가능한 문항을 죽인다.
3. 단계 4 의 6줄은 **준수 여부를 문항별로 따로 기록한다.** 지켜지지 않으면 그 항목은 문장이 아니라
   슬롯/조립기 대상이라는 뜻이고, 그 경계가 다음 라운드의 입력이다.
4. `columns.*.answer_policy` 는 이번에 옮긴 5건 외에도 남아 있다 — 전수 훑기는 별도 항목으로
   올린다(이번 범위 밖). 옮긴 자리에는 "→ answer_rules 로 이관(2026-09-04)" 주석을 남겨
   같은 문장이 두 곳에서 갈라지지 않게 한다.
