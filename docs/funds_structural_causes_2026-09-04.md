# 실패 25건의 구조 원인 — 온톨로지·KG 층위 진단 (2026-09-04 2차 기준)

> 대상: 2차 실측 ❌ 15 · 🟡 10. 증상이 아니라 **온톨로지·KG 구조에서 원인**을 찾는다.
> 근거는 전부 배포된 DB 실측(`data/financial_products.db`).

---

## 0. 진단 한 줄

**우리 KG 는 값 사전(label → code)이지 관계 그래프가 아니다.** 그래서 질의 계획을 구조로 제약할 수단이 없고, 제약은 전부 프롬프트 문장에 실린다. **흔들리는 자리와 프롬프트 문장에만 있는 자리가 정확히 겹친다.**

```
kg_node   40,845          kg_edge  5,704 — 관계는 3종뿐
kg_alias  66,603          hasAssetClass 3,169 (Index→AssetClass)
kg_closure 9,967          coversRegion  2,532 (Index→Region)
                          subsidiaryOf      3 (Security→Security)
```

🔴 **관계 3종이 전부 펀드 도메인 밖이다.** Index·Security 는 ETF·채권이 쓰는 축이고, **공모펀드 질의가 쓰는 관계는 0개**다. `Fund` 노드 6,867개는 `src` 로도 `dst` 로도 **관계가 하나도 없다** — R1 로 `feedsInto` 를 걷어낸 뒤 순수 alias 보유자가 됐다.

즉 공모펀드에 대해 KG 가 아는 것은 이것뿐이다:

| 아는 것 | 모르는 것 |
| :-- | :-- |
| `00080008` = 미래에셋자산운용 | **이 펀드의 운용사가 그것이라는 사실** |
| `1등급` = 매우 높은 위험 | 이 펀드가 몇 등급인지 |
| `KR7…` = 이 펀드 | 이 펀드에 어떤 클래스가 달렸는지 |

관계가 없으니 "무엇을 어느 컬럼에서 찾아야 하는가" 는 **온톨로지가 아니라 규칙 문장**이 정한다.

## 1. 구조 결함 A — 펀드와 조직 사이에 관계가 없다 (3건)

`KG-006`❌ `X22`❌ `KG-031`🟡

운용사(`or_co_xtn_itt_cd` 271노드)와 수탁사(`trusc_xtn_itt_cd` 48노드)는 **각각 접지돼 있다**. 역할이 섞인 노드는 0개라 그 자체는 깨끗하다. 문제는 그다음이다 — **`hasManager` · `hasTrustee` 같은 관계가 없다.**

그래서 *"이 펀드의 운용사와 수탁사는 어디야?"* 는 KG 가 관여할 여지가 없는 순수 SQL 문제가 되고, 플래너가 `FROM ext_fund_page` 로 잘못 잡아도 **구조가 막지 못한다**. `KG-006` 이 두 회차 모두 실패한 이유다.

`KG-031`(역외 포함 합산)도 같은 뿌리다. `Org_00130001`(피델리티 역외)과 `Org_…`(국내 법인)이 **같은 브랜드라는 관계**가 없어 합산 여부를 구조가 아니라 판단으로 정한다.

> ⚠️ 한 노드가 여러 (테이블, 컬럼)에 붙어 있는 것도 여기 딸린 문제다. `Org_00080008` 은 `public_funds.or_co_xtn_itt_cd` · `domestic_etfs.cu_fund_mgmt_co` · `ref_fund_mgmt_co` 세 자리에 붙어 있고, **어느 자리가 이 질문의 것인지** 를 고르는 구조가 없어 `KG-010` 의 *"같은 이름의 항목이 여러 자료에 있어"* 기각이 나온다.

## 2. 구조 결함 B — 클래스가 개체가 아니다 (6건)

`DOM-06`❌ `AA24`❌ `KG-005`❌ `FND-C02`❌ `KG-029`❌ `S2`🟡

**데이터의 행 단위는 클래스(8,969)인데 KG 의 노드 단위는 펀드(6,867)다.** 그 사이를 잇는 개체가 없다.

| | 표현 | 접지 |
| :-- | :-- | :-- |
| 펀드 | `Fund` 노드 6,867 (`rptt_ksd_itm_no`) | ✅ alias 6,867 |
| **클래스** | **노드 없음** — `itm_nm` 접미 문자열 | 🔴 |
| 수수료체계 | `han_clas_nm` **195종** | 🔴 alias **0** |

결과가 이렇다:

- `DOM-06` *"A클래스와 C클래스 중 보수가 낮은 쪽"* — **클래스가 개체가 아니라 비교 대상 자체를 지목할 수 없다.** PDF §3.1 이 설명하는 클래스의 존재 이유를 못 답한다
- `AA24` *"종류A 3년 수익률"* — 클래스 표기가 `itm_nm` 접미에 있다는 것이 규칙 문장뿐이라, 플래너가 `han_clas_nm='종류 A'` 로 가서 0행
- `KG-005` *"868개"* — 펀드/클래스 변환이 **SQL 표현식(`FUNDUNIT` COALESCE 식)으로만** 존재해, 그 식을 안 쓰면 클래스 수가 펀드 수로 나간다
- `KG-029` — 같은 이유의 반대 방향. 사용자가 **다른 키를 지정**했는데 슬롯이 덮는다. 키가 개체 축이 아니라 하드코딩된 식이라 협상이 안 된다

## 3. 구조 결함 C — 유형 축이 흩어져 있고 대부분 미접지 (5건)

`DOM-01`❌ `DOM-05`❌ `KG-012`❌ `KG-018`❌ `DOM-11`🟡

'유형' 을 말하는 컬럼이 최소 넷인데 **접지된 것은 하나뿐**이다.

| 컬럼 | 뜻 | DB 값 | KG alias |
| :-- | :-- | --: | --: |
| `zrin_btyp_nm` | 대유형 | 18 | **18 ✅** |
| `zrin_ptn_nm` | 소분류 | **102** | **0 🔴** |
| `or_attr_desc` | 약관 분류 | 14 | **0 🔴** |
| `fd_set_pcd` | 설정 형태 | 3 | **0 🔴** |
| `hdge_fd_yn` | 헤지펀드 | 2 | **0 🔴** |

*"재간접 공모펀드는 몇 개야?"* 를 보면 왜 흔들리는지 알 수 있다 — **'재간접' 은 세 군데에 있다**:

```
zrin_ptn_nm   글로벌리츠재간접 · 일본리츠재간접 · 아-태 리츠재간접 …
or_attr_desc  재간접
itm_nm        2,684 클래스에 '재간접' 문자열
```

셋 중 무엇을 쓸지가 **구조에 없으므로** 플래너가 매번 고른다 → 1차 913펀드, 2차 1,003펀드. `KG-012`(중국주식·소분류)가 3/3 재현으로 실패하는 것도 소분류 102종이 통째로 미접지이기 때문이다. `Z10`(인도주식)이 이번에 회수된 것은 **구조가 고쳐져서가 아니라 이번엔 잘 골라서**다.

## 4. 구조 결함 D — 한 낱말이 두 축에 걸리는데 우선순위가 구조에 없다 (2건)

`T13`🟡 `FND-014`❌

'미국' 은 `Country`(17노드)에도 `Region`(60노드)에도 있다. 둘 다 정당한 축이고 답이 갈린다(98펀드 vs 114펀드). **어느 축이 기본인가** 가 노드 속성이 아니라 가드 코드와 규칙 문장에 있다.

`FND-014` 는 같은 문제의 극단이다 — '정보가 없는' 이 **어느 속성의 결측인지** 를 묶어 주는 구조가 없어, 위험등급 결측을 물었는데 `fd_yr1_ern_r`(1년 수익률) 결측으로 셌다. 속성이 노드에 매달려 있지 않고 컬럼으로 흩어져 있으면 이런 오선택을 구조가 못 막는다.

## 5. 구조 결함 E — 부정·배제가 온톨로지에 없다 (1건)

`FND-006`❌

온톨로지는 **값의 존재**만 표현한다. `MMF` 는 `zrin_ptn_nm` 값이고 노드다. 그러나 *"MMF를 **제외하고**"* 의 **제외** 는 온톨로지 어디에도 대응물이 없다 — `query_rules.부정조건` 문장이 전부다.

그래서 2차에서 MMF 5개를 당당히 나열했다. 접지는 성공했고(MMF 를 찾았다), **연산자만 뒤집혔다.** 접지가 성공할수록 더 확신 있게 틀린다.

## 6. 구조 결함 F — 부재(absent)가 속성 단위라 복합 질문을 못 쪼갠다 (1건)

`OFFICIAL-002`🟡 — **주최 공식 문항**

`absent_properties` 는 `hasInvestmentStrategy` 처럼 **속성 하나**를 "없다" 고 선언한다. 그런데 질문은 *"구조**와** 투자전략"* 이다. 구조·보수·환매는 있고 전략만 없다.

지금 처방은 `vocab` 정규식의 부정 전방탐색이다:

```yaml
vocab: ["^(?!.*(?:구조|보수|수수료|환매|…)).*(?:투자[ ]?전략|운용[ ]?전략|…)"]
```

**질문을 쪼개는 구조가 없으니 낱말로 막는다.** 그래서 게이트는 정확히 비켜 갔는데(설계대로) **HCX 플래너가 통째로 거절**했다 — 구조가 "절반은 답하라" 를 강제하지 못한다.

## 7. 구조 결함 G — 답변 규약이 구조가 아니라 문장이다 (5건)

`Y4`🟡 `DOM-07`🟡 `DOM-08`🟡 `DOM-13`🟡 `FND-C01`🟡

숫자는 다 맞고 **옆에 붙어야 할 한 마디가 없다** — '누적'·'결측 39%'·'판매완료는 청산이 아니다'·'상위가 전부 MMF'.

이것들은 온톨로지에 **선언은 되어 있다**(`answer_policy`·`range_by_table`·`absent_in`). 다만 선언이 **답변 조립을 강제하지 않고** 프롬프트 문장으로만 전달된다. `순자산_억원`·`총보수_퍼센트` 처럼 **SELECT 별칭으로 구운 것만 지켜진다**는 것이 R8 에서 이미 확인됐다.

## 8. 구조 결함 H — 이름 매칭이 KG 밖에 있다 (2건)

`X3`❌ `KG-010`❌

종목명은 KG 의 접지 대상이 아니다(`itm_nm` alias 0). 이름 조회는 `REPLACE(itm_nm,' ','') LIKE` 문자열 연산이라 **오타 한 글자**('코어택')를 흡수할 구조가 없다. 같은 부류인 `Z20`('코어태크')이 이번에 통과한 것은 구조가 아니라 플래너가 잘 풀어서다 — **두 문항이 갈리는 것 자체가 근거**다.

## 9. 종합 — 무엇이 흔들리고 무엇이 안 흔들리나

| 층 | 문항 | 2차 결과 |
| :-- | --: | :-- |
| **게이트 즉답**(부재 선언·상수 컬럼·값 사전) | 37 | 회귀 **0** |
| **기계 조립**(SELECT 별칭·closure 확장) | 49 | 회귀 **0** |
| **프롬프트 문장**(query_rules·answer_rules) | 나머지 | **회귀 9 전부 여기** |

회귀 9건 중 **Ground·Gate 단계가 1차와 다른 것은 0건**이다 — 전부 접지 이후 계획 단계에서 갈렸다. 회수 10건 중 구조로 닫은 것은 4건(`FND-005` 조립기 · `DOM-10`·`DOM-12`·`DOM-09` 게이트)이고 **나머지 6건은 이번에 잘 풀린 것**이라 다음 회차에 다시 뒤집힐 수 있다.

**결론: 개별 문항을 고치는 것이 아니라, 프롬프트 문장에 있던 것을 구조로 내리는 것이 회귀를 막는다.**

## 10. 구조로 내릴 수 있는 것 — 비용 순

| 순위 | 구조 조치 | 닫히는 문항 | 비용 |
| :-: | :-- | :-- | :-- |
| 1 | **소분류·약관분류 접지** — `zrin_ptn_nm`(102) · `or_attr_desc`(14) 를 `FundAttribute` 또는 새 `FundType` 축으로 alias 등록 | `DOM-01` `DOM-05` `KG-012` + `Z10` 고정 | yaml 생성기 한 번. **R5 와 같은 모양** |
| 2 | **역할 관계 신설** — `hasManager` · `hasTrustee` edge (펀드→조직) | `KG-006` `X22` `KG-031` | edge 생성기. 값은 이미 컬럼에 있다 |
| 3 | **답변 규약을 SELECT 별칭으로** — 결측률·모수·'누적' 을 별칭으로 굽는다 | `Y4` `DOM-07` `DOM-08` `DOM-13` `FND-C01` `S2` | R8 과 같은 방식. enforce 슬롯 |
| 4 | **`fd_set_pcd`·`hdge_fd_yn`·`ofsfd_yn` 접지** (2~3종 닫힌 축) | `KG-018` `DOM-11` | 작다 |
| 5 | **클래스 개체 신설** — `FundClass` 노드 + `hasClass` 관계 | `DOM-06` `AA24` `KG-005` `FND-C02` `KG-029` `S2` | 🔴 **크다.** 노드 +8,969. 프리즈 전 권하지 않는다 |
| 6 | **부정 연산자**(E) · **질문 분해**(F) | `FND-006` `OFFICIAL-002` | 온톨로지 표현력 확장 — 프리즈 후 |

🔴 **1번이 가장 싸고 가장 많이 닫는다.** 소분류 102종은 이미 DB 에 있는 값이고, R5 에서 `FundAttribute` 191종을 등록한 것과 **완전히 같은 작업**이다. 접지가 생기면 값 검사가 통과하고, 그 자리는 게이트·기계 조립 층으로 내려와 흔들리지 않는다.
