### A. 🔴 OFFICIAL-004 — 가드 두 개가 서로를 잡아먹어 **모든 사용자 조건이 사라졌다** (부류 Z)

배포본으로 재현했다:

```
IN  : … FROM domestic_etfs WHERE cu_base_index LIKE '%Aerospace%' ORDER BY pd_abrv_nm ASC LIMIT 30
IDX : … WHERE (REPLACE(ref_base_index,' ','') GLOB 'Aerospace' OR … GLOB 'Aerospace[CTP]R*') …
POP : … WHERE pd_grp_no = 'ETF' AND pd_sale_yn = 1 ORDER BY pd_abrv_nm ASC LIMIT 30   ← 조건 전소실
```

`ensure_etf_index_canon` 이 사용자 술어를 **자기가 만든 canon** 으로 바꾸는데, 그 canon 의 리터럴이 한국어 질문에 없다(HCX 가 영문 지수명을 쓴 경우). 바로 뒤 `ensure_etf_base_population` 의 「날조 술어 제거」가 *질문에 근거 없는 술어*로 판정해 지워 버린다. 남는 것은 기본모수뿐 — **필터 0개짜리 전수 조회가 그럴듯한 답으로 나간다.** 무응답보다 나쁘다.

같은 함수의 두 번째 구멍도 재현됐다: OR 이 섞인 한 절에 지수 컬럼이 끼면 **OR 반대편 가지까지 통째로 버린다**.

```
IN  : WHERE cu_base_index LIKE '%우주%' OR pd_nm LIKE '%항공%'
IDX : WHERE (REPLACE(ref_base_index,' ','') GLOB '항공' OR …)        ← pd_nm 가지 소멸
```

### B. 🔴 CROSS-002 — 오염 컬럼이 JOIN 절에 있으면 확정식 가드가 못 본다 (부류 V)

`ensure_etf_index_canon` 은 **WHERE 의 절**만 훑는다. HCX 가 `JOIN overseas_etfs ON domestic_etfs.ref_base_index = overseas_etfs.cu_base_index` 를 쓰자 국내 쪽만 확정식이 되고 해외 쪽 오염 컬럼은 그대로 남았다. 실측상 해외 `cu_base_index` 는 6,037행 중 결측 11행뿐인 **벤치마크** 컬럼이라(ARK Blockchain → `S&P 500 TR`) 추종지수로 조인하면 무관 상품이 쏟아진다. 가드 docstring 의 "해외는 정상이라 대상이 아니다" 는 *결측률* 기준이지 *의미* 기준이 아니다.
