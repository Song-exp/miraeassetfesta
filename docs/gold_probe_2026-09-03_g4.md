### B. 🔴🔴 `UNANS-001` — 감점 축이 열렸다

11R 답변(177자): 유사 3건 되묻기. 13R 답변(566자): 목록 + 투자 판단 권유.

트레이스에 **되묻기·정확일치 판정 마커가 하나도 없다.** 최종 SQL 은 이렇다.

```
SELECT pd_nm, pd_abrv_nm, cu_base_index, cu_fund_mgmt_co, … FROM domestic_etfs
WHERE pd_nm LIKE '%AI%' AND pd_nm LIKE '%로봇%' LIMIT 30
```

`KODEX` 가 없다. **사용자가 지목한 브랜드 조건이 통째로 사라진 채** 3행을 받아 "찾을 수 없습니다" 뒤에 그대로 나열했다. 이건 11R 에 `OFFICIAL-004` 에서 잡았던 **부류 Z 와 정확히 같은 병**(사용자 조건 소실 → 그럴듯한 목록)이 상품명 축에서 재발한 것이다. ③-1~③-3 은 지수 컬럼 경로만 닫았다.

형제 문항 `OFFICIAL-NA-003`("KODEX AI로봇 ETF 정보 알려줘")은 정확일치 0건 → 유사 4건 되묻기로 **정상 동작**한다. 질문 차이는 `AI 로봇`(띄어쓰기)뿐이다. 즉 **정확일치 판정이 공백 정규화에 취약**하고, 실패하면 안전망 없이 LIKE 조회로 떨어진다.

꼬리("투자 전 각 상품의 특성과 위험 요소를 충분히 이해하고 … 신중하게 고려하여 투자 결정을 내리시기 바랍니다")는 ③-20 이 잡았어야 할 문형이다. 트레이스에 면책·금지문형 가드 마커가 없다.

부수: 운용사를 `cu_fund_mgmt_co`("KB"·"삼성액티브")에서 뽑는다 — 12R `cbefa14` 가 **폐기하기로 한 컬럼**인데 그 조치가 WHERE·축에만 걸리고 SELECT 에는 안 걸렸다. 정본은 `ref_fund_mgmt_co`(`KB Asset Ltd`·`Samsung Active Asset Management`).

### C. 🔴 부류 AC — **가드가 만든 SQL 파손** (새 부류 · 이번 라운드 최대 신규 결함)

세 가드가 각자 다른 방식으로 문법이 깨진 SQL 을 만들었고, 전부 「무응답」으로 끝났다.

**C-1 `_wrap_sort_col`(`src/runtime/pipeline.py`) — 산술식의 첫 토큰만 감싼다**

```python
m = re.search(rf"\b{col}\b(\s+as\s+\w+)?", head, re.I)
alias = m.group(1) or f" AS {col}"
return head[:m.start()] + f"{agg}({col}){alias}" + head[m.end():], True, False
```

HCX 가 쓴 `or_co_rwrd_r + sale_co_rwrd_r + trusc_rwrd_r + ofwk_trus_rwrd_r AS tot_commission_rate` 에서 `col=or_co_rwrd_r` 만 잡아 `MIN(or_co_rwrd_r) AS or_co_rwrd_r + sale_co_rwrd_r …` 를 만든다. **정렬 축이 산술식인 모든 랭킹**이 이렇게 깨진다(`FND-005`).

**C-2 같은 함수 — 테이블 별칭 접두를 안 본다**

`p.fd_nast_suma` 의 컬럼 부분에만 매칭이 붙어 `p.MAX(fd_nast_suma)` 가 된다(`FND-010`). **HCX 가 별칭을 쓴 모든 펀드 랭킹**이 대상이다.

**C-3 `ensure_amount_eok_columns` — 선두가 `(` 인 SQL 을 못 읽는다**

```python
existing = [it for it in _split_select_items(re.sub(r"^\s*select\s+(distinct\s+)?", "", head, flags=re.I)) …]
head = sql[:re.search(r"\bfrom\b", sql, re.I).start()]
```

`(SELECT '국내 ETF' AS 구분, pd_abrv_nm, du_last_aum` 은 `^select` 로 시작하지 않아 접두 제거가 불발하고, 괄호 깊이 때문에 항목 분해도 한 덩어리가 된다. 그 결과 금액식으로 `(SELECT '국내 ETF')` 를, 별칭으로 `"구분, pd_abrv_nm, du_last_aum_억원"` 을 주입했다(`CROSS-003`). 같은 함수는 `union` 도 검사하지 않아 **UNION 의 첫 가지만 보고 SQL 전체를 고친다**. 참고로 `ensure_fund_rank_representative` 는 첫 줄에서 `join|union` 을 걸러 이 병을 피한다 — 나머지 SELECT 목록 편집 가드에는 그 방어가 없다.

**C-4 재생성이 SELECT 열을 지우면 위치 ORDER BY 가 남는다**

`OFFICIAL-005`: 1차 6열 + `ORDER BY 6` → 재생성이 `cu_risk_factor` 를 빼 5열 → `ORDER BY 6` 잔존 → 실행 오류. 「SQL 검사 통과」가 찍힌 뒤에 터졌으니 **검사가 위치 ORDER BY 범위를 안 본다**.

**③-4 · 부류 AC — SELECT 목록을 편집하는 가드는 단일 SELECT 에서만 발동한다**
