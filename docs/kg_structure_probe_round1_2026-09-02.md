### 빈 결과(0행) 처리의 일반 정책 — 개별 조립기 패치가 아니라 정책

현재 `_count_answer` 는 1행 `0 | 0` 을 받으면 무조건 "조회 조건에 해당하는 공모펀드는 0개" 로 **단언**한다. 도메인 관점에서 0행은 세 가지가 섞여 있다:

| 0행의 실체 | 이번 사례 | 옳은 행동 |
| :-- | :-- | :-- |
| **(a) 진짜 0** — 조건의 모든 개체·값이 KG/값사전에서 식별됐고 결과가 없음 | KG-011 (KB×국민은행), KG-014 (등급 0 — 단 게이트가 먼저 잡아야) | "0개" 단언 + 이웃 분포(실제 수탁사 분포 등) 병기 |
| **(b) 조건 식별 실패** — Ground 매칭 없음 상태에서 HCX 가 코드·리터럴을 지어냄 | KG-003 `'A011'`, KG-004 `80000000`, KG-025 `'삼성'` | "**질문의 '…' 를 데이터의 개체로 식별하지 못했다**" 유보 + 후보 제시(되묻기). 0 을 말하지 않는다 |
| **(c) SQL 결함** — 템플릿 잔재·컬럼 오선택·모수 오설정 | KG-012 `<CHN>`, KG-017 `han_clas_policies`, KG-001 영문 LIKE | 기각→재생성(검사기) · 재생성도 실패면 유보 |

**일반 규칙(R1)**: *0행은 "WHERE 절의 모든 리터럴이 (i) 값사전(distinct) 또는 (ii) KG alias 또는 (iii) Ground 가 준 코드 집합에 속한다" 가 성립할 때만 단언한다. 하나라도 검증 밖이면 그 리터럴을 지목해 유보(되묻기)한다.* 이 규칙이 덮는 문항: KG-001·003·004·012·017·025 (+ 과거 FND-030·026 계열). 이 조건은 R3(리터럴 검증 강화)의 산출물을 그대로 쓰므로 **R3 → R1** 순서다. 단언 문장에는 어떤 조건으로 셌는지(개체·컬럼·모수)를 한 줄로 굽는다 — KG-011 의 머리말 오류(수탁 조건 탈락)도 같은 규칙으로 닫힌다.

**부재 속성 정책(R2)**: 값을 "0" 이 아니라 "없다" 로 답해야 하는 부류(좌수·보수·보유종목 시계열·운용역…)는 0행 정책 이전에 **게이트에서 HCX 0회로 끊는다**. 근거는 ttl ABSENT 선언(§③-8)에서 자동 생성된 어휘표다 — 좌수만 박아 넣는 예외가 아니라 "ABSENT 선언 = 게이트 어휘" 의 일반 규칙.

### S6 🟡 RiskGrade 값 범위의 도메인별 분리

- **결함**: `fp:riskGradeValue` 0~6 이 `DomesticBond ∪ DomesticETF ∪ PublicFund` 공용, `gate.py` 상수 `0<=g<=6` 공용 → 펀드 0등급을 정의역으로 허용(KG-014 게이트 미발동), 7등급 즉답 문구가 "0~6"(KG-013). 0 은 채권 '미분류' 코드('00').
