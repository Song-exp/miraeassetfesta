## 1. 🔴 HCX 플래너 연결 — 파이프라인의 빈 자리 채우기

### 현재 상태 (사실)

```
질의 ─▶ Normalize ─▶ Ground(KG 매핑) ─▶ Gate(3종 기각) ─▶ [ Plan ] ─▶ Guard(SQL 검사) ─▶ Execute ─▶ [ Answer ]
                       ✅ 동작            ✅ 동작          ❌ 미연결      ✅ 동작        ✅ 동작      ❌ 미연결
```

- `src/runtime/pipeline.py` 의 `Planner` 프로토콜 두 메서드가 비어 있다: `plan_sql(question, grounding) -> SQL` · `compose_answer(question, rows) -> str`
- 플래너에 넘길 재료는 준비됨: `ctx.planner_context(tables)` (도메인 yaml `query_rules`·`normalization` 평문, 국내ETF 1개 테이블만 1.3k자), `gate.detect_tables()`·`gate.is_cross_query()` (교차질의면 `ext_*` 조인 허용)
- 미연결 상태의 응답: *"현재 시스템 구축 중으로 이 질의에는 답변을 제공할 수 없습니다."* — **평가 35문항 중 게이트 기각분(답변불가 5 내외)을 제외한 전부가 0점**

### 4-1 초고수익률 728% — 결정할 것

`applied_yield > 50%` 인 **96행**은 전부 신용등급 **C0** · 위험등급 **11(매우높은위험)** · 평가가가 액면의 27~45% 인 유동화 후순위 tranche 다(발행사 신보·중진공·기보). 문제는 **96행 전부 `bd_ofr_tcd='공모'`** 라서 기존 `특수구조제외`(사모 제외)로 **하나도 걸러지지 않는다**는 것. `수익률정상`(`> 0`)·`유동화위험금지`(발행사명 위험판단 금지) 어느 규칙도 랭킹에서 빼지 않는다 → **"수익률 높은 채권 추천" 의 1~5위가 전부 이 행들**(1위 신보2024제15차 728.5%).

권고안 (검토기록 §10-⑤, 합의되면 그때 `query_rules` 반영):

```
① 조회·사실확인 질의  → 그대로 답한다. 728.5% 는 사실이다.
                        (기존 특수구조제외 규칙의 "조회·사실확인에서는 제외하지 않는다" 와 동일 방침)
② 추천·랭킹 질의     → pd_risk_gcd='11'(매우높은위험) 기본 제외 + 사모 제외(기존 규칙 유지)
③ 제외 사실을 반드시 밝힌다  ← 기존 특수구조제외 규칙이 이미 "제외 사실 명시" 를 요구
④ 안전장치: 조건을 pd_risk_gcd='11' OR crd_grd='C0' 로 둔다 (현 데이터는 C0 ⊂ 위험등급11)
⑤ 가격 기준 필터는 쓰지 않는다 — AAA 320행이 함께 걸린다(오폭 확인됨)
```

- **왜 신용등급이 아니라 위험등급인가**: 세 후보 기준을 전수 비교한 결과가 §10-② · ③ 에 있다.
- **결정이 풀어주는 것**: 채권 추천·랭킹 답변의 신뢰도. 지금 상태로 API 를 돌리면 "수익률 높은 채권" 질의에서 부실 tranche 가 1위로 나온다.

### ~~4-2~~ 는 왜 회의에서 빠졌나 (08-28 종결)

쟁점은 *"잔존일수 0 이 값 없음인가, 만기가 오늘이라는 진짜 값인가"* 였다. **진짜 값이 맞다** — 49행 전부 만기일이 기준일(2026-08-21) 이하이고, `mat_dt <= 20260821` 집합과 **대칭차집합 0** 으로 완전히 일치한다. 만기가 미래인데 0 인 행은 **0건**.

그럼에도 **영값배제 기본을 그대로 두는 것**이 결론이다. 두 가지가 별개이기 때문이다 — *0 이 진짜 값인가*(예)와 *답변 모수에 넣어야 하나*(아니오).

- 49행은 판매 관련 6개 컬럼(`buy_yield`·`bdbns_abl_chnl_tcd`·`bdbns_abl_chnl_nm`·`avg_annual_tax_yield`·`buyable_quantity`·`sale_yield_base_dt`) 전수 교차에서 **적중 0건** — 애초에 판매 대상이 아니다.
- 예외로 올리면 "만기 임박한 채권"(잔존 30일 이내) 모수가 578 → **627** 로 늘고, **이미 만기가 지난 49건이 상위**에 온다. 살 수 없는 채권을 추천하는 셈.
- "만기 지난 채권 있나" 류 질의는 `mat_dt` 로 답하면 되므로 예외 등록 없이도 답변 가능하다.

조치는 `remaining_days.note` 한 줄 보강(17건 기입 시 함께)이며, **`query_rules` 는 건드리지 않는다.** 상세·재현 SQL 은 검토기록 §5-3 · §8-(l).

> ⚠️ 다만 여기서 **새 건이 하나 나왔다** — 만기가 2개월 지난 `아우딘퓨쳐스3CB(사모/전환/풋)` 1행이 `dur = 0.4319` 라 `듀레이션정상` 규칙을 **통과한다**("금리위험 낮은 채권" 정렬에 살아남음). 채권 17건 기입 범위 안에서 `듀레이션정상` 에 `remaining_days > 0` 을 더할지로 처리한다 — 회의 안건 아님. 검토기록 **P-16**.

### 4-3 이 급하지 않은 이유

`(사)` 로 사모를 판정하면 오탐률 **50.0%** 인데(`(사)` 1,984행 중 1,981행이 실제로는 **공모**), 이건 우리 데이터만으로 결론이 나서 **08-27 에 이미 확정**됐다 — "공모/사모는 `bd_ofr_tcd` 로만 판정, 종목명 추론 금지"(`query_rules.공모사모판정` 신설, 17건 승인 시 함께 기입). 즉 **챗봇 오답은 이 규칙만으로 막힌다.** 주최 문의(4-3)는 `(사)` 를 *활용*하고 싶을 때만 필요하다. 문의를 보낸다면 §0-4 OQ-1 과 함께 나가는 것이 낫다.
