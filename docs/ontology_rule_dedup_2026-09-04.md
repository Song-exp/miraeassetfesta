## 1. 중복 — 펀드에서 실제로 나온 것

### A. 🔴 글자까지 동일 — `판매중만` == `구매가능`

```yaml
판매중만:  sale_yn = '판매중'      # always_on
구매가능:  sale_yn = '판매중'      # always_on
```

둘 다 `always_on` 이라 **매 질의 프롬프트에 같은 줄이 두 번** 실린다.

⚠️ 다만 `구매가능` 은 4도메인 공통 개념 이름이고 도메인마다 조건이 다르다(채권 `mat_dt>=20260824` · 국내ETF `pd_lste_dt=99991231 AND pd_sale_yn=1` · 해외ETF `1=1`). **이름을 지우면 도메인 간 규약이 깨진다.** 펀드에서만 두 개념이 우연히 일치한 것이다.

→ 해법은 삭제가 아니라 **직렬화 단계에서 동일 조건식 병합**:
```
구매가능 · 판매중만: sale_yn = '판매중'
```

### B. 🔴 모수 4겹 중첩 — 5규칙 · 435자 · 전부 always_on

```
판매중만  sale_yn = '판매중'                                   15자
공모만    prvo_pbff_desc = '공모'                              21자
   └→ 기본모수  판매중 AND 공모                                 98자   ← enforce on (BASEPOP)
        └→ 집계_TopN_필수  기본모수 + <정렬컬럼> NOT NULL AND <> 0   286자
```

`기본모수` 는 이미 **`enforce` 슬롯이 SQL 에 직접 주입**한다. 프롬프트에 네 겹으로 더 실을 이유가 약하다.

펀드 `always_on` 18개 총 **2,767자** 중 이 다섯이 435자(16%)다.

### C. 🔴 `answer_rules` 안에 같은 사실 두 번 — 기준가

| | 내용 |
| :-- | :-- |
| `answer_rules[10]` | 기준가는 상품 간 크기 비교가 무의미하다(설정 시 1,000 기준) — 비교 요청이면 이유를 말하고 비교하지 않는다 |
| `answer_rules[26]` | 기준가로 상품의 좋고 나쁨을 판단하지 않는다 — 설정 시 1,000 에서 출발해 누적된 값이라 **상품 간 크기 비교가 무의미하다** |

**같은 근거·같은 결론.** [26]이 더 완전하다(`FND-R03` 사례 포함) → [10]은 기준일 병기 부분만 남기고 흡수하면 된다.

### D. 🟡 한 사실이 세 층에 흩어짐 — 보수 ‰

| 위치 | 말하는 것 |
| :-- | :-- |
| `query_rules.보수단위` (trigger 7) | SQL 에 `/10.0` 환산 별칭을 넣어라 |
| `answer_rules[6]` | 보수 4종은 ‰다, 값÷10 이 % |
| `answer_rules[27]` | 결과의 `총보수_퍼센트` 를 그대로 옮겨라 |

층이 달라 **정당한 분업**이다(SQL / 개념 / 전사). 다만 셋을 함께 읽어야 이해된다. 그리고 오늘 `FND-005` 는 **셋이 다 있는데도** 10배 오류를 냈다 — 규칙 추가가 아니라 SELECT 별칭 강제가 답이라는 증거다.

### E. 🔴 중복이 아니라 **모순** — `종목단위` ↔ `대표행`

```yaml
종목단위:  행 = itm_no (dedup 불필요 — 2차)                    # always_on · 27자
대표행:    🔴 랭킹·Top-N·집계는 클래스(행)가 아니라 펀드 단위다 …    # always_on · 232자
```

**정반대 지시가 둘 다 always_on** 이다. 인계문서 §8 이 기록한 그 모순이고, 문장 한정 처방은 되돌려진 상태다(`KG-025` 가 깨져서). 지금은 `펀드단위` enforce 슬롯이 실행 계층에서 막고 있다.

→ 중복 정리 대상이 아니라 **미해결 항목**으로 분류한다. 프롬프트로 푸는 건 이미 실패했다.

## 2. 일반화 — 원칙을 먼저, 지금 규칙을 few-shot 으로

### 지금 구조

펀드 규칙은 한 줄에 **원칙 + 컬럼명 + 값 목록 + 실측 근거**를 함께 담는다. 장점은 근거가 붙어 있다는 것이고, 대가는 **목록 밖 사례로 전이되지 않는다**는 것이다.

오늘 실측이 그 대가를 보여줬다:

| 실패 | 이미 있던 규칙 | 왜 안 걸렸나 |
| :-- | :-- | :-- |
| `DOM-09` 설립국가↔투자지역 | `국가태그` — "국가는 `fd_ivst_rgn_desc` 로 못 푼다" | trigger 13개에 **'설립' 이 없다** |
| `FND-006` "MMF를 제외하고" 반전 | `부정조건` — 배제 낱말은 `<>`·`NOT IN` | trigger 9개에 **'제외하고' 가 있는데도** 미발동 |
| `FND-005` ‰→% 10배 | `보수단위` + AR[6] + AR[27] | trigger 7개에 **'총보수' 가 있는데도** 미발동 |

세 건 다 **규칙은 있는데 도달하지 않았다.** 규칙을 더 쓰는 게 아니라 원칙을 위로 올려야 한다.

### 제안 — 펀드 always_on 재편

| # | 새 일반 원칙 (always_on · 2~3줄) | 아래로 내릴 현재 규칙 (trigger 예시) |
| :-: | :-- | :-- |
| **G1** | **질문의 낱말이 그 컬럼의 값 집합에 없으면 그 컬럼으로 풀지 않는다.** 값 집합을 먼저 확인하고 없으면 다른 컬럼·태그·소분류를 찾는다 | `국가태그`(지역 6종에 '중국' 없음) · `유형별분포`(대유형 19 → 소분류 85) · `해외구분` |
| **G2** | **플래그 컬럼이 특정 모수에서만 채워지면 0행을 "없다"의 근거로 쓰지 않는다** | `헤지펀드`(`hdge_fd_yn` 은 사모 등록분만) · AR[28] |
| **G3** ⬆ | **구조 컬럼 1순위 · 종목명 LIKE 폴백.** 이름으로 풀었으면 답에 밝힌다 | 이미 `이름표기_우선순위` 로 존재 — **trigger → always 승격** |
| **G4** | **컬럼 선언 단위와 답변 단위가 다르면 SELECT 에 환산 별칭을 넣는다.** 말로 적으면 답변기가 무시한다 | `보수단위`(‰) · `순자산_억원` 규약 |

| **G6** ⬆ | **배제 낱말은 부정 조건이다.** 등호로 뒤집지 않고, NULL 은 `COALESCE` 로 감싼다 | 이미 `부정조건` 으로 존재 — **trigger → always 승격** |
