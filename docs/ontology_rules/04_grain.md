# 규칙 4. 행 단위(grain) — `COUNT(*)` 는 종목 수가 아니다

> 테이블의 한 행이 무엇 하나인지를 도메인마다 선언한다. 이걸 안 하면 **모든 집계가 틀린다.**

## 1. 데이터가 이랬다

- 채권은 한 종목이 시장·기준일·`info_seq` 조합으로 **2~4행**이 된다.
- 펀드 `mtco_itm_no` 는 운용사 내부 번호라 **여러 운용사에 걸쳐 중복**되고, 선행 0 손실로 길이가 1~7 로 섞인다.

## 2. 그래서 이렇게 정했다

- `row_grain` 을 4개 도메인 전부에 선언 (100% 적용된 몇 안 되는 규칙).
- 채권 `대표행` — 종목 단위 질의는 `GROUP BY pd_no` 또는 `pd_exg_mkt='장내'` 우선.
- 펀드 `펀드단위` — 운용사코드 + 7자리 zero-pad 한 `mtco_itm_no` **합성키**.

## 5. 안 지키면

‘AA- 이상 채권 몇 개’ 에 **1,078 종목이 중복 계산**된다. 펀드는 클래스와 펀드를 혼동해 개수가 몇 배로 부푼다.

## 6. 검토 체크리스트

> 전수조사에서 나온 규칙이므로 **규칙 단위로 판정**한다. 각 항목에 결론과 근거를 적고,
> 판정이 바뀌면 `ontology/enums/*.yaml` 또는 `ontology/shared/*.yaml` 을 고친 뒤 재생성한다.
