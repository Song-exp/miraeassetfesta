### 2.1 특화 데이터를 어떻게 수집·정제했는가 [ETF 통합, 도메인 단락 각자]

### 2.3 어떤 검색 방법론을 왜 택했는가 [리드]
- 2.3.1 왜 질의 생성인가 — 관계형 마스터에서 SQL 생성이 그래프 탐색보다 나은 이유, 벡터 DB 비채택 근거
- 2.3.2 파이프라인 개요 — Route → Ground → Gate → Clarify → Plan → 검증 → 실행 → 조립, 각 단계가 읽는 층
- 2.3.3 Route — 사람이 쓴 단어 목록 없이 kg_alias·범주값·약어명으로 자동 생성한 어휘, 한국어 머리명사 규칙, 다의어 처리
- 2.3.4 Ground — 개체 해소 우선순위, 대상 테이블 alias 없는 노드 폐기, closure·자회사 전개, 구상호·후계 법인 병합
- 2.3.5 Gate — 생성 전 기각 4종(ABSENT·enum·범위·상수), HCX 호출 0회로 답변불가 처리
- 2.3.6 Clarify — 조건 누락 질의의 되묻기, 단일턴 평가에서의 위치(답변불가 정답형 ②)
- 2.3.7 Plan — HCX 프롬프트 구성(개체 매핑은 DB 실제 값만, 조인키, 규칙 2층 always_on/triggered, 되묻기·답변불가 규칙, 스키마)
- 2.3.8 SQL 검증 — validate_sql, WHERE 리터럴 값 검사기(커버리지 ≥98% 컬럼), 재생성 1회, 0행 시 조건별 진단
- 2.3.9 답변 조립 — 목록형은 기계 조립(HCX 0회), 모수·기준일·단위 병기, HCX 답변 생성 구간
- 2.3.10 HCX 사용 구간 명세 — 필수 2구간(Intent·답변 생성) 준수, 비필수 구간 타사·유료 LLM 0건
- 2.3.11 교차질의 — 조인키 4쌍, 해외 ISIN 조인 폐기 근거, 펀드 grp 단독 금지 근거, UNION ALL 템플릿
- 2.3.12 선행연구 근거와 우리 실측 — 인용 등급표(A·B 기반 / C·D 착안), 규칙 2층 A/B 대조 결과
- 2.3.13 하지 않은 것 — 0행 자동 재시도·LIKE 완화·그래프 탐색·edge 종류 확장, 각각 왜
