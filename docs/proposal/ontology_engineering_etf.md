# 기술 제안서 §02-② 온톨로지 엔지니어링 — ETF 트랙 원고

> 주최 요구(규격 p.10): *"어떤 온톨로지 엔지니어링을 적용했는가"* — **"무엇을 만들었나"가 아니라 "왜 그렇게 설계했나"**.
> 그래서 이 원고는 **데이터 결함 → 그것이 만든 설계 결정** 순서로 쓴다. 수치는 [`NUMBERS.md`](NUMBERS.md) 인용.
> 담당: 이병철(국내ETF·해외ETF) · 최종 갱신 2026-08-26

---

## 1. 설계 원칙 — 값을 고치지 않고 "의미"를 선언한다

주최는 *"0이나 값이 없는 데이터는 **의도된 내용**"* 이라고 못박았다(8/24 공지).
따라서 결측을 채워 넣는 대신, **그 0이 무슨 뜻인지를 온톨로지에 선언**하고 질의 규칙으로 걸러낸다.
값을 고치면 *"왜 없는지"* 를 답할 근거 자체가 사라지기 때문이다.

이 원칙이 만든 3계층:

| 계층 | 무엇 | ETF 트랙 예 |
| :-- | :-- | :-- |
| 값의 의미 | `missing_reason` · `zero_is_value` · `value_semantics` | 총보수 0 = 미입력(무보수 아님) |
| 질의 규칙 | `query_rules` | `보수유효: cu_charge_rt > 0` — 0값을 정렬에서 배제 |
| 부재 선언 | ttl `ABSENT` | 해외ETF 위험등급 속성을 **아예 만들지 않음** |

## 2. 결함 → 설계 (ETF 트랙 8건)

### 2-1. ETN 545건 혼입 → `owl:disjointWith`

국내ETF 마스터에는 ETF 1,235건과 **ETN 545건(30.6%)** 이 한 테이블에 섞여 있다.
ETN은 증권사가 발행한 채무증권이라 구성종목 개념이 없고 발행사 신용위험을 진다 — 상품 성격이 다르다.

→ `fp:ETF owl:disjointWith fp:ETN` 으로 **동시 소속 불가**를 선언.
→ 🔴 **다만 테이블 클래스를 `fp:ETF` 하위로 두지 않았다.** `fp:DomesticETF ⊂ fp:ETF` 로 쓰면 같은 테이블의
ETN 545건까지 ETF로 단정해 `disjointWith` 와 논리 모순이 된다. 상품종류 판별은 `pd_grp_no` 컬럼이 한다.
*(테이블 = 데이터 출처, 상품종류 = 실제 분류 — 두 축을 분리한 것이 이 온톨로지의 핵심 구조 결정이다.)*

### 2-2. 해외ETF에 위험등급 컬럼 자체가 없음 → `ABSENT` 선언

*"위험등급 낮은 해외ETF 알려줘"* 는 데이터로 답할 수 없다. 그런데 국내ETF에는 위험등급이 있어서
LLM이 유추로 답을 지어낼 위험이 크다.

→ `etf_gl.ttl` 에 **속성 부재를 명시적으로 선언**하고, 런타임 Gate가 이를 읽어 **HCX 호출 0회로 기각**한다.
→ 평가 답변불가 5문항은 *"답변을 생성하면 감점"* 이므로, 이 선언이 곧 점수 방어 장치다.

### 2-3. 총보수 0값 150건 → `zero_is_value: false` + 모수 명시

국내ETF 총보수는 유효값이 **67건뿐**이고 0값 150건은 미입력이다. 0을 그대로 정렬하면
*"총보수 0%인 무보수 ETF"* 라는 환각이 나온다.

→ `보수유효: cu_charge_rt > 0` 규칙 + 답변에 **유효 모수 67건을 명시**한다.
→ 주최 8/25 답변(*"값이 0인 행은 아예 포함하지 않는 게 맞다"*)과 정확히 일치하는 처리다.

### 2-4. 위험등급이 1~6이 아니라 **0~6** → 범위 제약

숫자가 클수록 안전한 역방향 척도이고, 채권에는 0등급(미분류)도 존재한다.
`1~5` 로 제약하면 정상 데이터가 차단된다.

→ `fp:riskGradeValue` 에 `owl:withRestrictions [minInclusive 0][maxInclusive 6]`.
→ *"위험등급 7등급 ETF"* 같은 없는 값 질의는 enum 밖이라 Gate에서 기각된다.

### 2-5. 2차 데이터에서 레버리지 **부호가 소실** → 이름 규칙으로 방향 판정

1차에는 `cu_lev_fector` 가 음수(-2.0)로 인버스를 표현했으나, 2차 배포본에서 인버스 상품 163건이
**양수로 바뀌었다**. 부호만 믿으면 인버스를 레버리지로 오분류한다.

→ 방향은 상품명 `'인버스'` 키워드(`derivation_rules.inverse_direction`), 배수는 `ABS(cu_lev_fector)` 로 분리 판정.
→ 🔶 다만 `레버리지: ABS(cu_lev_fector) > 1` 규칙은 인버스2X도 함께 잡는다(308건 중 98건).
*"레버리지 ETF 추천"* 에 인버스가 섞이는 문제라 **경계 정의는 팀 합의 사항으로 남겨둔다**(회의 안건).

### 2-6. 기초지수 표기 불일치 → Index를 **독립 개체**로 정규화

같은 S&P500인데 해외는 `S&P 500 TR`·`S&P 500 CR`·`S&P 500 NR` 로, 국내는 `ref_base_index` 로 표기가 갈린다.
문자열 비교로는 *"같은 지수 추종 ETF+펀드"* 교차질의가 성립하지 않는다.

→ 지수를 **독립 개체(`fp:Index`)** 로 세우고 수익률방식·철자 변형을 **alias 로 한 노드에 묶었다**.
→ 결과: `Idx_MSCI_ACWI` 하나에 **국내ETF + 공모펀드 + 해외ETF** 가 동시에 매달린다(3중 연결).
→ 자동 등록 3,151노드 + 패밀리 `closure` 로 "같은 지수 계열"을 전개한다.

### 2-7. 지역 표기가 한글·영문 이원화 → Region 계층 + 참조컬럼 연결

국내는 한글 11종(`미국`), 해외는 영문 59종(`United States of America`), 2차 신규 참조컬럼은 영문 23종.

→ `fp:Region` 을 **계층**(일본 ⊂ 아시아 ⊂ 글로벌)으로 세우고 세 표기를 같은 노드의 alias 로 통합.
→ 🔧 감사에서 2차 신규 컬럼 `ref_geo_focus` 가 KG에 **연결되지 않은 것을 발견**(0/23)해 alias 22개 + 노드 1개 추가,
매핑률 **0% → 87%** 로 복구했다. *(빌드 산출물인 coverage report 가 이런 누락을 잡아내는 장치로 작동한 사례.)*

### 2-8. 구성종목이 마스터에 아예 없음 → 외부 수집 + Security 개체

*"삼성전자를 담은 ETF"*·*"에코프로 자회사 편입 ETF"* 는 주최 공식 예시 질문인데,
마스터 4종 어디에도 구성종목 컬럼이 없다.

→ 국내는 KRX/코스콤 경유 공개 API, 해외는 **SEC EDGAR NPORT-P** 공시로 수집(합계 98만 행).
→ 종목을 `fp:Security` 개체로 세워, **한 노드에 ETF holdings와 펀드 holdings를 함께** 매단다.
→ `삼성전자` → `Sec_kr_005930` 하나로 ETF·펀드 양쪽이 조회되어 **상품군 교차질의가 성립**한다.
→ 🔴 현금성 항목(`원화현금`·`설정현금액` 등 티커 없는 10,123행)은 **종목이 아니므로 노드화하지 않았다** —
"구성종목 수" 집계가 오염되지 않도록 한 판정이다.

## 3. 무결성 관리 — "원천이 틀리면 답변이 틀린다"

주최는 *"데이터의 신뢰성/무결성 관리 역시 과제의 일부"* 라고 명시했다(8/24). 적용한 장치:

| 장치 | 내용 | 실제로 잡아낸 것 |
| :-- | :-- | :-- |
| **빌드 검증 게이트 V1~V7** | yaml이 DB에 없는 컬럼·값을 가리키면 **산출물 생성을 거부** | 2차 전환 시 대문자/값 불일치 12건 |
| **coverage report** | 축별 미매핑 값을 매 빌드마다 리포트 | `ref_geo_focus` 0/23 누락 발견(§2-7) |
| **교차 대조 검증** | 실세계에 알려진 값으로 코드 의미 확인 | 거래소 `AMX` 를 AMEX로 오독 → VOO·SPY·IVV가 전부 NYSE Arca 상장인 사실로 **정정** |
| **gold 문항 사람 검증** | SQL 실행 성공만이 아니라 *"정답이 정답인가"* 를 사람이 판정 | 1차 기준 판정 7건이 2차 데이터에서 **답변 가능해진 것**을 발견(공식예시 2건 포함) |
| **ttl 파서 검증** | rdflib 로 실제 파싱 | 자동 생성 노드 ID의 특수문자(`Sec_o_74751*AK2`)로 **ttl 전체가 파싱 불가**였던 버그 발견·수정 |
