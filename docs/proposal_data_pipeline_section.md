## 1. 데이터 계층 — 무엇을 어디서 가져와 어떻게 우선순위를 두는가

| 계층 | 원천 | 규모 | 역할 | 충돌 시 |
| :-- | :-- | --: | :-- | :-- |
| **L0 마스터** (주최 제공, 8/24 배포본) | 국내채권·국내ETF·해외ETF·공모펀드 4테이블 | 53,375행 · 280컬럼 | 모든 답변의 기준 데이터 | **항상 우선** |
| **L1 판정** (온톨로지) | `ontology/enums/*.yaml` · `shared/*.yaml` · `codebooks/*.csv` → `ontology.ttl` + `kg_*` | 노드 120 · alias 213 | 결측/0/센티넬 의미, 코드↔명칭, 축 유도, 질의 규칙 | 마스터 값을 바꾸지 않음 — 배제·해석만 |
| **L2 외부 보강** | 구성종목(국내 KRX/코스콤 경유, 해외 SEC NPORT-P, 펀드 미래에셋 웹) · 설명서 · 코드북 | 구성종목 409k행 · 설명서 8,443건 | 마스터에 없는 사실(구성종목·법인명·TER) | 마스터 non-null 이면 마스터, null 이면 L2, 출처 태그 병기 |

원칙 3가지: ① 값을 고치지 않고 **배제**한다 (주최: 0/결측은 의도된 값) ② 파생값은 DB 컬럼이 아니라 **yaml 규칙**으로 선언한다 ③ 외부 자료는 **발행일 ≤ 2026-08-24** 만 (주최 8/24 공지), 기준일이 마스터(8/22)와 다르면 답변에 병기한다.

## 2. 적재 Flow

```
1.금융상품/*.xlsx (8파일)          data/external/ (수집물, git 제외)
        │ scripts/build_db.py             │ scripts/load_external_web.py
        │  · 선행0 보존 컬럼 15종 지정       │ scripts/load_external_holdings.py
        │  · 스키마 시트 → schema_metadata   │  · 발행일 ≤ 8/24 assert
        ▼                                  ▼
   data/financial_products.db  ── 마스터 4 + ext_* 4 + kg_* 4 + build_info(버전·기준일)
        ▲
        │ scripts/build_ontology.py  (yaml 검증 V1~V5 실패 시 산출물 생성 안 함)
   ontology/enums·shared·codebooks ──▶ ontology.ttl + kg_node/alias/edge/closure + kg_coverage_report.md
```

- **재현성**: 8파일 + `data/external/` 만 있으면 `build_db → load_external_* → build_ontology` 3단계로 DB·TTL 전체가 재생성된다. 손으로 만든 산출물은 없다.
- **무결성 게이트**: `build_ontology.py` 는 yaml 이 DB 에 없는 컬럼·값을 가리키면(죽은 alias) 빌드를 거부한다. 2차 데이터 전환 시 이 게이트가 12건의 대문자/값 불일치를 잡아냈다.
- **버전 추적**: `build_info` 테이블에 소스 파일·행수·데이터 버전(`v2_20260824`)·기준일을 기록해 API 응답의 기준일 서술과 DB 가 어긋나지 않게 한다.

## 4. 활용 로직 — 질의가 데이터에 닿는 경로

1. **Ground**: 질의 문자열을 KG 노드 레이블(운용사·지수·등급·지역…)에 매핑 → `retrieved_context` 에 어떤 컬럼의 어떤 값으로 해석했는지 기록
2. **Gate** (HCX 호출 전 기각): ① 속성 부재(해외ETF 위험등급) ② enum 밖 값(AAAA) ③ 기준일 이후 시점 → 불가응답. 교차질의(구성종목·복수 상품군)는 `ext_*` 조인 허용 플래그
3. **Plan**: 대상 테이블의 `query_rules`·`normalization`(yaml → `RuntimeContext.planner_context`)을 HCX 프롬프트에 실어 SQL 생성 — 0/NULL 기본 배제, 판매중 한정, ETF/ETN 분리, 인버스 이름 판정 등이 여기서 강제된다
4. **Guard**: SELECT 단일문 · 테이블 화이트리스트(마스터 4 + ext 4, ext 단독 금지) · LIMIT 필수
5. **Execute → Answer**: 0건이면 지어내지 않고 "확인되지 않음". 결과에는 기준일·단위(KRW/USD)·기간(1y/1d)·출처(마스터/외부)를 병기
