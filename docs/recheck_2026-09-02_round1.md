## ④ P2-14 권고 (미특정 라우팅 → 펀드 가드 우회)

**착수한다 — 단, 방식은 "라우터 수리"가 아니라 "가드 완성"이다.**

실측이 말해 주는 것: 미특정 경로에서도 `기점오류 NOT IN`·`근거컬럼`·(HCX 가 쓴) 기본모수는 **이미 살아 있다**. 펀드 가드 대부분이 `_FUND_TBL`(FROM public_funds) 기준으로 짜여 있어 §7 구조 리스크 1 의 서술("펀드 가드 전체 우회")은 현재 코드 기준으로는 과장이고, 실제로 뚫린 것은 **HCX 가 GROUP BY 를 안 쓰면 대표행 가드가 빈손인 설계**다. 이것은 라우팅과 무관하게 정상 경로에서도 비결정적으로 재발할 수 있는 구멍(§6-2s 018 잠재 리스크 그대로)이라 P1 이 P2-14 의 본체다.

권고 순서:
1. **P1 (GROUP BY 주입 + COALESCE 키)** — 라우팅 결과와 무관하게 SQL 모양만으로 대표행을 보장. 마이다스·한화 도배 둘 다 이 층에서 끝난다.
2. **7-b SQL 사후 라우팅 보정** — FROM 테이블로 `tables` 를 확정해 답변 규칙(도메인 단일)·`residual_name_token`(이름 필터)을 살린다. 미특정 경로에서 남는 마지막 우회 지점이 이 둘이다.
3. **7-a 라우터 오타 1줄** — 비용 0 의 보조. 단 이것만으로 닫았다고 보지 말 것(외래어·띄어쓰기·신조어 표현형은 무한).
4. §7 구조 리스크 1 문구를 "가드는 FROM 기준으로 이미 적용됨 · 잔여 = GROUP BY 주입·답변규칙·이름필터" 로 정정.

**착수 근거 강도**: R7 은 마이다스 노출까진 안 갔지만 gold 3행 중 2행이 틀린 명백한 ❌ 이고, 같은 구멍이 정상 경로 018 에서 "우연 무해" 로 등재돼 있다. 두 실측이 같은 층을 가리키므로 P2 이월이 아니라 **P1 급**으로 올리는 것이 맞다.
