### ④-3 🟡 경로 간 순자산 축 불일치 — 목록(MAX) vs 개별 조회(SUM) (신규 관찰 · gold 재정의 안건)

`ensure_fund_list_grouping` 은 펀드키 그룹의 `MAX(fd_nast_suma)`(대표 클래스), `ensure_fund_lookup_grouping` 은 `SUM(fd_nast_suma)`(클래스 합 — 코드 주석 "이 DB 의 fd_nast_suma 는 클래스별 값"). DB 실측: KB중국본토A주 14클래스 **MAX 1,453억 / SUM 3,345억**, 한국투자베트남그로스 1,066 / 2,528, 삼성달러표시MMF법인 4,839 / 6,514. 결과 ① 같은 펀드 순자산이 문항마다 다르다(T14 3R 2,528 vs 4R 1,066 · V15 20 vs T4 35 vs 합 92) ② **목록 순위가 바뀐다**(CHN 2위: MAX 기준 솔로몬 1호 1,393 → SUM 기준 G2이노베이터 2,282, rptt 기준 차이나그로스 1호 2,632). 3R 의 목록 gold(R3 "1,453억 첫 행")는 SQL 과 같은 MAX 로 계산한 것이라 **SQL 정합이지 도메인 정합은 아니다**. 도메인(§4.8 "굴리는 돈의 총액 · 클래스 합계")과 개별 조회 규약에 맞춰 **목록도 SUM** 을 권고 — F(rptt 접기)와 같은 커밋에서 `_list_answer` 순자산 열을 `SUM` 으로 바꾸고 3R·4R 목록 gold 를 SUM 으로 재산정(R3·S6·S7·T4·T5·T10·T13·V8·V9 순서 변동 예상). 리드 판정 안건으로 올린다 — 확정 전엔 머리줄에 "순자산 = 대표 클래스 기준" 고지.
