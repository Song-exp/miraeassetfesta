- 4R 동일 바이트 21건은 gold 재확인 결과 전부 종전 판정 유지(V12 ❌ 포함).
- `_sql_precheck` 기각·재생성 0회 · ABSENT 게이트 0회 · `[Retry]` 0회.
- ④-3 고지는 목록 9건 머리줄에만 붙고 값·순서 불변(SUM 전환은 리드 판정 대기 — 정당).
- KG 라벨 병합·국가 태그 확정식 wrap 교정은 R3·S6·S7·T4·T5·T10·T13·V8·V9·V10·V14·W12 에서 종전 값 유지.

## ③ 수정안 — 부류 단위 · 프리즈 전 필수 vs 이월 (A 용)

원칙: 문항별 예외 없음 · 이름 하드코딩 없음 · 같은 목적 가드 중복 없음. **6R 은 수리 없이 안정성 확인만** 이므로, 아래 "필수" 5건은 전부 **한 함수 안의 한 조건** 수준이고 각각 회귀 테스트가 결정적(HCX 0회)이다.

### 🔴 프리즈 전 필수

#### N [Ground 0 고유명 후보] 머리명사(오타형 포함)는 후보가 아니다 — R7 · S1

**일반 규칙 N**: *라우터가 머리명사로 소비한 낱말(정상·오타 표기 모두)은 상품 고유명 후보에서 제외한다. 후보에서 일반어를 지울 때 PRODUCT 키(오타 키 포함)도 함께 지우고, 잔여가 2자 미만이면 후보 없음.*
- `_standalone_name_token`: `rest` 계산에서 `_GENERIC_NAME_TOKEN ∪ PRODUCT 키` 를 길이순으로 제거('공모펌드' → '' → 후보 없음). 라우터의 오타 흡수와 결정층이 **같은 사전** 을 보게 되어 두 층의 해석이 일치한다. 후보를 뽑는 자리에 라우터 trace 의 머리명사(`Route … 머리명사 펌드`)를 넘겨 그 span 을 빼는 것도 같은 효과 — 사전 하나면 충분.
- 회귀 테스트: ① `_standalone_name_token("공모펌드 중 1년 수익률이 가장 높은 3개 알려줘")` → None ② `"1년 수익률이 가장 높은 공모펌드 5개"` → None ③ `"삼성코리아대표증권자투자신탁 1년 수익률"` → '삼성코리아대표증권자투자신탁'(불변) ④ `"KB차이나그로스 펀드 위험등급"` → 'KB차이나그로스'(불변).

#### O [0행 결정] HCX 자작 숫자 범위 술어가 단독 0행이면 걷어내고 1회 재실행 — S2

**일반 규칙 O**: *0행 진단에서 단독 0건인 조건이 **숫자 리터럴 비교** 이고 그 리터럴이 질문 텍스트에 없으면(사용자 값이 아님), 그 절을 제거하고 같은 SQL 을 한 번 더 실행한다. 사용자 값(질문에 있는 숫자·이름·등급)은 종전대로 완화하지 않는다.* 이미 있는 `ZeroRowDiagnosis.counts` 를 그대로 쓰므로 새 층이 아니다. trace `[Guard] 0행 원인 절 제거 — fd_yr3_ern_r < -100 (질문에 없는 값 · 규칙 하한과 방향 반대) · 재실행 3행`.
- 회귀 테스트: ① S2 SQL(`< -100`) → 재실행 3행 −80.36/−78.08/−77.8 ② `"수익률 -50% 이하 펀드"` 같은 질문 숫자는 제거 대상 아님(0행이면 확인 불가 유지) ③ R7/S1 의 `LIKE '%공모펌드%'` 는 문자열 리터럴이라 대상 아님(N 이 앞에서 막음).
- 근본 처방은 G-1 랭킹 템플릿(이월 참조) — 그때 O 는 자연히 발동 0 이 된다.

#### P [템플릿] 확정식이 보존하는 부가 절은 **단순 술어** 뿐 + 실행 실패 재시도 — V5

**일반 규칙 P**: *템플릿이 원 WHERE 에서 옮겨 싣는 절은 `컬럼 (=|<>|<|>|<=|>=|IN|LIKE|IS [NOT] NULL|BETWEEN) 리터럴` 형뿐이다. 집계·윈도우(`OVER(`)·서브쿼리·함수 호출이 든 절은 버린다(trace 에 "부가 절 폐기" 한 줄). 그리고 `[Execute]` 의 sqlite3 오류는 종료 사유가 아니라 **재생성 사유** 다 — `_sql_precheck` 와 같은 "재생성 1회" 경로로 돌린다.*
- `ensure_fund_manager_ranking` extra 필터 한 줄 + `_sql_precheck` 에 "WHERE 절 안 `OVER(`/집계 함수 → 기각" 한 줄(정적 검사가 결정적이므로 실행 전에 잡힌다).
- 회귀 테스트: ① V5 5R SQL(json 8단계 원문) → extra=[] → 4R 과 동일 템플릿 → 5행 gold ② S11 SQL 불변 ③ `"주식형 펀드 순자산이 가장 큰 운용사 3곳"` 의 `or_attr_desc = '주식형'` 은 보존.

#### I′ [Ground] 경계·성분 판정은 **원문 질문** 기준 · 라벨이 낱말의 부분이면 낱말 전체를 덩어리로 — W2 · W3

**일반 규칙 I′**(4R I-1 의 완결): *Country(및 경계 조건부 노드)의 `_boundary_hit` 과 `_country_name_component` 는 `consumed` 가 아니라 `question` 원문으로 판정한다 — 앞 라벨의 소비가 뒤 라벨의 경계를 만들지 않는다. 성분 판정 ⓑ 는 라벨을 **포함하는 낱말 전체**('미래에셋베트남'·'피델리티재팬')를 덩어리로 DB 실측(`_name_chunk_exists`)하고, 성분이면 그 낱말 전체(브랜드 포함)를 이름 검색 토큰으로 싣는다. 이름 토큰이 실리는 개별 조회에는 Country 태그 필터를 싣지 않는다(태그는 클래스별 결측이 있어 이름이 특정한 펀드의 합계를 깬다 — W2 실측).*
- `_ground`: 경계 검사 인자만 `question` 으로(소비 중복 방지는 `label not in consumed` 로 이미 됨). `_country_name_component` ⓑ: `w == label` 조건을 `label in w` 로 넓히고 chunk = w 전체(공백 제거) — 이때 토큰은 chunk 전체(Org 가 먼저 소비한 브랜드도 이름 리터럴엔 포함 — 코드 필터와 이름 필터는 별개 축).
- 회귀 테스트: ① `_ground("미래에셋베트남 펀드 순자산")` → Org + `'베트남' ⚙ 상품명 성분(낱말 '미래에셋베트남')` · 토큰 '미래에셋베트남' · Country 필터 0 ② `"피델리티재팬 펀드 1년 수익률"` → Org + ⚙ 성분 · 토큰 '피델리티재팬' → 묶기 14클래스 34.36~36.28 ③ `"베트남에 투자하는 공모펀드"`·`"미래에셋이 운용하는 베트남 펀드"`(독립 낱말) → Country 유지 ④ T14·V15·S4·W4·W7 불변 ⑤ `ensure_fund_country_tag` 도 같은 함수를 쓰므로 W2 의 wrap 없는 LIKE 는 애초에 안 생긴다.

#### J′ [SQL가드 체인] 이름 토큰은 체인 **끝** 에서 사후조건으로 확인한다 — W6

**일반 규칙 J′**: *`name_token` 이 있으면 가드 체인의 마지막에 "SQL 의 itm_nm LIKE 리터럴 중 하나가 토큰을 포함한다" 를 확인하고, 아니면 `ensure_fund_name_filter` 를 한 번 더 돈다(멱등). 어느 가드가 절을 걷어내든 토큰은 살아남는다.* 대안(같은 효과): `ensure_fund_series_boundary` 가 'N호' 절을 걷어낼 때 절 안의 이름 LIKE 리터럴에서 'N호' 만 떼어 보존 — 하지만 절 제거는 다른 가드에도 있으므로 사후조건 한 줄이 중복 없이 넓다.
- 회귀 테스트: ① W6 HCX SQL(이름+4호 결합 LIKE) → 최종 SQL 에 `LIKE '%미래에셋디스커버리증권투자신탁%'` + 4호 GLOB → 묶기 → 2클래스 2등급 ② T6·R6·W5 불변(이미 토큰 LIKE 있음) ③ 개별 조회 판정(`_has_name_filter` 참)이라 `목록 펀드 묶기` 로 빠지지 않음.

**필수 5건의 순서·묶음**: I′ 와 J′ 는 `_ground`/가드 체인의 인접 자리라 한 커밋 · N 은 `_standalone_name_token` 한 곳 · P 는 템플릿+precheck 한 커밋 · O 는 0행 결정 한 곳. 전부 합쳐도 5R 커밋의 절반 크기. 6R 에서 R7·S1·S2·V5·W2·W3·W6 재검 + ⑤ 형제 Y1~Y16.

## ④ 관찰

### ④-1 두 층이 같은 낱말을 반대로 해석 — 결정층이 넓어질수록 사전이 하나여야 한다

R7·S1 은 라우터(오타 흡수)와 후보 추출(상품명 승격)이 **각자의 사전** 을 갖고 있어 생긴 결함이다. 5R 에서 결정층이 Ground 0 까지 후보를 뽑게 되면서 라우터가 소비한 낱말이 후보 풀에 들어왔다. 같은 결로 ② 국가어 경계(Ground `consumed` vs 국가 가드 `question`)도 5R 에서 "한 함수 공유" 로 합쳐졌으나 **입력 텍스트가 다르다**(I′). 규칙: 판정 함수를 공유할 때 입력(원문)도 공유한다.

### ④-2 비결정 잔재 — HCX 가 SQL 을 내는 자리에서 가드가 "존중" 하는 부분

| 자리 | 5R 발현 | 4R | 성격 |
| :-- | :-- | :-- | :-- |
| 운용사 템플릿 부가 절 보존 | V5 윈도우 함수 | 잔재 0 | P |
| 수익률 랭킹 범위 술어 | S2 `< -100` | `< 0` | O/G-1 |
| 이름+호수 결합 LIKE | W6 | (T6 는 분리) | J′ |
| ETF 범위 문장 | W10 무고지 | V7 '국내' | B-4 고지 |
| V16 말미 문장 | "본인에게" | "투자자에게" | 면책 잔존(HCX) |
| 기본모수 | T9·V4·W5·W9 SQL 무모수(전부 판매중이라 무해) | — | 코드 핀·'클래스' 경로·Org 코드 경로에 기본모수 주입이 없음 — 판매완료 클래스가 있는 펀드(KB브라질 3·피델리티재팬 1)에서 발현 가능 |

6R 안정성 확인 때 이 여섯 자리를 **같은 질문 2회 실행** 으로 보는 것을 권한다.

### ④-3 순자산 축 — 개별 조회 SUM(T14 2,528 · W11 3,344) vs 목록 MAX(S7 1,066 · R3 1,453) 는 고지로 설명되나 같은 펀드가 두 값으로 나가는 상태는 유지. W2 는 태그 필터가 섞이며 **제3의 값**(1호 UH 550 — 태그 있는 클래스 합)까지 만들었다 — I′ 가 닫히면 소멸.

### ④-4 펀드키 발현(불변) — S7 한국투자베트남그로스 UH 7칸 · V9 키움러시아 5칸 · S6 인도중소형 5칸 · R3 차이나그로스 3칸. 개별 조회는 rptt 접기로 표시 해소(T14 4줄·W2 4줄·W9 3줄).

### ④-5 지연 — 조립기 경로는 전부 2~5s. 30s+ 는 HCX SQL 생성(V7·W10·T9·S1·W4). 조립기가 SQL 까지 템플릿으로 내는 경로(운용사 집계 S11 2.9s)만 지연이 없다 — G-1 템플릿의 부수 이득.
