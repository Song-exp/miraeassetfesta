`[Ground] 운용사 코드 역조회`(12R P15)는 KG 미매핑 브랜드에 DB 역조회로 코드를 확정한다. 문제는 **확정 결과를 `=` 단일 등호 술어로 SQL 에 흘린다**는 것이다. 브랜드는 법인코드에 1:1 이 아니다 — 같은 라운드 **V11 이 그 반례를 스스로 출력한다**: `'삼성' 이름 229펀드 = 00040010 207 · 00080135 10 · 00040024 9 · 00040067 1 · 00040007 1 · 00040001 1`.

**비결정적으로 갈린다는 것이 더 나쁘다.** 같은 펀드를 묻는 T7(`삼성코리아대표증권자투자신탁`)은 마커는 떴지만 SQL 에 `or_co` 가 안 실려 9클래스를 정확히 답한다. 즉 **정답이 HCX 가 힌트를 받아쓰느냐에 달렸다** — 11R §④-6 에서 "정답이 우연에 달린 문항은 남아 있지 않다"고 적은 것이 이 라운드에 뒤집혔다.

역조회 마커가 뜬 17문항 중 **`or_co` 등호가 실제로 SQL 에 들어간 것은 9문항**(S3·S4·T8·U1·U3·U12·V13·W1·Y8·Y10). 그중 브랜드가 단일 코드인 경우(KB·한화·유리·신한)는 무해했고, **다코드 브랜드(삼성)에서만 터졌다.**

### ②-5 🔴 회귀 원인 ③: **부류 E 가 닫히기는커녕 노출이 늘었다** (V13 · U14)

V13 은 11R 에 값 술어가 안 붙어 14 를 맞혔던 문항이라 **회귀**다. 같은 펀드를 묻는 U2·T8 은 술어가 없어 14 를 낸다 — **부류 E 는 HCX 가 값 술어를 쓰느냐에 달린 복권**이다. 관측된 오염 문항: R4(9/10) · V3(4/7) · W3(13/14) · S12(3건) · V13(8/14) · U14(4/7).

### ②-6 🔴 회귀 원인 ④: **조립기 발동이 여전히 SELECT 컬럼 조합에 달렸다** (Y14 — 부류 AA 의 반대 얼굴)

V12 는 회수됐는데 Y14 는 반대로 떨어졌다. Y14 의 SELECT 는 `CAST(SUM(fd_nast_suma) AS INTEGER) AS fd_nast_suma` 와 `"순자산_억원"` 을 **둘 다** 싣는다(같은 금액의 두 표현). 개별 조회 조립기가 이 조합을 못 받아들여 `None` 을 돌려주고 HCX 산문으로 갔다.

같은 라운드에서 U1·W2·Y10·W4·Y8 은 **같은 SELECT 모양인데 조립기가 돈다.** Y14 만 다른 것은 `[Guard] 호수 경계 주입`·`[Guard] 이름 토큰 사후조건`·`[Guard] 펀드 기본모수 사후조건` 3개가 추가로 돌아 SQL 이 길어진 것뿐이다. **발동 조건이 컬럼 집합 동등성 판정이라 가드 하나가 늘 때마다 깨진다** — 11R §③-1 이 지적한 성질이 잡음 집합만 늘렸을 뿐 구조로는 안 닫혔다.

### ③-1 [A] 🔴 부류 AC — **역조회한 운용사 코드는 이름 검색과 AND 로 묶지 않는다** (S3 ❌)

### ③-2 [A] 🔴 부류 E — `COUNT(*)` 모수 분리를 **개별 조회·펀드단위 랭킹에도** (11R ③-2 재상신 · 미착수)

- **일반 규칙**: 펀드 단위로 묶는 SQL 의 `COUNT(*) AS 클래스수` 는 **값 컬럼 술어와 무관하게 기본모수 전체를 센다.** 랭킹 경로에 이미 적용된 「값 술어를 WHERE→HAVING(`MAX/MIN` 감싼 형태)으로 이동」을 `ensure_fund_lookup_grouping` 재작성 끝에서도 호출한다. 진입 조건의 `having` 불개입도 함께 푼다(가드가 스스로 만든 HAVING 이므로).
- **닿는 층**: SQL 가드 `ensure_fund_lookup_grouping` · `ensure_fund_rank_representative`(`HAVING COUNT(*) > 1` 같은 HCX 조어도 같이 걷는다 — U14 SQL 에 실재).

### ③-3 [A] 부류 AD — **억원 표기는 조립기도 SQL 이 구운 열을 쓴다** (7문항)

- **일반 규칙**: 금액을 억원으로 굽는 자리는 **한 곳뿐이어야 한다.** SQL 에 `순자산_억원`(= `ROUND(x/1e8)`) 열이 있으면 조립기는 **그 열의 문자열을 그대로 옮기고**, 원 단위 컬럼에서 스스로 나눗셈하지 않는다. 열이 없을 때만 조립기가 굽고, 그때도 `ROUND` 다.
- **닿는 층**: 조립기 `_lookup_answer` 의 금액 포맷 지점(억원 병기 가드가 아니라 조립기다).
- **닫히는 문항**: **U1**(1,911→1,912) · **W11**(3,344→3,345) · **Y12**(963→964) · **T14**(766→767) · **Y10**(50→51) · **W2**(109·114·6→110·115·7) · **U11**(2→3).
