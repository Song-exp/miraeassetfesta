## 1. 서버 실측 오답 4건 (49.50.134.229 · 질문 4개만 보냈음)

### ① `"Li Auto를 담은 국내 ETF 알려줘"` → **데이터 조회 중 오류**

```sql
SELECT pd_nm AS 상품명 FROM domestic_etfs
WHERE TRIM(ext_etf_holdings.ticker) = 'LI' AND domestic_etfs.wu_inv_rgn = '국내' LIMIT 30
```

**한 질의에서 결함 3개가 동시에 터졌다.**

| | 결함 | 결과 |
| :-: | :-- | :-- |
| ⓐ | Ground 가 `Li Auto`(부분명)를 라벨 `Li Auto Inc` 에 못 붙임 | 근거 없이 `ticker='LI'` 로 **추측** |
| ⓑ | `국내 ETF` 의 `국내` 가 `wu_inv_rgn` 필터로 들어감 | 중국 기업이라 조건이 맞아도 **0건** |
| ⓒ | `ext_etf_holdings` 를 FROM 없이 참조 | **OperationalError** |

> 🔴 ⓒ 는 Guard 문제다. `[Guard] SQL 검사 통과` 를 찍고 Execute 에서 죽었다.
> 답변이 *"데이터 조회 중 오류가 발생해 확인할 수 없습니다"* 로 나갔는데, **평가에서 이건 답변 실패**다 —
> 답변불가 질의가 아닌데 답변불가처럼 나간다.

### ② `"KODEX 200 총보수 알려줘"` → **"확인되지 않습니다"** (존재하는 상품인데)

```sql
SELECT cu_charge_rt FROM domestic_etfs WHERE pd_nm = 'KODEX 200' LIMIT 30   -- 0행
```

사람은 **약어명**으로 부르는데 정식명으로 찾았다. 정식명은 `삼성 KODEX200 증권상장지수투자신탁[주식]` 이라 공백 위치까지 다르다.

| 조회 방식 | KODEX 200 | TIGER 200 | KODEX 반도체 | TIGER 미국S&P500 |
| :-- | --: | --: | --: | --: |
| `pd_nm =` | **0** | **0** | **0** | **0** |
| `TRIM(pd_abrv_nm) =` | 1 ✅ | 1 ✅ | 1 ✅ | 1 ✅ |

`pd_nm LIKE '%KODEX 200%'` 도 안 된다 — 14건을 주면서 **정작 본체를 안 준다**(정식명은 `KODEX200`).
약어명이 정식명 안에 통째로 든 상품은 **983/1,780(55%)** 뿐이다.

### ③ `"인버스 ETF 3개 알려줘"` → **1번 답이 ETN**

*KB증권 KB 블룸버그 인버스 2X 천연가스 선물 **상장지수증권**(H) 제46호*

플래너가 낸 SQL 은 **내 yaml 규칙 원문 그대로**였다(규칙→프롬프트→SQL 경로는 정상 작동).
다만 `pd_grp_no='ETF'` 가 없었다.

> 실측 — 인버스 조건 **235건 중 ETN 189건(80%)** · ETF 46건. 앞에서 3건 자르면 ETN 이 나오는 것이 **구조적**이다.

### ④ `"총보수 낮은 국내 ETF 5개 알려줘"` → 결함 4건

| | 결함 |
| :-: | :-- |
| ⓐ | `국내` 가 `wu_inv_rgn` 필터로 들어가 **8건이 잘림** (이번엔 Top5 가 우연히 같았다) |
| ⓑ | **상품명 변조** — `브이아이`→`브이 아이`, `중장기국공채액티브증권상장지수투자신탁`→`중장기 국공채 액티브 증권 상장 지수 투자신탁` |
| ⓒ | 유효 모수 **67건** 미명시 (`answer_policy` 요구사항) |
| ⓓ | 투자 권유 표현 — *"투자자들에게 유리한 상품들입니다"* |

> ✅ **형이 넣은 `보수유효`(`cu_charge_rt > 0`)는 정상 작동했다.** 미입력 0값이 상위를 도배하지 않았다.
