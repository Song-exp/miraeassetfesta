## 1. 인사이트 8개

### I-1. KG 의 본업은 "질문의 표기 → 테이블·컬럼·raw 값" 사전이다
- 실패의 **54.6% 가 WHERE 필터·enum 값 오류**, 조인 오류는 Other 21% 의 일부 (`ENT-1` Fig. 4).
- LLM 이 개체명을 지어내면 질의 성공 **0%**, 링킹된 이름을 글자 그대로(verbatim) 쓰게 하니 **82%** (`KGG-1` §5).
- 링킹 산출물에 별칭·경로 후보를 더하면 +4~9pt (`KGQA-1` Table 3).
- **우리에게**: `kg_alias` 62,558 건이 하는 일이 정확히 이것이다. KG 의 품질 지표는 노드 수가 아니라 **"질문에 나올 표기 중 raw 값으로 이어지는 비율"** 이다.

### I-2. 그라운딩은 "학습에도 없고 이름으로도 못 맞히는 사실"에서만 효과가 있다
- 공개 KG(PrimeKG) 는 **+0**, 학습 밖 합성 사실은 **+75~79pt**, LLM 없는 데이터 계층만으로 100% (`KGG-1` Table 2·3·4).
- 반대로 이름이 값을 암시하면(INN 약명 → 적응증) LLM 은 컬럼 없이도 84% 를 맞힌다 (`KGG-1` §6) — 우리에겐 **환각 경보**다.
- **우리에게**: 2026-08-22 스냅샷의 보수·위험등급·벤치마크 배합은 전부 학습 밖 → 그라운딩이 결정적. 반면 "ETF 가 무엇인가" 류 일반 설명을 프롬프트에 넣을 이유는 없다. 답은 **SQL 결과 행에서만** 조립한다.

### I-3. 규칙 문서 한 장이 모델 교체보다 크다
- 약 4KB(2,200토큰) 규칙 문서로 **+17.2~+23.2pp**, 모델 간 차이는 ~5pp, 작은 모델+문서 > 큰 모델−문서 (`SL-1` Table 1·2).
- 주최가 인용한 `JAMIA-1`: 스키마만 8.3% → 규칙 문서 78.3%, **스키마 축소만으로는 10%** (Table 1–3). 기전은 "후속 서한 = `CLASSIFICATION like '%FU Attempt%'`" 같은 **개념→(컬럼, 값) 규칙** 이 스키마엔 없기 때문 (p.5).
- 이득이 몰린 실패 5범주: 테이블 선택 · 스냅샷 합산 · 지표 공식 · 센티넬/기본값 · 기준일 해석 (`SL-1` §5.4).
- **우리에게**: `ontology/enums/<domain>.yaml` 이 그 문서다. 온톨로지 작업의 우선순위는 개체 그래프 확장이 아니라 **이 문서의 빈칸** 이다.

### I-4. 규칙은 "무엇을 넣나" 만큼 "어떤 형식으로, 얼마나 골라 넣나" 가 중요하다
- 규칙 저장소 **전부 주입 39.0 < 선별 주입 47.5**, BM25 로 고르기만 해도 41.2 (`DK-1` Table VI). 짧은 evidence(21.4) > 긴 문서(15.9) > 없음(6.8) (`ENT-1` Table 2).
- 형식: `'자연어 표현' refers to <SQL 조각>` 이 평문보다 +3.9~9.2pp (`DK-1` Table VI). 사람 검수 규칙이 LLM 자동 규칙보다 +3.9~7.1 (`DK-1` Table VII·IX) — **틀린 규칙 하나가 규칙 없음보다 나쁘다.**
- 단 반대 근거: 2.2K 토큰 문서는 통째 주입이 검색형보다 낫다 (`SL-1` §6.5).
- **화해**: 문서가 작으면 통째, 크면 선별. 우리 도메인 규칙은 12~14KB 로 중간 → 실측으로 정해야 한다.

### I-5. 관계형·집계형 데이터에서는 "질의 생성" 이 "그래프 탐색" 을 압도한다
- 관계형 스키마를 그래프화한 Northwind 에서 질의 생성 **55.3** vs 트리플 검색 **0.7** · 홉 탐색 **3.4** (`KGQA-1` Table 1). 경로 검색의 이득은 백과사전형 다중홉 KG(WebQSP)에서만.
- 실행 결과를 한 번 되먹이면 55.3 → 64.9 (`KGQA-1` Table 7) — 고친 것은 "속성이 어느 관계에 붙는가" 를 실제 샘플로 본 것.
- **우리에게**: KG 는 SQL 플래너를 **돕는 층** 이지 답을 찾는 층이 아니다. 그래프 탐색 기능을 붙일 이유가 없고, 관계는 "SQL 조건으로 펼 값 집합" 을 주는 만큼만 가치가 있다.

### I-6. 거절은 통계가 아니라 구조로 한다
- "생성 전·실행 없이" 답변가능성을 가르는 게이트 정식화 (`REF-1` §3.1). 학습 탐침은 HCX 에선 불가하지만, **API 프롬프트 거절도 금융 도메인에서 97.2 F1** (`REF-1` Table 1).
- 학습 탐침의 약점 = 의미 근접 컬럼(`revenue` vs `gross_profit`) (`REF-1` §4.4) — 규칙·alias 가 정확히 강한 곳.
- 경고: "빈 결과 = 오류" 를 전제로 조건을 완화해 고치는 방법(`VAL-1` §3.2.2·§3.3, LIKE 완화)은 **거절이 정답인 문항에서 환각 경로** 다. 시간 앵커(`today()`) 오해석은 빈 결과 = **잘못된 거절** 을 만든다 (`SL-1` §5.4 ⑤).
- **우리에게**: 거절 3단 — ① 스키마 부재·enum 밖 = Gate(생성 전) ② 범위 밖·추천·예측 = 프롬프트 규칙 ③ 값 부재 = 실행 후 0행. 0행은 재시도하지 않는다.

### I-7. 이름 문자열에 박힌 정보는 LLM 이 추론해 버린다 — 미리 데이터로 굳혀라
- `KGG-1` inferable 발견(I-2) + GAK 패턴 "추출 1회 → 노드/컬럼으로 물질화 → 이후 LLM 0회" (`KGG-1` Table 5).
- **우리에게**: 종목명의 `(채권혼합)`·`제2호`·`UH`·`2.2배` 는 LLM 이 이름에서 추론하기 쉬운 값이다. 오전에 파생 컬럼으로 굳혔다가 **저녁 리드 결정으로 폐기** — 규칙(조건식)으로 프롬프트에 주고, 컬럼은 오답이 실측되고 행을 묶어야 할 때만(파생 판단 사다리 ④). 정보량이 같다면 DB 를 흔들지 않는 쪽이 D-7 에 맞다.

### I-8. 스키마 링킹·FK 그래프는 우리 병목이 아니다
- 스키마 링킹이 oracle 이어도 실행 정확도 차이 1.5pp (`SCH-1` §5.3). 컬럼 프루닝(soft linking) 단독 기여 −0.8pp (`VAL-1` Table 1). 스키마 축소만으로는 10% (`JAMIA-1` Table 3).
- FK 그래프 경로 탐색은 8테이블·고정 조인 키에서 최단경로가 항상 1 → 퇴화 (`SCH-1` §3 Notation).
- 재현율 우선(union) 이 정밀 선택보다 +2~12pp — "노이즈는 무시할 수 있지만 빠진 조인은 지어낼 수 없다" (`SCH-1` §5.3).
- **우리에게**: 280컬럼은 다 넣는다. 도메인 라우팅이 애매하면 둘 다 넣는다. FK 를 KG edge 로 만들지 않는다.

## 2. 우리 KG·온톨로지 구성요소별 참고 포인트

### 2-1. `kg_node` — 무엇이 노드가 될 자격이 있나

노드는 **"질문에 그 표기로 등장하고, 어떤 컬럼의 raw 값으로 이어지는 개념"** 일 때만 가치가 있다 (I-1·I-5). 판정 기준:

| 기준 | 통과 예 | 탈락 예 |
| :-- | :-- | :-- |
| 질문 어휘로 등장하는가 | 운용사·지수·종목·자산군·등급·지역 | 내부 코드값 자체(`'10'`), 센티넬 |
| 컬럼 raw 값과 매핑되는가 | `Org_00080008` → `or_co_xtn_itt_cd='00080008'` + 43 표기 | 값이 없는 개념 노드(빈 클래스) |
| 라벨이 그럴듯하지만 값이 쓰레기인가 | — | `Fund_…` label `삼성KODEX` (alias `'KR'`) — 08-30 제거 19개 |

- **하지 말 것**: FIBO 처럼 데이터에 없는 클래스를 통째로 임포트해 빈 노드를 만드는 것(`FIBO_funds-model` 조건부 판정) — I-2 에 따라 값이 없는 노드는 답변에 기여하지 못한다.
- **개체 종류(node_type)의 우선순위**: 질문 빈도 × 표기 변형 수. Organization(43종 표기)·Index(복합식 253종)·Security 가 상위.

### 2-2. `kg_alias` — KG 의 실질이자 품질 지표

- **커버리지 지표를 둔다**: 컬럼별 `distinct raw 값 중 alias 로 잡힌 비율` + `gold 질문 어휘 중 매핑된 비율`. 노드 수(39,658)가 아니라 이것을 제안서에 쓴다 (I-1).
- **별칭의 원천 3층**: ① 원본 distinct 자동 등록(`*_auto.yaml`) ② 코드북(`codebooks/*.csv`) ③ 수동(`security_alias_manual.csv`). `DK-1` 의 "사람 검수 +4~7pp" 는 ③이 ①을 이긴다는 뜻 — 고빈도 개체부터 사람이 검수.
- **복합값은 성분으로 alias 를 붙인다**: `'KOSPI200 25% + 종합채권01Y 75%'` 가 통째 노드면 "KOSPI200 추종 펀드" 질의가 47% 를 놓친다(오늘 실측, E-3-12). `KGQA-1` Table 9 의 교정 사례("속성이 어느 관계에 붙는가")와 같은 유형 — 성분 지수 노드에 복합식 raw 값을 alias 로 추가 부착하면 런타임 변경 없이 IN 목록이 넓어진다.
- **verbatim 원칙을 프롬프트에 명시**: "IN 값은 매핑 목록의 raw 값 그대로, 목록 밖 값 생성 금지" (`KGG-1` §5). 부분일치가 필요한 컬럼(`query_rules` 의 LIKE 규칙)만 예외로 연다.
- **언어·표기 변형**: 한글/영문(`MSCI CHINA`/`MSCI CHINA(USD)`), 공백·대소문자(`Call`/`CALL`), 조사가 붙은 한국어 표기(`AAAA인`) — `_min_len` 같은 길이 하한과 조사 경계를 alias 매칭 규칙에 둔다 (`REF-1` 의 "의미 근접 컬럼" 약점이 규칙엔 강점).

### 2-3. `kg_edge` · `kg_closure` — 잡을 관계와 잡지 않을 관계

런타임이 관계를 쓰는 유일한 경로는 **closure 로 후손 alias 를 펴는 것** 이다. 그러니 edge 하나의 정당성은 **"어떤 질문 어휘를 어떤 값 집합으로 펴는가"** 로만 설명돼야 한다.

| 관계 | 펴 주는 것 | 근거 | 판단 |
| :-- | :-- | :-- | :-- |
| **계층** (상위 어휘 → 하위 값) | "투자등급" → AAA~BBB- 10종 · "아시아" → 국가 코드 · "주식형" → 국내/해외주식형 | `KGG-1` 1-hop lookup 만으로 충분 (§5) · closure 8/30 도입 실측(정본 18개 alias 0 → 후손으로 해소) | **유지·보강** — 질문 어휘가 상위 개념인 곳만 |
| **동일성** (정본 ↔ 표기·식별자) | NVIDIA 정본 → 주식·회사채·LEI 노드 | `KGQA-1` 별칭 후보 +4~9 (Table 3) | **유지** — 사실상 alias 의 확장 |
| **구성** (복합 → 성분) | 복합 벤치마크 → 성분 지수 | 직접 논문 근거 없음, 우리 실측 47~83% 손실 | **alias 부착으로 대체 가능** — edge 보다 싸다 |
| **조인 경로** (마스터 ↔ ext) | 구성종목·설명서 질의 | `SCH-1` +6~12pp 는 **프롬프트 문자열** 효과 (Prompt 3) | **edge 아님** — `JOIN_KEYS` 를 문장으로 프롬프트에 |
| **모자·시리즈** (`feedsInto`, 패밀리) | 답변 묶기 | 근거 없음 | 검색용 아니라 **답변 조립용** — 그룹핑 키로 |
| **FK 그래프** | — | `SCH-1` 8테이블 퇴화 (§3) | **넣지 않음** |
| **통계·유사도 edge** (임베딩 이웃) | — | `KGQA-1` 트리플 검색 0.7 (Table 1) · 한국어 미검증 | **넣지 않음** |

- closure 는 `build_ontology.py` 가 이행적으로 미리 만든다 — 런타임 그래프 탐색이 아니라 **사전 계산된 값 집합** 이라는 점을 제안서에 쓴다(I-5 와 정합).

### 2-4. `ontology/enums/*.yaml` — 규칙 문서(semantic layer) 체크리스트

`SL-1` §3.1 의 5범주로 도메인 yaml 을 점검한다. 비어 있는 칸이 곧 오답 후보다 (I-3).

| 범주 | 우리 yaml 위치 | 점검 질문 |
| :-- | :-- | :-- |
| ① 테이블 선택·행 단위 | `row_grain` · `query_rules.종목단위/펀드단위` | 클래스(A/C/Ce) 다중 행을 어떻게 묶는지 한 줄로 적혀 있나 |
| ② 지표·단위·공식 | `columns.*.unit` · `answer_policy` · `derivation_rules.totalFeeApprox` | ‰ vs %, 누적 vs 연율, 합산 금지(순자산 MAX) |
| ③ 조인 경로 | `pipeline.JOIN_KEYS` (코드) | yaml 에 **문장으로도** 있어야 프롬프트에 실린다 (`JAMIA-1` p.5) |
| ④ 관례·센티넬·결측 | `normalization.dummy_as_missing` · `zero_as_missing` · `missing_reason` 4분류 | 센티넬(`-100`)·더미(`000…`)·기준일 REAL 저장 — `SL-1` §5.4 ②④ 가 바로 이것 |
| ⑤ 모호성 해소 | `query_rules.기본모수` · `벤치마크검색` · `이름표기_우선순위` | "최근/현재" = 2026-08-22 고정 문장이 있나 (`SL-1` §5.4 ⑤) |

- **형식**: 규칙은 가능한 한 `'한국어 표현' → <컬럼 조건 SQL 조각>` 으로 (`DK-1` Table II·III). 지금 `query_rules.자산군_주식형` 처럼 SQL 조각이 있는 규칙이 모범.
- **두 층**: `always_on`(기본 모수·0/센티넬 배제·LIMIT) / `triggered`(`triggers: [표기 변형]` 이 질문에 있을 때만) — I-4 의 화해안. gold 63 으로 전부 vs 선별 paired 비교.
- **`refusal_rules` 신설**: `REF-1` 부록 A 의 답변불가 9유형 중 우리 문항에 걸리는 것(DB 밖 정보·실시간·미래 예측·추천·인과 설명) 을 평문으로 (I-6 ②).
- **틀린 규칙 방지**: 규칙마다 gold 문항 1개 이상을 대응시켜 pytest 에 (`DK-1` Table IX 의 교훈).
- **크기 목표**: 도메인당 ~2,200토큰 근처(`SL-1` §4.2). 넘으면 `triggered` 로 뺀다.

### 2-5. `derivation_rules` · 이름 규약 — 추론 대신 규칙, 규칙으로 안 되면 그때 파생

- 이름·태그에서 유도되는 속성(자산군·레버리지·시리즈·헤지·만기)은 **LLM 이 추론하지 않게 조건식으로 프롬프트에 준다** (I-7). 규칙의 원천은 yaml 한 곳(`query_rules`), 형식은 `'표현' → SQL 조건식`(호수는 `GLOB '*[^0-9]2호*'` 경계식).
- **파생 판단 사다리**(2026-08-30 저녁 리드 결정): ① 질문이 모호 → `clarify` ② HCX 가 다르게 계산 → 규칙을 "설명"이 아니라 "복사할 조건식"으로 ③ KG 로 정확값 주입 ④ 그래도 불안정하고 **오답이 실측**됐고 **행을 묶어야** 할 때만 DB 파생 컬럼. 지금은 ④에 해당하는 축이 없다(클래스 도배는 `(or_co, mtco_itm_no)` GROUP BY 로 해결).
- 우선순위: 구조 컬럼 > 태그 > 이름 조건식(주최 값 우선). 이름 vs 구조 컬럼 **불일치는 실측 표로 남긴다**(헤지 표기↔`exchdg_yn` 모순 1, 연금 태그만 2,525) — 규칙 검수 목록이 된다.

### 2-6. 검증 자산 — 온톨로지의 품질을 재는 법

- **paired 비교**: 같은 gold 63 을 규칙 유/무·선별/전부로 재실행, McNemar b/c + Wilson 95% CI (`SL-1` §4.4). 1~3문항 차이는 노이즈(`KGG-1` §6 N=8 파일럿 교훈).
- **오류 라벨**: `ENT-1` 4분류(Filter / Scope / Aggregation / Other) + `SL-1` 5범주 + `JAMIA-1` pass/partial/fail. partial 이 많으면 값 사전 문제, fail 이 많으면 규칙·의도 문제.
- **거절 문항 유형 라벨**: 컬럼 부재 / 값 부재 / 범위 밖 / 주관·추천 / 모호 — 유형별 규칙 커버리지를 센다 (`REF-1` ▶3).
- **0행 진단**: sqlglot 로 WHERE 조건을 하나씩 빼 실행(LLM 0회, `VAL-1` §3.3.1) → "A 조건 N건·B 조건 M건은 있으나 동시 만족 0" 으로 거절 근거를 값으로 준다.

## 4. 제출·제안서 관점 — 온톨로지의 두 형태

`SL-1` §3 은 시맨틱 레이어를 **context form**(프롬프트에 넣는 규칙 문서) 과 **runtime form**(없는 개념 참조 시 에러를 내는 결정론적 컴파일러) 으로 나눈다. 우리 아키텍처는 둘 다 갖고 있다:

```
context form  = ontology/enums/*.yaml (query_rules·normalization·columns) → 플래너 프롬프트
runtime form  = [Gate] absent_in·enum 기각 · validate_sql · KG alias 의 verbatim IN · (신설) enum 값 검사기
```

제안서에는 "온톨로지 = OWL 파일" 이 아니라 **"규칙 문서(context) + 구조적 게이트(runtime) + 값 사전 KG"** 세 층으로 서술하고, 각 층에 위 카드의 수치를 하나씩 붙인다(써도 되는 수치 목록은 `선행연구_종합_2026-08-30.md` §4).
