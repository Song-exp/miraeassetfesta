# 선행연구 카드 작성용 과제 맥락 (2026-08-30)

> 카드의 `▶ 적용`·`🚫 적용 가능성` 은 아래 제약과 **직접 대조**해서 쓴다. 성능이 좋다는 것은 판정이 아니다.

## 과제
미래에셋 AI 페스티벌 "금융상품 Agent" — 사용자의 자연어 질문(한국어)에 **DB 에 있는 값만으로** 답하는 챗봇.
채점: 제안서 40 / 답변 40 / 소스코드 20. **환각(없는 값·없는 컬럼을 지어 답함)은 감점**, "확인되지 않습니다" 로 거절하는 것이 정답인 문항이 있다.
코드 프리즈 2026-09-06. 남은 기간 1주.

## 데이터 (SQLite 하나)
- 마스터 4테이블: 국내채권 21,882 · 국내ETF 1,780 · 해외ETF 6,037 · 공모펀드 23,676 행. 컬럼 합계 280 (+ 공모펀드 종목명 파싱 파생 `nm_*` 27).
  주최가 준 스냅샷(기준일 2026-08-22). **외부 실시간 데이터·웹검색 금지**(발행일 ≤ 8/24 자료만).
- 외부 보조 4테이블(`ext_*`): ETF 구성종목, 펀드 구성종목·설명서 사실. 마스터와 조인 키가 정해져 있음(`JOIN_KEYS`).
- 값의 특성: 위장결측(더미 `000000000000`, 센티넬 `-100`), 코드 컬럼(코드북으로 이름 매핑), 복합 표기(벤치마크 `'KOSPI200 25% + 종합채권01Y 75%'`), 별칭 폭발(운용사 '미래에셋' 표기 43종), 한 펀드가 클래스(A/C/Ce…)별로 여러 행.

## 지금 아키텍처 (바꾸지 않을 것)
```
질문 → [Ground] KG 개체 매핑 (kg_node 39,658 · kg_alias 62,558 · kg_edge 7,414 · kg_closure)
        질문 안의 표기 → 노드 → 그 노드(+closure 후손)의 alias = (테이블, 컬럼, raw 값) → "이 컬럼에 이 값들로 IN" 으로 플래너에 전달
     → [Gate] 부재 선언(absent_in)·enum 범위 밖 질의는 LLM 호출 0회로 기각 ("해당 상품엔 그 속성이 없습니다")
     → [Plan] HCX(HyperCLOVA X, API 호출만 · 파인튜닝 불가 · rate limit 있음) 가 SQL 생성.
        프롬프트 = KG 매핑 + 도메인 규칙(yaml `query_rules`·`normalization` 평문) + 스키마(컬럼 한글명)
     → validate_sql (SELECT 만·허용 테이블·LIMIT) → 실행 → 답변 조립 (0행이면 "확인되지 않습니다")
```
- 온톨로지/규칙은 `ontology/enums/<domain>.yaml` 에 사람이 판정해 적는다: 컬럼별 결측 사유 4분류(`none/missing/not_applicable/mixed`)·답변 정책·단위, `query_rules`(기본 모수, 0/센티넬 배제, 부분일치 규칙), `normalization`(더미 규칙, trim, 코드 폭), `derivation_rules`(자산군·레버리지 등 유도), `name_features`(종목명 파싱 → 파생 컬럼).
- KG 는 값-사전 역할이 크다: 개체(Organization·Index·Security·Fund·AssetClass·Region…)와 그 표기 변형(alias). 관계(edge)는 `feedsInto`(모자펀드)·`coversRegion`·`hasAssetClass`·`subsidiaryOf` 정도이고 **런타임은 edge 를 필터로 쓰지 않는다** (closure 로 후손 alias 확장만).
- 평가 자산: gold 63문항(SQL 재현 검증), pytest 68.

## 하드 제약 (적용 가능성 판정 기준)
1. **LLM 은 HCX API 만** — 모델 학습·파인튜닝·임베딩 모델 추가 학습 불가. 프롬프트·검색·규칙·전처리 수준의 방법만 쓸 수 있다.
2. **HCX 호출 수** — 질문당 1~2회가 현실적(rate limit · 응답 3~6초). 다중 샘플링·self-consistency 10회 같은 방법은 비용상 어렵다.
3. **데이터는 스냅샷 하나** — 실시간 피드·웹·외부 KB 사용 금지. 질문-SQL 학습 데이터도 없다(gold 63 뿐).
4. **환각 감점** — 없는 값을 만들면 안 된다. 거절이 정답인 문항 존재.
5. **한국어 질의** · 금융상품 도메인 · 스키마는 작지만(280컬럼) 도메인 규칙이 무겁다(결측 의미·단위·모수).
6. **1주 안에 반영 가능한 것만** — 대규모 인프라(그래프 DB 도입, 벡터 인덱스 재구축)는 어렵다. SQLite + yaml + 파이썬 안에서.

## 이번 조사가 답해야 하는 질문
- **어떤 관계(edge)를 KG 에 잡아야 답변이 좋아지는가** — 지금은 alias(값 사전)만 사실상 쓰고 있다. 관계를 더 잡는 것이 정확도에 기여한다는 근거가 있는가, 있다면 어떤 종류(계층·동의·구성·조인 경로)인가.
- **관계 외에 무엇이 답변 정확도를 좌우하는가** — 도메인 규칙 문서(semantic layer), 값 링킹(value/entity linking), 스키마 링킹, 거절(abstention), 검증(execution feedback) 중 근거가 강한 것.
- 각 방법이 **위 하드 제약 안에서** 쓸 수 있는가.
