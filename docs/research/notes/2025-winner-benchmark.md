## 2. ✅ 그대로 차용할 것 (검증된 승리 공식)

### 2-1. 아키텍처 — 우리 설계와 거의 동일

```
              HyperClovaX (중앙 오케스트레이터)
        ┌──────────┼───────────┐
   Clarifier     Parser      Fin.Tools ── DB ── API
                 Retriever
```

| 대상작 노드 | 역할 | 우리 대응 (agent_architecture_notes.md) |
| :--- | :--- | :--- |
| **Clarifier** | 조건 부족 시 역질문 | `clarify` 분기 (질의 D-020과 동일) |
| **Parser** | 인텐트 분석 | Route/Ground 노드 |
| **Fin.Tools** | 종목·시장·패턴 데이터 조회 | RDB/SQL 조회 |
| **Retriever** | Web Search로 최신·어려운 개념 보완 | ⚠️ 우리는 제약 있음(§3-2) |

→ **대상작이 우리 9노드 설계 방향이 옳다고 증명.** Clarifier(역질문)를 별도 노드로 둔 것도 일치.

### 2-2. 외부 데이터 → DB 적재 (속도·안정성)

> slide 5: "데이터 원천은 **YFinance, KRX API 사용**, **주기적으로 DB에 적재 → 안정성·속도 확보**"

우리가 논의한 **"구성종목 외부보완 후 별도 테이블 + 15초 SLA용 캐싱"**과 정확히 같은 패턴.

### 2-3. 기대효과 = 사업화 정량화 (⭐ 5번 항목의 모범답안)

> slide 20: 잠재고객 = **Σ(연령대별 투자자수 × GPT 사용률) = 최대 250만명**
> + 수익모델: **매매 API 수수료 / 구독 기능**

이오랑 수석이 "5번(기대효과·확장성)이 수상의 핵심 요소"라 강조. 대상작은 **숫자로 사업성을 증명**했다.
→ 우리 기술제안서 §5도 이렇게 **정량화 + 수익모델**을 넣어야 한다.

## 3. ⚠️ 그대로 따라하면 안 되는 결정적 차이

### 3-1. 🔴 도메인이 다르다 — 기술적분석 ≠ 금융상품검색

- 대상작: **주가 차트 패턴**(적삼병 등 캔들) = 기술적 분석
- 우리: **금융상품 검색·비교**(ETF/채권/펀드 속성·보수·수익률) = 상품 정보
- → 적삼병·캔들패턴 로직은 **우리 과제와 무관.** 아키텍처는 빌리되 도메인 로직은 전면 재설계.

### 3-2. 🔴 실시간 vs 스냅샷 — 감점 함정

- 대상작: YFinance **실시간** 주가 + Retriever로 **최신 뉴스** 검색
- 우리: **2026-07-11 스냅샷 고정.** 이후 데이터 = **감점**
- → **대상작의 "웹검색으로 최신정보 보완"을 그대로 쓰면 우리는 감점.**
  Retriever를 쓰더라도 **7/11 이전으로 제한**해야 함. 우리 과제의 핵심 제약.

### 3-3. 🟡 LangGraph — 대상작은 사용, 우리 팀은 미사용 결정

- 대상작 slide 7: **LangGraph** 비선형 구조 (에이전트 자율 툴호출·오류 재시도·병렬 툴)
- 우리: `agent_architecture_notes.md` §8에서 **재현성 위해 순수 Python** 결정
- → 대상작이 LangGraph로 대상을 탔다는 건 유효한 데이터포인트. 단 우리 "15초 SLA·Dockerfile 재현성"
  논리도 유효. **워크샵 재검토 안건.**

### 3-4. 🟡 온톨로지 — 대상작엔 부재 (2026의 새 축 = 우리 무기)

- 확인한 슬라이드(1~8)에 **온톨로지/지식그래프가 나오지 않음.**
- 2026 과제는 **온톨로지가 핵심 주제**(이오랑 수석 25분 강의, `ontology.ttl` 소스코드 필수).
- → **이것이 2026의 차별점이자 우리 무기.** 대상작 아키텍처 + **온톨로지 강화**가 승부수.
  (⚠️ 슬라이드 9~19 미확인 — 대상작이 온톨로지를 아예 안 썼다고 단정은 못 함. "발표에서 강조 안 됨" 수준.)

```
[대상작에서 차용]              [우리가 더할 것]
──────────────────────────────────────────────
```
