## ❓ 문제
Vishwanath et al. (Nature Medicine 2026) 이 "범용 프론티어 LLM 이 임상 RAG 도구보다 낫고, 검색이 강한 모델을 오히려 해친다"고 보고한 데 대한 후속 질문 (§1): 평문 검색 대신 **구조화된 KG 그라운딩**이면 결론이 바뀌는가, 그리고 더 근본적으로 **그라운딩은 언제 도움이 되는가**.
기존 의료 KG-RAG 연구는 MedQA 상승을 보고하지만 "그 사실이 모델 학습 안에 있었는가(knowledge boundary)"를 분리한 적이 거의 없다고 지목 (§8).

## 📊 데이터
- **공개 KG (in-training 가정)**: PrimeKG (drug/disease/phenotype/gene, MIT) 를 samyama-graph 에 적재, 노드명 임베딩 → HNSW 벡터 검색 (§2, §5). 평가는 MedQA 객관식 exact-match, N=150–200, 모델 사다리 gpt-4.1-nano → gpt-4o-mini → gpt-4.1 → gpt-5.2 (§6 Setup).
- **합성 반사실 KG (out-of-training)**: 가상의 약·질병·표현형, seed 62. 어떤 모델의 학습에도 없는 사실. KG 로 답할 수 있는 4지선다, N=150 (§6, Table 3).
- **하이브리드 KG**: 알려진 층(교과서 질병→약 사실 24개) + 신규 층(합성 사실 80개)을 한 그래프에 적재 (§6, Table 4).
- **GAK 실험**: 신규 사실 40개(질문 80개), 답이 비구조 문서(monograph)에만 있음 (§6, Table 5).
- **실제 out-of-training**: 2026 FDA 신약 승인 13건 (§6 p.6).
- **재현 파트**: HealthBench(oss_eval 전체 / Consensus N=150) · MedQA 500문항, temperature 0 · seed 62 (§4, Table 1). 우리 과제와 무관하므로 카드에서는 다루지 않음.

## 🛠 방법
같은 기저 모델을 고정하고 그라운딩 arm 만 바꿔 비교 (§5, Figure 1):
- **A0**: 검색 없음, 파라메트릭 기억만.
- **A_kg (naive KG-RAG)**: 질문을 벡터 검색 → 1-hop 임상 서브그래프 확장(degree 상한) → 트리플로 포맷해 컨텍스트에 넣음.
- **A_text**: 원문 구절을 컨텍스트에 직접 넣는 평문 RAG, 질문당 LLM 1회.
- **A_agent**: 고정 에이전트(gpt-4.1)가 ① 벡터 검색으로 개체 링킹 → ② **해결된 개체명을 글자 그대로(verbatim)와 특정 관계 타입으로 제한한** 다중 hop Cypher 작성 → ③ 실행 → ④ 오류·빈 결과면 최대 2회 자기수정. 반환 행이 그라운딩 컨텍스트. 질의 작성자를 고정한 것은 "답하는 모델이 그라운딩으로 득을 보는가"를 Cypher 실력과 분리하기 위함 (§5 p.5).
- **A_det**: LLM 없이 사전 코딩된 핸들러가 Cypher 조회를 직접 발행해 보기와 대조 — **데이터 계층을 LLM 에서 분리**하는 통제군.
- **A_GAK**: 그래프에 없으면 에이전트가 원문에서 사실을 추출 → 출처 태그를 단 노드/엣지로 물질화 → 이후 같은 개체 질문은 캐시 히트(LLM 0회).
- 사용한 엔진 기능은 **벡터 검색 + Cypher 조회뿐**. PageRank·경로·최적화 프리미티브는 "임상 객관식은 lookup 모양"이라 쓰지 않음 (§5 p.4–5).
- 엔진 이슈: 허브 노드의 1-hop 확장에 LIMIT 푸시다운이 없어 수백만 행이 생김 → degree 상한 인접 리스트를 미리 계산해 우회 (§5 Engine findings p.5).

## ⭐ 핵심 발견
- **공개 KG 에서는 무효과.** PrimeKG + MedQA 에서 naive·agentic 모두 모델 강도와 무관하게 |Δ| ≤ 3.4pt, CI(±4–7) 안. 에이전트가 82% 비어있지 않은 올바른 질의를 냈는데도 그렇다 (Table 2, §6 p.5). 두 번의 독립 재실행에서도 |Δ| ≤ 5.5 (§6 Robustness p.7).
- **학습 밖 사실에서는 결정적.** 합성 KG 에서 A0 ≈ 21–23%(4지선다 우연 수준) → A_agent 98.7–100%, +75.4~+78.7pt, 모든 모델에서 균일 (Table 3). 3 seed × 4 모델 평균 +76.6 ± 2.9 (§6 Robustness p.7).
- **한 벤치마크 안에서 경계가 갈린다.** 하이브리드: 알려진 층은 A0 이미 100% → 그라운딩 +0; 신규 층은 A0 22.5–32.5% → 100% (Table 4). **LLM 없는 A_det 는 두 층 모두 100%** — 사실이 그래프에 있으면 데이터 계층만으로 충분 (Table 4, §6 p.6).
- **개체 링킹이 질의 성공을 좌우.** LLM 이 개체명을 지어낼 때 성공률 0% → 벡터 개체 링킹 + few-shot 방향 예시 후 82% (§5 p.5).
- **"학습 밖" ≠ "모를 것".** 2026 FDA 신약 13건에서 A0 ≈ 84% — INN 명명법(-drostat→고혈압 등)으로 **이름에서 적응증을 추론**. 이름이 아무것도 암시하지 않는 1건(pivekimab sunirine)만 A0 ≈ 8%(1/12), A_det·A_agent 는 정답. 법칙 정제: **그라운딩은 사실이 학습에도 없고 표면 구조로 복원도 안 될 때 도움된다** (boundary = training ∪ inferable) (§6 p.6–7).
- **GAK 경제성.** 평문 RAG 는 80문항에 LLM 80회, GAK 는 추출 40회 + 캐시 히트 40회로 같은 100% (Table 5).
- **소표본 신호는 노이즈.** N=8 파일럿에서 보인 깔끔한 crossover(+25→−12.5)가 N=200 에서 사라짐 (§6 p.5).

## ▶ 적용
과제 맥락 문서의 질문에 대한 답과 행동:

1. **"KG 그라운딩이 언제 도움되는가" → 우리 스냅샷은 정확히 '학습 밖' 영역.** 2026-08-22 기준 국내채권 21,882·펀드 23,676 행의 개별 값(보수·위험등급·설정일·벤치마크 배합)은 HCX 학습에 없고 이름으로 복원되지도 않는다. Table 3·4 의 "+0 vs +77" 이분법에서 우리는 +77 쪽 → **제안서의 "KG·DB 그라운딩 근거"로 Table 4 와 §7 을 인용**한다. 반대로 공개 상식(ETF 가 무엇인지, 레버리지 뜻)은 그라운딩해도 이득 없음 — 프롬프트에 일반 금융 설명을 길게 넣을 이유가 없다.
2. **A_det 100% = 우리 [Gate]·SQL 실행 결과가 답이라는 설계의 실증.** 답은 LLM 이 아니라 데이터 계층에서 나와야 한다 (Table 4). 행동: 답변 조립 단계에서 HCX 가 SQL 결과 밖의 값을 덧붙이지 못하게 결과 행만 템플릿으로 조립하는 현행 방식을 유지하고, "확인되지 않습니다" 판정도 0행이라는 데이터 사실에서만 나오게 둔다.
3. **"inferable" 발견은 우리에게 환각 경보다.** 종목명(`TIGER 미국S&P500`, `(H)`, `레버리지`, `A/C-e 클래스`)은 INN 처럼 클래스 정보를 담고 있어 HCX 는 컬럼이 NULL 이어도 이름에서 값을 추론하려 한다 (§6 p.6 의 A0 84%). 행동: ① 이름에서 추론 가능한 속성은 **`name_features` 로 미리 파생 컬럼에 물질화**해 LLM 추론 대신 컬럼 판정으로 답하게 한다 (GAK 의 "추출 1회 → 물질화 → 캐시" 와 같은 구조, Table 5). ② 파생 컬럼도 없는 속성은 Gate 의 absent_in 으로 거절해 이름 추론을 차단한다.
4. **개체 링킹은 verbatim + 관계 타입 제약으로.** 0%→82% (§5) 의 비결은 벡터 검색 자체보다 "해결된 개체명을 그대로 쓰라"는 제약이다. 우리 [Ground] 는 이미 kg_alias 로 raw 값을 찾으므로 벡터 인덱스 없이 같은 효과를 낸다. 행동: 플래너 프롬프트에 **"IN 절 값은 아래 매핑 목록의 raw 값을 글자 그대로만 사용, 목록 밖 값 생성 금지"** 를 명시하고, 부분일치가 필요한 컬럼(`query_rules` 의 LIKE 규칙)만 예외로 열어 둔다. 조인 방향 few-shot(§5 의 "direction examples")에 해당하는 `JOIN_KEYS` 예시 1–2개를 프롬프트에 넣는다.
5. **관계(edge) 를 더 잡을 근거는 이 논문에 없다.** 사용한 관계는 질병→약 1-hop lookup 뿐이고 그래프 알고리즘·경로는 의도적으로 안 씀 (§5). 즉 이 논문은 "값이 그래프에 있는가"를 증명했지 "관계가 많을수록 낫다"를 증명하지 않았다. 행동: 이번 주 edge 확장(구성·조인 경로)은 이 논문을 근거로 밀지 말고, alias 커버리지(별칭 43종 같은 값 사전) 보강을 우선한다.
6. **평가 해석.** gold 63 에서 변형 간 차이 1–3문항은 N=8 파일럿의 허상(§6)과 같은 수준이다. 행동: 변형 비교표에 Wilson 95% CI 를 함께 적고, CI 가 겹치면 "차이 없음"으로 기록한다.
7. **재시도 정책.** A_agent 는 오류·빈 결과에 최대 2회 자기수정 (§5). 우리는 SQL 오류(validate_sql 실패)에는 1회 재생성이 가능하나, **0행은 재시도 대상이 아니다** — 우리 과제에선 0행이 정답(거절)인 문항이 있으므로 빈 결과 재시도는 환각 경로가 된다.

## ⚠️ 한계
- **저자 인정** (§9): 공개 데이터 결과는 부정적이며, 긍정 결과는 **가상 개체의 합성 KG** — 실제 사설 임상 그래프에서의 상승은 미래 과제. 질의 작성자는 고정 gpt-4.1 이라 약한 모델이 스스로 질의를 쓰는 경우는 검증 안 됨. prior-strength 에 따른 crossover 는 두 극단만 봐서 관찰 불가. MedQA exact-match 라 추론 품질은 무시.
- **내가 본 것**:
  - 합성·하이브리드 질문은 "KG 로 답할 수 있게" 구성되었고 A_det 는 질문 유형별 사전 코딩 핸들러다 (§5). 100% 는 데이터가 있으면 lookup 이 맞는다는 확인이지, **자연어→질의 변환의 어려움**(우리의 진짜 병목: 한국어·결측 의미·모수)에 대한 증거가 아니다.
  - 알려진 층 24 사실 · 신규 80 사실 · FDA 13건 — 규모가 작다. FDA 실험은 저자도 "run-to-run noise" 를 인정 (§6 p.6).
  - 상승폭 표기가 절마다 다르다: 초록 +68~+79, 기여 +68~+78, Figure 2 캡션 +72~+77, Table 3 +75.4~+78.7. 인용은 표 수치로.
  - samyama-graph 는 저자 소속사의 엔진이고 A_GAK 는 자사 아키텍처(Kunkunuru & Mandarapu 2026)를 검증하는 구도 — 벤더 논문임을 감안.
  - 4지선다 객관식이라 거절(abstention)·환각 감점 상황은 전혀 다루지 않는다. "확인되지 않습니다" 문항 설계에 쓸 근거는 없다.
  - Figure 2 는 렌더링하지 못해 캡션 수치만 확인.

## 🚫 적용 가능성
**조건부** — *결론(지식 경계 법칙)은 가능, 파이프라인은 불가.*
- **가능 (제약 3·4 에 부합)**: "그라운딩은 학습 밖 사실에서만 결정적, 데이터 계층만으로 100%" (Table 3·4) 는 우리 스냅샷·환각 감점 상황을 정당화하는 설계 근거로 바로 쓴다. verbatim 개체 제약(§5)과 이름 추론 → 파생 컬럼 물질화(§6 p.6, Table 5 의 캐시 구조)는 yaml·파이썬·프롬프트 수준이라 제약 1·6 안에서 이번 주에 반영 가능.
- **불가 (제약 1·2·6 위반)**: Cypher 그래프 DB, HNSW 벡터 개체 링킹, gpt-4.1 고정 질의 에이전트, 오류·빈 결과 2회 자기수정 루프는 도입하지 않는다. 우리는 SQLite + kg_alias 로 같은 역할을 이미 하고 있고, 빈 결과 재시도는 제약 4 와 충돌한다.
- **근거 부재**: 관계(edge) 추가가 정확도를 올린다는 증거는 이 논문에 없다 (§5 는 1-hop lookup 만 사용). edge 설계 질문은 다른 문헌에서 답해야 한다.
