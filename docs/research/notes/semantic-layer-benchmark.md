## 연구 질문

자연어 → DB 질의에서, **명시적 비즈니스 시맨틱을 주면 LLM 성능이 개선되는가.**
모델이 진술되지 않은 의미 맥락을 추론하지 못해 생기는 실패를 다룹니다.

## 방법

- 대상 모델 3종: **Claude Opus 4.7 · Claude Sonnet 4.6 · GPT-5.4**
- 데이터: Cleaned Contoso Retail Dataset, **질문 100개**
- 프로토콜: paired single-shot — 같은 모델을 두 번 평가
  - ① 스키마만
  - ② 스키마 + **손으로 쓴 4 KB 마크다운** (측정값 정의·관례·모호성 해소 규칙)

## 결과

| 조건 | 정확도 |
| :--- | :--- |
| 시맨틱 레이어 **있음** | **67.7 ~ 68.7%** |
| 시맨틱 레이어 **없음** | **45.5 ~ 50.5%** |
| 차이 | **+17 ~ +23 %p** (모든 모델에서) |

- 모든 교차 비교가 **p < 0.01** 유의
- 저자 결론: 시맨틱 레이어가 **"유의한 분산의 사실상 전부"** 를 설명
- **모델 선택 자체의 차이는 미미** — 세 모델이 거의 같은 값

## 저자 해석

> 명시적 비즈니스 시맨틱은 **"모델을 더 유능하게 만드는 것이 아니라,
> 모델이 무엇을 하도록 요구받는지를 바꾼다."**

## ▶ 우리 프로젝트에 적용

### 🚫 적용 가능성: **가능**

우리 구조가 이미 이 논문의 실험 조건 ②와 같습니다.

| 논문 | 우리 |
| :--- | :--- |
| 4 KB 손으로 쓴 마크다운 (측정값 정의·관례·모호성 해소) | `ontology/enums/<domain>.yaml` — `answer_policy` · `normalization` · `query_rules` · `derivation_rules` |
| 스키마만 주는 조건 | 프로파일러 없이 원본 테이블만 LLM 에 노출하는 경우 |

### 직접 함의 3가지

**① "LLM 을 튜닝하면 된다" 는 근거가 없습니다.**
세 프론티어 모델의 차이가 미미했습니다. 우리는 HyperCLOVA X 로 **고정**돼 있어
모델 교체 자체가 불가능한데, 논문 기준으로 그건 애초에 큰 변수가 아닙니다.

**② 우리 EDA 산출물이 곧 성능 변수입니다.**
`answer_policy`(모수 명시), `derivation_rules`(다축 컬럼 분해), `trim_columns` 는
논문이 말하는 "관례·모호성 해소 규칙" 그 자체입니다.

**③ 상한선의 위치를 알려줍니다.**
시맨틱 레이어를 붙여도 **67~68%** 입니다. 100% 가 아닙니다.
→ 나머지 30%를 "확인할 수 없음" 으로 정직하게 처리하는 가드레일이
   정확도만큼 중요하다는 뜻이며, 이는 우리 감점 구조(환각 = 즉시 대형 감점)와 부합합니다.

## ⚠️ 한계 — 그대로 적용하기 전에 확인할 것

- **초록만 읽었습니다.** 실패 사례 분류, 4 KB 문서의 실제 구성, 환각 측정 방법은 미확인입니다.
  ("Hallucination" 이 제목에 있으나 수치를 확보하지 못했습니다.)
- 도메인이 **소매(Contoso)** 이고 질문 100개입니다. 금융 마스터 데이터,
  특히 우리처럼 **행 단위가 비정규(종목 × 속성태그)** 인 경우는 다룬 바 없습니다.
- 대상 모델에 **HyperCLOVA X 가 없습니다.** "모델 차이 미미" 결론이
  HCX 에도 성립하는지는 별도 확인이 필요합니다 — 우리 자체 평가셋 80문항이 그 역할을 합니다.
- 4 KB 는 작습니다. 우리 `<domain>.yaml` 은 이미 그보다 크고 4개 테이블로 늘어납니다.
  **컨텍스트에 통째로 넣는 방식은 15초 SLA 에서 검증이 필요합니다**
  (→ `docs/agent_architecture_notes.md` 의 "yaml 을 통째로 프롬프트에 넣지 않는다" 와 연결).
