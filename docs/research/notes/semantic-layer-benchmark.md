## ❓ 문제
자연어→SQL 에서 **오답과 확신에 찬 환각은 같은 원인의 두 얼굴**이라는 관점: 모델이 스키마에 없는 비즈니스 의미(어느 테이블이 관례인지, 지표 공식, 센티넬 값, 모호한 표현의 해석)를 **추론하도록 강요**받기 때문 (§1 p.2, §2.1). 특히 문법상 유효하고 실제 컬럼을 참조하며 에러 없이 행을 돌려주는데 틀린 **silent hallucination** 이 가장 위험하다고 지목 (§1 p.2, §5.4 p.17–18).

지목한 기존 방법의 실패: 파인튜닝·프롬프트 엔지니어링·RAG·구조화 출력은 모두 "생성 확률" 을 조정할 뿐, 모델이 여전히 아무 토큰이나(없는 컬럼 포함) 생성할 수 있다는 근본 원인을 건드리지 않는다 (§2.1 p.4, §1 p.3). 학술 벤치마크→기업 스키마로 갈수록 정확도가 붕괴(Spider ~91% → Spider 2.0 17–21% → BEAVER ~0%)하는 것도 "구조화된 의미 맥락의 부재" 로 해석 (§2.3 p.5).

## 📊 데이터
- **Cleaned Contoso Retail Dataset** (Thakur 2023, Kaggle) — MS ContosoRetailDW 의 정제 CSV. 25 테이블(FactOnlineSales·FactSales·FactInventory 일별 스냅샷·FactStrategyPlan·FactExchangeRate + Dim*), 매출 기간 2007–2009. ClickHouse 에 적재 (§4.1 p.10).
- **질문 100개**, 5 난이도 × 20 (simple / medium / complex / advanced / expert). 데이터 관례에 걸리는 문항을 **의도적으로 포함**: 문자열 불리언(`IsSalesPerson`='Yes'/'No'), 시점 합산 금지 스냅샷, 센티넬 FK(`PromotionKey=1`="No Discount"), 데이터 마지막 날짜 2009-12-31 기준의 "최근" 해석, 고객 vs 매장 지역 기본값 (§4.1 p.10–11).
- 참조 SQL(`expected_sql`) 실행 결과가 정답 행. q33 은 참조 쿼리가 ClickHouse 메모리 한도를 넘어 제외 → **n = 99** (§4.4 p.12–13).
- 분할 없음(학습 데이터 없음, 전부 평가용). 질문-SQL 학습 없이 single-shot 만 (§4.2).

## 🛠 방법
**Paired single-shot 프로토콜** — 같은 모델·같은 질문·같은 하네스·같은 판정자에서 딱 하나만 바꾼다 (§4 p.10).

- **Raw 조건**: 질문 + 25 테이블 전체 CREATE TABLE DDL. 도구·반복·실행 피드백·재시도 **모두 없음** (§4.2 p.11).
- **Semantic-layer 조건**: 위와 동일 + **마크다운 문서 1개 (약 4 KB = 8,969자, ~2,200 토큰)**. 내용: 팩트 테이블 선택 규칙, 지표 공식(총마진·반품률·AOV·재고회전·동일점포 성장·최근성 세그먼트), 차원 계층, 데이터 관례·함정(문자열 불리언·스냅샷·센티널 키), 암묵적 기본값, 명시적 모호성 해소 규칙. 분석가가 손으로 작성, 코드 아님, **강제되지 않는 조언적(advisory) 문서** (§4.2 p.11).
- 저자가 정의하는 시맨틱 레이어 구성 5범주: ① 팩트 테이블 선택 규칙 ② 지표와 공식 ③ 차원 계층과 조인 경로 ④ 데이터 관례·quirk(문자열 불리언·센티넬·스냅샷/누적·통화·"현재 날짜") ⑤ 모호성 해소 규칙 (§3.1 p.8–9). 두 형태 구분: **runtime form**(YAML 데이터 모델 + 결정론적 컴파일러, 없는 measure 참조 시 에러) vs **context form**(프롬프트에 넣는 자연어 문서). 이 논문은 context form 만 실험 (§3 p.8, §3.2 p.9).
- 모델 3종: Claude Opus 4.7, Claude Sonnet 4.6 (`claude -p`), GPT-5.4 (`codex exec`). reasoning effort 전부 "medium" 고정 (§4.3 p.11–12).
- 판정: LLM judge `claude-sonnet-4-6`, JSON 스키마 강제, 어떤 조건인지 모르고 시맨틱 문서도 안 보여줌. **strict**(행 일치, 열 순서·1% 미만 수치 편차 무시) 와 **analytical**(집계 분해·소수/퍼센트 단위·null 카테고리 행 허용) 두 판정 중 analytical 이 주지표 (§4.4 p.12–13).
- 통계: Wilson 95% CI, 쌍대 비교는 two-sided exact McNemar, 불일치 개수 b/c 병기 (§4.4 p.13, §4.6 p.14).
- "silent hallucination rate" 는 **별도 지표로 보고하지 않음** — §5.4 정성 분석만. 분해는 future work (§4.6 p.14).

## ⭐ 핵심 발견
- **문서 하나로 +17.2 ~ +23.2 pp**. Opus 4.7 50.5→67.7, Sonnet 4.6 46.5→68.7, GPT-5.4 45.5→68.7 (analytical, n=99, McNemar p ≤ 0.0015) (Table 1 p.15). 모델 간 격차는 양쪽 조건 모두 약 5 pp — 문서 효과가 그 4–5배 (§5.1 p.15).
- **맥락이 모델 선택을 지배**: 시맨틱 클러스터 내부 3쌍 전부 ns (p ≥ 0.79), raw 클러스터 내부도 ns (p ≥ 0.42), 클러스터 교차 9쌍은 전부 p < 0.01 (Table 2 p.16, §5.2). 저자 스스로 "within-study 통계 주장이며 보편 주장 아님" 이라 한정 (§5.2 p.16).
- **가장 작은 모델 + 문서 > 가장 큰 모델 − 문서** (Sonnet+Sem 68.7 vs Opus raw 50.5, Table 1; §6.1 p.18). 모델을 올려서 문서 부재를 메울 수 없다 (§5.2 p.16, §6.4 p.20).
- **이득이 몰린 실패 범주 5개** (§5.4 p.17): ① 다중 팩트 테이블 선택("sales" 가 어느 테이블인지) ② 스냅샷을 시점 합산해 약 1000배 값 ③ 지표 공식 ④ 암묵적 기본값·센티넬(`PromotionKey=1`, 문자열 `IsWorkDay`, 1글자 코드 `Gender`) ⑤ 시간 앵커(데이터 마지막 날 2009-12-31 대신 `today()` 로 해석 → **빈 결과**). 이들은 SQL 만 봐서는 정답과 구분 불가 (§5.4 p.17–18).
- **잔여 ~30% 실패는 문서에 없는 패턴**(백분위·상관·표준편차·ABC 분류·임계값 순위·재귀 CTE·다중 CTE 피벗·진짜 모호한 문항) — 저자는 "메커니즘을 바꿀 게 아니라 문서에 named measure 를 더 적어 고칠 것" (§5.4 p.18, §6.4 p.20).
- **실행 피드백·재시도 없이** 얻은 수치다 (§4.2 p.11). 즉 +17–23 pp 는 검증 루프의 기여가 아니라 순수 맥락의 기여.
- **all-in-prompt > 검색 기반 발견**: 동등한 의미 지식을 도구로 탐색하게 한 agentic 시스템이 schema-only 베이스라인을 **넘지 못했다** (companion repo 내부 실험, 상세 미보고) (§6.5 p.21).
- 비용: 입력 토큰 14K–23K/질문, 지연 8.1–15.6 s, 출력 271–439 토큰. 문서 자체는 ~2,200 토큰이라 prompt caching 시 한계비용 ≈ 0 (Table 1 p.15, §5.3 p.16–17).
- context form 은 **조언**이라 이 수치는 runtime form 의 **하한** (§6.2 p.19). 거절(abstention)은 runtime form 이 구조적으로 강제 — 모델 밖 개념 참조 시 에러 반환 (§2.5 p.5–6).
- 2차 인용(이 논문 실험 아님, 방향 참고용): 온톨로지 제약 하에서는 **환각된 클래스/속성이 0**, 오류가 property path 로만 남음 — 오류 "종류" 가 바뀐다 (Allemang & Sequeda 2024, §2.6 p.6, §6.3 p.20). Bayer 사례: 문서 없이 스키마만 좁히면 실패율이 50% 까지만 줄어 "문서가 일하는 것이지 스키마 축소가 아님" (§2.7 p.7). BIRD evidence 의 7–10% 는 결함이고 자동 생성 evidence 가 사람 것을 이길 수 있음 — 출처보다 **품질** (§2.6 p.6).

## ▶ 적용
과제 맥락 문서의 세 질문에 이 논문이 답하는 범위에서:

**Q1. 어떤 관계(edge)를 KG 에 잡아야 하는가 → 이 논문은 근거를 주지 않는다.**
문서 5범주 중 "차원 계층·조인 경로" 가 있지만 (§3.1) 범주별 ablation 이 없어 조인 경로가 얼마나 기여했는지 분리 불가. §5.4 의 이득 범주 5개 중 관계형 구조가 필요한 것은 ① 테이블 선택 하나뿐이고, 나머지 ②④⑤ 는 전부 **값 관례·센티넬·기준일** — 우리 `normalization`/`query_rules` 의 영역. KG edge 의 근거는 2차 인용(Sequeda/OBQC)뿐. → **남은 1주에 edge 를 늘리는 작업은 이 논문을 근거로 정당화되지 않는다.** alias 값-사전 + closure 유지.

**Q2. 관계 외에 무엇이 정확도를 좌우하는가 → 도메인 규칙 문서가 가장 강한 근거, 검증 루프는 필요조건 아님.**
1. **도메인별 압축 규칙 문서를 §3.1 5범주로 재편해 프롬프트에 통째로 넣는다.** 대응: ① 테이블 선택 → 채권/국내ETF/해외ETF/공모펀드 라우팅 + 클래스(A/C/Ce) 다중 행 처리 원칙 ② 지표·단위 → `answer_policy` 의 단위·모수 ③ 조인 경로 → `ext_*` 의 `JOIN_KEYS` 를 문장으로 명시 ④ 관례·quirk → 더미 `000000000000`·센티넬 `-100`·코드북·결측 4분류 ⑤ 모호성 해소 → '미래에셋' 43종 표기, 벤치마크 복합 표기, 기본 모수. 논문 문서는 2,200 토큰(§4.2)이므로 **도메인당 이 크기 근처를 목표** — Ground 단계에서 도메인이 정해지면 그 도메인 문서만 싣는다.
2. **규칙을 검색해 오는 방식으로 바꾸지 않는다.** §6.5 의 내부 실험(검색 기반 < all-in-prompt)이 그 반대 방향을 가리킨다. 기존 노트의 "yaml 을 통째로 넣지 않는다" 는 **크기** 문제이지 **방식** 문제가 아니다 — 통째로 넣되 도메인별로 잘라 작게 만드는 것이 논문과 정합.
3. **기준일 2026-08-22 를 프롬프트에 고정 문장으로 박는다.** §5.4 ⑤ 시간 앵커 실패는 **빈 결과**를 만든다. 우리 파이프라인은 0행 → "확인되지 않습니다" 이므로 이 실패는 **잘못된 거절**로 나타난다 — 환각은 아니지만 정답 문항을 놓친다. "최근·현재·올해" 류 표현의 해석 규칙을 ⑤ 에 명시.
4. **Gate·validate_sql 은 runtime form 의 역할 — 유지.** 논문 수치는 context form 만의 하한(§6.2)이고, 거절은 runtime 이 구조적으로 보장한다(§2.5). 우리는 이미 두 형태를 다 갖고 있다.
5. **잔여 실패는 문서 확장으로 잡는다 — gold 63 으로 paired ablation.** §5.4 처방 그대로: gold 실패 문항을 §5.4 범주로 분류 → 빠진 규칙을 문서에 추가 → 같은 63문항을 규칙 유/무로 재실행해 McNemar b/c 만 세면 된다 (§4.4). 63문항 × 2 조건 = 126 호출, 하드 제약 2 안에서 가능.
6. **모델 교체·튜닝 논의는 닫는다.** HCX 고정은 논문 기준으로 큰 변수가 아니다(§5.2, §6.4) — 단 HCX 미검증(아래 한계).

## ⚠️ 한계
**저자 인정 (§6.5 p.20–21):**
- 데이터셋 1개·웨어하우스 1개·n=99. ±10 pp 는 검출되지만 ±5 pp 는 경계 — "모델 무차별" 은 이 연구 안의 통계 주장.
- context form 만 실험. runtime form 과의 관계는 미답.
- 판정자(Sonnet 4.6)가 피험 모델 2개와 같은 계열. 쌍대 설계라 델타는 안 부풀지만 잔여 편향 미정량.
- single-shot · medium effort 고정. agentic/반복/고 effort 에서 효과가 유지되는지 별개 질문. "agentic 이 못 이겼다" 는 상세 미보고.
- 문서 작성자가 데이터셋을 본 사람. 완전 블라인드 문서라면 효과가 작을 수 있음. **문서 품질·커버리지가 효과의 상한.**

**내가 본 것:**
- 제목에 "Hallucination" 이 있지만 **환각률 수치는 없다** (§4.6 이 명시). 정확도 벤치마크로 읽어야 한다.
- 문서 5범주에 대한 **ablation 이 없다** — 규칙·조인 경로·지표 공식 중 무엇이 이득을 냈는지 분리 불가. §5.4 범주별 건수도 없음(정성 서술만). 우리 Q1 에 답하지 못하는 직접 원인.
- 저자 소속 Cube 는 시맨틱 레이어 벤더. §2.7 산업 수치(Snowflake·AtScale·Databricks)는 저자도 "directional" 이라 함 — 인용하지 말 것.
- **영어·프론티어 모델만.** 한국어 질의·HCX 는 미검증. "모델 무차별" 이 프론티어 밖(HCX)까지 성립하는지는 이 논문으로 말할 수 없다.
- 질문 성격이 다르다: 논문은 윈도우 함수·CTE·코호트 등 **분석형** 질의(§4.1), 우리는 조회·필터·거절형. 잔여 30% 가 백분위·CTE 에 몰려 있으므로(§5.4) 우리 상한은 더 높을 수도, 반대로 별칭·위장결측 같은 우리 고유 함정은 논문에 없으므로 더 낮을 수도 있다. 수치 자체를 옮겨오면 안 된다.
- analytical 판정은 관대하다(집계 분해·단위 환산 허용, §4.4). strict 수치는 본문에 표로 없음(p.13 "secondary check" 언급만).
- 저자의 "reasoning effort 를 올려도 비교 결과는 안 바뀔 것" 은 기대이지 측정이 아니다 (§4.3 p.12).

## 🚫 적용 가능성
**가능** — 방법의 실체가 "손으로 쓴 ~2,200 토큰 규칙 문서를 프롬프트에 넣는 것"(§4.2) 이라 하드 제약 6개와 전부 양립한다.
1. LLM 은 HCX API 만 → 프롬프트 수준 방법, 학습 불필요 ✔
2. 질문당 1–2회 호출 → 논문 자체가 single-shot·재시도 없음(§4.2)으로 효과를 냈다 ✔ (우리보다 적은 호출)
3. 스냅샷 하나·학습 데이터 없음 → 문서는 사람이 쓰고 gold 63 은 평가에만 쓴다 ✔
4. 환각 감점 → context form 은 조언이라 잔여 30% 가 남는다(§5.4). Gate·validate_sql(runtime form) 로 보강해야 하며 우리는 이미 갖고 있다 ✔ — 단 §5.4 ⑤ 형 실패가 "잘못된 거절" 로 나올 수 있어 기준일 고정 필요
5. 한국어·금융·무거운 도메인 규칙 → 논문의 이득이 바로 "무거운 관례" 에서 나왔다(§5.4). 한국어·HCX 는 미검증이므로 gold 63 paired 재실행으로 **자체 확인이 전제** (▶ 적용 5)
6. 1주 → 문서 재편 + 126 호출 ablation, 인프라 변경 없음 ✔

**단 이 논문이 답하지 않는 것**: KG 관계(edge) 추가의 효과. 그 근거는 Sequeda/Allemang(§2.6, §6.3) 등 별도 논문에서 찾아야 하며, 이 카드로 edge 작업을 정당화하지 말 것.
