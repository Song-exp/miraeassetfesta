# 선행연구 종합 — "어떤 관계를 잡아야 답을 잘하나, 관계 외에 무엇을 봐야 하나" (2026-08-30)

## 0. 한 줄 결론

**관계형 스냅샷 위의 QA 에서 정확도를 움직이는 것은 (1) 값이 데이터 계층에 있는가, (2) 개념→(컬럼·값·조건) 규칙 문서가 있는가, (3) 그 규칙이 질문에 맞게 골라져 SQL 조각 형태로 들어가는가, (4) 필터 값이 DB 실제 값 그대로인가 — 이 넷이다. "관계(edge) 를 더 잡으면 좋아진다"는 직접 근거는 10편 중 0편이었다.** 우리 KG 가 값-사전(alias) 역할에 집중하고 있는 것은 근거상 옳은 우선순위다.

## 1. 질문 ① — 어떤 관계를 잡아야 하는가

### 1-1. 근거가 말하는 것

| 관계 종류 | 근거 | 우리 상태 | 판단 |
| :-- | :-- | :-- | :-- |
| **동일성·별칭** (표기 변형 → 같은 개체 → raw 값) | KGG-1: 개체명을 verbatim 으로 제약하니 질의 성공 0→82% (§5) · KGQA-1: 링킹 산출물에 별칭 후보 추가가 +4~9pt 의 일부 (Table 3) · ENT-1: 실패 54.6% 가 WHERE/enum **값** 오류 (Fig. 4) | `kg_alias` 62,558 · closure 로 후손 alias 확장 | **핵심. 더 넓힌다** — 운용사 43종 같은 별칭 커버리지, 복합 벤치마크 성분(KOSPI200 47%·MSCI ACWI 83% 손실 실측) |
| **조인 경로** (마스터↔ext) | SCH-1: 조인 경로 문자열을 프롬프트에 주면 다중조인 문항 +6~12pp (Table 3), 단 8테이블에선 그래프 퇴화 (§3) · JAMIA-1: 문서에 PK/FK 관계 서술 (p.5) · ONT-1: 온톨로지에 "개념 간 경로" 포함 (§3) | `JOIN_KEYS` 고정, cross 질의에만 프롬프트 | **KG edge 가 아니라 프롬프트 문장** — `ext_*` 개체가 걸리면 "X = Y 로 잇는다" 한 줄 명시 |

| **구성** (복합 벤치마크 = 성분 지수 + 비중 · 펀드 → 구성종목) | 직접 근거 없음. KGQA-1 Northwind 사례가 "속성이 어느 관계에 붙는가"를 샘플로 교정 (Table 9) | 복합식 253종이 통째로 Index 노드 · 구성종목은 ext 조인 | **우리 실측으로 정당화** (E-3-12) — 논문 근거 아님. 성분 alias 부착은 리드 판단 |
| **시리즈·모자** (`feedsInto`, `seriesOf`) | 직접 근거 없음 | `feedsInto` 1,704 · `nm_series_family` 파생 | 답변 조립(그룹핑)용. 검색 정확도 근거는 없다 |
| **FK/스키마 그래프** | SCH-1: 8테이블·고정 조인 키에서는 최단경로가 항상 길이 1 (§3 Notation 예외) | — | **넣지 않는다** |

### 1-2. 그래서

- KG 는 **"질문의 표기 → 테이블·컬럼·raw 값"** 사전이 본업이고, 관계는 그 사전을 **펴 주는(closure) 용도**까지만 근거가 있다. 이 구조를 제안서에 "값 링킹을 런타임 탐색 대신 사전 구축 KG 로 고정, LLM 호출 0회" 로 쓴다 (VAL-1 ▶1 · KGG-1 ▶4).
- 남은 1주에 edge 를 늘리는 작업은 **정확도 근거가 없다**. 대신 alias 커버리지(별칭·복합식 성분)와 아래 §2 를 한다.
- 주최 테크세션의 "프롬프트 설명 주입 +2.4pp vs 런타임 식별 +20pp" 는 아직 검색 요약 수준이지만, KGG-1 의 "학습 밖 사실은 데이터 계층이 답해야 한다(+77pp, Table 3·4)" 와 같은 방향이다.

## 3. 이번 주(프리즈 9/6 전) 실행 목록 — 근거 순

1. **enum/alias 값 검사기** — `validate_sql` 확장, WHERE 리터럴 ↔ `ontology/enums` + `kg_alias` 대조. LLM 0회. (ENT-1 ▶3 · KGG-1 ▶4)
2. **Sub-SQL 0행 진단기** — sqlglot AST 로 조건 하나씩 제거 실행, 거절 답변에 근거 부착. LLM 0회. (VAL-1 ▶2)
3. **`refusal_rules` + 기준일 앵커 문장** — REF-1 부록 A 9유형 중 우리 문항에 걸리는 5종 · "최근/현재" = 2026-08-22. (REF-1 ▶2 · SL-1 ▶3)
4. **규칙 2층화 실험** — `always_on` / `triggered(triggers:[표기])`, gold 63 으로 전부 vs 선별 paired 비교, Wilson CI 병기. (DK-1 ▶1 · SL-1 ▶5 · KGG-1 ▶6)
5. **조인 경로 문장화** — cross 질의 시 `JOIN_KEYS` 를 "X 로 잇는다" 한 줄. (SCH-1 ▶2 · JAMIA-1 ▶2)
6. **조건부 재생성 1회** — validate 실패 또는 KG 컬럼≠WHERE 컬럼일 때만. (KGQA-1 ▶3 · VAL-1 ▶3)
7. **gold 실패 라벨링** — ENT-1 4분류(Filter/Scope/Aggregation/Other) + SL-1 5범주 + JAMIA-1 pass/partial/fail. 제안서의 오답 분석 표가 된다.

하지 않는 것: KG edge 확장(근거 없음) · 벡터 인덱스(1주·한국어 미검증) · LLM 프로브 탐색·self-consistency(호출 예산) · 0행 재시도·LIKE 완화(환각) · 모델 교체.
