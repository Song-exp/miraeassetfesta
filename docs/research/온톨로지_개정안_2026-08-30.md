## 2. 개정할 것 — 우선순위 순

### R-1. KG 편입 기준 개정 — "다른 테이블로 건너가는가" → "질문 어휘가 컬럼 값으로 이어지는가"

- **현행 원칙** (`ONTOLOGY_BUILD_PLAN` §3.1 ②): *"이 값으로 다른 테이블을 찾아가야 하는가? 예 → KG 개체 · 아니오 → SQLite 컬럼 그대로(범주형이어도)"*. 예시로 펀드 `or_attr_desc`(11종)는 KG 에 안 간다고 못 박음.
- **결과**: alias 가 없는 **저카디널리티 범주 컬럼 37개** — 채권 10(`bd_inrt_tcd` 고정/변동/고정+변동 · `bd_intp_tcd` 이표/복리/할인 · `std_pd_mcls_nm` 회사채/특수채/국공채 · `pd_risk_nm` …), 국내ETF 9(`cu_strtegy` 실물복제/액티브 · `pd_dvid_cycl` · `pd_grp_no` ETF/ETN …), 해외ETF 4(`cu_index_repl_mthd` · `pd_exg_mkt_cd` …), 펀드 14(`or_attr_desc` · `han_clas_fee_type` 수수료선취/미징구 · `han_clas_policies` 33종 · `int_dvd_desc` · `ovrs_fd_desc` …). 플래너는 이 컬럼의 **이름과 한글명만** 받고 값 어휘는 못 받는다 → "변동금리 채권"·"수수료 선취 클래스"·"실물복제 ETF" 는 HCX 가 리터럴을 **추측**한다.
- **어긋나는 인사이트**: I-1 — 실패의 54.6% 가 WHERE/enum **값** 오류(`ENT-1` Fig. 4). KG 의 본업이 값 사전이라면 "건너가는가" 는 기준이 아니다.
- **개정안**: 기준 ② 를 *"질문에 그 값의 표기가 등장하고 SQL 조건의 리터럴이 되는가 → 값 사전에 등록"* 으로. 실체는 둘 중 하나 — (a) `enums/<domain>.yaml` 에 `value_vocab:` 블록(컬럼 → 허용 값·표기 변형) 을 두고 `loader.planner_context()` 가 `normalization` 옆에 싣는다(**`--yaml-only` 5초 배포**) (b) 생성기가 도메인 전용 범주값도 `kg_alias` 에 등록(노드 타입 `Category`, KG 재생성 동반). **(a) 를 권한다** — 37컬럼 × 평균 6값이라 프롬프트 +2~3KB, 그리고 R-4 의 값 검사기가 같은 목록을 읽는다.
- **비용**: 반나절. 검증: gold 에 "변동금리·이표채·실물복제·수수료선취" 문항 4개 추가.

### R-2. 규칙 문서의 크기·층 — 도메인 10배 편차를 없애고 `always_on / triggered` 로

- **현행**: 플래너 컨텍스트 채권 **16,406B** · 펀드 **14,438B** vs 국내ETF 1,660B · 해외ETF 1,407B. 전부 통째 주입, 선별 없음.
- **어긋나는 인사이트**: I-4 — 전부 주입 39.0 < 선별 47.5(`DK-1` Table VI), 짧은 evidence > 긴 문서(`ENT-1` Table 2). 다만 `SL-1` 은 8,969자 문서는 통째가 낫다고 했다 — **채권·펀드는 그 2배**, ETF 는 그 1/5 이다.
- **개정안**: 규칙마다 `scope: always_on | triggered` + `triggers: [표기…]`. `always_on` = 기본 모수·0/센티넬 배제·단위·기준일(≈ `SL-1` 5범주 ①②④⑤ 핵심). `triggered` = 위험등급 방향·벤치마크 검색·이름 표기 구조어휘·연금 등 어휘가 나올 때만. `planner_context(tables, question)` 로 시그니처 확장. **ETF 쪽은 반대로 채워야 한다** — 1.5KB 는 `SL-1` 5범주 점검표로 빈칸을 찾는다(총보수 결측·상장폐지·ETN 구분·분배주기).
- **검증**: gold 63 을 통째 vs 2층으로 paired 재실행, McNemar b/c + Wilson CI (`SL-1` §4.4). 126 호출.

### R-3. `clarify` 블록이 프롬프트에 닿지 않고, 역질문 경로가 코드에 없다

- **현행**: 채권 yaml 의 `clarify.다의어`(수익률 5가지 뜻 · "싸다" 는 가격↔수익률 정반대 · 등급 = 신용/위험 별개 축)·`사람의_선택`(안전의 정의·보유기간) 은 **`planner_context` 가 싣지 않는다**(`query_rules`·`normalization` 만). `pipeline`·`gate` 에 `clarify`/역질문 코드 0건. gold 의 역질문형 3문항("안전한 ETF 추천"·"수수료 저렴한 해외 ETF 추천"·"수익률 좋은 펀드 추천")은 그대로 HCX → SQL 로 간다.
- **어긋나는 인사이트**: I-3 5범주 ⑤ 모호성 해소(`SL-1` §3.1)가 프롬프트에 없고, I-6 의 거절 3단 중 ②(범위 밖·추천·모호 = 프롬프트 층)가 비어 있다. `REF-1` Table 1: 언어적 모호성은 어떤 방법도 80% 대 → **기본값을 답하고 가정을 명시**하거나 역질문.
- **개정안**: ① `clarify.다의어` 의 기본값 항을 `query_rules` 로 이관(SQL 조각 형식: `'수익률' → after_tax_yield, 답변에 '개인 세후 기준' 명시`) ② `_SQL_SYSTEM` 에 출력 두 갈래 추가 — `ASK: <되물을 한 문장>`(조건 부족) · `REFUSE: <사유 코드>`(범위 밖) — 파이프라인이 SELECT 가 아니면 이 두 접두만 인정하고 그대로 답변으로 조립. HCX 호출 수 불변.

### R-4. `validate_sql` 에 값 검사기 · 0행에 Sub-SQL 진단

- **현행**: `validate_sql` = SELECT·허용 테이블·LIMIT·금지어. WHERE 리터럴은 검사하지 않는다. 0행이면 즉시 "조건에 해당하는 상품이 데이터에서 확인되지 않습니다" — 어느 조건 때문인지 근거 없음.
- **어긋나는 인사이트**: I-1(54.6% 가 값 오류) · I-6(거절 근거를 값으로).
- **개정안**: ① WHERE 의 `컬럼 = '리터럴'` / `IN (...)` 을 파싱해 (컬럼, 값) 이 `kg_alias.raw_value` ∪ `value_vocab`(R-1) 에 있는지 확인 — 없으면 **재생성 1회**(KG 매핑 컬럼 ≠ WHERE 컬럼일 때) 또는 거절. LLM 0회, alias 커버리지 96~100% 라 오탐 적음. ② 0행이면 sqlglot 로 조건을 하나씩 뺀 Sub-SQL 실행 → "A 조건 N건 · B 조건 M건 · 동시 만족 0" 을 답변에 부착(`VAL-1` §3.3.1). **0행 재시도는 하지 않는다**.
- **비용**: 1일. `sqlglot` pip 1줄.

### R-5. 게이트를 3단으로 — 지금은 1단(스키마 부재 7건·enum 2종·미래 날짜)만

- **현행 `gate.check`**: ① absent 7 선언(`(entity, table)`) ② `crd_grd` enum · 위험등급 0~6 ③ 미래 연월. 그 외 거절은 전부 0행에 의존.
- **gold 거절형 18문항의 유형별 현재 경로**: 존재하지 않는 값(KODEX AI로봇·코스피300·ZZZZ·Kimi) → 0행 ✓ / 없는 enum(AAAA·7등급) → 게이트 ✓ / 미래 → 게이트 ✓ / 부재 속성(해외ETF 위험등급) → 게이트 ✓ / **상수 컬럼 위반**(KRX 상장 해외ETF · EUR 거래) → 0행에 기댐 / **역질문형 3** → 경로 없음 ✗ / 결측 의도값("기타비용 가장 낮은") → 규칙에 기댐.
- **개정안**: `REF-1` 부록 A 9유형 중 5종을 `refusal_rules` 로 — 실시간·기준일 이후(`SL-1` ⑤) · DB 밖 정보 · 추천/의사결정 · 미래 예측 · 인과 설명. 게이트 ①②③ 는 유지, `constant_columns` 선언(해외ETF `pd_trd_ccy=USD`, 시장 AMX/NAS/NYS)은 absent 와 같은 층으로 승격(LLM 0회 기각). 계획 **P1-2 를 이 구조로 재정의**.
