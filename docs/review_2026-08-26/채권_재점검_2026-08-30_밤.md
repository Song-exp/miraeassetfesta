## 2. 찾은 것과 처리

### 🔴 코드 — 첫 실행에서 터진다 (리드 몫이었으나 두 줄이라 반영, 미커밋)

| | 문제 | 근거 | 처리 |
| :-: | :-- | :-- | :-- |
| ① | **SQL 출력 상한 512 토큰** | 추천 질의 SQL 은 yaml `구조`(693자)·`보강`(533자) CASE 를 그대로 옮겨 **1,757자 ≈ 660~840토큰**. 512 에서 잘리면 SELECT 가 중간에 끊겨 validate/실행 실패 → "확인 불가" | `planner.SQL_CONFIG.max_tokens` 512 → **1536** (상한이지 사용량이 아니라 비용 불변). 테스트 `test_sql_budget_smaller_than_answer` 전제("SQL 은 짧다")를 실측에 맞게 교체 |
| ② | **날짜가 `20271231.0`** | `mat_dt·isu_dt·crd_grd_dt·sale_yield_base_dt` 가 DB 에 REAL (엑셀 숫자 → pandas). `str()` 그대로 답변 생성기에 감. 또 `pd_nm` 고정폭 패딩(최대 98자, 평균 18 vs 실제 15)이 retrieved_context 를 부풀리고 답변에 공백이 따라붙음 | `pipeline._cell()` — `*dt` 컬럼의 정수값 실수는 정수로, 문자열은 strip |

## 3. "이름 정보를 피처로 뺄까, 추출에 맡길까" — **뺀다**

### 판단 기준 (데이터 복잡성이 아니라 이 세 가지)
| 기준 | 뺀다(파생 컬럼) | 맡긴다(질의 시 LIKE) |
| :-- | :-- | :-- |
| ① 패턴이 결정적이고 건수가 재현되는가 | 정규식 = LIKE, 건수 일치 (구조 10종·ESG 3종 전부 ✅) | 자유 문자열(발행사 부분 일치·회차) |
| ② WHERE/ORDER 축이거나 **매 추천 행**에 붙는가 | 구조·보강·ESG — 추천마다 붙음 | 한 번 조회하고 끝 |
| ③ 표기가 여러 형(4형 LIKE)·예외(콜마)가 있는가 | 있음 → 매번 복사시키면 위험 | 단일형 |

### 채권 실측이 말하는 것
- **판정할 게 없다.** 13개 이름 패턴 전부 정규식 = LIKE 4형 = 건수 일치. LLM 에 "추출" 시키는 건 판단이 아니라 **693자 조건식 받아쓰기**이고, 한 글자만 틀려도 SQL 오류 → "확인 불가".
- **안내판의 41%** 가 이 받아쓰기용이다: 구조표시 1,130 + 신용보강 936 + ESG 433 = **2,499 / 6,055자**. 컬럼이 있으면 "SELECT 에 `drv_structure` 를 붙인다" 한 줄(~300자)로 준다.
- **SQL 이 1,757자 → 약 400자.** ①번 위험(토큰 상한)과 받아쓰기 오류가 동시에 사라진다.
- 이름은 종목마다 고정(pd_no 당 pd_nm 1개, 예외 2건은 공백). 빌드 시 한 번 파싱하면 끝.
- 컬럼이 이미 있는 건 이미 뺐다: 사모 → `bd_ofr_tcd`, FRN → `bd_inrt_tcd`, 이표/할인 → `bd_intp_tcd` ("이름 파싱 회귀 금지"). 지금 남은 건 **컬럼이 없는 이름-전용 정보**뿐이다.

### 뺄 것 / 남길 것 (채권)
| 뺀다 → 파생 컬럼 | 남긴다 → 질의 시 LIKE |
| :-- | :-- |
| `drv_structure` 구조 10값('' 포함) — 은행 자본성증권은 컬럼 신호 그대로 | `발행사조회` — KG 매핑 있으면 정확 일치, 없으면 LIKE (이름은 자유 문자열) |
| `drv_esg` 녹/사/지/'' | 회차·특정 종목명 검색 |
| `drv_credit_layer` A~F — 컬럼 기반이지만 533자라 같은 이유 | `(정부보증)` 7행 — B 층에 이미 포함 |
| `drv_is_abs` 유동화 4,045 | |

ETF·펀드도 같은 기준이 그대로 적용된다: ETF **인버스 225**(부호 소실로 이름만이 근거)·**(H) 235**·TR 53 은 컬럼이 없으니 후보, 펀드 재간접 3,803·파생 2,132·(H) 933·(UH) 582 는 `zrin_*` 컬럼이 1순위고 이름은 폴백이다.

### 어떻게 (리드와 합의할 모양)
1. **정의는 yaml 이 소유** — `name_encoding.special_structure_flags`·`esg_labels` 의 패턴+건수를 `scripts/build_derived.py` 가 읽어 `domestic_bonds` 에 `drv_*` 컬럼을 채우고, yaml 의 count 를 **assert** 로 쓴다. 그러면 "런타임이 안 읽는 문서 칸"(0f5f2e9 의 문제)이 실행되는 정의가 된다.
2. `schema_metadata` 에 `(파생) 구조` 처럼 등록 — `schema_text` 가 실어야 HCX 가 "존재하는 컬럼" 으로 본다. 화이트리스트(`TABLES`)는 그대로.
3. 주최 원본 대조("차이 0")는 **원본 컬럼만** 비교하게 유지. DB 는 git 밖이라 배포 zip 재배포 필요.
4. `query_rules.구조표시·신용보강·ESG라벨` 은 컬럼 이름 한 줄로 줄이고, 원문은 `채권_규칙_원문_2026-08-30.md` 에 남는다.

**하지 말 것**: 답변 생성 단계(compose_answer)에서 이름을 읽어 구조를 말하게 하는 것 — 조회 결과 밖 사실이 되어 환각 검사 규칙과 충돌한다.
