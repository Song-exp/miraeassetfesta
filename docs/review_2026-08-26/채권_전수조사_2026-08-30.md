## 2. 🔴 테스트 전에 고쳐야 할 것 6건

### A. `고위험제외` 조건식이 **국공채 전체를 추천에서 떨어뜨린다** — 내 어제 실수 · ✅ 08-30 반영

**무슨 일인가**: 어제 넣은 규칙의 조건 `NOT (pd_risk_gcd='11' OR crd_grd='C0')` 는 SQL 의 NULL 규칙 때문에 **신용등급이 비어 있는 행을 전부 버린다**. `crd_grd` 가 NULL 이면 `crd_grd='C0'` 은 NULL, `FALSE OR NULL` 은 NULL, `NOT NULL` 은 NULL → WHERE 에서 탈락.

| 조건식 | KRW·수익률>0 21,680행 중 통과 | 떨어진 무등급 행 |
| :-- | --: | --: |
| 어제 식 `NOT (… OR …)` | 17,337 | **3,099 (국공채 2,840 전부 포함)** |
| NULL-안전 식 | 20,436 | 0 |

**고친 것** (yaml `query_rules.고위험제외`): 조건식 `pd_risk_gcd <> '11' AND COALESCE(TRIM(crd_grd),'') <> 'C0' AND bd_ofr_tcd <> '사모'` · 추천 모수 **19,411행 / 18,074종목** · 최고 9.82% · 6% 초과 34종목 · 국공채 최고 4.89%.

**고친 식으로도 빠지는 국공채가 있나** (사용자 질문, 08-30 실측): 국공채 2,840행 → 구매가능 2,839 → 고위험제외 **2,839(0건 탈락 — 국공채 위험등급은 6등급 2,839 · 해당없음 1)** → 사모 제외 2,838. **없다.** 단 종전 `특수구조제외` 가 분리채권 209 + 물가채 6 = **215행을 빼고 있었다** → C 에서 해소.

### B. 게이트가 "2027년 만기 채권" 을 기각한다 — 단어가 아니라 **HCX 의 해석으로 판정** (리드 소관 · 설계안)

**무슨 일인가**: `_FUTURE` 정규식이 미래 연도만 보고 기각한다. "2027년에 만기되는 채권"(5,982종목) · "2030년 만기 국고채" · "만기가 2026년 12월인 채권" 이 전부 "기준일 이후 시점 질의" 로 막힌다. 채권은 만기 질문이 가장 흔하다.

**왜 단어 목록으로 못 푸나** (08-30 논의): "2027년 전에 끝나는 채권 추천해줘" 처럼 만기라는 단어 없이 만기를 묻는 문장이 얼마든지 있고, 반대로 "2027년 발행 시장 전망" 처럼 단어가 있어도 시점 질문인 문장이 있다. **뜻을 읽어야 하고, 그건 LLM 몫이다.** 역질문은 쓰지 않는다(사용자 결정).

**데이터가 주는 열쇠**: 이 DB 에서 **미래 날짜를 가진 컬럼은 `mat_dt`(만기일, 최대 2083-06-05) 하나뿐**이다 — 발행일 최대 2026-09-10, 등급일·종가일 최대 2026-08-21. 따라서 질문의 미래 연도가 SQL 에 정당하게 들어갈 자리는 `mat_dt` 조건밖에 없다.

**설계**: HCX 는 이미 질문을 읽고 SQL 을 쓴다. **그 SQL 에 연도를 어디에 썼는지가 곧 HCX 의 해석**이다 — 추가 호출 0회.
```
① gate: 미래 연도로 기각하지 않는다. 대신 근거문서에 한 줄 —
   "질문의 2027 은 데이터 기준일(2026-08-22) 이후다. 데이터에서 미래 날짜는 mat_dt(만기일)에만 있다 —
    만기 조건으로만 쓸 수 있고, 그 시점의 가격·수익률·전망은 없다."
② pipeline 실행 전 검사(validate_sql 옆): 질문에 기준일 이후 연도가 있으면
   그 연도가 SQL 의 mat_dt 조건식 안(BETWEEN·SUBSTR·CAST 등 어떤 형태든 mat_dt 와 60자 이내)에 있는가?
   있음 → 만기 질문 → 실행.  없음 → 시점·전망 질문 → 현재 기각 문구 "제공된 데이터의 기준일은 2026-08-22 입니다. 이후 시점의 정보는 확인할 수 없습니다."
```

| 질문 | 만기 단어 | HCX 가 쓸 SQL | 결과 |
| :-- | :-: | :-- | :-- |
| 2027년 전에 끝나는 채권 추천 | ✗ | `mat_dt < 20270101` | 통과 ✅ |
| 2027년까지 가져갈 수 있는 채권 | ✗ | `mat_dt <= 20271231` | 통과 ✅ |
| 2027년 채권 시장 전망 | ✗ | 2027 을 쓸 데 없음 | 기각 ✅ |
| 2027년 기준 수익률 | ✗ | 〃 | 기각 ✅ |
| 2027년에 발행될 채권 | 발행 | `isu_dt` 에 2027 → mat_dt 아님 | 기각 ✅ (발행일엔 미래가 없다) |

**남는 위험**: HCX 가 "2027년 기준 수익률" 을 만기로 잘못 읽어 `mat_dt` 조건을 쓰면 만기 2027년 목록 + 현재 수익률이 나간다 — 틀린 수치는 아니고 답변 생성기가 기준일을 명시하므로 감점 방향으론 안전. 더 조이려면 같은 SQL 호출에 첫 줄 주석 `-- 연도해석: 만기|시점` 을 시키고 SQL 검사와 어긋나면 기각(호출 수 불변) — 1차 테스트에서 오해석이 보이면 붙인다.

**같이 고칠 것** (gate.py, 별개): `_CRD_TOKEN` 이 CB·DC·CD 를 신용등급으로 잡아 기각한다. ~~stop 목록 `{CB, DC, CD, …}`~~ 는 단어 목록이라 쓰지 않는다(08-30 정정). 대신 **표준 등급표로 판정**: `data/external/lookups/credit_grade_scale.csv` 의 표준 등급(AAA~D, 20종)에 있는 토큰만 '등급' 으로 본다 →
- 표에 없고 등급 모양도 아님(CB·DC·CD·ABC): 등급이 아니다 → **무시**하고 통과 (CB=전환사채, DC=퇴직연금형).
- 표에 없으나 등급 모양(AAAA): '존재하지 않는 등급' → 기각.
- 표에 있으나 데이터 0건(BB+·B0·CCC·CC·D — `등급서열` 규칙): 기각이 아니라 '해당 등급 채권은 데이터에 없습니다' 로 답변.
- 표에 있고 데이터 있음(15종): 통과.

'등급 모양' 도 목록이 아니라 표준표의 형태(A~D 문자 1~3개 + 선택적 +/-/0)에서 온다 — AAAA 는 A 가 4개라 형태 밖, CB 는 C 뒤에 B 가 오는 순서가 표준표에 없다.

### D. "위험등급 낮은 채권" 과 "AA- 이상" 을 플래너가 **풀 수 없다** — 규칙 2개 신설

**무슨 일인가**:
- 위험등급 방향(`'11'=매우높은위험 … '16'=매우낮은위험`)은 `columns.pd_risk_gcd.layer` 에만 있고 **`query_rules` 엔 없다** → 플래너는 못 본다. "위험등급 낮은 채권" 을 숫자 낮은 `'11'` 로 짜면 **1등급(매우높은위험, 평균 수익률 16.6%)** 이 나온다 — 정반대. `BONDS_MASTER` §10-C-1 이 "런타임 반영 미완" 이라 적어 둔 그 항목이다.
- 등급 서열도 어디에도 없다. `등급정규화` 는 "AA→AA0" 만 말한다. "AA- 이상" 을 풀려면 AAA>AA+>AA0>AA- 순서를 알아야 한다 (OFFICIAL-001 이 정확히 이 문항).

**고칠 것** (`query_rules` 에 신설):
```
위험등급방향: "pd_risk_gcd 는 문자열 '11'~'16' + '00'. 뒷자리가 등급 — 11=매우높은위험(1등급) 1,441행 · 12=높은위험 74 · 13=다소높은위험 146 ·
              14=보통위험 1,424 · 15=낮은위험 9,849 · 16=매우낮은위험(6등급) 8,929 · 00=해당없음 19.
              🔴 숫자가 클수록 안전하다. '위험 낮은/안전한' = pd_risk_gcd='16' (넓게는 IN ('15','16')) · '위험 높은' = '11'.
              답변엔 pd_risk_nm 문구('매우낮은위험(6등급)')를 그대로 인용한다."
등급서열:     "crd_grd 서열(높→낮): AAA > AA+ > AA0 > AA- > A+ > A0 > A- > BBB+ > BBB0 > BBB- > BB0 > BB- > B+ > B- > C0 (2차 15종).
              'AA- 이상' = TRIM(crd_grd) IN ('AAA','AA+','AA0','AA-') · 'BBB- 이상(투자등급)' = 위 10종.
              표준 등급 중 BB+ · B0 · CCC · CC · D 는 2차 데이터에 0건 — '존재하지 않는 등급' 이 아니라 '해당 채권 없음'.
              무등급 4,020행(국공채 2,840 전부 + 특수채 254 + 회사채 926)은 등급 조건 질의의 모수에서 빠지며, 국공채는 '등급이 부여되지 않음' 으로 답한다."
```

### G. 역질문(`clarify`) 규칙이 플래너에 **전혀 전달되지 않는다**
`planner_context` 는 `query_rules`·`normalization` 만 싣는다. yaml 의 `clarify` 11종(수익률 다의어 · **"싸다" 되묻기 필수** · 등급 신용/위험 · 보유기간 …)은 프롬프트에 없고, `src/` 어디에도 `clarify` 를 읽는 코드가 없다. `_SQL_SYSTEM` 프롬프트에도 "되물어라" 는 출력 형식이 없다 — 플래너는 SQL 한 문장만 낼 수 있다.
→ "싼 채권 알려줘" 는 되묻지 못하고 가격 낮은 것 또는 수익률 높은 것 중 하나를 임의로 고른다. **역질문은 유효 답변으로 채점되는데(주최 8/25) 그 경로가 없다.** 리드에게 설계 요청 항목. 채권 쪽에서 당장 할 수 있는 것: `clarify.다의어.싸다` 처럼 "기본값 금지" 인 것만 `query_rules` 로 옮겨 "…이면 SQL 대신 '가격이 낮은 것과 수익률이 높은 것 중 무엇을 원하시나요' 로 답한다" 를 명시 (플래너가 SELECT 가 아닌 문장을 내면 Guard 가 기각하므로, 파이프라인 지원이 있어야 실제로 동작).

### H. 컬럼별 `answer_policy` 가 **답변 생성기에 안 간다**
