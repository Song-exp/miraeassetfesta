### ③ 결론

**기준일 = 2026-07-11 확정.** 요청서가 상정한 세 갈래 중 **①주최 명시**다. 파일명 유래설(②)은 기각 — 파일명은 선언과 일치하는 방증일 뿐 출처가 아니다. 주최 확인 질문지(⑰)에서 기준일 항목을 뺄 수 있다.

**단, 2-24 증거는 반증이 아니라 다른 것을 재고 있었다.** 정리하면 두 날짜는 층위가 다르다:

- **2026-07-11 = 추출일** — 주최가 스냅샷을 뜬 날. 평가 기준 시점.
- **2026-02-24 = 채권 마스터의 내용 갱신 정지일** — 계산 컬럼(`REMAINING_DAYS`·`DUR` 등)이 이 시점에 굳어 있다.

둘의 차이 **137일**이 그대로 계산 컬럼의 지연으로 남는다.

**⚠️ 새로 확정된 함정 — `REMAINING_DAYS` 원값 사용 금지.**

7-11 기준으로 이미 만기가 지났는데 `REMAINING_DAYS > 0` 인 채권이 **3,296건**(`<` 경계 기준 · `<=` 기준 3,301건) 있다. 원값을 그대로 쓰면 이 3,296건이 "아직 살아있는 채권"으로 답변에 나간다. 매수 모수 254 는 `MAT_DT` 기준이라 무사했지만, "잔존만기 3년 이내" 류 질의는 전부 137일씩 밀린다.

대체 식을 만들어 검증했다. `MAT_DT` 가 REAL(`20260711.0`)이라 `julianday(MAT_DT)` 가 바로 안 먹혀 **CAST 2단계**가 필요하다:

```sql
CAST(julianday(substr(CAST(CAST(MAT_DT AS INTEGER) AS TEXT),1,4)||'-'||
substr(CAST(CAST(MAT_DT AS INTEGER) AS TEXT),5,2)||'-'||
substr(CAST(CAST(MAT_DT AS INTEGER) AS TEXT),7,2)) - julianday('2026-07-11') AS INTEGER)
```

검증: 이 식의 값이 `REMAINING_DAYS - 137` 과 정확히 일치하는 건 20,106건(84.0%, 역산 수렴분 전건). 이 식으로 잔존>0 은 **25,888건**.

## B2. 영구채 판정 건수(is_perpetual 450) 재확정 ✅ 확정 (08-21)

**쟁점** — 등재 건수 450 이 어떤 패턴으로도 재현되지 않았다(현행 `신종|영구` 473 · 도메인 문서 원패턴 467 · `신종자본` 단독 296). 어느 집합이 영구채인지 정하고 패턴·건수를 못박는 작업.

**왜 중요한가** — 영구채는 듀레이션이 0 으로 기재돼 있어 "금리위험 낮은 채권" 정렬에서 **가장 위험한 채권이 가장 안전해 보이는 역전**을 만든다. 집합 정의가 이 방어의 토대다.

### ① 검사 방법

요청서 §B2 는 "450 을 산출한 사람에게 먼저 물어보라"고 하지만 채권은 단독 담당이라 대상자가 없다. 대신 **레포에서 숫자를 역추적**했다 — `docs/` 전체에서 450 을 grep.

```
docs/eda/domestic_bonds_notes.md:788
| 신종자본 | `신종자본` 296 | + `(신종)` **450** | 1.5× |
```

이 표기를 그대로 코드로 옮겨 재현을 시도하고, 후보 4종의 차집합을 전 행 육안 판정했다.

```python
A = {n.strip() for n in names if re.search(r'신종|영구', n)}                 # 현행 yaml
B = {n.strip() for n in names if re.search(r'신종자본|[(/]신종[)/]', n)}     # 도메인 문서 해석
C = {n.strip() for n in names if '신종자본' in n}                            # 단독
D = {n.strip() for n in names if '신종자본' in n or '(신종)' in n}           # notes.md:788 재현 가설
```

오탐 잔여 점검은 `'신종'` 뒤에 오는 글자를 전수 조사했다.

```python
odd = set()
for n in names:
    for m in re.finditer(r'신종', n):
        nxt = n[m.end():m.end()+1]
        if nxt not in ('자', '(', ')', '/', ''):
            odd.add((nxt, n.strip()))
```

### ② 결과

**(1) 450 재현 성공 — 출처 확정.**

| 집합 | 정의 | 행 기준 |
| :-: | :--- | ---: |
| A | `신종\|영구` (현행 yaml) | 473 |
| B | `신종자본\|[(/]신종[)/]` | 467 |
| C | `신종자본` 단독 | 296 |
| **D** | **`'신종자본' or 리터럴 '(신종)'`** | **450** ← 등재값과 정확히 일치 |

D 가 450 이다. 즉 원 산출은 **괄호로 닫힌 `(신종)` 만** 보는 방식이었다. 워크샵 C-1("450 미재현")이 여기서 종결된다.

**(2) 그러나 450 은 오답 — 표기 변형 3종을 놓친다.**

## B5. 듀레이션 0 = "영구채 산출 불능" 판정 검증 ✅ 판정 교체 (08-21)

**쟁점** — 듀레이션이 0인데 잔존만기가 남은 채권 500건을 "영구채라 평가사가 산출을 못 한 표기"로 판정하고 `듀레이션정상` 규칙에서 제외해 왔다. 근거는 표본 예시(SK텔레콤 신종자본증권) + 도메인 논리뿐이고 500건 전수 확인이 없었다. **합격 기준: 패턴 부합 비율 ≥90%.**

### ① 검사 방법

요청서 §B5 의 지시대로 부합 비율을 재고, **미달이면 미부합 행의 유형을 규명**하는 데까지 갔다(B2 ⑥에서 미달이 예고돼 있었다).

```python
pool = [r for r in rows if r['DUR'] == 0 and r['REMAINING_DAYS'] and r['REMAINING_DAYS'] > 0]   # 500건
B5PAT = re.compile(r'신종자본|[(/]신종[)/]|영구|코코|조건부자본')   # 요청서 원안
miss  = [r for r in pool if not B5PAT.search(nm(r))]
```

미부합분에 대해 채권종류·잔존만기·동반 결측·장내외 구성을 교차 분해하고, 종목명 표본에서 공통 패턴을 찾았다. 가설이 나온 뒤에는 **역방향 검정**(그 속성을 가진 모집단이 실제로 DUR=0 이 되기 쉬운가)까지 돌렸다.

### ④ 🔴 신규 발견 1 — 규칙이 막는 범위가 너무 좁다

`듀레이션정상` 은 `DUR = 0` 만 막는다. 그런데 **듀레이션이 잔존만기와 전혀 안 맞는 채권이 1,101건 더** 있다.

| DUR / 잔존연수 | 건수 | 비고 |
| :--- | ---: | :--- |
| 0 (DUR=0) | 500 | ← 지금 막는 건 여기뿐 |
| 0 초과 ~ 0.05 | 278 | 🔴 통과 |
| 0.05 ~ 0.2 | 366 | 🔴 통과 |
| 0.2 ~ 0.5 | 457 | ⚠️ 통과 |
| 0.5 ~ 1.05 | 19,545 | 정상 (92.2%) |
| 1.05 초과 | 55 | ⚠️ |

극단 사례: **잔존 20.8년인데 DUR 0.01** (`케이비캐피탈 신종자본증권 367(사모/콜/후)`). `DUR=0` 이 아니라서 규칙을 통과하고, "금리위험 낮은 채권" 정렬에서 **1위**로 올라온다.

정상값일 가능성도 있다 — FRN 은 다음 금리재설정일까지가 듀레이션이고, 영구채는 콜 행사 가정으로 산출하면 짧게 나온다. 그러나 실측상 `0<r<0.05` 구간 278건 중 **FRN 79건(28.4%) · 영구채 20건(7.2%) · 둘 다 아님 179건(64.4%)** 이라 대부분이 설명되지 않는다. 콜 행사일 컬럼이 없어 데이터만으로는 판별 불가 — **워크샵 안건으로 올림**.

### ⑤ 🔴 신규 발견 2 — `is_callable` 이 콜옵션 68행을 놓친다

## B4. "지금 살 수 있는 채권 254건" 해석 검증 ✅ 지지 + 정정 (08-21)

**쟁점** — 매수 정보 7컬럼이 42,394건 중 881건에만 있다(결측 97.9%). 이 결측을 "값을 모른다"가 아니라 "**미래에셋 진열대에 없다**"로 해석하고 추천 모수를 254 로 잡았다. 틀리면 "이 채권은 현재 판매 중이 아닙니다"라는 답변 전체가 오답이 되는, 채권 도메인에서 가장 위험한 단일 가정이다.

**⚠️ 범위 제약** — 요청서 최신본의 비수집 방침(2026-08-20): 254건(0.6%)이 적다고 타사 판매·호가 데이터를 수집해 메꾸지 말 것. 채권 시장은 기관 중심(관행 거래 단위 ~100억, 개인 비중 1~2%)이라 **이 비율 자체가 도메인과 정합**하다. B4 의 목적은 모수 확장이 아니라 해석 검증뿐.

### ① 검사 방법

두 가설을 경쟁시켰다.

- **가설 A (진열대)** — 결측이 구조적. 레코드 단위로 있거나 없거나, 대상이 리테일 성격을 띤다.
- **가설 B (수집 실패)** — 결측이 무작위. 컬럼별로 제각각 비고, 유형 편중이 없다.

구별 검정으로 **BUY 7컬럼의 결측 조합 분포**를 썼다. 수집 실패라면 조합이 흩어지고, 진열대라면 전부-있음/전부-없음 두 가지로 수렴한다.

```python
BUY7 = ["BUY_YIELD","CORP_PRETAX_YIELD","CORP_AFTER_TAX_YIELD","AFTER_TAX_YIELD",
        "PREF_TAX_YIELD","DEPO_EQUIV_YIELD_154","BUYABLE_QUANTITY"]
pat = collections.Counter(tuple(r[c] is not None for c in BUY7) for r in rows)
len(pat)      # 2^7 = 128 중 실제 등장 조합 수
```

이어서 254 의 성격을 전체와 대조했다 — 사모 비율, 특수구조 비율, 채권종류 분포, 거래 단위, 잔존만기.

### ② 결과

**(1) 🔬 결정적 — 결측이 완벽한 all-or-nothing.**

```

   41,513건   전 7컬럼 결측
      881건   전 7컬럼 존재
```

중간이 **하나도 없다**. 수집 실패라면 "3개만 있음", "5개만 있음" 같은 조합이 나와야 한다. **가설 B 기각.** 이 7컬럼은 레코드 단위로 통째로 채워지거나 통째로 빈다 — 진열 여부라는 단일 사실이 만드는 패턴이다.

**(2) 사모가 사라진다** — 사모는 개인에게 팔 수 없는 상품이다.

| :--- | ---: |

| 매수정보 보유 881 | 0.1% |

**(4) 소매채권으로 편중된다.**

## B1. 사모 채권 판정 기준(is_private) 검토 ✅ 확정 (08-21)

**쟁점** — 사모 발행 여부를 담는 컬럼이 없어 종목명 괄호 표기를 파싱해 `is_private` 플래그를 만든다. 원래 등재된 10,067 은 재현 불가라 폐기하고 "이름에 '사모'가 든 전체 = 15,261건"으로 교체했다. ①교체가 맞는지 ②사모를 추천에서 뺄지 ③기존 `특수구조제외` 에 섞을지 별도 규칙으로 뺄지를 정하는 작업.

### ① 검사 방법

```python
# 재현 — 두 값이 같아야 '사모'가 전부 괄호 안에만 등장한다는 뜻
sum(1 for n in names if re.search(r'[(/][^()]*사모', n))   # yaml 패턴
sum(1 for n in names if '사모' in n)                        # 부분일치

# 오탐 확인 — 무작위 30건 육안
random.seed(0); random.sample([n.strip() for n in names if '사모' in n], 30)

# 제외 비용
rec = [n for (n,) in q("SELECT PD_NM FROM domestic_bonds WHERE BUYABLE_QUANTITY>0 AND MAT_DT>20260711")]
len([n for n in rec if '사모' in n])
```

표본 30건만으로는 오탐을 놓칠 수 있어, **'사모' 앞뒤 문맥을 전수 집계**해 회사명 결합 가능성을 추가로 점검했다(B2 에서 '성신종합유통' 오탐을 이 방법으로 잡았다).

### ② 결과

**(1) 재현 일치 ✅**
```
yaml 패턴 [(/][^()]*사모 : 15,261
'사모' 부분일치          : 15,261
```
'사모'는 예외 없이 괄호 안에만 등장한다.

**(2) 오탐 0건.** 표본 30건이 전부 진짜 사모 표기다.
```
한국자산캐피탈17(PCBO사모/콜)      시큐센3CB(사모/전환)
한솔테크닉스90(사모)              호텔롯데 54(사모/강제)
에어서울1(사모)                   메리츠화재해상보험신종자본증권 3(사모/콜/후)
```
`PCBO사모` 는 프라이머리 CBO 사모 발행분으로 이것도 진짜 사모다.

**문맥 전수 점검** — '사모' 앞뒤 문맥 540가지 중 괄호·슬래시와 무관한 것은 **3가지뿐**이고, 전부 진짜 사모였다:
```
'172사모신'  '233사모신'  '264사모신'   ← 우리카드 …사모신종(사모/콜/후)
```
회사명에 우연히 '사모'가 들어간 사례는 없다. B2 의 '성신종합유통' 같은 오탐이 여기엔 존재하지 않는다.

**(3) 🔬 제외 비용 — 254 중 단 1건.**
```
추천 모수 254건 중 사모 1건 → 제외 시 253건
   LG전자 75(사모)   AA0 · 수량 68.6억
```

**(4) 왜 이렇게 적은가 — 사모는 이미 사실상 추천 대상 밖이다.**

| | 값 |
| :--- | ---: |
| 사모 전체 | 15,261건 |
| 그중 **장외** | **15,261건 (100.0%)** |
| 그중 장내 | 0건 |
| 그중 매수정보 보유 | **1건 (0.0%)** |
| 그중 신용등급 있음 | 1,846건 (12.1%) |

전건이 장외이고, 매수정보를 가진 것은 `LG전자 75(사모)` 하나뿐이다. B4 에서 "254 중 유일한 장외 1건"으로 나왔던 그 종목과 동일하다.

**(5) 합집합 수치가 낡아 있었다.**

| | 행 |
| :--- | ---: |
| 구조 플래그 합집합 (yaml 기재) | 15,306 |
| **실측 (실행 가능한 10종)** | **15,796** |
| 사모까지 포함 | 19,670 |

기재값 15,306 은 {콜·CB·후순위·FRN·영구채·EB·코코} **7종만**의 합집합이었다. 이후 추가된 `is_puttable`(2,150)·`is_bw`(133)·`is_stripped`(221)·`is_inflation_linked`(6)가 반영되지 않았다 — yaml note 자신이 "is_bw·is_puttable 반영 시 증가 예정"이라고 예고한 상태 그대로였다.

⚠️ 15,796 은 **`is_frn` 미포함**이다. pattern 이 산문("변 계열 4종")이라 집계 자체가 안 된다 — **B3 완료 후 재계산이 필요하다.**

### ③ 결론

**세 가지를 확정했다.**

**ⓐ 15,261 교체는 옳다.** 재현 일치 + 오탐 0건.

**ⓑ "제외하면 추천 모수가 궤멸한다"는 오판이었다.** 요청서와 yaml 주석이 공유하던 이 우려는 "15,261이면 전체의 36%"라는 **전체 기준 비율**에서 나온 것이다. 그러나 추천 모수는 전체가 아니라 254 이고, 그 안의 사모는 1건이다. 제외 비용은 **254 → 253**.

**ⓒ 별도 규칙으로 분리한다.** 사모는 "구조"(전환·콜 같은 옵션)가 아니라 "발행 방식"이므로 `특수구조제외` 에 섞으면 의미가 흐려진다. 요청서가 제시한 대로 `사모제외` 를 신설했다.

```
사모제외: 추천·랭킹 질의는 is_private 15,261건 제외 + '사모 발행분 제외' 명시.
          조회 질의는 제외하지 않고 사모 여부만 표시 (제외 비용 254→253)
```

조회까지 막지 않는 이유는, 사모 채권에 대한 **사실 조회는 정당한 질의**이기 때문이다. 막아야 하는 것은 개인에게 권유하는 추천·랭킹뿐이다.

## B3. 변동금리채 정규식(is_frn) 확정 ✅ 확정 (08-21)

**쟁점** — `is_frn` 의 pattern 필드가 정규식이 아니라 산문(`"변 계열 4종 — '천변' 오탐 1건 제외"`)으로 적혀 있었다. 런타임은 이 필드를 읽어 실행하므로 **기계가 쓸 수 없는 상태**였다. FRN 643건은 표면금리 해석이 일반채와 완전히 달라(스냅샷 값), 패턴이 없으면 "변동금리채 보여줘"가 절반 이상 누락된 채 나간다.

### ① 검사 방법

`docs/eda/domestic_bonds_notes.md` §D.8 에서 원 산출식을 확인했다. **"표기 4종"이라는 표현이 오해를 부르고 있었다** — 실제 산출식은 4개 패턴의 합집합이 아니라 단일 규칙이었다.

```sql
SELECT COUNT(*) FROM domestic_bonds WHERE PD_NM LIKE '%변%';                    -- 644
SELECT COUNT(*) FROM domestic_bonds WHERE PD_NM LIKE '%천변%';                  -- 1  (오탐)
SELECT COUNT(*) FROM domestic_bonds
 WHERE PD_NM LIKE '%변%' AND PD_NM NOT LIKE '%천변%';                            -- 643
```

"표기 4종"은 결과의 **내역 설명**이지 판정 규칙이 아니다. 이를 정규식으로 옮기고, B2·B1 에서 쓴 문맥 전수 점검으로 잔여 오탐을 확인했다.

### ② 결과

**(1) SQL 원문 재현 ✅** — 644 / 1 / 643 전부 일치.

**(2) 정규식 확정.**
```
(?<!천)변   →  643건   (목표 643)
'대전천변고속도로5' 매칭 여부: False
```

lookbehind 를 쓴 이유는 SQL 과의 의미 차이 때문이다. `NOT LIKE '%천변%'` 는 **행 전체**를 배제하지만 정규식 lookbehind 는 **해당 '변' 하나만** 배제한다. 두 방식이 갈리는 행(이름에 '천변'과 다른 '변'이 함께 있는 경우)을 실측했더니 **0건**이라 결과가 동일하다 — 안전하게 치환 가능하다.

**(3) 표기 4종 내역 재현.**

| 표기 | 건수 |
| :--- | ---: |
| `(변)` | 271 |
| `(콜/변)` | 232 |
| `(변동)` · `(K변동)` | 29 |
| 그 외 | 111 |
| **합계** | **643** |

## B6. 할인채 표면금리 = 할인율 판정 검증 ✅ 지지 (08-21)

**쟁점** — 종목명에 '할인'이 붙은 172건은 이자를 안 주는 대신 액면(1만원)보다 싸게 파는 채권인데, 표면금리 컬럼에 0이 아니라 2.38~3.55% 값이 들어 있다. 이를 "표면이율란에 **할인율**을 적은 것"으로 판정했고(§D.15), 그 판정으로 "SRFC_IRT=0 → 무이표채" 규칙 전체가 뒤집혔다. **그런데 결정 증거가 단일 종목의 가격식 재현 1건뿐**이었다. 표본을 늘려 재현하는 작업.

**합격 기준: 10건 중 9건 이상 오차 ±0.5% 이내.**

### ① 검사 방법

요청서 §B6 의 검정식은 무이표 가격식이다 — 이자를 안 주는 채권은 **만기 상환액을 현재가치로 할인한 값**이 곧 가격이다.

```python
model = 10000 / (1 + r/100) ** (d/365)     # r = SRFC_IRT, d = 잔존일수
```

여기서 한 가지를 먼저 짚었다. **§D.15 의 결정적 증거는 이 식을 `SRFC_IRT`(2.42)가 아니라 `APPLIED_YIELD`(2.799)로 계산한 것**이었다(`10,000 ÷ 1.028^0.54`). 둘은 다른 주장이다 — 전자는 "SRFC_IRT 가 할인율"이고 후자는 "가격이 무이표 구조"다. 그래서 **양쪽을 다 돌리고**, 판정을 가르는 세 번째 모델을 추가했다.

```python
def coupon_price(coupon, ytm, days):        # 이표채였다면 가격이 액면 근처로 올라온다
    t = days/365; c = coupon/100; y = ytm/100
    return 10000 * (c/y * (1 - (1+y)**-t) + (1+y)**-t)
```

이 세 모델의 오차를 **살아있는 전건 69건**에 대해 비교하면, 표본 10건보다 강한 판정이 나온다.

### ② 결과

**(1) 요청서 지정 검정 — 10/10 통과.**
```
한국수출입금융 2509마-할인-303    모델 9,907 vs 실제 9,894   오차 0.14% ✅
한국수출입금융 2601가-할인-1      모델 9,777 vs 실제 9,757   오차 0.20% ✅
국민은행4602할인일1-23           모델 9,724 vs 실제 9,717   오차 0.07% ✅
우리은행 29-04-할인01-갑-16      모델 9,964 vs 실제 9,962   오차 0.03% ✅
...                                                    → 10/10 (기준 9건)
```

표본 운이 아닌지 확인하려 **seed 0~4 로 5회 반복**했더니 전부 10/10 이었다.

**(2) 🔬 결정적 검정 — 전건 69건, 세 모델 비교.**

| 모델 | n | 중앙오차 | ±0.5% 이내 |
| :--- | ---: | ---: | ---: |
| 무이표 (할인율 = `SRFC_IRT`) | 69 | 0.079% | **69/69 (100%)** |
| 무이표 (할인율 = `APPLIED_YIELD`) | 69 | 0.008% | **69/69 (100%)** |
| **이표채 (쿠폰 = `SRFC_IRT`)** | 69 | 0.837% | **15/69 (21.7%)** ← 기각 |

**이것이 판정의 핵심이다.** `SRFC_IRT` 가 쿠폰(이자율)이라면 그 이자가 가격을 받쳐줘 **액면 근처(9,980)**여야 한다. 실제 가격은 **9,852** 다. `SRFC_IRT` 를 **할인율로 넣었을 때만** 가격이 재현된다.

§D.15 예시 종목 직접 재현:
```
한국수출입금융 2509다-할인-1  (SRFC_IRT 2.42 · APPLIED_YIELD 2.799 · 잔존 196일 · 실제 9,851.89)
   무이표(SRFC_IRT)       → 9,872   오차 0.21%
   무이표(APPLIED_YIELD)  → 9,853   오차 0.01%
   이표채 가정            → 9,980   오차 1.30%   ← 액면 근처로 뜬다
```

**(3) 액면 미만 100%** — 살아있는 69건 전부 `EVAL_PRICE < 10,000`. 10,000 이상인 103건은 **전건 만기 도래분**이다(상환액 반영). 무이표채의 정의와 정확히 맞는다.

**(4) '박제 vs 시세' 구조도 재현.**
```
APPLIED_YIELD − SRFC_IRT :  중앙 +0.234%p · 60/69 에서 양수
잔존만기 중앙 123일 (단기물)
```
발행 시 고정된 할인율과 현재 시세의 차이로 정합한다(§D.15 가 보고한 +0.21%p 와 일치).

### ③ 결론

**판정 지지.** 근거가 단일 종목 1건에서 **살아있는 전건 69건**으로 확대됐고, 요청서 합격 기준(10건 중 9건)을 10/10 으로 통과했다.

더 중요한 것은 **이표채 가정이 21.7% 로 기각**됐다는 점이다. 요청서의 검정은 "무이표 가격식이 맞는가"만 봤는데, 경쟁 모델을 세우니 "SRFC_IRT 가 쿠폰이 아니라 할인율"이라는 주장 자체가 직접 확인됐다.

**⚠️ 다만 사용 시 주의 하나.** ①의 `SRFC_IRT` 검정이 통과한 것은 이들이 **단기물(잔존 중앙 123일)**이라 두 이자율(2.42 vs 2.799)의 가격 차가 ±0.5% 안에 들어오기 때문이다. 오차는 `APPLIED_YIELD` 쪽이 **10배 작다**(0.008% vs 0.079%). **현재가를 계산할 때는 `APPLIED_YIELD` 를 쓸 것** — `SRFC_IRT` 는 발행 시 박제값이다.

## B8. 유동화 채권 식별 범위 검증 ✅ 확장 (08-21)

**쟁점** — MBS·ABS 같은 유동화 채권은 발행자가 회사가 아니라 SPC(자산 금고)라서 발행사 이름으로 위험을 판단하면 안 된다는 규칙(`유동화위험금지`)을 8/20 신설했다. 식별 기준을 `BD_KND IN ('MBS','유동화회사채')` = 4,957건으로 잡았는데, 채권종류에는 안 잡히고 **종목명·발행사명에만 '유동화'가 뜨는 약 200건**을 포함할지 정하는 작업.

### ① 검사 방법

요청서가 지시한 200건 판정을 하되, "규칙 밖에 또 뭐가 있나"를 함께 봤다 — 200건의 `BD_KND` 분포를 뽑자 곧바로 더 큰 문제가 드러났다.

```python
base  = [r for r in bd if r[1] in ('MBS','유동화회사채')]                    # 4,957
extra = [r for r in bd if r[1] not in ('MBS','유동화회사채')
         and ('유동화' in r[0] or '유동화' in r[2])]                          # 200
collections.Counter(r[1] for r in extra)     # ← 이 분포가 단서였다
```

### ② 결과

**(1) 현행 규칙 재현 ✅** — 4,957 = MBS 2,159 + 유동화회사채 2,798.

**(2) 규칙 밖 200건 — 전건이 SPC.**

| | 건수 |
| :--- | ---: |
| `BD_KND` 공란 (종목명에만 '유동화') | 169 |
| `BD_KND = 'Conduit회사채'` | 31 |
| **SPC 작명 부합** (`유동화전문`·`제○차`) | **200/200 = 100%** |

```
티월드제일백이십차유동화전문1-25       신보2025제1차유동화전문1-2(사)
카드오토제육차유동화전문1-1(콜)        퍼스트파이브지제오십육차유동화전문…
```

합격 기준("표본이 SPC 발행이면 확장")을 100%로 충족한다.

**⚠️ 다만 요청서가 제안한 확장안으로는 부족하다.** `OR PD_PBCM LIKE '%유동화%'` 는 **31건만** 잡는다 — 나머지 169건은 **발행사명이 공란**이고 종목명에만 '유동화'가 있기 때문이다. `PD_NM` 조건을 함께 넣어야 200건이 전부 회수된다.

**(3) 🔴 더 큰 구멍 — `Conduit회사채` 2,792건이 통째로 규칙 밖이다.**

200건 중 31건이 Conduit 인 것을 보고 그 종류 전체를 확인했다.

```
Conduit회사채 2,792건 · 발행사 표본
   엘씨글로리제이차(주)   가양가양제오차(주)     디비닉스제사십이차(주)
```

그리고 **도메인 문서가 이미 이렇게 분류하고 있었다**:

> `docs/domain/domestic_bonds.md:942`
> **유동화회사채 / Conduit회사채** | 5,590 | **ABS(자산유동화증권).** … `Conduit` 은 여러 중소기업 채권을 한 그릇에 모아 발행하는 구조

**(4) 🔬 폐기된 '7,749건'이 재현된다.**

`유동화위험금지` 규칙에는 "이전 '7,749건'은 어떤 조합으로도 재현 불가(출처 미상) — 폐기"라고 적혀 있었다. 실측하면:

```
MBS 2,159 + 유동화회사채 2,798 + Conduit회사채 2,792 = 7,749   ← 정확 일치
```

재현 불가가 아니었다. **이전 재현 시도가 Conduit 을 빼놓았을 뿐이다.** 폐기 결정을 취소해야 한다.

**(5) 같은 파일 안에서 두 규칙이 어긋나 있었다.**

담보축(`axis_derivation.collateralType`)은 이미 **SPC 4종 7,783건**을 쓰고 있었다:
```
7,783 = MBS 2,159 + SLBS 34 + 유동화회사채 2,798 + Conduit회사채 2,792   ← 재현 확인
```
`유동화위험금지` 만 4,957 로 좁게 잡혀 있었다. `SLBS` 34건(학자금대출 유동화)도 마찬가지로 빠져 있었다.

### ③ 결론

**식별 범위를 4,957 → 7,952 로 확장한다.**

```sql
TRIM(COALESCE(BD_KND,'')) IN ('MBS','SLBS','유동화회사채','Conduit회사채')
OR PD_NM LIKE '%유동화%' OR PD_PBCM LIKE '%유동화%'
```

| 단계 | 건수 | 추가 |
| :--- | ---: | ---: |
| 현행 2종 | 4,957 | |
| + Conduit회사채 | 7,749 | +2,792 ← 폐기됐던 값 |
| + SLBS | 7,783 | +34 ← 담보축과 일치 |
| **+ 종목명 '유동화'** | **7,952** | +169 ← 요청서가 지목한 200건의 잔여분 |

**요청서가 지목한 200건보다 Conduit 2,792건이 14배 큰 구멍이었다.** "삼성카드 채권 위험해?" 류 오답이 새어 나가는 경로가 훨씬 넓었던 셈이다.

**오탐 점검** — 확장 후 SPC 작명 미부합이 308건 나오지만, 전부 `BD_KND='Conduit회사채'` 로 **선언된** 도관체다(링스켑코리아·코스모스그린 등 작명 규칙만 다름). 종류 컬럼 자체가 근거이므로 오탐이 아니다.

### ④ ⚠️ 작성 중 밟은 함정 — TRIM 누락

규칙을 yaml 에 넣고 실행 검증했더니 **7,952 가 아니라 3,014** 가 나왔다. `BD_KND` 에 패딩이 있어서 `TRIM` 없이 `IN` 비교하면 대부분 매칭되지 않는다.

이 yaml 의 **첫 번째 규칙이 `문자열비교`("범주형·이름은 TRIM 후 비교")**인데 그걸 어긴 것이다. 규칙 본문에 `TRIM(COALESCE(...))` 를 넣고 재검증해 7,952 를 확인했다. **런타임이 규칙 문자열을 그대로 실행한다면 이런 누락이 곧 오답**이므로, 규칙 자체가 TRIM 을 포함해야 한다.

## B9. 역질문(clarify) 10종 타당성 검토 ✅ 완료 (08-21)

**쟁점** — 채권 질의는 용어가 다의적이라("수익률"만 해도 4가지) 되묻는 게 정답인 경우가 있다. `clarify:` 절에 10종이 반영돼 있는데 **아직 구현 전 설계 단계**라 지금이 문구를 고칠 마지막 기회다. 잘못된 되묻기는 사용자를 막고, 잘못된 기본값은 오답이 된다. **'싸다' 1종만 기본값 금지가 확정돼 있고 나머지 9종은 미정**이었다.

### ① 검사 방법

요청서의 세 가지를 수행했다 — ①문구를 소리 내 읽고 일반 사용자가 답할 수 있는가 ②무응답 시 안전한 기본값 ③FRN_금리비교는 실제 종목으로 조건부 답변 1건 직접 작성.

여기에 하나를 더했다. **clarify 절이 인용한 수치를 전부 재검증**했다 — 이 절은 다른 B 항목이 바꾼 값들(영구채 450 등)을 그대로 안고 있었기 때문이다.

### ② 결과

**(1) 🔴 인용 수치 2건이 낡거나 틀렸다.**

| 인용 | 문제 | 조치 |
| :--- | :--- | :--- |
| 만기: "영구채 **450**건이 57년" | B2 에서 471 로 확정됨 | 🔧 471 로 교체 (57.3년은 재현 확인 — `SK텔레콤신종자본증권 3`, 20,920일) |
| 답변모수: "시장 전체(**16,349**)" | **어떤 조합으로도 재현 안 됨** | 🔧 폐기 → 재현 가능한 정의로 교체 |

16,349 를 찾으려 조합을 훑었으나 근접값이 없었다:
```
전체 42,394 · 만기 전 25,888 · 평가 보유 20,612 · 수익률 정상 19,915
등급 보유 15,179 · 장내 15,669 · 사모 제외 16,913 · 수익률정상+사모제외 16,103
```
B2 의 450, B8 의 7,749 와 같은 **출처 미상 수치**다. 다만 그 둘과 달리 grep·조합 탐색 모두 실패해 복원하지 못했다. 재현 가능한 정의로 교체했다 — **조회 모수 25,888 / 추천 모수 254**.

**(2) '싸다' 기본값 금지 — 근거가 더 강해졌다.**

기존 근거는 "가격↔수익률 역관계"라는 이론이었다. 실측하니 상관계수는 **-0.057** 로 거의 0 이었다(만기·신용도 차이가 뒤섞이기 때문). 그래서 상관 대신 **순위**로 검정했다:

```
"싼 채권 Top-20"   가격 낮은 순  vs  수익률 높은 순
   겹침: 0건

가격 낮은 Top5 : 한국주택금융공사MBS 2026-3(2-1)(사) …
수익률 높은 Top5: 신보2023제5차유동화전문1-2(사) …
```

두 해석이 **완전히 다른 종목**을 내놓는다. 기본값을 두면 절반이 오답이라는 판정이 순위 기준으로 재확인됐다. (상관계수를 근거로 쓰면 오히려 "관계가 약하다"는 반대 결론이 나올 뻔했다.)

**(3) '안전/위험' 역질문 근거 재현 ✅**
```
평균 듀레이션(금리위험)  국공채 4.52 > 특수채 4.01 > 회사채 2.05
부도위험은 정확히 반대 순서
```

**(4) 🔴 FRN_금리비교 — 적용 모수에 큰 제약이 있다.**

```
전체 FRN                   643
살아있음(7-11 기준)         354
+ 갱신일 2-24 (신뢰 구간)    217   ← 조건부 답변이 성립하는 모수
+ 매수 가능                   0   ← ⛔
```

**매수 가능한 FRN 이 0건**이다. 이 역질문은 **조회 질의 전용**이며, "지금 살 수 있는 변동금리채" 질의에는 되묻지 말고 "당사 매수 가능 목록에 변동금리채는 없습니다"로 바로 답해야 한다. 되묻기가 오히려 사용자를 막는 경우다.

**(5) FRN 조건부 답변 실제 작성 — 계산 성립 확인.**

```
한국주택금융공사 MBS2019-1(1-1)(콜/변)
   AAA · 잔존 27.9년 · SRFC_IRT 3.400% · YTM 3.805%

비교군: 같은 등급·잔존 ±30% 고정금리채 532건 · 평균 표면 3.042%
손익분기: 3.042%  →  현재 여유 +0.358%p
```

> "표면금리 3.400%는 2026-02-24 시점의 적용 금리이고 다음 재설정일에 바뀝니다. 같은 등급·만기대 고정금리채의 평균이 3.042%이므로, 이 채권의 적용금리가 3.042% 아래로 내려가면 고정금리채가 유리해집니다. 현재는 0.358%p 여유가 있습니다."

사용자가 기준금리를 답하지 않아도 **이 형태로 답이 나간다** — 되묻기는 정밀화용이다. (이 종목은 MBS 라 `유동화위험금지` 도 함께 걸린다.)

### ③ 결론 — 10종 전건 기본값 확정

원칙을 하나 세웠다. **되묻되, 사용자가 답하지 않아도 "확인할 수 없습니다"로 끝내지 않는다 — 기본값으로 답하되 그 기본값을 반드시 밝힌다.**

| :-: | :--- | :--- |
| 1 | 수익률 | 개인 세후(`AFTER_TAX_YIELD`) + 산출 기준 명시 |

## 방법론 메모 — 이번 검토에서 반복해 통한 것

**① 미재현 수치는 레포에서 grep 하면 나온다.** "숫자를 낸 사람"이 없어도 `docs/` 전체 grep 으로 B2 의 450(→ `notes.md` §D.11 표)과 B8 의 7,749(→ MBS+유동화+**Conduit**)의 출처를 찾았다. 반면 B9 의 16,349 는 grep·조합 탐색 모두 실패해 폐기했다. **미재현 수치가 나오면 조합 탐색 전에 grep 을 먼저 할 것.**

**② 문맥 전수 점검이 표본 30건보다 강하다.** B2 의 '성신종합유통' 오탐은 표본으로는 놓쳤을 것이다. 종목명 파싱 판정에는 **매칭 문자열의 앞뒤 글자를 전수 집계**하는 방법이 정착됐다(B2·B1·B3 에서 반복 사용).

**③ 검정식을 그대로 돌리기 전에 "무엇을 반증하는가"를 확인할 것.** B5 는 지정 패턴이 17% 라 기각됐지만 원인을 찾으니 다른 설명이 98% 였고, B6 은 지정 검정을 통과했지만 경쟁 모델(이표채 가정)을 세우자 판정이 훨씬 강해졌다. B9 의 '싸다'는 상관계수로 보면 근거가 무너질 뻔했으나 순위로 보니 확정됐다. **단일 지표의 적합도보다 경쟁 모델·대안 지표와의 비교가 결정적이다.**

**④ 규칙 문자열은 반드시 실행해 볼 것.** B8 에서 `TRIM` 을 빠뜨려 7,952 대신 3,014 가 나왔고, B7 에서 `--` 주석이 YAML 폴딩으로 뒤 SQL 을 삼켰다. 둘 다 검증 없이 넘어갔으면 그대로 오답이 됐다.

**⑤ "재현됐다"와 "옳다"는 다르다.** `is_callable` 은 감사에서 pattern↔count 정확 재현으로 통과했지만, B5 에서 실제로는 콜옵션 68행을 놓치고 있음이 드러났다. 감사가 통과시킨 나머지 7종도 같은 눈으로 볼 필요가 있다.
