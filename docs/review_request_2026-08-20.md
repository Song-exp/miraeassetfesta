### 채권 담당

#### B1. 🆕 사모 채권 판정 기준(is_private) 검토 — 참조 §1-B

**무엇을** — 채권에는 "사모 발행"(공모가 아니라 소수 투자자에게 직접 파는 방식) 여부를 담는 컬럼이 없고, 종목명 괄호 표기(`(사모/콜)` 등)를 정규식으로 파싱해 `is_private` 플래그를 만든다. 원래 등재돼 있던 건수 10,067은 어떤 패턴으로도 재현이 안 되는 출처 미상 수치여서, 오늘 "이름에 '사모'가 들어간 전체 = **15,261건**"으로 교체했다. 이 교체가 맞았는지 확인하는 작업이다.

**왜** — 사모 채권은 개인 고객에게 추천하면 안 되는 상품이라 **추천 질의의 제외 대상 후보**다. 15,261이면 전체의 36%가 제외되는 셈이라, 이 판정 하나가 추천 모수를 좌우한다. 또 사모는 "특수구조"(전환·콜 같은 구조 옵션)가 아니라 "발행 방식"이므로, 기존 `특수구조제외` 규칙에 섞어 넣을지 별도 규칙로 뺄지도 정해야 한다.

**어떻게**
1. 재현 — 두 값이 같아야 한다 ('사모'가 전부 괄호 안에만 등장한다는 뜻):
   ```python
   sum(1 for n in names if re.search(r'[(/][^()]*사모', n))   # → 15261
   sum(1 for n in names if '사모' in n)                        # → 15261
   ```
2. 오탐 확인 — 표본 30건을 눈으로 보고 "괄호 안 '사모'가 정말 사모 발행 표기인가"(발행사명·상품명에 우연히 '사모'가 들어간 경우가 오탐):
   ```python
   random.seed(0); print(*random.sample([n.strip() for n in names if '사모' in n], 30), sep='\n')
   ```
3. 제외 비용 산출 — 추천 모수(지금 살 수 있는 254건)에서 사모를 빼면 몇 건이 사라지나:
   ```python
   rec = [n for (n,) in q("SELECT PD_NM FROM domestic_bonds WHERE BUYABLE_QUANTITY>0 AND MAT_DT>20260711")]
   len([n for n in rec if '사모' in n])
   ```
4. 결정 — 개인 추천 질의에서 사모 제외가 타당한가. 타당하면 `특수구조제외`와 분리된 `사모제외` 규칙로 만들지 문구 확정.

**합격 기준**: ①재현 일치 ②표본 30건 오탐 0건 ③제외 여부 결정문. **기록**: `domestic_bonds.yaml` → `is_private` 주석 ✅ + `특수구조제외` rule 의 "별도 결정 필요" 문구를 결정 결과로 교체.

#### B2. 영구채 판정 건수(is_perpetual 450) 재확정 — 참조 §1-B

**무엇을** — 영구채(만기가 사실상 없는 신종자본증권)도 종목명 파싱으로 식별하는데, 등재된 건수 450이 **어떤 패턴으로도 재현되지 않는다** (현행 패턴 `신종|영구`는 473, 도메인 문서의 원패턴 `신종자본 또는 (신종)`은 467, `신종자본` 단독은 296). 어느 집합이 "영구채"인지 정해서 패턴과 건수를 다시 못박는 작업이다.

**왜** — 영구채는 듀레이션이 0으로 잘못 기재돼 있어(§B5 참조) "금리위험 낮은 채권" 정렬에서 **가장 위험한 채권이 가장 안전해 보이는 역전**을 일으키는 핵심 필터다. 집합 정의가 흔들리면 이 방어가 통째로 흔들린다.

**어떻게**
1. 세 후보의 차집합을 뽑아 행 단위로 "영구채 맞나" 판정:
   ```python
   A = {n.strip() for n in names if re.search(r'신종|영구', n)}                  # 473
   B = {n.strip() for n in names if re.search(r'신종자본|[(/]신종[)/]', n)}      # 467
   C = {n.strip() for n in names if '신종자본' in n}                             # 296
   sorted(A - B)        # 6건 — 맨몸 '신종'·'영구' 표기: 영구채인가?
   sorted(B - C)[:30]   # '(신종)' 표기 171건 표본: 신종자본증권인가?
   ```
2. 포함할 집합을 정하고 그 패턴으로 count 정확 재현. (450 을 원래 산출한 사람이 팀에 있으면 산출 방식을 먼저 물어볼 것 — 그게 제일 빠르다.)

**합격 기준**: 차집합 전 행 판정 + 새 pattern 으로 count 재현. **기록**: pattern·count 갱신 + `# 🔧 정정`.

#### B3. 변동금리채 정규식(is_frn) 확정 — 참조 §1-B

**무엇을** — 변동금리채(FRN, 금리가 시장금리에 연동)도 종목명으로 식별하는데, yaml 의 pattern 필드가 정규식이 아니라 산문(`"변 계열 4종 — '천변' 오탐 1건 제외"`)으로 적혀 있다. 런타임은 이 필드를 읽어 실행하므로 **지금 상태로는 기계가 못 쓴다**. 표기 4종을 실제 정규식으로 바꾸는 작업이다.

**왜** — FRN 643건은 표면금리 해석이 일반채와 완전히 다르고(스냅샷 값), `(변)` 표기만 잡으면 42%밖에 못 잡는다. 패턴이 없으면 "변동금리채 보여줘"가 절반 이상 누락된 채 나간다.

**어떻게**
1. `docs/eda/domestic_bonds_notes.md` §5.1-⑦ 에서 표기 4종 목록을 확인한다.
2. 4종 각각의 정규식을 만들어 합집합이 정확히 643 이 되게 조합하고, '천변'(오탐 1건)이 빠지는지 확인:
   ```python
   pat = re.compile(r'<확정한 정규식>')
   len([n for n in names if pat.search(n)])          # → 643
   [n for n in names if '천변' in n]                  # 이 1건이 매칭 안 돼야 함
   ```

**합격 기준**: 643 재현 + '천변' 미포함. **기록**: pattern 을 실행 가능한 정규식으로 교체.

#### B4. 🔶 "지금 살 수 있는 채권 254건" 해석 검증 — 참조 §1-A #5

**무엇을** — 채권 42,394건 중 매수 정보(BUY_YIELD 등 7컬럼)가 있는 건 881건뿐이고, 수량>0·만기 전 조건까지 걸면 **254건(0.6%)**만 남는다. 우리는 이 결측 97.9%를 "값을 모른다"가 아니라 "**미래에셋 진열대에 없다**(당사가 지금 팔지 않는다)"로 해석했고, 그래서 추천 질의의 모수를 254로 잡았다. 이 해석이 맞는지 확인하는 작업이다.

**왜** — 이 해석은 데이터가 아니라 도메인 추론(개인의 채권 매수 관문은 증권사 리테일 진열대, 개인투자용국채는 미래에셋 단독판매)에서 나왔다. **틀리면 "이 채권은 현재 판매 중이 아닙니다"라는 답변 전체가 오답**이 된다 — 채권 도메인에서 가장 위험한 단일 가정이다.

**어떻게**
1. 모수 사다리 재현:
   ```sql
   SELECT COUNT(*) FROM domestic_bonds WHERE BUY_YIELD IS NOT NULL;                        -- 881
   SELECT COUNT(*) FROM domestic_bonds WHERE BUYABLE_QUANTITY > 0;                         -- 325
   SELECT COUNT(*) FROM domestic_bonds WHERE BUYABLE_QUANTITY > 0 AND MAT_DT > 20260711;   -- 254
   ```
2. 외부 대조 — 미래에셋증권 앱/웹의 장외채권 판매 목록에서 5종목을 골라 254 목록과 성격을 대조한다. ⚠️ 지금 페이지는 8월 시점이라 7/11 스냅샷과 종목이 다를 수 있다 — 확인할 것은 종목 일치가 아니라 "**이 컬럼이 리테일 진열대 성격인가**"(254 목록의 상품 유형·거래 단위가 개인 판매용과 부합하는가).

**합격 기준**: 사다리 재현 + 성격 부합/불일치 판정문. **기록**: `BUY_YIELD.answer_policy` ✅ 또는 해석 수정.

> ⚠️ **비수집 방침 (2026-08-20 확정)** — 254건(0.6%)이 적다고 **타사 판매·호가 데이터를 수집해 메꾸지 말 것**. 채권 시장은 기관 중심(관행 거래 단위 ~100억, 개인 비중 1~2%)이고 소매는 증권사 진열대 모델이라 **이 비율 자체가 도메인과 정합**한다. 타사 판매 여부는 "이 데이터에 수록되어 있지 않습니다 — 각 증권사 장외채권 목록에서 확인 가능"이 정답이다. 이 작업(B4)의 목적은 모수 확장이 아니라 **해석 검증**뿐이다.

#### B5. 🔶 듀레이션 0 = "영구채 산출 불능" 판정 검증 — 참조 §1-A #6

**무엇을** — 듀레이션(금리위험 지표)이 0인데 잔존만기가 남아 있는 채권이 500건 있다. 이론상 금리위험 0인 채권은 존재하지 않으므로, 우리는 이 0을 "값"이 아니라 "**영구채라 평가사가 산출을 못 한 표기**"로 판정하고 `듀레이션정상` 규칙에서 제외했다. 500건이 정말 영구채류인지 전수 성격을 확인하는 작업이다.

**왜** — 판정의 근거가 표본 예시(SK텔레콤 신종자본증권) + 도메인 논리뿐이고 500건 전수 확인은 없었다. 판정이 틀리면 "금리위험 낮은 채권 Top-N"에서 실제로 위험한 채권이 안전한 것으로 나간다.

**어떻게**
```python
rows = [n for (n,) in q("SELECT PD_NM FROM domestic_bonds WHERE DUR=0 AND REMAINING_DAYS>0")]  # 500건
pat = re.compile(r'신종자본|[(/]신종[)/]|영구|코코|조건부자본')
hit = [n for n in rows if pat.search(n)]; len(hit)/len(rows)   # 이 비율이 판정의 근거
sorted(set(rows) - set(hit))[:30]                              # 미부합 행 표본 — 어떤 유형인가
```

**합격 기준**: 비율 ≥90% → 판정 지지. 미달이면 미부합 행 유형 보고(판정 재검토). **기록**: `DUR.answer_policy` 에 비율 병기.

#### B6. 🔶 할인채 표면금리 = 할인율 판정 검증 — 참조 §1-D

**무엇을** — 종목명에 '할인'이 붙은 172건은 이자를 안 주는 대신 액면(1만원)보다 싸게 파는 채권이다. 그런데 이들의 표면금리 컬럼(SRFC_IRT)에 0이 아니라 2~3.5%대 값이 들어 있어, 우리는 "**표면이율란에 할인율을 적은 것**"으로 판정했다(§D.15). 이 판정으로 "SRFC_IRT=0 → 무이표채" 규칙 전체가 뒤집혔는데, **결정 증거가 단일 종목의 가격식 재현 1건**뿐이다. 표본을 늘려 재현하는 작업이다.

**왜** — couponType(이표/할인/복리) 축 전체가 이 판정 위에 서 있다. 틀리면 "표면금리 높은 채권"·"무이표채" 질의가 갈린다.

**어떻게** — 무작위 10건에 대해 무이표 가격식(현재가 ≈ 10000/(1+할인율)^잔존연수)이 성립하는지:
```python
rows = q("""SELECT PD_NM, SRFC_IRT, EVAL_PRICE, REMAINING_DAYS FROM domestic_bonds
            WHERE PD_NM LIKE '%할인%' AND EVAL_PRICE > 0 AND REMAINING_DAYS > 0""")
random.seed(1)
for nm, r, ev, d in random.sample(rows, min(10, len(rows))):
    model = 10000 / (1 + r/100) ** (d/365)
    print(f"{nm.strip()[:30]:32s} 모델 {model:,.0f} vs 실제 {ev:,.0f}  오차 {abs(model-ev)/ev*100:.2f}%")
```

**합격 기준**: 10건 중 9건 이상 오차 ±0.5% 이내 → 판정 지지. **기록**: `SRFC_IRT.trap` ✅ (반례는 행 목록 첨부).

#### B8. 🆕 유동화 채권 식별 범위 검증 — 참조 §1-A #14

**무엇을** — MBS·ABS 같은 유동화 채권은 발행자가 회사가 아니라 SPC(자산 금고)라서, 발행사 이름으로 위험을 판단하면 안 된다는 규칙(`유동화위험금지`)을 오늘 신설했다. 식별 기준을 `BD_KND IN ('MBS','유동화회사채')` = 4,957건으로 잡았는데(이전에 떠돌던 '7,749건'은 재현 불가라 폐기), 채권종류 컬럼에는 안 잡히고 **종목명·발행사명에만 '유동화'가 뜨는 약 200건**을 규칙에 포함할지 정하는 작업이다.

**왜** — 이 200건이 SPC 발행이면 규칙 밖에서 "삼성카드 채권 위험해?" 류 오답이 새어 나간다.

**어떻게**
```python
bd = q("SELECT PD_NM, TRIM(COALESCE(BD_KND,'')), TRIM(COALESCE(PD_PBCM,'')) FROM domestic_bonds")
base  = [r for r in bd if r[1] in ('MBS','유동화회사채')]; len(base)   # 4,957 (현행 규칙)
extra = [r for r in bd if r[1] not in ('MBS','유동화회사채')
         and ('유동화' in r[0] or '유동화' in r[2])]; len(extra)        # ≈200 (규칙 밖)
[f"{r[0].strip()[:30]} | {r[1]} | {r[2][:20]}" for r in extra[:20]]    # 표본 — SPC 발행인가?
```

**합격 기준**: 표본이 SPC 발행이면 규칙을 `OR PD_PBCM LIKE '%유동화%'` 로 확장, 아니면 현행 유지. **기록**: `유동화위험금지` rule 확정.

**어떻게** — 항목마다 ① 되묻는 문구를 소리 내 읽고 일반 사용자가 답할 수 있는 질문인지 ② 무응답 시 안전한 기본값이 뭔지 ③ FRN_금리비교는 실제 FRN 1종목으로 조건부 답변 예시를 1건 직접 작성해 계산이 성립하는지 확인.

**기록**: 항목별 ✅/문구 수정 + 기본값 필드 추가.

#### E2. 수익률 필터의 매개변수형 개정 검증 — 참조 §2-A #3

**무엇을** — 수익률 컬럼에는 -100 이라는 센티넬(거래중단·상폐 표시값)이 섞여 있어 Top-N 을 오염시킨다. 원래 규칙은 1년 수익률에만 필터를 걸었는데, 감사에서 센티넬이 **전 기간(1m·3m·6m·ytd·1y)에 존재**함이 밝혀져 "질의가 실제로 정렬/필터하는 그 기간 컬럼에 건다"는 매개변수형으로 개정됐다. 기간별 센티넬 분해를 재현하고, 규칙 문안이 SQL 생성기에 전달 가능한 형식인지 보는 작업이다.

**왜** — 이 규칙은 고정 문자열이 아니라서 SQL 생성기가 컬럼을 갈아 끼워야 한다. 형식이 애매하면 구현 단계에서 해석이 갈린다.

**어떻게**
```sql
SELECT 'm1', COUNT(*) FROM domestic_etfs WHERE du_er_1m = -100
UNION ALL SELECT 'm3', COUNT(*) FROM domestic_etfs WHERE du_er_3m = -100
UNION ALL SELECT 'm6', COUNT(*) FROM domestic_etfs WHERE du_er_6m = -100
UNION ALL SELECT 'ytd', COUNT(*) FROM domestic_etfs WHERE du_er_ytd = -100
UNION ALL SELECT 'y1', COUNT(*) FROM domestic_etfs WHERE du_er_1y = -100;
-- 기대: 20 · 37 · 53 · 44 · 98
SELECT COUNT(*) FROM domestic_etfs WHERE du_er_1y = -100 AND du_clpr <> 0;   -- 0 (전건 종가0 동반 = 상폐 확인)
```
규칙 원문(`<질의 대상 기간 컬럼> > -100 …`)을 보고 `{column}` 플레이스홀더 등 형식 제안이 있으면 적는다 (구현은 별도 트랙).

**기록**: rule ✅ + 형식 의견.

#### E3. 전일NAV 그룹 분리 판정(ETF 깨짐/ETN 정상) 재현 — 참조 §2-A #5

**무엇을** — 전일NAV·등락금액 컬럼은 원래 "전부 깨짐, 사용 금지"였는데, 감사에서 **ETF 1,137건만 깨졌고(전일값 자리에 오늘값 복사) ETN 379~380건은 정상**임이 밝혀져 그룹별 분리 판정으로 뒤집혔다. 이 분해를 재현하고 비대칭 판정이 맞는지 보는 작업이다.

```sql
SELECT COUNT(*) FROM domestic_etfs WHERE pd_grp_no='ETN' AND du_nav_yday IS NOT NULL

SELECT COUNT(*) FROM domestic_etfs WHERE pd_grp_no='ETF' AND du_nav_yday = du_last_nav
  AND du_nav_yday IS NOT NULL;                                                               -- 1,137 (ETF: 복사 깨짐)
```

**기록**: `columns.du_nav_yday` ✅ + 서술 방식 의견.

#### F1. 🆕 펀드 개수 집계의 세 필터 정정 검토 — 참조 §3-A #2

**무엇을** — 공모펀드 테이블은 행=종목×속성태그(95,619행)이고, "펀드 몇 개?"에 답하려면 운용사코드+펀드번호 합성키로 묶어야 한다. 등재된 정답은 4,643개인데, 오늘 실측해 보니 문서에 적힌 필터(더미 식별자 배제)만으로는 **4,645**가 나오고, 오염 8종목(따옴표 섞인 행)까지 배제해야 4,643이 재현됐다. 즉 **세 필터(더미+오염+합성키)가 전부 있어야** 하는데 규칙 본문에는 둘만 명시돼 있었다 — 이 정정을 확인하고 규칙 문안을 확정하는 작업이다.

**왜** — 런타임이 규칙 본문만 읽고 실행하면 "펀드 몇 개?"에 4,645를 답한다. 2건 차이지만 정답과 다른 수다.

**어떻게**
```sql
-- ① 더미 배제만 → 4,645
SELECT COUNT(*) FROM (SELECT DISTINCT or_co_xtn_itt_cd,
  CASE WHEN length(mtco_itm_no)>=7 THEN mtco_itm_no ELSE substr('0000000'||mtco_itm_no,-7) END
  FROM public_funds
  WHERE NOT (mtco_itm_no IS NULL OR mtco_itm_no=''
    OR replace(replace(mtco_itm_no,'KR',''),'0','')=''
    OR (length(mtco_itm_no)>1 AND replace(mtco_itm_no,substr(mtco_itm_no,1,1),'')='')));
-- ② ①의 WHERE 에 AND mtco_itm_no NOT LIKE '%"%' AND itm_no<>'"' 추가 → 4,643
```
판단: 오염 배제 2조건을 `펀드단위` 규칙 **본문**에 넣을지 (현재는 `펀드단위_검증` 주석에만 있음).

**합격 기준**: 4,645→4,643 재현 + 규칙 문안 결정. **기록**: `public_funds.yaml` query_rules ✅.

#### F2. 🆕 당사판매여부 빈칸 = NULL 정정 검토 — 참조 §3-A 정규화

**무엇을** — `thco_sale_yn`(미래에셋증권 취급 여부)은 'Y' 아니면 빈칸인데, yaml 이 빈칸을 `''`(빈 문자열)로 등재하고 있었다. 실측하면 `=''`는 **0행**이고 실체는 NULL(4,024행·694종목)이라 오늘 정정했다 — SQL 을 `=''`로 짜면 조건이 항상 거짓이 되는 함정이었다. 이 정정과, 빈칸의 두 가지 뜻을 구분한 answer_policy 를 확인하는 작업이다.

**왜** — "미래에셋에서 안 파는 펀드" 질의가 0건 또는 전건으로 나가는 함정이었고, 빈칸의 뜻도 하나가 아니다(판매완료 683종목=레거시 / 판매중 11종목=채널 미취급 — 후자는 데이터가 정상이라 "정보가 부족하다"고 답하면 거짓).

**어떻게**
```sql
SELECT COUNT(*) FROM public_funds WHERE thco_sale_yn = '';                                  -- 0
SELECT COUNT(*), COUNT(DISTINCT itm_no) FROM public_funds WHERE thco_sale_yn IS NULL;       -- 4,024 · 694
SELECT sale_yn, COUNT(DISTINCT itm_no) FROM public_funds
 WHERE thco_sale_yn IS NULL GROUP BY 1;                                                     -- 판매완료 683 · 판매중 11
```

**기록**: `thco_sale_yn.value_semantics` ✅.

#### F3. 🔶 "주식형 펀드" 판별 규칙의 폴백 정확도 — 참조 §3-A #6

**무엇을** — 자산군 컬럼(`or_attr_desc`)의 '주식형'만 세면 4,280종목인데, '재간접'·'06' 으로 분류된 것 중 이름에 '(주식'이 붙은 1,461종목을 추가 회수하는 규칙(`자산군_주식형`)이 반영돼 있다(합계 5,741 — 34% 차이). 이 이름 파싱 폴백이 실제로 주식형을 회수하는지 표본 검사하는 작업이다.

**왜** — 회수분이 오염이면 "주식형 펀드 몇 개/Top-N"의 모수가 34% 부풀려진다. 근거가 "재간접 3,022 중 1,604가 실제 주식형"이라는 관측 하나다.

**어떻게**
```sql
SELECT COUNT(DISTINCT itm_no) FROM public_funds WHERE trim(or_attr_desc)='주식형';   -- 4,280
SELECT COUNT(DISTINCT itm_no) FROM public_funds WHERE trim(or_attr_desc)='주식형'
   OR (trim(or_attr_desc) IN ('재간접','06') AND itm_nm LIKE '%(주식%');             -- 5,741
SELECT DISTINCT itm_nm FROM public_funds
 WHERE trim(or_attr_desc) IN ('재간접','06') AND itm_nm LIKE '%(주식%' LIMIT 30;     -- 회수분 표본
```

**합격 기준**: 표본 30건 중 주식형 아닌 것 ≤2건 → 유지, 초과 시 폴백 조건 수정. **기록**: `자산군_주식형` rule ✅ + 정확도.

#### F4. 🔶 순자산 MAX 집계의 근사 오차(268펀드) 영향 — 참조 §3-A #7

**무엇을** — 펀드 순자산은 클래스(종목)마다 같은 값이 반복 기재돼 있어 SUM 하면 3.31배 과대계상된다(1,545조 vs 실제 466.7조). 그래서 "펀드 단위 MAX" 규칙이 반영돼 있는데, **0을 배제해도 클래스 간 값이 서로 다른 펀드가 268개** 남아서 MAX 도 근사값이다. 이 268개가 순자산 Top-N 순위에 실제로 영향을 주는지 확인하는 작업이다.

**왜** — 268개 중에 대형 펀드가 있으면 "순자산 Top5" 순위 자체가 흔들린다. 없으면 "근사"로 두고 넘어가도 된다.

**어떻게**
```sql
-- 값 갈리는 268펀드 재현
SELECT COUNT(*) FROM (
  SELECT or_co_xtn_itt_cd, CASE WHEN length(mtco_itm_no)>=7 THEN mtco_itm_no
         ELSE substr('0000000'||mtco_itm_no,-7) END k
  FROM public_funds WHERE fd_nast_suma>0 GROUP BY 1,2 HAVING COUNT(DISTINCT fd_nast_suma)>1);  -- 268
```
이어서 펀드 MAX 순자산 상위 30 목록을 뽑고, 268 목록과 겹치는 펀드가 있는지 대조. 있으면 그 펀드의 MAX/MIN 격차 기록.

**합격 기준**: Top-30 영향 유/무 판정. **기록**: `fd_nast_suma` 집계함정 주석에 병기.

#### F5. 행 구조·0값 3갈래 판정 재현 — 참조 §3-A #1·#8

**무엇을** — 펀드 테이블의 두 기둥 판정을 재현하는 작업이다: ① 행=종목×속성태그 구조(그래서 COUNT(\*) 금지 — 안 지키면 8.6배 과대) ② 0값의 3갈래 처리(순자산 0 = 센티넬 294종목 / 수익률 9기간 전부 0 = 결측 69종목 / **5기간 0 + 3년 비영 = 107종목은 미확정** — 최근 1년 무변동이라 운용 정지 후보).

**왜** — ①은 펀드 도메인의 모든 집계가 걸린 기둥이고, ②의 107종목은 아직 방침이 "값으로 두되 수익률 최저 Top-N에서 제외"로만 잠정 결정돼 있어 의견이 필요하다.

**어떻게**
```sql
SELECT COUNT(*) FROM public_funds;                                              -- 95,619
SELECT COUNT(DISTINCT itm_no) FROM public_funds;                                -- 11,139
SELECT COUNT(*) FROM (SELECT DISTINCT itm_no, prfd_attr_cd FROM public_funds);  -- 95,619 (행=종목×태그 증명)
```
0값 3갈래(294/69/107)는 `public_funds.yaml` → `zero_as_missing` 절에 적힌 컬럼 목록 그대로 재현.

**합격 기준**: 전 수치 재현 + 107 처리 방침 의견. **기록**: `zero_as_missing` ✅.
