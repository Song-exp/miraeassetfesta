### 🆕 그 과정에서 새 종류를 찾았다 — `롱숏`

| 종목코드 | 상품 | 배수 | 기초지수 |
| :-- | :-- | --: | :-- |
| `KR7360140008` | KODEX 200롱코스닥150숏선물 | +1.0 | `KOSPI 200 Long 100% KOSDAQ150 100% Futures` |
| `KR7360150007` | KODEX 코스닥150롱코스피200숏선물 | +1.0 | `KOSDAQ150 Long 100% KOSPI 200 Short 100% Futures` |

**인버스가 아니라 스프레드 전략**이다. 한쪽을 사고 한쪽을 판다.

- ❌ *"인버스 ETF"* 질의에 넣으면 안 된다
- ❌ *"레버리지"* 도 아니다 (배수 1배)
- ❌ *"시장이 내리면 버는 상품"* 도 아니다 — **두 지수의 상대 성과**로 번다

> 리드 지시의 취지가 이것이다 — 문자열을 쓰되 **걸러지는 종류를 세분화해서 온톨로지에 명시**해야
> "안 걸리는 것"이 없어진다. 롱숏은 규칙이 없었으면 조용히 인버스 질의 밖에 남아 있었을 것이다.

## 4. ✅ `자산군_지수불일치` 철회 완료 (2026-08-31)

인버스 계열은 오탐 0 으로 확인됐으나, 이 규칙만은 성격이 달라 **철회했다.**

- 오분류 **1건**(`TIGER 우선주`) 잡으려고 지수명에 `Stock`·`Equity`·`Preferred` 가 들어가면
  주식으로 보는 문자열 규칙이었다 — 서현 지적에 정확히 해당한다.
- [`docs/eda/domestic_etfs_axis_mismatch.md`](../eda/domestic_etfs_axis_mismatch.md) §3 에
  *"상품명 키워드로 바꿔도 정확도가 92% → 92% 로 안 오른다"* 는 실측과
  **"컬럼 정본 + 주최 문의"** 방침이 이미 있었는데 그걸 안 보고 만들었다.

**→ `query_rules.자산군오분류_제외` 로 교체.**

```
pd_itm_no NOT IN ('KR7261140008')
```

| | 전 | 후 |
| :-- | :-- | :-- |
| 방식 | 지수명 문자열 패턴 | **종목코드 지정** |
| 근거 | 단어 포함 | **구성종목 실측**(삼성전자우 26.8% 등 전부 우선주) |
| 서현 지적 | 🔴 해당 | ✅ 해당 없음 |
| 결과 | 1건 제외 | **동일** |

`채권형질의` 의 `LIKE` 도 6개 → **3개**로 줄었다.

> 🔴 **같은 유형 오분류가 또 나오면 문자열 규칙을 다시 만들지 말고 종목코드를 추가한다.**
> 2026-08-31 전수 재확인 — 자산군(채권·단기자금·원자재) × 주식계 지수 교차에서 **이 1건뿐**이다.
