## 1. 🔴 온톨로지 제출 규격 미충족 — **확인 요청**

`PROJECT.md` §5 에 `[!CAUTION]` 으로 이렇게 적혀 있음:

> *"파일 경로와 이름이 규격으로 고정되어 있음. **단일 `ontology.ttl` 하나로는 요건 미충족**"*

그런데 `scripts/build_ontology.py` 는 지금 `ontology.ttl` **한 개만** 생성함.

### 대조표

| 규격 (`PROJECT.md` §5) | 현재 산출물 |
| :--- | :--- |
| `common.ttl` + `bond_kr` + `etf_kr` + `etf_gl` + `fund_pub` **5종** | ❌ `ontology.ttl` **1개** |
| 네임스페이스 `fp: <http://mafest.ai/product#>` (*"임의로 바꾸지 말 것"*) | ❌ `: <http://miraeasset.festa/ontology#>` |
| `riskGrade` **0~6** 범위 제약 (1~5 로 하면 실데이터 차단) | ❌ 없음 |
| `inverseOf` 역관계 | ❌ 없음 |
| `DatatypeProperty` (`fp:expenseRatio` 예시) | ❌ 없음 — `ObjectProperty` 만 있음 |
| `ETF owl:disjointWith ETN` | ✅ 있음 |

> ℹ️ 배포용 PDF(8p)에는 온톨로지 규격이 없음. 위 규격의 근거는 `PROJECT.md` §5 이고,
> 그 문서가 *"원문: 도메인별 Ontology.ttl 제출 기준"* 을 인용하고 있음 (원문 자료는 레포에 없음).
> **원문이 실제로 5분할을 요구하는지 형이 확인해 주면 확실해짐** — 아니라면 1번은 안 해도 되는 일임.

### 하려는 것

`scripts/build_ontology.py` 의 `emit_ttl()` 만 고쳐서:

1. **5개 파일로 분할 출력**
2. **`fp:` 네임스페이스로 교체**
3. **`riskGrade` 0~6 제약 · `inverseOf` · `DatatypeProperty` 추가**

**yaml(원천)은 안 건드림.** 생성기만 고치는 거라 지금까지 쌓인 판정·검토 결과는 그대로 유지됨.

### 분할 방식 (제안)

```
common.ttl   ← fp:Product 계층 + 공유 개체 6축(지수·지역·운용사·위험등급·통화·자산군)
bond_kr.ttl  ← 국내채권 전용
etf_kr.ttl   ← 국내ETF 전용
etf_gl.ttl   ← 해외ETF 전용
fund_pub.ttl ← 공모펀드 전용
```

🔴 **공유 개체는 반드시 `common.ttl` 에 둬야 함.** 도메인 파일로 쪼개면
*"같은 지수 추종하는 ETF + 펀드"* 같은 **교차질의 연결이 끊김**
(예: `Idx_MSCI_ACWI` 한 노드에 국내ETF·펀드 3,846종목·해외ETF가 같이 매달려 있음).

### 영향 범위 — 미리 확인해 둠 ✅

형한테 물어보려던 *"ttl 경로 참조하는 데 있나"* 는 **직접 확인했고, 없음**:

```
ontology.ttl 참조 위치 → scripts/build_ontology.py 내부뿐 (TTL_PATH)
런타임(src/runtime/·src/api/) → kg_* 테이블만 사용, ttl 파싱 안 함
```

**즉 5분할해도 런타임·API 에 영향 없음.** 되돌리기도 생성기 커밋 revert 하나로 끝남.

### 👉 확인 요청

- 원문 규격이 실제로 **5분할 + `fp:` 네임스페이스**를 요구하는 게 맞는지
- 맞으면 **제가 진행하겠음.** 다른 의도가 있었으면 알려주면 그대로 맞추겠음
- 바쁘면 진행하고 결과만 공유하겠음 (되돌리기 쉬운 작업이라 리스크 낮음)
