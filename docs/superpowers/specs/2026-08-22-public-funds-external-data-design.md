# 공모펀드 외부 데이터 활용 설계 — 검증 후 선별 적재

> 작성 2026-08-22 · 대상 `public_funds` 전용 (**채권·ETF 제외**)
> 선행: `docs/eda/public_funds_feature_overview.md` · `ontology/enums/public_funds.yaml`
> 외부 데이터 실물: `data/external/` (2026-08-22 `external/` → `data/external/` 이동 완료)

## 1. 배경

공모펀드 마스터 45컬럼에는 **설정일·보수·구성종목·모자관계가 하나도 없다.** 이 값들은 웹·투자설명서
수집으로 확보돼 `data/external/` 에 있으나, DB에는 적재되지 않았고(`ext_*` 테이블 0개) 일부는
yaml 판정 근거로만 인용돼 있다.

수집물을 통째로 올리면 **7/11 마스터 옆에 8/18 시계열 값이 나란히 앉는다.** 이 프로젝트에서 반복된
사고는 전부 "값이 거기 있으니까 집었다" 유형이었으므로, **런타임이 손댈 수 없는 것은 애초에 DB에
넣지 않는다**를 설계 원칙으로 둔다.

## 2. 범위

**포함** — 공모펀드(`public_funds`)에 관한 외부 데이터만.
**제외** — 채권·ETF 외부 데이터(`holdings/`·`holdings_overseas/`·채권 lookups)는 이 설계의 대상이 아니다.

여는 능력 4 + 1 (합의):

| # | 능력 | 예시 질의 |
| :-: | :--- | :--- |
| ① | 구성종목 역검색 | "삼성전자 담은 펀드" |
| ② | 보수 비교 | "어떤 클래스가 싼가" |
| ③ | 설정일·상품 나이 | "2020년 이후 설정된 펀드" |
| ④ | 모자형·클래스 성격 | "이 펀드 구조" · "온라인 클래스 있나" |
| ⑤ | 환매 조건 | "환매하면 돈 언제 들어와" (추가 합의) |

### 3.1 보수 소스 대조 (D4 근거)

| 항목 | 웹 `TFEE` | 설명서 `fee_total_pct` |
| :--- | :--- | :--- |
| 커버리지 | **10,565** (판매완료 포함) | 8,443 (웹의 부분집합, `right_only`=0) |
| 분해 | **5종**(총·판매·운용·수탁·사무) | 총보수 하나 |
| 내부 정합 | **5종 합 = 총보수 8,998/8,998 완전 일치** | — |
| 자체 표기 | — | "총보수 절 첫 수치, 표 파싱 아님 — **근사**" |

둘 다 >0 인 8,180건에서 **일치율 15.2%**, 중앙 절대차 **0.22%p**. 웹은 내부 정합이 완벽하고
설명서는 스스로 근사라고 밝힌 값이므로 웹을 채택한다. 설명서에서는 **불변 플래그만** 가져온다
(`redemption`·`issuance`·`is_masterfeeder`·`is_multiclass`·`is_convertible_fund`).

### 4.1 V5 — 직접 검증이 불가능한 이유

판매완료 중 `thco` 빈칸 683종목의 설정일 보유가 **110/683 (16%)** 뿐이다. 웹 페이지가 없는 그룹이
정확히 그 그룹이기 때문이다. 이는 대리지표를 **반증하지 않는다** — "웹에 페이지조차 없다"는 사실
자체가 레거시 방증이다. 검증 실패가 아니라 **검증 방법을 바꿔야 하는 항목**으로 기록한다.

### 4.2 결과 처리
