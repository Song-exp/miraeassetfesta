## 1. 최상위 4단계 (가로 흐름)

```
┌──────────────┐   ┌──────────────────┐   ┌───────────────────────────┐   ┌──────────────┐
│ ①  사용자    │──▶│ ②  HCX 의도 파악 │──▶│ ③ 온톨로지 탐색 · SQL 추출 │──▶│ ④ 답변 생성  │
│    질문      │   │   [HCX-005 1회]  │   │    (본 시스템의 핵심)      │   │              │
└──────────────┘   └──────────────────┘   └───────────────────────────┘   └──────────────┘
     입력                 LLM                   선언(온톨로지) + KG + 코드          LLM 또는 코드
```

**색 구분 제안** — ②·④의 LLM 구간과 ③의 결정 구간을 다른 색으로. ③ 안에서도 "선언·KG"(온톨로지 자산)와 "코드 가드"(결정층)를 톤 차이로.

## 2. 박스별 내용

### ① 사용자 질문

```
GET /answer?question_id={id}&question={질문}
예) "삼성전자를 담은 ETF 중 순자산이 가장 큰 건?"
```

### ② HCX 의도 파악 · [HCX-005 1회]

```
질의 정규화
   ↓
의도 분류 (JSON 한 덩이)
   { domain: 채권 | 국내ETF | 해외ETF | 펀드 | 교차 | 불명
     task  : 조회 | 개수 | 랭킹 | 비교 | 추천 | 설명 | 답변불가 | 되묻기
     entities  : [질문에 그대로 있는 고유명]
     constraints: [질문에 그대로 있는 조건 어구] }
   ↓
출력 검증 (코드) ── 목록 밖 낱말 → '불명' · 질문에 없는 어구 → 버림
```

> 캡션용 한 줄: **"의도는 LLM 이 읽고, 그 출력은 코드가 검증한다 — 지어낸 값은 다음 단계로 넘어가지 못한다."**

### ③ 온톨로지 탐색 및 SQL 추출  ★ 확대 박스

입구에서 **질문에 따라 두 갈래로 갈린다.**

```
                        ┌─────────────────────────────────────────┐
                        │  질문 분기                               │
                        │  "선언만으로 판정되는 질문인가?"          │
                        └───────────────┬─────────────────────────┘
              ┌───────── 예 ────────────┘         └──── 아니오 ─────────┐
              ▼                                                        ▼
┌──────────────────────────────────┐            ┌──────────────────────────────────┐
│ 3-1. 온톨로지 규칙 필터링         │            │ 3-2. KG 를 타고 SQL 추출          │
│      (SQL 없이 즉답)              │            │      (조회로 답하는 질문)         │
└──────────────────────────────────┘            └──────────────────────────────────┘
```

#### 3-1. 온톨로지 규칙 필터링 — 선언을 읽어 먼저 거른다

```
① 상품군 판정 (Route)
     상품 명사 + 온톨로지 값 어휘(DB·yaml 자동 생성)
     → 채권 / 국내ETF / 해외ETF / 펀드 / 교차 / 미특정
        └ 미특정이면 ②의 의도 분석 결과로 보정

② 부재 선언 대조 (ABSENT)
     ttl·yaml 이 "이 속성은 없다" 고 선언한 축
     예) 펀드 좌수 · 운용역 · 기준가 시계열 · 연환산 수익률 / ETF 신용등급 / 채권 등급 이력
     → "수록되어 있지 않습니다" + 대안 안내

③ 값 표준표 대조
     신용등급 27종 표준표에 없는 표기(AAAA·BBB++) → 기각
     위험등급 1~6 범위 밖(0·7등급) → 기각

④ 기준일 창
     데이터 기준일 2026-08-24 이후 시점 질의 → 기각

⑤ 다의어 되묻기
     '위험한' · '싼' · 기준이 여럿인 유사 조건 → 선택지를 제시하고 되묻기

⑥ 도메인 밖
     상품군 낱말·KG 매핑·스키마 어휘가 하나도 없음(인사·잡담) → 서비스 안내

  ▶ 산출: 답변불가 / 되묻기 / 안내 문장   (SQL 생성 없음 · LLM 추가 호출 없음)
```

#### 3-2. KG 를 타고 SQL 추출 — 답할 수 있는 질문만 내려온다

```
① KG 접지 (Ground)
     질문 낱말 → 지식그래프 노드 → 실제 DB 값으로 확정
     "삼성전자" → Security 노드 → ext_etf_holdings.stock_name = '삼성전자'
     "미국"     → Region 노드   → overseas_etfs.wu_inv_rgn = 'United States of America'
     · 노드 40,845 · 별칭 66,603 · 엣지 5,704 · 관계 클로저 9,969
     · 계열 관계 전개(에코프로 → 자회사) · 운용사 코드 역조회
        ↓
② 근거문서 조립
     스키마(그 상품군만) + 접지 결과 + 해당 규칙만
     (도메인 규칙 · 되묻기 규칙 · 답변불가 규칙)
        ↓
③ SQL 계획 [HCX-005 1회]  →  SQL 한 문장 | 되묻기 | 답변불가
        ↓
④ 확정식 치환 — 반드시 맞아야 하는 유형은 코드가 SQL 을 세운다(LLM 문장 통째 교체)
     · 편입 종목 조회 (○○를 담은 ETF·펀드) — KG 접지 + 조인 계약
     · 상품 개요 조회 (구조·특징)
     · 유사 채권 조회
        ↓
⑤ 결정층 가드 사슬 — 선언을 SQL 에 강제한다
     모수 주입(판매중·공모 / ETF·판매중 / 원화·만기 미도래)
     축 확정식(월배당·연금·환헤지·인버스·배수·추적오차·투기등급)
     정렬축 교정 · 서수 ORDER BY 정규화 · 동률 2차 정렬
     대표행 묶기(클래스 → 펀드 단위) · 근거 컬럼 보강
     질문에 없는 조건·임계 제거 · 0/센티넬 제외
        ↓
⑥ 안전 검사
     단일 SELECT · 테이블 화이트리스트 · LIMIT ≤ 30 · 값 사전 대조 · 상수 WHERE 기각
     실패 → 사유를 붙여 재생성 1회 → 또 실패면 "확인할 수 없음"
        ↓
⑦ 실행  read-only SQLite · 최대 30행
        ↓
⑧ 0행 처리
     유사 후보 되묻기(가까운 표기 제시) 또는 0행 원인 진단
     → 조건을 임의로 완화하지 않는다
```

> 캡션용 한 줄: **"온톨로지가 무엇을 물을 수 있는지 정하고, 지식그래프가 그 말을 DB 값으로 바꾸고, 코드가 그 조건을 SQL 에 강제한다."**

## 3. 경로별 LLM 호출 수 (그림 우측 범례 제안)

| 경로 | HCX 호출 | 예 |
| :-- | :-: | :-- |
| 선언으로 즉답 (3-1) | **1회** (의도만) | "위험등급 7등급 펀드" · "AAAA 채권" · "안녕" |
| 확정식 + 기계 조립 | **2회** | "삼성전자 담은 ETF 몇 개" · "국민성장펀드 구조" |
| 일반 조회 + 작성 | **3회** | "A클래스와 C클래스 중 보수가 낮은 쪽" |

> 재생성이 붙으면 각 +1. 실측 응답 0.2~7초(일부 문항 40초대), 하드 타임아웃 300초 이내.

## 4. 디자인 지시 요약

1. **가로 4단**(①→②→③→④)이 주 흐름. ③이 가장 크고, 그 안에 3-1·3-2 두 레인을 위아래로 둔다.
2. ③ 입구의 **분기 마름모**("선언만으로 판정되는가")에서 위 레인(3-1)은 곧바로 ④를 건너뛰고 답으로 나가는 화살표를, 아래 레인(3-2)은 ①~⑧ 순차 화살표를 그린다.
3. **LLM 아이콘은 세 곳만** — ② 의도 파악, 3-2 ③ SQL 계획, ④ 답변 작성. 나머지는 전부 코드·선언임이 한눈에 보이게.
4. 좌측 또는 하단에 **온톨로지 자산 패널**을 두고 ③으로 점선 연결:
   `ttl 5분할(common · bond_kr · etf_kr · etf_gl · fund_pub)` · `yaml 규칙(도메인·되묻기·답변불가·모수)` · `지식그래프(노드 40,845 · 별칭 66,603 · 엣지 5,704)` · `마스터 4테이블 + 외부 4테이블`
5. 되묻기·답변불가·0행 경로는 **점선**으로 ④ 오른쪽 출구에 합류시켜 "정답의 한 형태"임을 보이게 한다.
