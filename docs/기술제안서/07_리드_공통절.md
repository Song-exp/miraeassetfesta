## 2.2.1 온톨로지 설계 원칙과 구조 (2쪽) + 그림 A
- **서사 순서 (리드 결정 09-03): AI 가 데이터를 가져오는 구조 → 온톨로지는 그 구조의 부품 → 데이터 적용 규율.** 데이터 결함 나열로 시작하지 않는다.
- ① LLM 이 테이블을 조회할 때 틀리는 간극 4개 표 — 어디를 볼지(어휘→테이블·컬럼) / 무슨 값으로(어휘→실재 리터럴) / 데이터 관행(0·행 단위·단위·기준일·서열) / 없는 걸 없다고(부재·enum). 간극마다 우리 실측 사고 1건
- ② 철학 한 줄: **"모델은 복사만 하게 하라"** — 추측·기억 대신, 질문 시점에 실재 값과 규칙을 놓아 주고 옮기게 하고, 옮긴 결과를 같은 사전으로 검사
- ③ 세 형태가 각각 어느 간극을 메우나 — 값 사전 KG(1·2) / 규칙 문서 yaml(3, 선별 주입) / 게이트(4, 생성 전 기각 + 생성 후 값 대조)
- ④ 왜 이 구조인가 — 관계형 마스터라 답은 SQL 한 문장(검색이 아니라 조건 조립) / 12초 예산이라 탐색을 빌드 시점으로 / 환각이 감점이라 "유사한 것 찾기"는 오답 경로. 벡터·그래프 탐색 비채택 근거
- ⑤ 증거 — 층별 분해(집행층 실패 지배적 → 목록형 답변 기계 조립, HCX 0회) · KG 구조 검증 35문항 추이
- ⑥ 데이터 적용 규율 (한 단계 아래): 값을 고치지 않고 의미를 선언 / 부재도 지식 / 출처 축≠분류 축 / 선언과 실행은 한 원천 / 그래프를 걷지 않는다
- 2층 구조: `enums/*.yaml`(컬럼층, 담당자별) ↔ `shared/*.yaml`(개체층 16종, 횡단) — 잇는 것은 `kg_entity` 한 줄
- 공유 개체 11종(닫힌 축 6 / 열린 개체 5) · inverseOf 3쌍 · skos:broader 계층 3종(Region·CreditGrade·Index) · edge 4종(hasAssetClass 3,172 · coversRegion 2,535 · feedsInto 1,704 · subsidiaryOf 3)
- `holds` 를 kg_edge 에 넣지 않은 결정 — 100만 행, ext_* 테이블 자체가 edge
- 빌드: `scripts/build_ontology.py` Load→Validate→Emit→Report, V1~V7 표(죽은 alias · raw 충돌 · 미완 포인터 · 코드북 출처/기준일 · 미지 컬럼 · absent_in · alias_extensions)
- 규칙 12종 목록 한 줄씩 — 도메인 절이 번호로 인용
- **그림 A** 삽입 (`03_구성도_설계.md` §2)
