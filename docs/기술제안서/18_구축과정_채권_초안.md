## 3. 부족한 데이터 → 외부에서 가져온 것

### 3.1 마스터에 없던 것

등급 문자열 `AA-`·`BBB+` 는 데이터에 있지만, **"AA- 이상" 이 어느 등급들인지, `BBB-`/`BB+` 가 투자/투기 경계라는 사실은 데이터 어디에도 없다.** 발행기관의 법정 손실보전 여부(신용보강 판단)도 없다. 이 둘만 밖에서 들여왔다.

### 3.2 코드북 — 출처·기준일·행수

`ontology/codebooks/` 15종은 전부 펀드·ETF 용(운용사·수탁사·지역·섹터)이고 채권 전용 파일은 없다. 채권 코드북은 `data/external/lookups/` 에 있다.

| 파일 | 출처 · 기준일 | 행수 | 지금 쓰임 |
| :-- | :-- | :-- | :-- |
| `credit_grade_scale.csv` | 한국기업평가 등급정의 · as_of 2026-08-20 (D 행 08-30 추가) | 21행 · 표준등급 20 | ✅ `shared/credit_grade.yaml` 노드 22(등급 20 + 밴드 2)의 원천 · 게이트 표준표 |
| `bond_issuer_background.md` | 발행기관 법정 손실보전 여부 | — | ✅ 규칙 `신용보강` 6층 필터의 근거 |
| `collateral_type_map.csv` · `issuer_industry_map.csv` | 담보축 · 업종축 | — | 🟡 1차 기준 오류 3건(지역개발채 1,266 오분류 등) → 보류 |
| `bond_tax_rules.md` · `bond_glossary.md` · `ktb_individual_structure.md` · `zeroin_methodology.md` | 세금 · 용어 · 개인투자용국채 · 위험등급 체계 | — | 배경 지식 (개인투자용국채는 2차에서 소멸) |

원칙: 코드북에는 출처·기준일 컬럼을 두고, 값을 고치지 않고 **옆에 붙인다**. `as_of` 가 기준일 2026-08-24 를 넘으면 빌드 V4 가 거부한다. [리드 검토] — V4 는 `ontology/codebooks/` 를 순회하므로 `lookups/` 의 채권 코드북에 같은 검사가 걸리는지 확인 필요.

### 3.3 수집하지 않은 것과 이유

채권은 4개 상품군 중 유일하게 **외부 수집(구성종목·설명서)이 없다.** 구성종목도 설명서도 없는 상품이기 때문이다. 등급 이력·발행사 재무·계열 정보·이표 지급일도 수집하지 않았다 — 데이터에 없는 것은 유추하지 않고 ABSENT 로 답한다(§5.2). 신용등급 결측 18.4% 도 외부 원천이 없어 보완하지 않는다.

| 표준표 밖 토큰을 모두 "없음" 처리 | 게이트 4분기 — `not_grade`(CB) / `unknown`(AAAA) / `no_data`(BB+, 표준이나 2차 0건) / `ok` | 표준표 형태 `^([A-D])\1{0,3}[+\-0]?$` |
| "정부가 보증하는 채권" 을 국공채로만 | 규칙 `신용보강` — 법정 손실보전 기관까지 층으로 | `bond_issuer_background.md` |
| 담보·업종 축 | 보류 (프리즈 전 범위 밖) | 코드북 오류 3건 |

2차 전환(08-24~25)에서 yaml 을 전면 재작성했다. 종목명 정규식 4종(사모·FRN·할인채·듀레이션0)을 버리고 전용 컬럼(`bd_ofr_tcd`·`bd_inrt_tcd`·`bd_intp_tcd`)을 읽는다. 무효화된 1차 판정은 항목마다 "1차:" 로 남겨 추적되게 했다.

### 4.2 결함 → 선언 (04 §B.2 압축)

**B.2-1. 신용등급의 서열이 데이터에 없다 → 표준표 코드북 + rank·밴드 노드 + `skos:broader` closure (1층) + 규칙 `등급서열` (2층) + 서열 확장 가드 (3층)**
`crd_grd` 는 문자열 15종이고 사용자의 `AA` 는 DB 에 `AA0` 다. 1층: 코드북 rank → 노드 20 + 밴드 2 = 22, `AA0` 는 alias. 2층: 규칙 `등급서열`·`등급정규화` — "이상·이하면 `TRIM(crd_grd) IN (서열 목록)`, `=` 단일 등급은 오답". 3층: 가드 `expand_grade_comparison` 이 SQL 의 `=` 나 불완전 `IN` 을 통째로 교체. 안 지키면 — 08-31 실측 "A등급 이상" 이 `crd_grd='A-'` 로 나가 599종목 중 49행만 조회.

**B.2-2. 위험등급 `'00'` 19행이 실재하고 6등급이 40.8% → 채권만 범위 0~6, ttl 제약과 게이트 상수를 한 선언에서 생성 (3층)**
`pd_risk_gcd` 는 `'11'~'16'` + `'00'`, 숫자 클수록 안전. 펀드는 등급 없는 클래스가 NULL 이라 0 이 아니다. `shared/risk_grade.yaml` `range_by_table` 에 `domestic_bonds: {min: 0, max: 6}` 한 줄 → 빌드가 `bond_kr.ttl` 의 `xsd:minInclusive 0 · maxInclusive 6` 과 게이트 범위 상수를 함께 생성. "7등급" 은 HCX 0회 기각, "0등급" 은 통과. 공용 상수 `1~6` 을 코드에 두던 시절의 KG-013/014 사고가 계기.

**B.2-3. 발행국·통화가 상수다 → `hasRegion` ABSENT + 규칙 `외화채없음` — "해외·외화 채권" 은 없다고 답한다 (3층 + 2층)**
`pd_ctry_cd` 21,881/21,882 = KR, `curr_cd` 21,881 = KRW. `kg_entity: null` 판정 → ttl `hasRegion` ABSENT(3층). Currency 는 KRW 하나만 alias, 규칙 `외화채없음` 이 `curr_cd='KRW'` 를 기본 조건으로(2층). 값 사전만으로는 부족했다 — 09-03 실측에서 HCX 가 실재하는 오염값 `'000'` 을 골라 BAC 1행을 "1종목" 으로 답함 → `gate_constants curr_cd` 어휘 게이트 + `forbidden_literal_use` 추가.

**B.2-4. "위험한 채권" 이 데이터 안에서 세 축으로 갈리고 둘은 정반대다 → `clarify.다의어.위험` 기본값 금지 + 결정층 되묻기 `risk_ambiguity_clarify` (2층 + 결정층)**
① 투자위험등급(1등급 1,394종목) ② 신용등급(C0 103종목) ③ 금리위험(듀레이션 — 국공채 장기물이 최고). ②③ 은 정반대. yaml `clarify` 만으로는 되묻기가 재현되지 않아 결정층 가드로 옮겼다 — 축 단서 없으면 HCX 호출 전에 되묻고, 축별 규모는 DB 실측으로 채운다. 안 지키면 — 09-02 실측 신보 유동화 후순위 5종목(728.524%) 단정.

**B.2-5. "판매 가능" 의 정의가 데이터에 없다 → `buyable_quantity` 무효, 구매가능 = `curr_cd='KRW' AND mat_dt >= 20260824`, 판정 기준일 8/24 를 답변에 병기 (2층 + 가드)**
`buyable_quantity` 는 주최 공지(8/24)로 무효. 판매 조건 있는 행은 634행뿐이라 그것으로 읽으면 97.1% 가 사라진다. 만기 미경과만 남는데 as-of 8/22(토)와 결제 가능일 8/24(월)이 다르다 — 8/22·8/23 만기 14종목은 모수 밖, 8/24 당일 20종목은 모수(`>=`). 모수 21,814행 / 20,431종목. 기준일 상수는 `gate.BUYABLE_CUTOFF` 한 곳, 가드가 무따옴표 날짜(`2029-08-22` = 뺄셈 1999)를 교정한다.

**B.2-6 (보조). 할인채·영구채는 컬럼 의미가 다르다 → `couponRate` 주석 + 규칙 `이자유형분리`·`듀레이션정상` (2층)**
할인채 689행은 `srfc_irt` 가 발행 할인율. 영구채 266행/237종목은 `mat_dt` 가 콜 개시일. ttl `fp:couponRate` 주석에 명시하고, 규칙이 표면금리 정렬에서 유형을 분리하며, `answer_rules` 가 "만기일 = 콜 개시일" 을 병기한다.

## 6. 질의 → 답변 — 완성된 구조가 쓰이는 자리

### 6.1 공식 예시 #1 "현재 판매 가능한 원화채권 중 AA- 이상 종목" (`OFFICIAL-001` · 10 §4.1)

서버 실측 2026-09-03 r15 · **2.4초** · HCX 1회(SQL 생성만).

| 단계 | 이 질의에서 일어난 일 | 개입한 층 |
| :-- | :-- | :-- |
| Route | "채권" 머리명사 → `domestic_bonds` · 값 `['AA-']` | 라우팅 어휘 (kg_alias raw + `synonyms`) |
| Ground | `'AA-' → CG_AAm → crd_grd='AA-'` · `'원화' → Curr_KRW → curr_cd='KRW'` | **1층** CreditGrade·Currency alias |
| Gate | 등급 토큰 `AA-` = 표준표 `ok` → 통과 | **3층** 등급 표준표 4분기 |
| Plan | 근거문서 22,594자 = KG 매핑 + 규칙(`구매가능`·`등급서열`·`등급정규화`·`대표행`…) + 되묻기·답변불가 + 스키마 → SQL 생성 | **2층** `query_rules` · `clarify` |
| 가드 | 등급 서열 확장 — `crd_grd='AA-'` 를 `TRIM(crd_grd) IN ('AAA','AA+','AA0','AA-')` 로 | **3층** `expand_grade_comparison` |
| 검증 | SELECT 단일문 · 테이블 화이트리스트 · LIMIT · WHERE 리터럴을 값 사전과 대조 | **3층** 값 검사기 (1층 alias 가 검사표) |
| 실행·조립 | 30행 + 전체 15,792종목(`COUNT(DISTINCT pd_no)` 별도 집계) → 기계 조립, HCX 0회 | `answer_rules` · 조립기 |

```
SELECT DISTINCT pd_no, pd_nm, crd_grd FROM domestic_bonds
 WHERE TRIM(crd_grd) IN ('AAA','AA+','AA0','AA-') AND curr_cd = 'KRW' AND mat_dt >= 20260824 LIMIT 30
→ "조건에 해당하는 채권은 전체 15,792종목이며, 그중 30개는 다음과 같습니다 (기준일 2026-08-24)."
```

세 절이 각각 다른 곳에서 왔다: "AA- 이상" 은 코드북→KG rank(§3·§5), "원화" 는 Currency alias + 규칙 `외화채없음`(§4.2 B.2-3), "판매 가능" 은 규칙 `구매가능` 의 8/24 앵커(§4.2 B.2-5). 잔여 🟡: 정렬축 미표기 · 무등급 4,020행이 모수 밖이라는 고지 없음(04 §B.3-1).

### 6.2 되묻기 — "위험한 채권" 다의어 (04 §B.2-4)
