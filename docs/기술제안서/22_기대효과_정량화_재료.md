### 1-4. 운영 — 바꾸는 데 걸리는 시간

| 변경 유형 | 작업 | 반영 시간 |

> 서술 예: *"신용평가사가 등급 체계를 바꾸면 코드북 파일 한 장을 갈고 빌드 한 번이면 끝난다. 규제 문구는 코드가 아니라 `answer_rules` 에 있어 컴플라이언스 담당자가 직접 고칠 수 있다."*

## 2. 사업성 서술 뼈대 (3축 · 대상작의 정량화에 대응)

**축 1 — 비용 구조가 다르다.** 일반 RAG 는 모든 질의에 LLM 을 부르고 문서를 통째로 싣는다. 우리는 답변불가에 0회, 답변 가능에 2회, 근거문서는 58% 줄였다. 질의량이 늘수록 격차가 벌어진다.

**축 2 — 틀린 답의 비용을 줄인다.** 금융상품 답변의 오류는 불완전판매 리스크다. 우리는 값을 지어내지 않도록 세 층에서 막고(값 사전·규칙·게이트), 79건의 실제 오답을 회귀 문항으로 고정했다. 답변마다 모수와 기준일을 밝히는 것도 같은 이유다 — **설명의무의 기계화**.

**축 3 — 확장 비용이 낮다.** 공유 개체 11종은 상품군과 독립이라, 새 상품군은 yaml 하나와 코드북으로 붙는다. 실제로 채권·ETF·펀드 세 도메인이 같은 개체 위에 올라가 있고, 지수 하나(`Idx_MSCI_ACWI`)에 세 상품군이 동시에 매달린다.
