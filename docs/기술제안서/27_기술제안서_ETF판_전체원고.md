# 0. 요약 (1쪽)

## 0.1 한 문장

**온톨로지는 LLM 이 SQL 을 틀리지 않게 만드는 3층 장치다.**

우리는 생성 모델에게 "금융을 이해시키려" 하지 않았다. 이해는 검증할 수 없기 때문이다. 대신 질문이 들어온 그 시점에 **실재하는 값과 지켜야 할 규칙을 눈앞에 놓아 주고, 모델은 그것을 옮기게** 했다. 그리고 옮긴 결과를 **놓아 줄 때 쓴 것과 같은 사전으로** 검사했다. 사전에 없는 값이 SQL 에 있으면 그 SQL 은 실행되지 않는다.

3층은 다음과 같다.

| 층 | 무엇 | 실물 | ETF 실측 규모 |
| :-- | :-- | :-- | --: |
| **1층 값 사전** | 사용자의 표기 → 데이터의 실제 리터럴 | `kg_alias` · `kg_closure` | ETF 관련 별칭 **44,681행** |
| **2층 규칙 문서** | 이 컬럼은 이렇게 써야 한다 | `enums/*.yaml` `query_rules`·`answer_rules` | 국내 54+31 · 해외 27+25 |
| **3층 게이트** | 아예 못 하게 막는다 | `absent_properties` · `range_by_table` · 상수 컬럼 | ABSENT 선언 4건 (ETF) |

## 0.2 제출물 위치

| 제출 항목 | 위치 |
| :-- | :-- |
| 기술 제안서 | 이 문서 (PDF·워드) |
| API 엔드포인트 | `https://49.50.134.229.nip.io/answer` — 명세는 **부록 D** |
| 온톨로지 ttl 5분할 | `ontology/common.ttl` · `bond_kr.ttl` · `etf_kr.ttl` · `etf_gl.ttl` · `fund_pub.ttl` |
| 소스코드 | 저장소 전체 — `README.md` 에 환경 구성·실행 명령 |
| 평가 재현 | **부록 E** — 평가셋 187문항 · 실행 스크립트 |

## 0.3 이 제안서가 주장하는 것

세 문장으로 줄이면 이렇다.

1. **데이터의 라벨은 거짓말을 한다.** 국내 ETF 총보수 컬럼의 값 `0` 은 "수수료 없음"이 아니라 "입력하지 않음"이었다. 세어보고, 실제 상품을 열어보고, 판정했다.
2. **판정은 사람이 yaml 에만 적는다.** ttl 도 지식그래프도 손으로 쓰지 않는다. `scripts/build_ontology.py` 가 생성하고, **검증 7관문을 통과하지 못하면 산출물이 나오지 않는다.**
3. **말로 쓴 규칙은 확률적으로만 지켜진다.** 그래서 반드시 지켜야 하는 것은 프롬프트가 아니라 **코드 가드**로 넣었다.

# 01. 전체 아키텍처 및 특화기능 (3쪽)

## 1.1 전체 구조

시스템은 **오프라인 빌드**와 **런타임 응답** 둘로 나뉜다.

```
[오프라인 빌드]  마스터 4테이블 + 외부수집 4테이블 + 코드북
                        ↓  EDA — 세어보고 실물 확인
                 ontology/enums/*.yaml   (컬럼층 — 판정과 규칙)
                 ontology/shared/*.yaml  (개체층 — 공유 개체)
                        ↓  scripts/build_ontology.py
                 ┌─ 검증 V1~V7 ─ 하나라도 실패하면 산출 중단 ─┐
                        ↓
                 ttl 5분할 (제출)  +  KG 4테이블 (런타임이 읽음)

[런타임]  질문 → Normalize → Route → Ground → Gate → Plan → Guard → Execute → Answer → 답변
                                      ↑        ↑      ↑       ↑
                                     1층      3층    2층    1층+코드
```

LLM(HyperCLOVA X)을 부르는 것은 **Plan(SQL 생성)과 Answer(문장 작성) 두 곳뿐**이다. 나머지 여섯 단계는 전부 우리가 만든 사전·규칙·코드다. 이것이 환각을 구조적으로 줄이는 방식이다 — 모델이 개입할 수 있는 표면적 자체를 줄였다.

## 1.2 특화기능 셋

### ① yaml 단일 원천에서 ttl·KG 를 생성하고, 검증을 통과해야만 산출한다

온톨로지를 손으로 관리하면 반드시 실물과 어긋난다. 우리는 사람이 만지는 파일을 **yaml 하나로 고정**하고 나머지를 전부 생성물로 만들었다. 생성 과정에 관문 7개를 두어, 예컨대 **yaml 에 적은 값이 DB 에 실재하지 않으면(V1 "죽은 별칭") 빌드가 실패**한다. 온톨로지와 데이터가 어긋난 채로 배포되는 경로가 없다.

### ② 출처 축과 분류 축을 분리했다

국내 ETF 테이블에는 **ETN 545건**이, 해외 ETF 테이블에는 **ETN 65건**이 섞여 있다. "국내ETF 테이블 ⊂ ETF" 라고 두면 그 610건을 ETF 라고 단정하게 된다. 그래서 **테이블(데이터가 어디서 왔는가)** 과 **상품 종류(ETF 인가 ETN 인가)** 를 별개 축으로 세우고, `fp:ETF ⟂ fp:ETN` 을 서로소로 선언했다. 종류 판별은 컬럼(`pd_grp_no`·`cu_etn_yn`)이 맡는다.

이 결정 하나가 실제 오답을 막았다. "인버스 ETF 3개" 질의에서 인버스 조건에 걸리는 235건 중 **189건(80%)이 ETN** 이다.

### ③ 값을 놓아 주는 사전과 값을 검사하는 사전이 같다

Plan 단계에서 모델에게 보여 준 값 목록과, Guard 단계에서 생성된 SQL 을 대조하는 값 목록이 **동일한 `kg_alias`** 다. 그래서 "보여 주지 않은 값을 모델이 지어냈다"는 사고를 기계적으로 잡아낼 수 있다.

실제로 잡았다. 9월 4일 "삼성전자를 담은 ETF" 질의에서 모델이 `삼성전자우`·`삼성전자보통주` 등 **데이터에 없는 표기 17종을 창작**해 `IN` 절에 넣었다. 결과가 259건으로 부풀었다(정답 239건). 사전에 없는 리터럴이므로 가드가 기각하고, 이후 grounding 문서에 **"주어진 값 외의 표기를 만들지 말 것"** 을 명시적 금지로 넣었다.

## 1.3 주최 필수 구성요소 대응

| 요구 | 우리 구현 | ETF 실물 |
| :-- | :-- | :-- |
| 온톨로지 설계 | 클래스·속성·부재를 ttl 로 선언, yaml 단일 원천 생성 | `etf_kr.ttl` 34줄 · `etf_gl.ttl` 21줄 · 공통부 `common.ttl` 58,971줄 |
| 지식그래프 구축 | 노드 11종·별칭·계층·관계를 DB 테이블로 | 노드 41,581 · 별칭 66,592 · 계층 9,966 · 관계 7,414 |
| 검색·질의응답 | 값 접지 → 게이트 → SQL 생성 → 값 검사 → 조립 | 8단계 파이프라인, LLM 2회 |
| 답변 불가 처리 | 부재를 지식으로 선언, **LLM 호출 0회**로 기각 | "위험등급 낮은 해외 ETF" → 컬럼 부재로 즉시 안내 |

### 용어

- **값 접지(grounding)** — 사용자가 쓴 표기를 데이터의 실제 리터럴로 바꾸는 것. "코덱스" → `KODEX`.
- **부재 선언(ABSENT)** — 데이터에 없는 속성을 "없다"고 명시적으로 기록하는 것. 없는 것을 없다고 말하는 데 생성 모델은 필요 없다.
- **기준일** — 데이터 스냅샷 시점 2026-08-22, 판정 기준일 2026-08-24. 이보다 뒤의 기준일을 가진 외부 자료는 규정 위반으로 빌드가 거부한다(V4).
- **코드 가드** — 프롬프트가 아니라 파이썬 코드로 강제하는 규칙. 확률이 아니라 항상 적용된다.

# 02. 제안 방법

## 2.1 특화 데이터 수집·정제 (3쪽)

### 2.1.1 무엇을 어디서 가져왔는가

| 층 | 대상 | 행 | 기준일 |
| :-- | :-- | --: | :-- |
| L1 마스터 (주최 제공) | `domestic_etfs` (컬럼 98) | 1,780 | 2026-08-22 |
| | `overseas_etfs` (컬럼 49) | 6,037 | 2026-08-22 |
| L2 외부 수집 | `ext_etf_holdings` — KRX 공시 | 75,859 | 2026-08-21 |
| | `ext_ovs_etf_holdings` — 미국 SEC NPORT-P | 906,848 | 2025-10-31 ~ 2026-06-30 (8종) |
| L3 코드북 | 지수 마스터·ETN 발행사·자산군 매핑 등 | csv 27종 | 전부 ≤ 2026-08-24 |

**외부 수집을 한 이유는 명확하다.** 두 ETF 마스터 어디에도 "이 ETF 가 무엇을 담고 있는가"가 없는데, **주최 공식 예시 5문항 중 3문항이 구성종목을 묻는다.** 마스터만으로는 대회 과제 자체를 풀 수 없었다.

수집물은 마스터를 덮어쓰지 않는다. `ext_` 접두 테이블에 따로 적재하고, 조인 계약(`external_join`)을 yaml 에 선언해 둔다. 원천을 훼손하지 않는다는 원칙이다.

### 2.1.2 판정 방법론 — 컬럼 하나를 판정하는 네 걸음

이 절이 우리 데이터 작업의 핵심이다. yaml 에 적힌 판정은 **하나도 짐작이 아니다.** 전부 다음 네 걸음을 거쳤다.

> **① 센다 → ② 이상한 분포를 발견한다 → ③ 실물을 확인한다 → ④ 판정을 문장으로 적는다**

총보수(`cu_charge_rt`)를 예로 든다.

| 걸음 | 실제로 한 일 | 결과 |
| :-: | :-- | :-- |
| ① 센다 | `GROUP BY` 로 값 분포를 뽑았다 | 유효 67 · `0` 150 · `NULL` 1,018 |
| ② 이상하다 | ETF 1,235건 중 **5.4%만 보수가 있다?** 상장 ETF 에 보수가 없을 리 없다 | 가설: `0` 은 무료가 아니다 |
| ③ **실물 확인** | `0` 인 상품 몇 개를 골라 **투자설명서를 직접 열었다** | 보수가 **적혀 있었다** |
| ④ 판정 | "`0` 은 미입력이다. 유효값은 `> 0` 뿐" | `query_rules.보수유효` 로 등재 |

**세 번째 걸음이 이 방법론의 요체다.** 숫자만 보면 "0이 많네"에서 끝난다. 실제 상품을 열어봐야 그 `0` 의 **뜻**을 알 수 있다. 이 과정을 국내 62컬럼·해외 37컬럼에 대해 반복했고(마스터 컬럼 98·49 중 질의에 쓰이는 것), 기록은 `docs/eda/` 에 남아 있다.

### 2.1.3 정제 원칙 — 값을 고치지 않고 의미를 선언한다

우리는 데이터를 **한 셀도 수정하지 않았다.** 결측을 채우지도, 이상값을 교정하지도 않았다. 대신 "이 값이 무슨 뜻인지"를 선언했다. 원천이 갱신되면 판정만 다시 확인하면 되고, 우리가 만든 왜곡이 데이터에 섞이지 않는다.

ETF 에서 선언한 유형은 다음과 같다.

| 유형 | 실측 | 선언 자리 |
| :-- | :-- | :-- |
| **0 이 결측** — 총보수 | 국내 `0` 150 · `NULL` 1,018 → 유효 67(5.4%) | `normalization.zero_as_missing` + `query_rules.보수유효` |
| **부호 소실** — 레버리지 배수 | 상품명에 '인버스' 235건 중 배수가 음수인 것 **23건뿐** | `derivation_rules.inverse_direction` — 방향은 이름, 크기는 절대값 |
| **상품군 혼입** — ETN | 국내 545 · 해외 65 | 축 분리 + `pd_grp_no='ETF'` 상시 규칙 |
| **원천 이원화** — 4축 이중 컬럼 | 운용사·기초지수·투자지역·자산군이 사내 등록분과 Refinitiv 로 두 벌 | 축마다 정본 컬럼 지정 |
| **원천 오분류** — 투자지역 | 미국 투자 ETF 가 한 컬럼만 보면 466건, 두 컬럼 합집합이면 **494건** | 합집합 규칙 (복구 28건) |
| **상수 컬럼** | 국내 `pd_curr_cd` 값 1종 | 게이트 — "외화 ETF" 질의를 생성 전 기각 |
| **표준과 실측의 불일치** | 주최 예시는 위험등급 1~5, 국내 ETF 실측은 **1~6** (6등급 21건 실재) | `range_by_table` — 테이블마다 범위를 따로 |

마지막 항목을 짚어 둔다. 주최 제공 예시대로 1~5 로 제약했다면 **실재하는 21건이 영구히 차단**됐을 것이다. 표준 문서보다 실측을 우선하되, 표준에만 있고 이번 적재분에 없는 값은 오류가 아니라 **보류(V1p)** 로 따로 표시한다.

### 2.1.4 신뢰성 관리와 한계

**커버리지를 답변에 밝힌다.** 국내 구성종목은 ETF 1,235건 중 1,160건(93.9%)을 수집했다. 해외는 5,972건 중 **1,356건(22.7%)** 뿐이다. 순자산이 큰 상품 위주이고, 보고 기준일도 8종류로 흩어져 **최대 8개월 시차**가 난다.

이 한계는 우리가 없앨 수 없다 — 미국 SEC 의 분기 공시라는 원천 자체의 성질이다. 우리가 할 수 있는 것은 **답변에 모수와 `report_date` 를 반드시 병기**하는 것까지이고, 그것을 `answer_rules` 로 강제했다.

**고칠 수 없는 오분류도 있다.** 투자지역은 두 컬럼의 합집합으로 43건을 복구했지만, `TIGER 중국소비테마` 처럼 **두 컬럼이 모두 틀린** 경우는 컬럼으로 복구할 방법이 없다. 값을 직접 고치지 않는다는 원칙의 비용이고, 전수조사 기록으로 남겼다.

## 2.2 온톨로지 엔지니어링 (12쪽) — 이 제안서의 본체

### 2.2.1 설계 원칙 — LLM 이 테이블을 조회할 때 벌어지는 네 가지 간극

온톨로지가 왜 필요한지는 "LLM 이 무엇을 틀리는가"에서 출발해야 한다. 우리가 실측으로 겪은 간극은 넷이다.

| # | 간극 | ETF 실제 사고 | 메우는 층 |
| :-: | :-- | :-- | :-- |
| ① | **어디를 볼지 모른다** — 어휘 → 테이블·컬럼 | "수수료"가 `cu_charge_rt` 인지 모름 | 1층 (컬럼 매핑) |
| ② | **무슨 값인지 모른다** — 어휘 → 실재 리터럴 | 데이터에 없는 `삼성전자우` 등 **17종을 창작** | 1층 (값 사전) |
| ③ | **데이터 관행을 모른다** — 0·단위·서열·기준일 | 총보수 `0` 을 "가장 저렴"으로 정렬 | 2층 (규칙 문서) |
| ④ | **없는 걸 없다고 못 한다** | 해외 위험등급 컬럼이 없는데 지어냄 | 3층 (게이트) |

여기서 우리 철학이 나온다. **"모델은 복사만 하게 하라."** 추측이나 기억이 아니라, 질문 시점에 실재하는 값과 규칙을 놓아 주고 옮기게 한다. 그리고 옮긴 결과를 같은 사전으로 검사한다.

이어지는 다섯 규율이 데이터를 다루는 방식을 정한다.

1. **값을 고치지 않고 의미를 선언한다** (§2.1.3)
2. **부재도 지식이다** — "없다"는 것을 기록해야 답할 수 있다
3. **출처 축 ≠ 분류 축** — 테이블과 상품 종류를 섞지 않는다
4. **선언과 실행은 한 원천에서** — yaml 하나에서 ttl 과 KG 가 함께 나온다
5. **그래프를 걷지 않는다** — 탐색은 빌드 시점에 끝내고, 런타임은 조회만 한다

다섯 번째는 응답 시간 예산(12초) 때문이다. 계층 전개를 런타임에 재귀로 풀면 예산을 넘긴다. 그래서 **`kg_closure` 9,966행에 미리 펼쳐 두고** 런타임은 한 번 읽는다.

### 2.2.2 yaml 단일 원천의 구조 — 두 층

사람이 손대는 파일은 yaml 뿐이다. 그 yaml 이 두 층으로 나뉜다.

#### 컬럼층 — `ontology/enums/<도메인>.yaml`

도메인 하나가 파일 하나다. `domestic_etfs.yaml` 은 최상위 키 15개로 이루어진다.

| 키 | 국내 ETF | 해외 ETF | 무엇을 적는가 |
| :-- | --: | --: | :-- |

| `answer_rules` | **31** | 25 | 답변에 반드시 밝혀야 할 것 |
| `synonyms` | 62 | 35 | 코덱스→KODEX, 월배당→매월분배 |
| `product_group` | 4 | — | ETF ⟂ ETN 축 |
| `normalization` | 3 | 3 | 공백 처리·0을 결측으로 볼 컬럼 |
| `derivation_rules` | 2 | 2 | 컬럼을 만들지 않고 규칙으로 유도 |
| `absent_properties` | 2 | 2 | **없는 것 선언** |
| `axis_derivation` | 2 | — | 축 유도 |

**규칙 하나는 조건식만 적지 않는다.** 네 요소를 함께 적는 것이 우리 형식이다.

```yaml
보수유효:
  조건: cu_charge_rt > 0 AND pd_grp_no = 'ETF'
  근거: 0·NULL 1,168행이 상위를 도배 (2026-08-31 실측)
  적용범위: 정렬·필터·Top-N 에만. 보수를 묻지 않은 질의에는 걸지 않는다
  반례: 9/2 개수 질의에 붙어 삼성자산운용 227개 → 18개로 학살
```

**조건만 적으면 절반만 맞는다는 것을 우리는 사고로 배웠다.** 이 규칙은 두 방향으로 실패했다. 8/31 에는 규칙이 없어 미입력 행이 "가장 저렴"을 도배했고, 9/2 에는 반대로 **과잉 적용**되어 보수를 묻지도 않은 개수 질의의 모수를 파괴했다. 그래서 `적용범위`와 `반례`를 규칙의 필수 요소로 만들었다.

#### 개체층 — `ontology/shared/*.yaml`

도메인을 가로지르는 개체다. 삼성전자는 ETF 에도 펀드에도 나오고, MSCI ACWI 지수는 국내 ETF·해외 ETF·공모펀드에 모두 걸린다. 이것을 도메인마다 따로 두면 온톨로지가 셋이 된다.

### 2.2.3 데이터의 비대칭에서 시작한다 — 그림 B-2

ETF 도메인은 테이블이 둘이다. 같은 상품군이니 같은 온톨로지를 쓰면 될 것 같지만, 두 데이터의 사정이 꽤 다르다.

국내에는 위험등급(`pd_risk_nm`)이 있는데 **해외에는 그 컬럼 자체가 없다.** 반대로 총보수는 해외가 6,037건 중 5,618건(93%) 유효한데 국내는 ETF 1,235건 중 **67건(5.4%)** 뿐이다. 국내는 네 축이 **컬럼 두 개에 이중으로** 들어 있는데 해외는 그 이중화가 없다.

**이 비대칭을 뭉개지 않고 그대로 드러내는 것**이 ETF 절의 설계 원칙이다.

*(그림 B-2 삽입: 국내·해외를 좌우 대칭으로, 가운데에 공유 개체. 이중선은 원천 이원화, 점선 ⊘ 는 부재 선언.)*

| 연결 | 국내 컬럼 (값 수) | 해외 컬럼 (값 수) | 비고 |
| :-- | :-- | :-- | :-- |
| Organization | `cu_fund_mgmt_co` 99 / `ref_fund_mgmt_co` 29 | `cu_fund_mgmt_co` 382 | 운용사. 구상호·후계 슬롯 |
| Index | `ref_base_index` 904 / `cu_base_index` 19 | `cu_base_index` 1,848 | TR·CR·NR 변형 → 정본 |
| Region | `wu_inv_rgn` 11 / `ref_geo_focus` 23 | `wu_inv_rgn` 59 | 한글·영문 이원화 |
| AssetClass | `wu_inv_ast_type` 9 / `ref_ast_type` 7 | `wu_inv_ast_type` 6 | |
| RiskGrade | `pd_risk_cd`·`pd_risk_nm` 6종 (**1~6등급**) | **⊘ 컬럼 없음** | 아래 ② |
| Currency | `pd_curr_cd` 1 | `pd_trd_ccy` 1 | 상수 게이트 |
| Security | `ext_etf_holdings` 경유 | `ext_ovs_etf_holdings` 경유 | 외부 수집 |
| CreditGrade | **⊘** | **⊘** | ETF 는 발행사 신용등급을 갖지 않는다 |

이중선의 네 축이 국내에만 있는 **원천 이원화**다. 어느 쪽이 정본인지는 축마다 다르다 — 운용사는 `ref_fund_mgmt_co` 가 정본이고, 기초지수는 `ref_base_index` 를 우선하되 비면 `cu_base_index` 로 떨어진다.

### 2.2.4 결함에서 선언으로 — 여섯 건

여섯 건 모두 같은 구조다. **데이터가 이렇게 생겨서(결함) → 이렇게 선언했고(층) → 실행 중 어느 단계가 그 선언을 읽으며(런타임) → 실제로 이런 사고를 막았다(실측).**

#### ① ETN 혼입 — 축 분리와 서로소 선언 (2층)

ETN 은 자산운용사가 만드는 펀드가 아니라 증권사가 발행하는 채무증권이라 성격이 다르다. 총보수 개념이 없어 국내 ETN 545건은 `cu_charge_rt` 가 전건 NULL 이다. `ETF만: pd_grp_no = 'ETF'` 규칙을 상시 주입한다.

**실측** — 8/31, 규칙이 없던 상태에서 "인버스 ETF 3개"의 1위로 `KB 블룸버그 인버스2X 천연가스선물 ETN` 이 나갔다. 규칙 도입 후 ETF 46건만 응답한다.

#### ② 해외 위험등급 부재 — 없다는 것을 선언한다 (3층)

해외 테이블에는 위험등급 컬럼이 없다. 이때 두 가지 잘못이 가능하다. 다른 컬럼으로 대충 답하거나, 있는 것처럼 지어내는 것이다.

우리는 **`ABSENT` 로 부재 자체를 선언**했다. `etf_gl.ttl` 에 이렇게 나간다.

```turtle
# ABSENT: fp:OverseasETF 에는 fp:hasRiskGrade 없음 — 위험등급 컬럼 자체 없음
#         → '위험등급 낮은 해외ETF' 질의는 HCX 호출 0회로 기각
```

"위험등급 낮은 해외 ETF" 가 들어오면 게이트가 **LLM 을 한 번도 부르지 않고** 기각하고, 대신 자산군·레버리지 여부로 답할 수 있다고 안내한다. 없는 것을 없다고 말하는 데 생성 모델이 필요하지 않다.

#### ③ 총보수 0 은 무료가 아니라 미입력 (2층)

§2.1.2 의 네 걸음으로 판정한 사례다. 규칙과 그 실패·수정 경위는 §2.2.2 에 적었다.

#### ④ 레버리지 부호가 90% 소실됐다 (2층)

인버스 상품은 배수가 음수여야 하는데, 상품명에 '인버스'가 든 235건 중 **배수가 음수인 것은 23건뿐**이다. 부호만 믿으면 90% 를 놓친다.

그래서 방향은 **이름으로**, 배수는 **절대값으로** 판정한다고 선언했다(`derivation_rules.inverse_direction`). 컬럼을 새로 만들지 않고 규칙으로 유도한다.

**해외도 같은 모양이다.** 9/1 실측에서 인버스 플래그만 건 조건이 진짜 인버스 8건(QBER·SNK·METQ 등)을 놓쳤다. 플래그·배수·이름의 합집합으로 확정했다. 덧붙여 해외 `cu_inverse_short_yn` 의 실제 값은 `'Y'` 183건과 NULL 5,854건뿐이고 **`'N'` 은 0건**이다 — `= 'N'` 조건은 항상 0행이므로 쓰지 못하게 규칙에 적었다.

#### ⑤ 지수 표기가 흩어진다 — 독립 개체로 (1층)

같은 지수가 `KOSPI 200`, `KOSPI200 TR`, `코스피200` 처럼 여러 표기로 나타난다. 문자열로 맞추면 끝이 없다. **`fp:Index` 를 독립 개체로 세우고**(노드 3,172개) 변형 표기를 그 개체의 별칭으로 모았다. TR·CR·NR 접미어는 계층으로 정본에 연결한다.

이 선언이 ETF 절을 넘어선다. `Idx_MSCI_ACWI` 하나에 국내 ETF·해외 ETF·공모펀드가 함께 걸린다 — **온톨로지가 도메인마다 따로가 아니라 하나라는 증거**다.

#### ⑥ 구성종목이 마스터에 없다 — 외부 수집과 Security 노드 (1층)

수집 경위는 §2.1.1 에 적었다. 온톨로지 쪽 결정은 **종목을 `Security` 개체로 세운 것**이다(노드 27,996개, 전체의 67%). 티커·ISIN·구성종목명 등 여러 표기를 한 노드로 모은다.

키에는 우선순위를 뒀다 — **티커 > ISIN > 이름**. 그리고 **이름만 같으면 병합하지 않는다.** 삼성전자와 삼성전기가 한 노드가 되면 안 되기 때문이다.

**실측** — 공식 예시 "캠브리콘이 편입된 중국 반도체 ETF" 에서 접지 단계가 표기 6종(`688256 C1`·`Cambricon`·ISIN·구성종목명 2종 등)을 한 노드로 내려준다. 이름 하나로 찾았다면 못 찾았을 질의다.

**여기서 뺀 것도 있다.** 종목 별칭에 CUSIP·LEI 같은 **불투명 식별자 17,362행(전체 별칭의 26%)** 이 들어 있었는데, 실측 결과 CUSIP 로만 잡히는 ETF 는 0건이고 이름으로만 잡히는 ETF 가 47건이었다. **재현율이 엄격히 낮으면서** 프롬프트에 실려 모델의 표기 창작을 유발하고 있었다. 값 사전에서 제외했다. 온톨로지는 크게 만드는 것이 목적이 아니다.

| V7 | 별칭을 확장하려는 대상 노드가 없음 | 확장이 유실된다 |

**V1 이 이 구조의 핵심이다.** 온톨로지를 손으로 관리하는 팀은 yaml 과 데이터가 어긋나도 알 수 없다. 우리는 매 빌드마다 **적어 놓은 값이 실재하는지 DB 와 대조**하고, 하나라도 어긋나면 ttl 과 KG 를 만들지 않는다. 즉 **온톨로지가 실물과 어긋난 채 배포되는 경로가 없다.**

## 2.3 검색 방법론 (3쪽)

### 2.3.1 왜 SQL 생성인가

주어진 데이터는 관계형 마스터 4테이블이다. "삼성전자를 담은 ETF 중 순자산 큰 것"의 답은 **조건 조립 한 문장**이지 유사도 검색이 아니다. 정확한 개수·정렬·집계를 요구하는 질문에 근사 검색은 구조적으로 틀린 도구다.

**벡터 DB 를 쓰지 않았다.** 임베딩 유사도는 "삼성전자"와 "삼성전기"를 가깝다고 말한다. 금융 상품 질의에서 그 근접성은 이득이 아니라 **오답 경로**다. 마찬가지로 그래프 탐색을 런타임에 하지 않았다 — 12초 예산 안에서 재귀 전개를 감당할 수 없고, 미리 펼쳐 두면 되기 때문이다(`kg_closure`).

### 2.3.2 온톨로지가 개입하는 네 지점

```
질문 → Normalize → [Route] → [Ground] → [Gate] → [Plan] → [Guard] → Execute → [Answer]
                       ①         ①          ②        ③        ④         ④
```

#### ① Route / Ground — 값 접지 (1층)

어느 테이블을 볼지 정하고, 질문 속 표기를 **데이터의 실제 리터럴**로 바꾼다. `kg_alias` 66,592행을 조회하고, 필요하면 `kg_closure`·`kg_edge` 로 확장한다.

- **계층 전개** — "아시아" → 국가 노드들로
- **자회사 전개** — "에코프로 자회사" → `subsidiaryOf` 로 계열사 전개
- **대상 테이블에 별칭이 없는 노드는 폐기** — 국내 ETF 질의에 해외 테이블 값을 내려보내지 않는다

마지막 항목은 사고에서 나왔다. 9/4 "삼성전자 담은 ETF vs 펀드" 교차질의에서 grounding 문서가 관련 없는 `ext_ovs_etf_holdings` 값을 먼저 나열해, 모델이 잘못된 테이블로 SQL 을 두 번 연속 만들었다. **짝이 맞는 외부 테이블만 내려보내도록** 코드를 고쳤다.

#### ② Gate — 생성 전 기각 (3층)

여기서 걸리면 **LLM 을 한 번도 부르지 않는다.** 네 종류를 검사한다.

| 검사 | ETF 예시 |
| :-- | :-- |
| 부재 속성 | "위험등급 낮은 해외 ETF" → 컬럼 부재 |
| 값 범위 | 위험등급 7등급 요청 → 국내 ETF 는 1~6 |
| 상수 컬럼 | "외화로 거래되는 국내 ETF" → `pd_curr_cd` 값 1종 |
| 개체 미발견 | 존재하지 않는 상품명 → 유사어 억지 매칭 금지, 되묻기 |

#### ③ Plan — 규칙 주입 (2층)

`build_grounding()` 이 프롬프트를 조립한다. 순서와 원칙이 정해져 있다.

1. **개체 매핑** — DB 에 실재하는 값만, 컬럼당 60개 이내
2. **조인키** — `ext_` 테이블은 마스터와 컬럼명이 다르다(`etf_code`, `pd_itm_no` 아님). 별칭 한정으로 모호성 제거
3. **규칙 2층** — 상시 규칙 + 질문에 걸리는 조건부 규칙만 선별 주입
4. **금지 사항** — **주어진 값 외의 표기를 만들지 말 것**

규칙을 전부 주입하지 않고 **조건부(triggered)로 선별**하는 이유는 프롬프트 크기다. 규칙이 54+31 개까지 늘어난 상태에서 전부 실으면 모델이 정작 중요한 것을 놓친다. 회귀 테스트가 **"ETF 알려줘" 같은 일반 질의의 프롬프트를 7,000자 이하로** 강제한다(현재 6,719자).

#### ④ Guard / Answer — 값 검사와 조립 (1층 + 코드)

생성된 SQL 을 **주입할 때 쓴 것과 같은 사전으로** 검사한다. 사전에 없는 리터럴, 선언되지 않은 컬럼, 다른 도메인의 테이블이 들어 있으면 해당 조건을 제거하거나 기각한다. 그 뒤 답변 단계에서 `answer_rules` 가 모수·기준일·단위 병기를 강제하고, **조회하지 않은 컬럼을 설명하지 못하게** 막는다.

**여기서 얻은 교훈 하나를 명시한다.** "보수를 묻지 않았으면 걸지 마라"는 굵은 경고가 규칙 본문에 있는데도 같은 실수가 **세 번** 재발했다. 그래서 반드시 지켜야 하는 셋 — 운용사 컬럼 정본화, 교차질의 테이블 짝 검사, 값 목록 창작 금지 — 은 규칙이 아니라 **코드 가드**로 옮겼다.

이때 배운 것이 하나 더 있다. **절반만 고친 가드는 안 고친 것보다 나쁘다.** 운용사 정본화 가드가 처음에는 `SELECT` 절만 고치고 `GROUP BY` 를 놓쳤는데, SQLite 는 이를 오류 없이 실행한다. 그래서 **틀린 답이 더 그럴듯해 보이는** 상태가 됐다(그룹 84개 vs 정답 28개). 지금은 `GROUP BY`·`ORDER BY`·`HAVING` 까지 함께 고친다.

### 2.3.3 교차질의와, 하지 않은 것

**조인키는 계약으로 고정했다.** ETF ↔ 구성종목은 국내 `pd_itm_no ↔ etf_code`, 해외는 `pd_itm_no` 에서 `.K`·`.O` 접미어를 제거한 티커로 잇는다. ISIN 조인은 커버리지 부족으로 폐기했다.

**하지 않은 것을 밝힌다.**

- **0행이 나와도 재시도하지 않는다.** 조건을 풀어 다시 던지면 "없다"가 "있다"로 바뀐다. 대신 **왜 0행인지 조건별로 진단**해 답변에 넣는다.
- **LIKE 완화를 하지 않는다.** 정확 일치가 0건이면 유사 후보를 제시하고 **되묻는다.**
- **타사 LLM 을 쓰지 않았다.** 필수 2구간(Plan·Answer) 모두 HyperCLOVA X 다.

# 04. 주요 기능 흐름도 (3쪽)

## 4.1 값 접지가 필요한 질의 — "에코프로 자회사가 편입된 ETF 중 순자산 큰 것"

| 단계 | 하는 일 | 근거 |
| :-- | :-- | :-- |
| Route | 국내 ETF + 구성종목으로 판정 | 어휘 사전 |
| **Ground** | "에코프로" → Organization 노드 → `subsidiaryOf` 전개 → 계열사 → 각 계열사의 Security 별칭 | `kg_edge` · `kg_alias` |
| Gate | 부재·범위 위반 없음 → 통과 | |
| Plan | 조인 계약 + `pd_grp_no='ETF'` + 순자산 단위 규칙 주입 | `query_rules` |
| Guard | 접지된 종목명 외 리터럴 없음 확인 | `kg_alias` |
| Answer | 모수·기준일 병기 | `answer_rules` |

**요점** — 사람이 3-hop(회사→자회사→종목→ETF)으로 느끼는 질문이, 값 접지 덕분에 **JOIN 한 번**으로 풀린다.

## 4.2 데이터 관행이 필요한 질의 — "총보수가 가장 낮은 국내 ETF"

접지할 개체가 없는 대신 **2층 규칙이 결정적**이다. `보수유효: cu_charge_rt > 0 AND pd_grp_no='ETF'` 가 없으면 미입력 1,168행이 상위를 도배한다. 답변에는 **"유효 모수 67건 기준"** 을 반드시 밝힌다 — 1,235건 중 67건이라는 사실을 숨기면 그 자체가 오답이다.

## 4.3 외부 수집이 개입하는 질의 — "캠브리콘이 편입된 중국 반도체 ETF"

주최 공식 예시다. 마스터에 구성종목이 없으므로 `ext_ovs_etf_holdings` 를 경유한다. 접지 단계가 표기 6종을 한 Security 노드로 모으고, 답변에는 **커버리지 22.7% 와 `report_date`** 를 병기한다.

## 4.4 답변 불가 — LLM 호출 0회로 끝나는 세 경로

| 질의 | 어디서 걸리나 | 응답 |
| :-- | :-- | :-- |
| "위험등급 낮은 **해외** ETF" | Gate — `ABSENT` (컬럼 부재) | 없음을 밝히고 자산군·레버리지 대안 제시 |
| "외화로 거래되는 국내 ETF" | Gate — 상수 컬럼 | 해당 축이 성립하지 않음을 설명 |
| "KODEX AI로봇 ETF 정보" | Ground — 정확 일치 0 | 유사 후보 제시 후 **되묻기** |

세 경로 모두 `think_trace` 에 근거가 남는다. **없는 것을 없다고 말하는 데 생성 모델을 쓰지 않는다**는 원칙의 실행이다.

# 05. 기대효과·확장성 (2쪽)

## 5.1 효과

**환각 경로를 구조적으로 좁혔다.** LLM 개입 지점이 8단계 중 2곳뿐이고, 그 2곳의 출력조차 값 사전으로 검사된다. 답변 불가 질의는 LLM 을 **0회** 호출하고 끝난다.

**규칙은 실측할 때마다 자란다.** 9월 4일 하루에만 실제 서버에 14문항을 던져 결함 12건을 찾고 규칙 12건을 더했다. 국내 ETF 규칙은 44→**54**, 해외는 23→**27** 이 됐다.

**회귀를 담장으로 막는다.** ETF 평가셋은 국내 36문항(사람 검증 31)·해외 28문항(사람 검증 27)이고, 전체 187문항·사람 검증 128건이다. 규칙을 고칠 때마다 전량을 다시 돌린다.

## 5.2 확장성

**yaml 파일 하나 = 도메인 하나.** 이 구조는 ETF 에서 설계했지만 실증이 이미 있다 — 같은 방식으로 국내채권(`query_rules` 41 · `answer_rules` 21)과 공모펀드(34 · 31)가 붙었다. 코드를 고치지 않고 yaml 을 추가해 도메인이 늘었다.

**공유 개체는 늘수록 이득이다.** `Idx_MSCI_ACWI` 하나에 국내 ETF·해외 ETF·공모펀드가 걸린다. 도메인이 늘어도 개체층은 다시 만들지 않고 별칭만 붙는다.

**현업 적용 지점.** 운용사 상호 변경은 `organization.yaml` 의 `formerName`/`successor` 슬롯에 한 줄을 더하면 되고, 지수가 개편되면 `index.yaml` 정본 규칙만 고치면 된다. 어느 경우든 **코드 배포 없이 빌드 한 번**이다.

## 5.3 한계 — 솔직하게

1. **해외 구성종목 커버리지 22.7%.** 원천(미국 SEC 분기 공시)의 한계이고, 답변에 모수·기준일을 밝히는 것까지가 우리 몫이다.
2. **지역 오분류 잔존.** 두 컬럼이 모두 틀린 경우는 복구 불가. 값을 고치지 않는다는 원칙의 비용이다.
3. **"레버리지"의 경계 미확정.** 배수 절대값 > 1 로 잡으면 324건인데 그중 **117건이 인버스**다. 업무 정의가 필요한 사안이라, 빼는 대신 **"인버스가 섞여 있다"고 답변에 밝히는** 방식으로 운용한다. 살 수 없는 것은 제외하고, 살 수는 있는데 위험한 것은 알린다.
4. **말로 쓴 규칙의 확률적 준수.** 코드 가드로 옮길 수 있는 것부터 옮기는 중이고, 아직 전부는 아니다.

값 범위 선언도 함께 나간다 — `fp:DomesticETF` 의 `riskGradeValue` 는 **1~6**(0등급 없음).
