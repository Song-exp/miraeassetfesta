# 01. 전체 아키텍처 및 특화기능

> *보강 단락 — 리드 §01 의 채권 몫. 3층 구조와 공유 개체의 정의는 리드 절이 맡고, 여기서는 그 구조가 채권 데이터에서 어떻게 서는지만 적는다.*

## 1.1 채권이 푼 문제는 "더 모으기"가 아니었다

국내채권은 4개 상품군 중 **유일하게 외부 수집이 없다.** 21,882행 × 58컬럼짜리 관계형 마스터 한 장이 전부다. 구성종목도 설명서도 상품 페이지도 없는 상품이라 크롤링할 대상 자체가 없다.

그래서 채권의 특화는 **"이미 있는 21,882행을 무엇으로 읽을지 판정해 선언으로 고정하는 것"** 이다. 값은 한 개도 고치지 않았다.

## 1.2 판정이 사는 세 층

| 층 | 무엇을 하나 | 채권의 실물 | 산출물 |
| :-- | :-- | :-- | :-- |
| **1층 값 사전 (KG)** | 이 컬럼 값이 어느 개체인가 | 발행사 alias 1,817 → 노드 1,816 · 신용등급 15 · 위험등급 7 · 통화 1 — 합 **alias 1,840 · 노드 1,839** | `kg_node`·`kg_alias`·`kg_closure` |
| **2층 규칙 문서 (yaml)** | 그 값으로 무엇을 어떻게 물어야 하는가 | 질의 규칙 **46** · 답변 규칙 **21** · 되묻기 **13** · 유사도 축 5 · 위험요인 재료 1 | `enums/domestic_bonds.yaml` (1,242줄) |
| **3층 게이트·가드** | 생성 전에 막고, 생성 후에 고친다 | 부재 선언 **7** · 금지 컬럼 4 · 위험등급 범위 0~6 · **결정층 가드 36** | `gate.py` · `pipeline.py` |

**같은 판정이 세 층에 동시에 나가는 것이 설계의 핵심이다.** 예를 들어 위험등급 범위 `0~6` 은 `shared/risk_grade.yaml` 의 `range_by_table` **한 줄**에서 ttl 제약(`xsd:minInclusive 0 · maxInclusive 6`)과 게이트 상수가 **함께 생성**된다. 코드에 `0~6` 이라는 상수를 따로 두지 않는다.

## 1.3 차별화 포인트 넷 — 이 제안서가 주장하는 것

이후 모든 절은 이 넷 중 하나의 증거다. 절마다 어느 것을 증명하는지 머리에 밝힌다.

### ① 생성되는 온톨로지 — 손으로 쓴 ttl·KG 가 없다

노드 1,839 개와 `bond_kr.ttl` 42줄은 전부 빌드 산출물이다. 사람이 쓴 것은 yaml 의 **"어느 컬럼 값이 이 개체인가"** 한 줄과 코드북 한 장뿐이다. 그리고 빌드는 **검증 7종(V1~V7)을 통과하지 못하면 산출물을 만들지 않는다.** `XS` 를 국가로, 오염값 `'000'` 을 통화로 등재하는 실수는 yaml 에 적는 순간이 아니라 빌드에서 막힌다.

→ 증거: §2.2.3 · §3.1 · §5.2

### ② 실행되는 온톨로지 — 런타임이 네 지점에서 읽는다

온톨로지가 문서로만 있으면 챗봇의 행동은 바뀌지 않는다. 우리 온톨로지는 실행 경로 위에 있다 — **값 접지 · 생성 전 기각 · 규칙 주입 · 생성 후 검증** 네 지점에서 읽힌다. 채권 규칙은 `planner_context` **23,559자**로 매 질의 프롬프트에 실리고, 답변 문장은 규칙 21개를 읽는 조립기가 만든다. 런타임에 그래프를 걷지 않는다.

→ 증거: §2.3 · §3.2 · §4.2

### ③ 선언된 부재 — 없는 것을 없다고 선언한다

"투자지역이 미국인 채권"은 조회 결과가 0건이어서가 아니라, `hasRegion` 속성이 **온톨로지에 선언돼 있지 않아서** LLM 호출 **0회**로 기각된다. 답변불가가 검색 실패가 아니라 **구조 판정**이다. 채권의 부재 선언은 **7건**으로 4개 도메인 중 가장 많다.

→ 증거: §2.2.2 · §4.3 · §5.1

### ④ 강제되는 선언 — 선언만으로는 안 지켜진다

이것이 우리가 실측으로 배운 것이다. 규칙을 yaml 에 적고 프롬프트에 실어도 모델은 어긴다. 그래서 **실제로 어긋난 자리에만** 결정층 가드 **36개**를 달았다. 가드 목록은 상상이 아니라 **오답기록 77건**의 목록이다.

→ 증거: §2.2.4 · §4.4 · §5.3

# 02. 제안 방법

## 2.1 어떤 특화 데이터를 어떻게 수집·정제했는가

> *보강 단락 — 리드/ETF 의 §2.1 통합 절에 들어갈 채권 몫.*
> *증명하는 차별점: ③ 선언된 부재 (그 전제인 "값을 고치지 않는다")*

### 2.1.1 수집 — 외부 수집 0, 코드북 1

다른 세 상품군은 외부 테이블 4장에 **1,052,478행**을 쌓았는데 채권 몫은 한 행도 없다. "안 했다"가 아니라 **모을 것이 없다**. 이유를 실측과 함께 적는다.

| 이유 | 실측 근거 | 그래서 |
| :-- | :-- | :-- |
| 채권은 바스켓이 아니라 **단일 청구권**이다 — "무엇을 담고 있나"라는 질문이 성립하지 않는다 | 외부 수집분은 전부 구성종목이다(ETF 국내 75,859행 · 해외 906,848행 · 펀드 59,206행) | 발행사·표면금리·만기·등급이 **상품 그 자체**이고 전부 마스터 58컬럼 안에 있다 |
| **종목 단위 상품 페이지가 없다** | 마스터 58컬럼에 url·설명서·공시 참조 컬럼이 **0개**(컬럼명 전수 스캔) | 긁을 주소가 없다. 발행 시 증권신고서만 있고 종목별 상시 소개면이 없다 |
| **시장데이터를 긁어도 대부분 비어 있다** | 장내 17,746행 중 종가가 있는 행 **1,270(7.2%)** · **16,476행(92.8%)이 0 = 그날 거래 없음** · 장외 4,136행은 종가 자체가 NULL | 유통이 없는 상품이라 **밖에 시세가 쌓이지 않는다** |
| 남은 것은 **규약상 못 쓰거나 유료**다 | 발행사 재무·계열·등급 이력은 유료 DB. 주최 규약은 "공시 및 기타 시장데이터는 2026-08-24 까지 발행된 자료만" 이고 허용 예시가 "ETF 구성종목(Holdings) 등" 이다 | 등급 이력은 채우는 대신 **부재로 선언**했다(§2.2.2) |

**그래서 밖에서 들여온 유일한 것이 값이 아니라 지식 한 장이다.**

| 코드북 | 무엇 | 왜 필요했나 |
| :-- | :-- | :-- |
| `credit_grade_scale.csv` (한국기업평가 등급정의 · `as_of` 2026-08-20) | 등급 표기 → rank 1~20 + 투자/투기 밴드 2 | 등급 문자열 `AA-`·`BBB+` 는 데이터에 있지만, **"AA- 이상"이 어느 등급들인지**, `BBB-`와 `BB+` 사이가 투자/투기 경계라는 사실은 데이터 어디에도 없다 |

이 코드북은 행을 늘리지 않는다 — 이미 있는 `crd_grd` 문자열에 **순서와 경계를 붙일 뿐**이다. 표 21행 = 표준등급 20(`C0`/`C` 동일) → KG 노드 22(등급 20 + 밴드 2). `as_of` 2026-08-20 ≤ 8/24 로 규약을 지킨다.

### 2.1.2 정제 — 값을 고치지 않고 판정만 했다

원칙 하나로 요약된다. **마스터는 불변이고, 우리가 한 것은 판정을 옆에 붙인 것이다.** 대표적인 판정 여덟 줄이다.

| 데이터가 이랬다 | 판정 | 선언 자리 |
| :-- | :-- | :-- |
| 한 종목이 장내·장외 2~4행 — 1,078종목 | 행 ≠ 종목. 종목 수는 `COUNT(DISTINCT pd_no)` | `row_grain` · 규칙 `대표행` |
| 신용등급 결측 4,020행(18.4%) | 국공채 2,840 은 **미부여**(정상) · 특수채·회사채 1,180 은 **미수록** | `crd_grd.answer_policy` |
| 위험등급 `'00'` 19행 실재 · 6등급 40.8% | 범위 0~6. 0 은 결측이 아니라 값 | `range_by_table` |
| **판매정보 13컬럼이 같은 21,248행에서 통째로 NULL** — 값이 있는 634행은 전부 장외 | 컬럼 13개의 결측이 아니라 **사실 하나**("지금 파는 물건이 아니다") | 규칙 `판매행` |
| **평가정보 8컬럼이 같은 16행에서 통째로 NULL** — 전부 장외, 만기는 미래 | 만기 경과가 아니라 "장외 평가정보 미수록" | 규칙 `듀레이션정상` |
| 표면금리 한 컬럼에 세 의미 — 고정 20,904 / 변동 830 / 할인 689 | 셋을 한 축에 정렬하지 않는다 | `srfc_irt.trap` |
| 고정폭 패딩 7컬럼(`pd_pbcm` 21,282 등) | 값은 안 고치고 **조회 시 TRIM** | `normalization.trim_columns` |
| 발행국 KR 21,881/21,882 · 통화 KRW 상수 | 지역·통화는 축이 아니다 | `kg_entity: null` · 부재 선언 |

### 2.1.3 결측 판정 프로세스 — "채우지 말고 분류하라"

"값이 비어 있다"를 **일곱 유형**으로 갈라 판정했다. 1차 데이터(42,394행)에서 유형을 세우고, 2차(21,882행)가 오자 **같은 조건식을 다시 돌려** 유형표를 갱신했다.

| 유형 | 2차 실측 |
| :-- | :-- |
| ① 구조적 부재 — 국공채 신용등급 | 국공채 2,840행 중 2,840 결측 (완벽 대응) |
| ①′ 같은 컬럼의 미수록 — 특수채·회사채 | 254 + 926 = 1,180 |
| ② 상태 표현 — 판매정보 13컬럼이 **한 덩어리로** 없음 | 동시 NULL 21,248 = 하나라도 NULL 21,248 |
| ③ 미산출 — 평가정보 8컬럼이 **한 덩어리로** 없음 | 동시 NULL 16 · 만기 경과와 교집합 0 |
| ④ 복구 가능 — 평가사 등급 컬럼 병합 | 컬럼 자체가 없어져 **유형 소멸** |
| ⑤ 센티넬·위장 결측 | 세후평균수익률 전량 0 · 통화 `'000'` 1행 · `mat_dt` 0 센티넬 4 |
| ⑥ 복사 위장 — `dirty` = `eval_price` | 21,655 / 21,866 (99.0%) |
| ⑦ 정상값 오해 — 비어 보이지만 값 | `srfc_irt`=0 579행 · `pd_risk_gcd`='00' 19행 |

**판정 순서는 ⑦ 정상값인가 → ⑤⑥ 위장인가 → ④ 복구 가능한가 → ①②③ 어떤 부재인가** 다. `IS NULL` 로만 세면 ⑤⑥⑦ 을 통째로 놓친다.

그리고 **컬럼별로만 세면 ②③ 의 실체를 놓친다.** 이 둘은 컬럼 21개의 결측이 아니라 **행 단위로 정보 묶음이 통째로 빠진 것**이고, 양쪽 다 "동시 NULL = 하나라도 NULL" 로 검증된다. 그래서 답변 정책도 컬럼 21개가 아니라 블록 2개에 하나씩 붙는다.

**기각한 대안 셋** — ⓐ 최빈값·같은 발행사 등급으로 **대치**: 값을 만드는 순간 환각이고 주최 공지("0·결측은 의도된 내용")와 충돌한다. ⓑ "확인할 수 없습니다" **일괄**: 국공채엔 오답이다 — 실제로 서버가 국고채 답변에 "신용등급 정보 없음"을 낸 적이 있다. ⓒ 등급 조건 질의에서 결측 행을 **조용히 제외**: 모수를 밝히지 않고 "전체 중"이라 말하면 오답이다.

## 2.2 어떤 온톨로지 엔지니어링을 적용했는가 — 채권 절

> *정본 절 — 합본 §2.2.2. 공유 개체 11종의 정의는 리드 §2.2.1 이 맡고, 여기서는 채권이 그중 무엇에 닿고 무엇을 부재로 선언했는지를 적는다.*
> *증명하는 차별점: ① 생성되는 온톨로지 · ③ 선언된 부재 · ④ 강제되는 선언*

채권은 공유 개체 11종 중 **4종에만 닿고 3종을 부재로 선언**한다. 스포크가 가장 적은 도메인이지만, 4도메인 중 유일하게 **서열이 있는 닫힌 축(CreditGrade)** 을 쓰고, 유일하게 **결정층 되묻기**를 갖는다. "AA- 이상" 같은 순서 질의는 온톨로지 없이 풀리지 않고, "위험한 채권"은 데이터 안에서 정반대의 두 축으로 갈리기 때문이다.

### 2.2.1 그림 B-1 — 채권이 쓰는 개체와 쓰지 않는 개체

### 2.2.2 부재 선언 7건 — 없는 것을 없다고 말한다 (차별점 ③)

| 부재 선언 | 왜 없나 | 그래서 이렇게 답한다 |
| :-- | :-- | :-- |
| `hasAssetClass` | 상품 자체가 채권이라 자산군 컬럼이 없다 | 클래스 계층(`DomesticBond ⊂ Bond`)으로 처리 |
| `tracksIndex` | 채권은 지수 추종 상품이 아니다 | "지수 추종 채권" 질의 기각 |
| `hasRegion` | 투자지역 컬럼이 없다. 발행국은 21,881/21,882 가 KR 인 사실상 상수 | "투자지역이 미국인 채권" → LLM 0회 기각 |
| `hasCreditGradeHistory` | 기준일 현재 등급만 있고 등급 추이가 없다 | "등급이 올랐어?" → 기각 + 대체 안내 |
| `hasYieldHistory` | 금리·수익률·가격이 8/21 스냅샷 한 시점뿐이다 | "요즘 금리가 어떻게 움직였어?" → 기각 |
| `hasIndustrySector` | 발행사의 업종·산업·섹터 분류 컬럼이 없다 | "우주항공 관련 발행사 채권" → 조건부 기각 |
| `hasCouponFrequency` | 이자지급 **방식**(이표/복리/할인/단리)은 있지만 **주기**(3개월·6개월)가 없다 | "몇 개월마다 이자 줘?" → 기각 |

**부재를 선언하는 일의 절반은 "어디까지 막지 않을지"를 정하는 일이다.** 어휘가 셋으로 갈린다.

- **무조건** — 축 이름 자체(`업종`·`섹터`·`테마`)는 언제나 기각한다. 단 '산업'은 한국산업은행을 비켜 가도록 부정 전방탐색으로 잘랐다.
- **접지 조건부** — "우주항공 관련 발행사" 같은 문형은 **발행사·종목 개체가 하나도 접지되지 않았을 때만** 기각한다. 접지된 질문까지 닫으면 답할 수 있는 질의를 막는다.
- **앵커 조건부** — 지급주기는 '이자·쿠폰·이표'가 함께 있을 때만 걸린다. 그렇지 않으면 "만기 몇 개월 남았어"를 오폭한다.

그리고 **부재는 도메인의 성질이지 어휘의 성질이 아니다.** 지급주기를 전역 규칙으로 올렸으면 안 됐다 — 같은 축이 **국내ETF 에는 실재**하기 때문이다(`pd_dvid_cycl` 이 분기 698 · 연 306 · 월 196 · 반기 8). 전역으로 막았으면 ETF 분배주기 질의가 함께 막혔다. 게이트가 **라우팅된 한 테이블의 선언만** 보게 설계한 것이 여기서 값을 했다.

### 2.2.3 빌드가 산출물을 거부한다 — V1~V7 (차별점 ①)

| 검증 | 무엇을 막나 |
| :-- | :-- |
| **V1** | 죽은 alias — 선언은 있는데 DB 에 그 값이 없다 → **오류, 빌드 거부** |
| **V1p** | 선언된 부재 — "표준 체계엔 있으나 이 적재분엔 없음"이라고 미리 밝힌 값 → 경고 |
| V2 | 한 원본 값이 두 노드에 매달림 |
| V3 | 미완 포인터 — 가리키는 개체가 없음 |
| V4 | 코드북 규정 — 출처·`as_of`(≤ 기준일) 필수 |
| V5 | 존재하지 않는 테이블·컬럼 참조 |
| V6 | 부재로 선언했는데 실제로는 컬럼이 있음 |
| V7 | alias 확장 대상 노드 없음 |

**V1 과 V1p 를 가른 것이 확장성의 핵심이다.** 둘 다 "죽은 alias"라는 같은 이름으로 나오던 시절에는, 경고를 보면 "표준표를 적재분에 맞춰 잘라라"로 읽혔다. 자르면 **새 데이터가 들어왔을 때 조용히 못 알아본다.** 그래서 자르지 않고 "선언된 부재"라는 제 이름을 붙였다.

현재 **오류 0 · 경고 9건**이고 9건 전부 V1p 다 — 신용등급 6종(`BB+`·`B0`·`CCC`·`CC0`·`C`·`D`) + 통화 3종(`USD`·`JPY`·`EUR`). 1차 데이터엔 있었거나 표준표에만 있는 값들이고, 3차에 다시 들어오면 **선언은 그대로 두고 값 사전만 갱신되면 된다.**

### 2.2.4 결함에서 선언으로 — 여섯 건

여섯 건 모두 같은 구조다. **데이터가 이렇게 생겨서(결함) → 이렇게 선언했고(층) → 실행 중 어느 단계가 그 선언을 읽으며(런타임) → 안 지켰을 때 실제로 이런 오답이 났다(강제).**

'층'은 §1.2 의 3층을 가리킨다. 마지막 줄이 **차별점 ④** 다 — 전부 상상이 아니라 서버 실측으로 관측한 오답이다.

#### ① 신용등급의 서열이 데이터에 없다 (1층 + 2층 + 3층)

**결함** — `crd_grd` 는 `AAA`·`AA0`·`AA-` 같은 문자열 15종이다. "AA- 이상" = `{AAA, AA+, AA0, AA-}` 라는 사실도, `BBB-`/`BB+` 가 투자/투기 경계라는 사실도 어느 컬럼에도 없다. `>= 'AA-'` 는 사전순이지 서열이 아니다. 게다가 사용자가 말하는 `AA` 는 DB 에 **0건**이고 `AA0` 로 적혀 있다.

**선언** — 표준표를 rank 1(AAA)~20(D) 노드로 선언하고, 투자등급(rank 1~10)·투기등급(11~20) 두 밴드를 상위 개념으로 두었다. 빌드가 밴드→등급을 closure 20 으로 펼친다(1층). DB 표기 `AA0` 는 `CG_AA` 의 alias 로 흡수한다. 규칙 `등급서열`·`등급정규화` 가 "이상·이하가 붙으면 `TRIM(crd_grd) IN (서열 확장 목록)`, `=` 단일 등급은 오답"을 SQL 생성기에 싣는다(2층).

**기각한 대안** — 서열을 규칙 문서 텍스트로만 싣고 모델이 목록을 만들게 두는 안. 실측에서 불완전한 `IN` 목록이 나왔다. 반대로 코드에 목록 상수만 두는 안 — 코드북을 교체할 때마다 코드를 고쳐야 한다.

**런타임** — Ground 가 "AA-"를 `CG_AAm` 으로 접지하고, Plan 이 규칙을 주입하고, 생성 뒤 가드 `expand_grade_comparison` 이 SQL 의 `crd_grd = 'AA-'` 나 불완전한 `IN` 목록을 서열 확장식으로 통째로 교체한다.

**안 지키면** — 서버 실측: "A등급 이상 회사채 표면금리 5% 초과"가 `crd_grd='A-'` 단일 등급으로 나가 모수 596종목 중 **49행만** 조회됐다. 같은 날 밤 재실측에서는 불완전한 `IN` 목록으로 상위 209종목이 누락돼, 1위 우리금융캐피탈458(7.5%) 대신 SC은행(5.2%)이 답으로 나갔다.

#### ② 위험등급 `'00'` 19행이 실재하고 6등급이 40.8% (3층)

**결함** — `pd_risk_gcd` 는 문자열 `'11'~'16'` + `'00'`. 뒷자리가 등급이고 **숫자가 클수록 안전**하다. `'00'`(해당없음) 19행은 결측이 아니라 값이다. 반면 펀드는 등급 없는 클래스가 NULL 이고 0 이 아니다.

**선언** — `range_by_table` 에 채권만 `0~6`, 펀드·국내ETF 는 `1~6` 으로 선언했다. 빌드가 이 한 줄에서 ttl 의 값 범위 제약과 게이트의 범위 상수를 **함께 생성**한다.

**기각한 대안** — `'00'` 을 적재 때 NULL 로 바꾸는 안(값 고치기 금지 위반이고 "0등급 채권 있어?"에 19종목을 답할 수 없게 된다). 4테이블 공용 상수 `1~6` 을 코드에 두는 안 — 실제로 그 공용 상수가 펀드 0등급을 정의역으로 허용한 사고가 있었고, 그 뒤 테이블별 선언으로 바꿨다.

**런타임** — Gate 가 질문의 "N등급"을 **라우팅된 테이블의** 선언 범위와 대조해 밖이면 LLM 0회로 기각한다.

**안 지키면** — 범위를 1~5 로 두면 정상 데이터 8,929행(6등급)과 19행(0등급)이 차단된다. 방향을 잘못 읽으면 "낮은 위험등급"이 "위험이 낮다"로 뒤집힌다.

#### ③ 발행국·통화가 상수다 (3층 + 2층)

**결함** — `pd_ctry_cd` 21,881/21,882 = KR(나머지 1행은 국제예탁기구 코드 `XS` 로 국가가 아니다). `curr_cd` 21,881 = KRW, 1행은 오염값 `'000'`. 투자지역 컬럼 자체는 없다. 1차 데이터의 외화채 21건은 2차에서 전부 소멸했다.

**선언** — `pd_ctry_cd` 를 "개체로 올리지 않음"으로 판정하고 `hasRegion` 을 부재로 선언했다(3층). 통화는 KRW 하나만 alias 로 잇고, 규칙 `외화채없음` 이 "외화·해외 채권은 **없는 상품이 아니라 이 데이터의 수록 범위 밖**"을 싣는다(2층).

**기각한 대안** — 발행국을 Country 개체로 등재해 '투자지역' 질의에 발행국을 대신 답하는 안. 발행국 ≠ 투자지역이고, 상수 컬럼을 축으로 올리면 "미국 채권"이 `XS` 1행에 접지된다.

**런타임** — '투자지역' 어휘는 Gate 가 부재 선언으로 LLM 0회 기각. '달러·외화·해외 채권'은 상수 컬럼 게이트가 받는다.

**안 지키면** — 서버 실측 2회. 처음엔 모델이 `curr_cd='XS'` 를 **지어냈고**(값 사전 등재로 차단), 다음엔 값 사전에 **실재하는 오염값 `'000'`** 을 골라 통화 미수록 1행을 "1종목"으로 답했다. 상수 컬럼은 값 사전만으로 부족하고 **어휘 게이트가 있어야** 닫힌다.

#### ④ "위험한 채권"이 세 축으로 갈리고 둘은 정반대다 (2층 + 결정층)

**결함** — 위험은 ① 투자위험등급(1등급이 가장 위험 — 1,394종목) ② 신용등급(C0 최하위 103종목) ③ 금리위험(듀레이션 — 국공채 장기물이 최고) 세 축이다. **②와 ③은 정반대다**(국공채 평균 듀레이션 3.97년 > 회사채 1.99년).

**선언** — `clarify.다의어.위험` 에 "기본값 금지·되묻기, 세 축, ②③ 정반대"를 선언했다(2층). 그러나 프롬프트 층만으로는 되묻기가 재현되지 않아 **결정층 되묻기**를 두었다 — 축 단서가 없는 "가장/제일 위험한" 질의는 LLM 호출 **전에** 되묻고, 축별 규모는 DB 실측으로 채운다.

**기각한 대안** — 기본 축으로 단정하는 안(아래 실측이 그 결과다). 세 축을 전부 조회해 한 답에 싣는 안 — 질문이 고르지 않은 축을 대신 골라 주는 것은 여전히 단정이다.

**런타임** — Route → Ground → Gate 통과 후 결정층에서 되묻는다. 단서 낱말이 있으면 되묻지 않고 그 축으로 답한다. 되묻기는 채권에 넷이다 — 위험 · 싸다(가격 낮음 ↔ 수익률 높음) · 유사채권 기준 · 등급 표기.

**실측** — "가장 위험한 채권 뭐야?" → 세 기준을 규모와 함께 제시하고 되묻는다. **0.3초 · LLM 호출 0회.**

**안 지키면** — 서버 실측: 같은 질문에 모델이 1등급 필터 + 수익률 내림차순으로 단정해 유동화 후순위 5종목(최고 **728.5%**)을 답했다. 수익률이 좋은 것이 아니라 평가가가 액면의 27~45%인 원금 손실 위험이 가격에 반영된 것인데, 그것을 "가장 위험한 채권의 답"으로 내놓는 순간 근거 없는 단정이 된다.

#### ⑤ "판매 가능"의 정의가 데이터에 없다 (2층 + 가드)

**결함** — `buyable_quantity` 는 >0 296행·=0 338행이지만 주최 공지로 값 자체가 무효다. 판매 조건이 있는 행은 634행뿐이라 "판매 가능"을 판매 조건 유무로 읽으면 **97.1%가 사라진다.** 만기 경과 여부만 남는데, 데이터 as-of 는 8/22(토)이고 실제 결제 가능일은 8/24(월)이다.

**선언** — 구매가능 = `curr_cd='KRW' AND mat_dt >= 20260824` (21,814행 / 20,431종목). 판정 기준일 8/24 는 as-of 8/22 와 다르다.

**여기서 한 번 더 갈렸다.** 이 선언이 **'살 수 있나'라는 문형 어휘에 걸려 있어서**, 같은 모수를 써야 할 순수 개수 질의("복리채 몇 종목")에는 아무 모수도 안 붙었다. 서버 실측 5문항 중 하한이 붙은 것은 한 문항뿐이었고, 나머지는 만기 경과 65종목을 세면서 답변엔 "(기준일 2026-08-24)"를 달았다 — **표기와 모수의 불일치**다. 그래서 규칙을 프롬프트로 미는 대신 **선언 자체가 SQL 을 고치게** 했다(`enforce` 슬롯). 집계·랭킹 SQL 에 모수 조건을 주입한다. 값 영향은 전수 대조했다 — 채권 gold 51문항 중 6문항만 값이 바뀌었고 전부 정정했다.

**안 지키면** — 서버 실측: "3년 안에 만기" 질의가 `mat_dt <= 2029-08-22`(따옴표 없음)로 나갔다. 날짜가 REAL 로 적재돼 있어 SQLite 는 이것을 **뺄셈**으로 읽어 `1999` 가 되고, 만기일 미수록 0값 4행만 통과했다. 따옴표를 붙이면 이번엔 타입 비교로 **전 행이 통과**한다.

#### ⑥ (보조) 할인채·영구채는 같은 컬럼의 뜻이 다르다 (2층 + 가드)

**결함** — 할인채 689행은 `srfc_irt` 에 지급 이자율이 아니라 **발행 할인율**을 적었다. 영구채 266행은 `mat_dt` 가 만기일이 아니라 **1차 콜 행사 개시일**이라 잔존이 짧게 잡히고, 듀레이션 이론위반 198행 중 101행이 영구채다.

**선언** — ttl `couponRate` 주석에 할인채 사실을 명시하고, 규칙 `이자유형분리`(표면금리 정렬에 할인채·변동금리를 고정 이표채와 한 축에 놓지 않는다)·`듀레이션정상`·답변 규칙 "영구채는 만기일 = 콜 개시일 병기"를 두었다.

**한 가지 경계** — 이 분리는 **추천·랭킹에만** 적용한다. 조건검색에 넣으면 모수가 599 → 497종목으로 줄어 그 자체가 오답이 된다.

**안 지키면** — 서버 실측: "A등급 이상 회사채 중 표면금리 높은 순 5개"가 `ORDER BY applied_yield`(수익률)로 나가 답변까지 "수익률 높은 순"으로 축을 바꿔 적었다. 등급 서열·회사채 필터·기준일이 전부 맞았고 **정렬 축 하나만 틀렸는데**, 실린 1·2위의 표면금리는 7.1%·3.0%로 상위권이 아니다(정답 1위 7.5%). **값이 전부 실제 행이라 환각 검사에 걸리지 않는다.**

### 2.2.5 선언은 이 6건이 전부가 아니다 — 규칙 78개의 전수

지면상 위 6건만 펼쳤다. 고른 기준은 **층이 셋 다 걸리는가**(선언 → 프롬프트 → 가드)이다. 채권 하나에 붙어 있는 선언의 전수는 아래와 같고, 부류별 전수표는 **부록 B** 에 있다.

| 부류 | 수 | 무엇을 다루나 |
| :-- | --: | :-- |
| A. 결측·0 의 뜻 | 8 | "비어 있음"을 무엇으로 읽는가 |
| B. 값의 뜻 | 13 | 코드·숫자·이름이 무엇을 가리키는가 |
| C. 무엇을 하나로 세는가 | 8 | 행·종목·모수 |
| D. 어떻게 적혀 있는가 | 7 | 패딩·날짜 타입·기준일·표기 변이 |
| E. 질문을 어느 축으로 읽는가 | 8 | 정렬축·발행시점축·유사도 |
| — 그 밖의 질의 규칙 | 2 | 가격축 · 안 물은 개수 조건 |
| **`query_rules` 소계** | **46** | (그중 32는 지시와 근거를 분리, `enforce` 슬롯 2) |
| F. 되묻기 `clarify` | 13 | 다의어 6 · 사람의 선택 5 · 존재하지 않는 개체 1 · 조건부 계산 1 |
| G. 답변 규약 `answer_rules` | 21 | 결과를 **문장으로 옮길 때** 틀어지는 자리 |

**A~E 가 SQL 을 어떻게 쓰는가라면, G 21개는 결과를 어떻게 말하는가다.** 값이 전부 맞아도 문장에서 틀어지는 자리가 따로 있어 분리했다 — 예를 들어 국공채 답변에 "신용등급 정보 없음"이 아니라 "**미부여**"라고 말하는 것, 위험등급은 숫자가 클수록 안전하다고 고정해 말하는 것, 정렬 결과를 **순서 그대로 위에서부터** 옮기는 것이 전부 여기 있다.

### 2.2.6 한계 (정직하게)

1. **신용등급 결측 18.4%는 보완 불가**다. 외부 원천이 없다. 국공채 2,840행은 "미부여", 회사채·특수채 1,180행은 "미수록(미평가)"으로 답하는 것이 정답이고 유추하지 않는다.
2. **중복 종목 8건의 두 줄 병기는 아직 선언까지만 있다.** 값이 갈리는 8종목(장외행의 종류·등급·발행사·듀레이션이 전부 NULL)은 어느 줄을 골라도 정보가 손실되므로 두 줄을 병기해야 하는데, 런타임은 종목 단위로 묶는 데까지만 강제한다.
3. **축 4종이 미확정**이다 — 발행주체 유형 · 만기 구간(단·중·장기 경계) · 담보 유형 · 발행사 분류. 경계값이 도메인 합의 사항이라 임의로 정하지 않고 골격만 두었다.

## 2.3 어떤 검색 방법론을 선택했고 왜 그렇게 설계했는가

> *보강 단락 — 리드 §2.3 의 채권 몫.*
> *증명하는 차별점: ② 실행되는 온톨로지*

### 2.3.1 왜 SQL 생성인가 — 문제가 검색이 아니다

원천이 관계형 마스터 한 장이고, 사용자 질문의 답은 대부분 **SQL 한 문장**이다. "판매 가능한 원화채권 중 AA- 이상"은 유사한 문서를 찾는 문제가 아니라 **조건 세 개를 정확히 조립하는 문제**다. 그래서 채택한 것과 하지 않은 것이 갈린다.

| 하지 않음 | 왜 |
| :-- | :-- |
| 벡터 DB·임베딩 검색 | 답이 SQL 한 문장인데 "유사한 것"을 끌어오면 그 자체가 환각 경로다. 등급 `AA-`와 `A-`는 임베딩상 가깝지만 답으로는 정반대다 |
| 그래프 탐색·추론 | 관계형 KG 에서 탐색 ≪ 질의 생성. KG 는 **값 접지 사전**으로 쓰고 탐색 대상으로 쓰지 않는다 |
| 0행 자동 재시도 · `LIKE` 완화 | 거절이 정답인 문항에서 조건을 풀면 없는 답을 만든다. **0행은 재생성 대상이 아니다** |
| 파생 컬럼 생성 | 값을 고치면 "왜 없는지"를 답할 근거가 사라진다 |

### 2.3.2 온톨로지가 개입하는 네 지점

파이프라인은 **Route → Ground → Gate → Plan → Guard → Verify → Execute → Answer** 다. 온톨로지는 네 곳에서 개입한다.

| 지점 | 무엇을 하나 | 채권의 실물 | LLM 호출 |
| :-- | :-- | :-- | :-: |
| ① **Route / Ground — 값 접지** | 질문의 낱말을 KG 개체로 매핑하고 실제 컬럼 값으로 바꾼다 | `'AA-' → CG_AAm → crd_grd='AA-'` · `'원화' → Curr_KRW → curr_cd='KRW'` | 0 |
| ② **Gate — 생성 전 기각** | 물어본 것이 애초에 없는 축이면 SQL 을 만들지 않는다 | 부재 선언 7 · 등급 표준표 4분기 · 범위 0~6 · 상수 컬럼 | **0** |
| ③ **Plan — 규칙 주입** | 개체 매핑 + 도메인 규칙 + 되묻기 규칙 + 스키마를 근거문서로 조립 | `planner_context` **23,559자** | 1 (SQL만) |
| ④ **Verify / Answer — 검증·조립** | 단일 SELECT · 화이트리스트 · LIMIT · **WHERE 값 사전 대조** → 통과하면 실행, 문장은 기계 조립 | 결정층 가드 36 · 값 검사기 | 0 (문장) |

**②가 이 설계의 특징이다.** 답을 못 찾아서 "없습니다"가 아니라, 온톨로지에 그 속성이 선언돼 있지 않아서 **생성 단계에 가기 전에** 끝난다.

### 2.3.3 판정이 프롬프트에 실려야 행동이 된다

컬럼 판정이 **문서에 있다**와 **챗봇이 그대로 행동한다**는 다른 문제다. 런타임이 yaml 에서 실제로 읽는 슬롯을 실측했다.

| yaml 슬롯 | 어디로 가나 | 채권 분량 |
| :-- | :-- | --: |
| `query_rules` 46 | 플래너 — **지시만** 싣고 근거(사고 이력·실측 수치)는 뺀다 | **23,559자** |
| `answer_rules` 21 | 답변 조립기 | 3,390자 |
| `clarify`·`synonyms`·`normalization` | 플래너·되묻기 | 1,227 · 559 · 727자 |
| 값 사전(`vocab`) | 리터럴 검사 | 3,389자 |
| `absent_properties`·`gate_constants` | 게이트 | **프롬프트 0자** — 게이트가 직접 읽는다 |
| `forbidden_columns`·`similarity_axes`·`risk_factor_profile` | 결정층 | **프롬프트 0자** — 코드가 표만 읽는다 |
| `columns` 판정문 23,456자 | **읽지 않는다** | — |

마지막 줄이 우리가 배운 것이다. `missing_reason`·`answer_policy` 같은 판정문은 **사람이 읽는 글**이고, 행동이 되려면 규칙 슬롯으로 한 번 더 옮겨져야 한다. 실제로 결측·함정 판정 40컬럼 중 **9컬럼이 어느 슬롯에도 없었다** — 예컨대 판매채널 컬럼은 yaml 에 답변 문장까지 써 두고 챗봇은 볼 수 없는 상태였다. 답변 규칙 한 줄로 7컬럼을 회수했다.

**이건 채권만의 일이 아니었다.** 같은 날 ETF 담당이 같은 부류를 고쳤다 — 어떤 컬럼이 이름과 달리 실시간이 아니라 종가 복사본이라는 판정이 메타에만 있어 프롬프트에 안 실렸고, 답변기가 종가를 실시간 시세로 팔 수 있었다. **두 도메인이 독립적으로 같은 구멍을 밟았다.**

### 2.3.4 되묻기와 답변불가도 정답 형태다

주최 안내대로 **되묻기는 유효한 답변**이다. 채권은 4도메인 중 유일하게 결정층 되묻기를 갖는다 — 위험(축 셋) · 싸다(정반대 둘) · 유사채권 기준(기준 채권이 여러 만기 구간) · 등급 표기(표준·데이터에 없는 토큰). **넷 다 LLM 호출 전에 끝난다.**

답변불가도 세 종류가 각각 다른 층에서 끝난다 — 존재하지 않는 enum 값은 게이트에서 **LLM 0회**, 매칭 없는 개체는 0집계 기계 조립, 부분일치만 있는 상품명은 유사 후보 되묻기.

# 03. 시스템 구성도 — 적재 → 색인 → 검색 → 생성

> *보강 단락 — 리드 §03 의 채권 몫.*
> *증명하는 차별점: ① 생성되는 온톨로지*

## 3.1 오프라인 (적재 · 색인)

```
[적재]  domestic_bonds 원본 (21,882행 × 58컬럼)
          └─ build_db.py ──────────────▶ financial_products.db
                                          + schema_metadata (한글 컬럼명 원천)

[판정]  프로파일러 전수 스캔 → EDA → 사람이 교차표로 판정
          └─▶ enums/domestic_bonds.yaml  (1,242줄)
          └─▶ shared/*.yaml              (credit_grade · risk_grade · currency · organization)
          └─▶ credit_grade_scale.csv     (코드북 — rank 1~20 + 밴드 2)

[색인]  build_ontology.py
          ├─ V1~V7 검증 ──── 실패하면 산출물을 만들지 않는다
          └─▶ bond_kr.ttl                (클래스 · 속성 · ABSENT 7 · 값 범위 제약)
              kg_node / kg_alias / kg_closure / kg_edge
              domestic_bonds.vocab.yaml  (범주형 12컬럼의 실제 값 = 리터럴 검사 사전)
```

**화살표의 방향이 이 그림의 요점이다.** 사람은 왼쪽 `yaml` 까지만 쓰고, 오른쪽 `ttl` 과 KG 4테이블은 손대지 않는다. 그리고 가운데 **검증이 산출을 막는다.**

## 3.2 온라인 (검색 · 생성)

```
질문
 ├─▶ [Route]    머리명사·라우팅 어휘 → domestic_bonds           (LLM 0회)
 ├─▶ [Ground]   낱말 → KG 개체 → 실제 컬럼 값                   (LLM 0회)
 ├─▶ [Gate]     부재 선언 · 등급 표준표 · 범위 · 상수 컬럼        (LLM 0회 · 여기서 끝나면 기각)
 ├─▶ [Plan]     근거문서 23,559자 조립 → SQL 생성                (LLM 1회)
 ├─▶ [Guard]    가드 36 — 서열 확장 · 모수 · 정렬축 · 날짜 리터럴 · TRIM · 무근거 상한 …
 ├─▶ [Verify]   단일 SELECT · 화이트리스트 · LIMIT · WHERE 값 사전 대조
 │                └─ 위반 시 재생성 1회 (예산 12초 · 0행은 재생성 안 함)
 ├─▶ [Execute]  SQLite read-only · 상한 30행 · 타임아웃 10초
 └─▶ [Answer]   목록·집계·분포는 기계 조립 (LLM 0회) — 모수·기준일·정렬축 머리줄
```

응답에 함께 나가는 `think_trace` 는 각 단계가 **실제로 한 일의 로그**이고 LLM 생성물이 아니다. 그래서 "왜 그렇게 답했나"를 사후에 재생할 수 있다.

| 걸음 | 채권에서 실제로 한 일 | 산출물 | 검증 |
| :-- | :-- | :-- | :-- |
| **① 데이터 수집** | 외부 수집 0 · 마스터 1장 + 코드북 1장 | DB · 코드북 CSV | 행·컬럼 수 대조 |
| **② 온톨로지 설계** | 58컬럼 전수 프로파일링 → 결측 7유형 판정 → 결함→선언 매핑 | `enums`·`shared` yaml | DB ↔ yaml **58/58 일치** |
| **③ 그래프 구축** | 선언 한 줄에서 ttl 제약·KG 노드·프롬프트 문서·게이트 상수를 **동시 생성** | `bond_kr.ttl` · KG 4테이블 · 값 사전 | V1~V7 (**오류 0 · 경고 9 전부 선언된 부재**) |
| **④ 검색** | Route → Ground → Gate → Plan → Guard → Verify → Execute → Answer | 응답 5필드 + `think_trace` | 서버 프로브 · gold 163/163 · 회귀 1,029 |

## 4.2 실례 — 공식 예시 #1 이 SQL 이 되기까지

**질의** — *"현재 판매 가능한 원화채권 중 AA- 이상 종목 알려줘"*
**실측** — 서버 프로브 · HTTP 200 · **2.4초** · LLM 호출 **1회**(SQL 생성만, 답변 조립은 기계)

| 단계 | 이 질의에서 일어난 일 | 읽는 온톨로지 요소 |
| :-- | :-- | :-- |
| Route | "채권" → `domestic_bonds` 단일 테이블 · 값 `['AA-']` | 라우팅 어휘 |
| Ground | `'AA-' → CG_AAm → crd_grd='AA-'` · `'원화' → Curr_KRW → curr_cd='KRW'` | **1층** CreditGrade·Currency alias |
| Gate | 등급 토큰 `AA-` 를 표준표와 대조 → 통과 | **3층** 등급 표준표 4분기 |
| Plan | 근거문서 = 개체 매핑 + 규칙(`구매가능`·`등급서열`·`등급정규화`·`대표행`) + 되묻기 + 스키마 | **2층** 규칙 문서 |
| Guard | **등급 서열 확장** — 단일 등급 비교를 서열 목록 `IN` 으로 교체 | **3층** 가드 |
| Verify | 단일 SELECT · 화이트리스트 · LIMIT · **WHERE 리터럴을 값 사전과 대조** | **3층** 값 검사기 |
| Answer | 30행 조회 → 목록 **기계 조립, LLM 0회** — 전체 종목 수·기준일 머리줄 | **2층** 답변 규칙 |

**생성된 SQL**

```sql
SELECT DISTINCT pd_no, pd_nm, crd_grd FROM domestic_bonds
WHERE TRIM(crd_grd) IN ('AAA', 'AA+', 'AA0', 'AA-')
  AND curr_cd = 'KRW' AND mat_dt >= 20260824
LIMIT 30
```

**응답 첫 줄** — *"조건에 해당하는 채권은 전체 15,792종목이며, 그중 30개는 다음과 같습니다 (기준일 2026-08-24)."*

한 줄에 세 개의 선언이 들어 있다. 등급 조건은 **코드북 서열**에서, 통화·만기 조건은 **구매가능 선언**에서, 전체 종목 수 15,792 는 `LIMIT 30` 과 무관한 **별도 집계**(`COUNT(DISTINCT pd_no)`)에서 왔다. 등급 결측 4,020행은 모수 밖이며 "AA- 미만"이 아니다.

## 4.3 답변불가 — LLM 호출 0회로 끝나는 경로 (차별점 ③)

| 질의 | 어디서 끝나나 | 답 |
| :-- | :-- | :-- |
| "투자지역이 미국인 채권" | Gate — `hasRegion` 부재 선언 | "투자지역 컬럼이 없습니다. 발행국은 21,881/21,882 행이 KR 입니다" |
| "신용등급 AAAA 인 채권" | Gate — 등급 표준표의 **형태**(`^([A-D])\1{0,3}[+\-0]?$`)에 걸린다 | 목록에 없어서가 아니라 표기 규칙에 없어서 기각 |
| "위험등급 7등급 채권" | Gate — 범위 선언 0~6 밖 | "0(매우높은위험)~6(매우낮은위험) 범위로 정의되어 있습니다" |
| "한전 채권 금리가 요즘 어떻게 움직였어?" | Gate — `hasYieldHistory` 부재 선언 | 기각 + 대체 안내(발행연도별 표면금리) |
| "이표채는 몇 개월마다 이자 줘?" | Gate — `hasCouponFrequency` 부재 선언 | "지급 **방식**은 있고 **주기**는 수록되어 있지 않습니다" |

**세 번째 줄이 요점이다.** "AAAA"를 막는 것은 등급 **목록**이 아니라 등급 **표기의 형태**다. 목록으로 막으면 새 데이터가 들어올 때마다 목록을 고쳐야 한다.

## 4.4 가드가 하는 일 — "안 지키면 이렇게 된다" (차별점 ④)

아래는 전부 **서버에서 실제로 관측한 오답**이다. 오답기록 77건 중 부류가 갈리는 것만 골랐다.

| 결함 | 안 지켰을 때 실제로 난 오답 | 지금 막는 층 |
| :-- | :-- | :-- |
| 등급 서열 | "A등급 이상 회사채"가 단일 등급으로 나가 모수 596종목 중 49행만 조회 | 가드 `expand_grade_comparison` |
| 날짜 타입 | "3년 안에 만기"가 뺄셈으로 읽혀 `mat_dt <= 1999` — 0값 4행만 통과 | 규칙 `날짜표기` + 리터럴 정규화 가드 |
| NULL 논리식 | 추천의 `NOT(a OR b)` 가 **등급 NULL 국공채 2,840행을 통째로** 탈락 | 규칙 `고위험제외` 의 NULL-안전 확정식 |
| 고정폭 패딩 | TRIM 없는 종류 비교가 16행 (TRIM 하면 2,031행) | 규칙 `문자열비교` + TRIM 가드 |
| 되묻기 부재 | "가장 위험한 채권"에 단정해 유동화 후순위 5종목(최고 728.5%)을 답함 | `clarify` + 결정층 되묻기 |
| **목록 선별 누락** | 정렬 결과의 2·4·5·6·7위만 나열해 **1위가 증발** — 값이 전부 실제 행이라 환각 검사에 안 걸린다 | 기계 조립 + `ensure_top_row_cited` |
| **정렬 축 치환** | "표면금리 높은 순"이 수익률로 정렬 — 축이 틀렸을 뿐인데 답은 통째로 다르다 | 규칙 `정렬축` + `ensure_sort_axis` |
| **동률 순서 비결정** | 표면금리 동률 종목의 등수가 물을 때마다 뒤바뀜 — 2차 정렬 키가 없으면 등수는 DB 가 준 우연이다 | `ensure_tie_break` |
| **가드가 축을 갈아끼움** | "최근 6개월 안에 **발행된**"에 창 강제 가드가 **만기** 창을 덧붙여 5종목의 발행일이 전부 창 밖 | 규칙 `발행시점축` — 발행 질의에는 불개입 |
| **무근거 상한** | "만기가 제일 긴 것"에 묻지도 않은 `mat_dt <= 20291231` 이 붙어 2029년 종목이 최장으로(실제 최장 2052년) | `strip_unasked_maturity_cap` |
| **표기 변이 누락** | "SK그룹 계열사"의 `LIKE '%SK%'` 가 한글 음역 16곳을 놓쳐 모수 205(실제 307) | 알파벳 26자 자모명 표로 확장 |
| **개체 경계 오매칭** | "신용등급 BBB++"에서 값 사전이 `BBB+` 를 잡아 100종목을 답함 — **환각이 아니라 결정층 매칭** | 등급 기호까지 경계로 + 되묻기 |
| **개체가 끊긴 자리로 답이 샘** | "에코프로 **자회사가** 발행한 채권"이 모회사 본체로 — 자회사 전개 노드와 채권 발행사 노드가 같은 법인인데 이어져 있지 않았다 | 법인 키가 같으면 잇는 규칙을 빌드에 |
| **없는 축을 이름으로 흉내** | "우주항공 관련 발행사"에 모델이 `pd_nm LIKE '%우주항공%'` 로 업종을 종목명 표기로 옮겨 적어 0행 → "상품 자체가 없다"(실제로는 11행 실재) | 부재 선언 + 값 검사기의 **리터럴 출처 검사** |
| **문자열 정렬로 등급 최저** | "신용등급 가장 낮은 3개"가 사전순 정렬로 A- 셋을 냄(정답은 BBB 계열) | 규칙 `등급서열` 의 rank 정렬 |

**세 번째 부류부터가 이 표의 요점이다.** 등급 서열이나 날짜 타입은 "틀린 답"이라 눈에 띈다. 그런데 **목록 선별 누락 · 정렬 축 치환 · 동률 비결정**은 **출력된 값이 전부 실제 DB 행이라 어떤 환각 검사에도 걸리지 않는다.** 이 부류는 선언만으로 막을 수 없고, 실행 계층에서 SQL 을 고치는 가드가 있어야 닫힌다.

그리고 **가드도 오답을 만든다.** 아홉 번째 줄이 그 사례다 — 오답을 막으려 넣은 창 강제 가드가, 질문이 정한 축과 다른 축을 강제해 새 오답을 만들었다. 결정층은 오답을 막는 자리이자 만드는 자리다.

# 05. 기대효과 · 확장성

> *정본 절 — 합본 §05 의 채권 몫.*
> *증명하는 차별점: ④ 강제되는 선언 (그리고 그 강제가 확장을 막지 않는다는 것)*

## 5.1 효과 — 무엇이 실제로 달라졌나

서버 실측 239문항 기준이다.

| 지표 | 값 |
| :-- | :-- |
| **답변 문장을 LLM 이 쓰지 않은 문항** | **193 / 239 (81%)** |
| LLM 을 한 번도 호출하지 않은 문항 | 14 (6%) — 게이트 기각 10 · 되묻기 3 |
| **환각 방지 문항**(주최 답변불가 3 + 자체 6) | **9 / 9 정답** |
| 전체 정답 | 170 / 231 (74%) — 개별 조회 90% · 목록 74% · 집계 72% |
| 응답 시간 | 중앙값 3.2초 |

**첫 줄과 셋째 줄이 함께 읽혀야 한다.** 목록 전사·집계 해석을 LLM 에 맡겼을 때 종목명 0건 전사, 1위 증발, 양수 집계를 "정보 없음"으로 읽는 사고가 났다. 기계 조립으로 옮긴 뒤 **이 유형의 회귀는 0**이다. 환각 방지 9/9 는 그 결과이지 별도의 방어막이 아니다.

**답변불가가 검색 실패가 아니라 구조 판정이다.** LLM 0회 14문항 중 게이트 기각 10건은 "결과가 없어서"가 아니라 "물어본 축이 온톨로지에 없어서" 끝났고, 그 이유가 코드가 아니라 ttl·yaml 에 적혀 있어 `think_trace` 가 그대로 인용한다.

## 5.2 확장성 — 기준은 "코드를 안 고쳐도 되는가"

확장성은 "yaml 이 있다"로 증명되지 않는다. **데이터나 상품군이 바뀔 때 코드를 고쳐야 하면 그건 확장이 아니라 재작업이다.** 그래서 과적합 점검을 돌려 **코드에 남아 있던 판정을 찾아 선언으로 옮겼다.** 옮긴 것과, 옮겼기 때문에 무엇이 쉬워졌는지를 적는다.

| 옮긴 것 | 전 (코드) | 후 (선언) | 데이터가 바뀌면 |
| :-- | :-- | :-- | :-- |
| **신용등급 서열** | 실재 15종을 적은 코드 상수 | 표준표 rank ∩ 값 사전 | 새 등급이 값 사전에 들어오면 서열이 **코드 수정 없이** 늘어난다 |
| **데이터 범위·기준일** | 날짜 상수 3개 + "외화채는 없다"를 박은 규칙 | `dataset.dates` · `scope.currency` | 외화채가 적재되면 **선언 한 줄** — 게이트가 스스로 "상수 컬럼인가"를 다시 판정한다 |
| **상품 종류 확정식** | 코드에 박은 확정식 15개 + 서술형 9개 | `kind_filters` | 전단채·CP 같은 새 종류는 선언 한 줄 |
| **"이 종류에 6등급이 있나"** | 8종을 열거한 코드 상수 | 종류 확정식으로 DB 에 1회 질의 | 열거가 늙지 않는다 |
| **발행사 통칭** | 손으로 적은 6개(나머지 1,811 발행사는 통칭 없음) | 변환 규칙 선언(`한국` 접두·`공사`·`공단` 접미 제거) | 발행사가 늘면 통칭도 **데이터에서 저절로** 생긴다 |

다섯 번째가 이 원칙의 실증이다. 대표 발행사 23표기로 접지를 실측하니 **6표기가 접지 0건**이었고 전부 '한국' 접두·'공사' 접미를 뗀 일상 표기였다(산업은행·기업은행·도로공사·수출입은행·토지주택공사·한국전력). **통칭을 더 적는 대신 변환 규칙을 선언**해 접지가 17/23 → 21/23 이 됐다. 옛 상수들은 지워지지 않고 **폴백으로 강등**됐다 — 선언이 없을 때만 쓰이고, 평소엔 아무도 읽지 않는다.

**그 뒤에 붙은 선언들은 처음부터 선언이었다.** "비슷한 채권"의 뜻(축·폭·구간)은 코드가 아니라 `similarity_axes` 표에 있고 코드는 표만 읽는다 — **펀드·ETF 도 같은 키를 선언하면 같은 코드가 돈다.** '위험요인'을 무엇으로 설명할지도 문장이 아니라 재료 표로 선언했다. 금리 이력 부재는 선언 한 항목이 게이트 어휘가 되어 **코드 변경 0** 으로 사고를 닫았다.

| 확장 | 무엇을 하면 되나 | 근거 |
| :-- | :-- | :-- |
| **평가사·등급 체계 교체** | 코드북 CSV 한 장 교체 + 빌드 1회. rank·밴드·closure·게이트 표준표·서열 확장 가드가 전부 그 파일에서 다시 생성된다 | 등급 관련 **코드 상수 0** |
| **3차 데이터 반입** | 같은 조건식을 다시 돌려 유형표를 갱신한다. 1→2차에서 이미 해봤고 유형 하나가 소멸하는 것까지 확인됐다 | 결측 블록 검증식이 수치 생성기에 편입 · 선언된 부재 9건 |
| **다른 상품군** | 같은 3층 틀을 그대로 — 컬럼 판정 → 답변 정책 → 규칙 슬롯 승격 → 빌드 검증 | ETF·펀드가 같은 틀로 이미 동작 |
| **유사 상품 추천을 다른 상품군에** | 그 도메인 yaml 에 `similarity_axes` 를 선언하면 같은 확정식·되묻기가 돈다 | 코드는 표만 읽는다 |
| **'위험요인' 설명을 다른 상품군에** | `risk_factor_profile` 을 선언하면 같은 조립기가 돈다 — ETF 는 위험등급·배수·변동성, 펀드는 위험등급·유형이 재료가 된다 | 코드는 표만 읽는다 |
| **축 추가** | 발행주체 유형·만기 구간·담보 유형·발행사 분류 4종은 골격만 두었다 | 경계값이 도메인 합의 사항이라 임의로 정하지 않았다 |

**표준 체계를 데이터에 맞춰 자르지 않는다.** `CCC`·`D`·`USD` 처럼 표준표엔 있고 이 적재분엔 없는 값은 **지우는 대신 "선언된 부재"로 표시**한다. 지우면 다음 데이터에서 조용히 못 알아본다.

## 5.3 현업 적용 지점

- **설명의무.** 결측 등급을 "미부여(국공채) / 미수록(회사채·특수채)"으로 구분해 답하는 것이 그대로 설명의무 관점의 가치다. **"등급 없음 = 위험"이라는 오해를 시스템이 만들지 않는다.**
- **컴플라이언스가 직접 고친다.** 규제 문구가 코드가 아니라 답변 규칙 yaml 에 있다 — 원금 손실 주의 문구, 사모·1등급 제외 고지, 모수 고지가 전부 **yaml 한 줄**이다. 문구 변경에 배포가 필요 없다.
- **고객 적합성 확인.** 위험 축이 셋으로 갈리는 질문에 단정하지 않고 되묻는 것이 **현장 접점의 실제 동작과 같다.** 창구 직원도 "위험한 상품"을 물으면 어떤 위험인지 되묻는다.

## 5.4 한계 (정직하게)

1. 신용등급 결측 18.4%는 외부 원천이 없어 보완 불가다.
2. 값이 갈리는 중복 8종목의 두 줄 병기는 선언까지만 있고 런타임 강제가 아직 없다.
3. 축 4종(발행주체 유형·만기 구간·담보 유형·발행사 분류)은 경계값이 도메인 합의 사항이라 골격만 두었다.
4. 등급 이력·발행사 재무·계열 정보는 데이터에 없어 **답하지 않는다.** 이것은 결함이 아니라 선언이다.
