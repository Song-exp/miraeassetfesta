### 3-4. 4.4 답변불가 — "세 경로 모두 HCX 0회" 가 아니다

07 §4.4 뼈대는 AAAA·Kimi·KODEX 세 경로가 HCX 0회로 끝난다고 적었는데, r15 실측은 **AAAA 만 HCX 0회(0.3초)** 다. Kimi 는 미특정 라우팅 → 4테이블 48,664자 근거문서 → HCX 가 `pd_nm LIKE '%김미%'` SQL 을 만들고 0집계를 기계 조립(**48.9초**), KODEX AI로봇은 HCX 가 정확일치 SQL 을 만들고 0행 → 유사 후보 4건 되묻기(2.1초). 답 자체는 셋 다 정답이다.

1. 07 §4.4 문구를 실측대로 정정하고 취합본 §4.4 그대로 간다 — 내가 취합본에 이미 그렇게 썼다.
2. Ground 매칭 0 + 머리명사 없음이면 HCX 전에 끝내는 결정층을 프리즈 전에 넣는다(Kimi 48.9초 절감 + "HCX 0회" 서사 회복).

기본값 1번. 2번은 형 일정.

### 3-5. '위험' 되묻기 사각 2건 — 프리즈 전 수리 권장 (코드 · 다른 세션이 pipeline.py 수정 중이라 내가 안 건드림)

수정은 정규식 두 줄 + 테스트 3문항. yaml `clarify.다의어.위험` 에도 "종류 낱말은 축 단서가 아니다" 한 줄과 C0 ⊂ 1등급 사실을 넣자는 제안(§2-7). 서버 확인용 문항은 `probe_bond_recheck.txt` BR-X05·X06 에 넣어 두었다.

### 3-6. "3년 뒤에 만기" 14,676 오답(재배포 전) — 가드는 `ac4835d` 로 닫혔고, 남은 건 **채권 단일 COUNT 기계 조립**

서버(재배포 전)가 '3년 뒤' 를 '3년 안에' 로 풀어 14,676 을 답했다(정답 2029년 전체 2,611). 형 세션의 `ac4835d` 확정표 가드가 이 SQL 을 2029 창으로 교체하는 것까지 오프라인으로 확인했다(오답기록 §2-9). 그런데 답변 문장은 여전히 HCX 가 쓴다 — 채권 단일 `COUNT(DISTINCT pd_no)` 결과는 기계 조립 경로가 없어서 기준일·모수·해석 창이 HCX 성실성에 달려 있다. 펀드 `_count_answer` 의 채권판(함수 1 + 테스트 3)을 넣자는 제안. `win_note` 를 답변 머리줄에 굽는 것까지 포함. pipeline.py 를 형 세션이 만지고 있어 내가 안 건드렸다 — 형이 하거나, 형 커밋 뒤 내가 한다.

### 3-7. 발행사 되묻기 후보 오류 — 내가 고쳤다(코드 1줄), `--code-only` 재배포 필요

"삼성전자가 발행한 채권 있어?" 서버 답이 "없다" 까지는 맞는데 되묻기 후보가 (주)중소기업은행·(주)KB국민카드… 였다. 재생성 리터럴 `'(주)삼성전자'` 의 앞 `(주)` 를 접미 정규식이 못 떼서 어두가 `(주` 가 된 것. `_ISSUER_SUFFIX` 에 접두 제거를 넣고 테스트를 늘렸다(오답기록 §2-11). pipeline.py 를 형 세션이 만지는 중이면 충돌 없게 한 줄이라 그대로 rebase 될 것. 제안 2건(발행사 값 위반 시 재생성 생략 · 되묻기 표기를 질문 낱말로)은 §2-11 에.

### 3-8. "달러로 발행된 채권" — 오염값 BAC 1행 노출(❌) → 3층 셋 수정(내가 함), 재배포 yaml+code 필요

8/31 체크리스트 #4 의 실패 조건 그대로 나왔다 — HCX 가 `curr_cd='000'`(통화 미수록 오염값)을 골랐고, 값 검사는 실재 값이라 통과, `SELECT *` 58컬럼이 dirty·ndy_*·코드값까지 답에 실렸다. 채권엔 ETF 의 `pd_trd_ccy` 같은 상수 컬럼 게이트가 없었다. 수정 3: ① yaml `gate_constants curr_cd`(HCX 0회 · '외국환평형기금채권'·'해외인프라' 이름은 안 걸림 실측) ② `forbidden_literal_use`(`'000'`·`<>'KRW'` 기각) ③ 목록 조립기 `SELECT *` 핵심 항목만 + 금지 컬럼 숨김 + 한글 라벨. 전체 테스트 통과. 오답기록 §2-12. **형 판단 2건**: `SELECT *` 를 SQL 층에서 표준 컬럼으로 치환할지(ETF·펀드 공통) · 값 사전에 "실재하지만 사용 금지" 표식을 두어 값 검사기가 기각하게 할지(지금은 코드 상수).

### 3-9. 실측 3문항 — 오거절 1(무이자 채권) · 표기 🟡 1(신종자본증권) · ✅ 1(여전채)

"이자를 아예 안 주는 채권은 왜" 가 오거절이었다 — HCX 가 이자지급구분/금리구분 두 축을 섞어 `bd_inrt_tcd='할인채'` 로 쓰고, 값 검사가 "그 값은 bd_intp_tcd 컬럼" 이라고 알려줘도 재생성이 같은 오류를 냈다. 2층에 '무이자·무이표' 어휘·규칙을 넣었다(`무이자질의`·동의어 3, yaml). **형 판단**: 값 검사 위반이 소유 컬럼(`owner`)을 이미 아니까 **컬럼 자동 교정 가드**(교정 뒤 같은 컬럼에 모순 등호가 남으면 재생성 사유에 명시)를 넣을지 — 재생성 1회를 같은 오류에 태우는 유형이 반복된다(오답기록 §2-13). "신종자본증권 만기 최단" 은 값이 맞았고 콜 개시일 병기·모수(신종 OR 영구 237)만 보강했다(조립기 코드 + 규칙 `영구채필터`). "여전채 top5" 는 가드 5개가 전부 작동한 정답이다.
