### 3-1. `_GRADE_SCALE` 코드 상수 — 프리즈 전 수리 목록에 넣을지

`src/runtime/pipeline.py:557` 의 `_GRADE_SCALE`(15종 하드코딩)이 등급 서열 확장 가드의 목록이다. 규칙 문서와 KG 노드 rank 는 코드북에서 오는데, **3층 가드만 코드 상수**라 "값 사전 = 값 검사기"(§01 차별화 3) 원칙에 어긋난 자리다. 지금은 15/15 일치하고 `BB+` 같은 2차 0건 등급은 게이트 `no_data` 가 먼저 받아 실해는 없다. 원고에는 한계 §B.3-2 로 정직하게 적어 두었다.

1. 이대로 두고 한계 절 서술 유지 — 코드 변경 0, 위험 0.
2. `kg_node` rank 로드로 교체(로더 10줄 + 테스트) — 원칙과 코드가 일치, 단 프리즈 전 회귀 1회 필요.

기본값은 1번으로 원고를 쓴 상태다. 2번이면 말해줘 — 내가 한다.

### 3-3. 4.3 국민성장펀드 — 서버는 전체 거절, 06 §C 설계는 부분 답변

r15 실측(`OFFICIAL-002`, 2.3초): Plan 단계에서 플래너가 **[Refuse] 전체 답변불가** — "구조와 투자전략 동향에 대한 정보가 없습니다". 그런데 `public_funds` 에 `itm_nm LIKE '%국민성장%'` **4행**이 있다. 06 §C 설계는 "구조(클래스·운용사·설정일)는 답하고 동향은 없다고 밝힌다" 였다. gold 는 보류 목록(OFFICIAL-002).

기본값 1번으로 취합본을 써 두었다.

### 3-4. 4.4 답변불가 — "세 경로 모두 HCX 0회" 가 아니다

07 §4.4 뼈대는 AAAA·Kimi·KODEX 세 경로가 HCX 0회로 끝난다고 적었는데, r15 실측은 **AAAA 만 HCX 0회(0.3초)** 다. Kimi 는 미특정 라우팅 → 4테이블 48,664자 근거문서 → HCX 가 `pd_nm LIKE '%김미%'` SQL 을 만들고 0집계를 기계 조립(**48.9초**), KODEX AI로봇은 HCX 가 정확일치 SQL 을 만들고 0행 → 유사 후보 4건 되묻기(2.1초). 답 자체는 셋 다 정답이다.

1. 07 §4.4 문구를 실측대로 정정하고 취합본 §4.4 그대로 간다 — 내가 취합본에 이미 그렇게 썼다.
2. Ground 매칭 0 + 머리명사 없음이면 HCX 전에 끝내는 결정층을 프리즈 전에 넣는다(Kimi 48.9초 절감 + "HCX 0회" 서사 회복).

기본값 1번. 2번은 형 일정.

### 3-5. '위험' 되묻기 사각 2건 — 프리즈 전 수리 권장 (코드 · 다른 세션이 pipeline.py 수정 중이라 내가 안 건드림)

"가장 위험한 채권 뭐야?" 는 서버에서 되묻기 ✅(0.3초)인데, 오프라인 재현으로 두 변종이 **되묻지 않고 HCX 로 간다**(오답기록 §2-7 표):
- "가장 위험한 **회사채**" · "가장 위험한 **공모** 채권" — `_RISK_CUE` 가 회사채·국공채·공모·사모를 축 단서로 취급. 종류는 범위이지 축이 아니라 9/2 단정 경로가 그대로 열려 있다.

## 4. 병철 확인 1건 — OFFICIAL-001 잔여 🟡 2건을 부록 E(평가 재현)에 어떻게 적을지

g1~g5 다섯 라운드 내내 OFFICIAL-001 은 ✅값/🟡 이고, 🟡 사유가 같다 — ① SQL 에 ORDER BY 가 없어 정렬축 미표기 ② 무등급 4,020행(국공채 2,840)이 모수 밖이라는 고지 없음. 15R 에서 gold 결함(모수 15,806 낡음)으로 **보류** 처리됐다. 처방(g1 §24 G-C′ — `_bond_list_answer` 에 정렬축·무등급 문장 병기)은 리드 파이프라인 몫이라 미집행.

1. 부록 E(평가 재현)에 "OFFICIAL-001 ✅값 · 🟡 표기 2건 · gold 보류" 를 그대로 적는다 — 한계 절 원칙과 정합.
2. 형이 G-C′ 를 프리즈 전에 넣으면 ✅ 로 올린다.

기본값 1번. 2번이면 형 일정에 달려 있다.
