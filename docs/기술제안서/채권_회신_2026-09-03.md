## 01. 전체 아키텍처 · 특화기능 — 채권 몫

### 1.1 한 문장

**국내채권은 4개 상품군 중 유일하게 외부 수집이 없다.** 21,882행 × 58컬럼짜리 관계형 마스터 한 장이 전부다. 그래서 채권의 특화는 "데이터를 더 모으는 것" 이 아니라 **이미 있는 데이터를 무엇으로 읽을지 판정해 선언으로 고정하는 것**이다. 값은 한 개도 고치지 않았다.

### 1.2 세 층 — 판정이 사는 자리

| 층 | 무엇 | 채권 실물 | 산출물 |
| :-: | :-- | :-- | :-- |
| **1층 값 사전 (KG)** | "이 컬럼 값이 어느 개체인가" | 발행사 1,817 alias → 노드 1,816 · 신용등급 alias 15 → 노드 22(등급 20 + 밴드 2) · 위험등급 7 · 통화 1 — 합 **alias 1,840 · 노드 1,839** | `kg_node`·`kg_alias`·`kg_closure` |
| **2층 규칙 문서 (yaml)** | "그 값으로 무엇을 어떻게 물어야 하는가" | `query_rules` **41**(그중 **24**는 `{text: 지시, evidence: 근거}` 분리) · `answer_rules` **21** · `clarify` 다의어 6 · `scope` · `kind_filters` · `synonyms` · `normalization` | `enums/domestic_bonds.yaml` |
| **3층 게이트·가드** | "생성 전에 막고, 생성 후에 고친다" | `absent_properties` 1 + shared ABSENT 3 · `gate_constants` 1 · `range_by_table` 0~6 · 결정층 가드 **23** | `gate.py` · `pipeline.py` |

**같은 판정이 세 층에 동시에 나가는 것이 설계의 핵심이다.** 예: 위험등급 범위 `0~6` 은 `shared/risk_grade.yaml` 의 `range_by_table` 한 줄에서 ttl 제약(`xsd:minInclusive 0 · maxInclusive 6`)과 게이트 상수가 **함께 생성**된다. 코드에 `0~6` 상수를 따로 두지 않는다 — 09-02 에 공용 상수가 펀드 0등급을 정의역으로 허용한 사고(KG-013/014) 뒤 테이블별 선언으로 바꿨다.

### 1.3 차별화 포인트 넷

1. **결측을 채우지 않고 유형으로 판정한다.** 같은 NULL 이 "해당없음" 과 "미수록" 으로 갈리면 답변 문장이 달라야 한다 — 신용등급 결측 4,020행 중 국공채 2,840 은 미부여(정상), 나머지 1,180 은 미수록. 대치(평균·최빈값)는 처음부터 금지했다.
2. **답변불가가 검색 실패가 아니라 구조 판정이다.** "투자지역이 미국인 채권" 은 결과가 0건이어서가 아니라 `hasRegion` 속성이 **온톨로지에 선언돼 있지 않아서** HCX 호출 0회로 기각된다. 이유가 코드가 아니라 ttl·yaml 에 적혀 있어 `think_trace` 가 그대로 인용한다.
3. **답변 문장을 LLM 이 쓰지 않는 경로가 표준이다.** 목록·집계·분포는 기계 조립이다(r15 239문항 중 81%가 답변 문장 비-LLM). SQL 은 생성해도 문장은 만들지 않는다.
4. **서열이 있는 닫힌 축을 유일하게 갖는 도메인이다.** "AA- 이상" 같은 순서 질의는 데이터만으로 풀리지 않는다 — 등급 서열표를 코드북으로 들여 rank·`skos:broader` closure 로 만들었다.

## 02. 제안 방법

### 2.1 어떤 특화 데이터를 어떻게 수집·정제했는가

#### 2.1.1 수집 — 외부 수집 0, 코드북 1

국내채권 마스터 **21,882행 × 58컬럼**이 유일한 원천이다. 구성종목도 설명서도 없는 상품이라 크롤링 대상이 없다. 대신 **마스터에 없는 지식 하나**를 코드북으로 들여왔다.

| 코드북 | 무엇 | 왜 필요했나 |
| :-- | :-- | :-- |
| `data/external/lookups/credit_grade_scale.csv` (한국기업평가 등급정의, `as_of` 2026-08-20) | 등급 표기 → rank 1~19 + 투자/투기 밴드 2 | 등급 문자열 `AA-`·`BBB+` 는 데이터에 있지만, **"AA- 이상"이 어느 등급들인지**, `BBB-`와 `BB+` 사이가 투자/투기 경계라는 사실은 데이터 어디에도 없다 |

#### 2.1.3 결측 판정 프로세스 — "채우지 말고 분류하라"

"값이 비어 있다"를 **일곱 유형**으로 갈라 판정했다. 1차 데이터(7/11, 42,394행)에서 유형을 세우고, 2차(8/24, 21,882행)가 오자 **같은 조건식을 다시 돌려** 유형표를 갱신했다.

### 2.2 어떤 온톨로지 엔지니어링을 적용했는가

#### 2.2.1 결함 → 선언 (대표 5건 + 보조 1건)

건마다 "데이터가 이랬다 / 그래서 이렇게 / 기각한 대안 / 런타임에서 / 실측 사례 / 안 지키면" 여섯 줄로 적었다.

노드는 전부 빌드 산출물이다. 사람이 쓴 것은 **"어느 컬럼 값이 이 개체인가"** 한 줄과 코드북뿐이다.

#### 2.2.3 빌드가 산출물을 거부한다 — V1~V7

| 검증 | 무엇을 막나 |
| :-- | :-- |
| V1 | **죽은 alias** — 선언은 있는데 DB distinct 에 값이 없다 → **errors**(빌드 거부) |

| V5 | 컬럼 실존 — 존재하지 않는 테이블·컬럼 참조 |
| V6 | ABSENT 선언인데 실제로는 컬럼이 있음 (선언 자체가 죽음) |
| V7 | `alias_extensions` 대상 노드 없음 |

**V1 과 V1p 를 가른 것이 확장성의 핵심이다.** 09-04 이전에는 둘이 같은 경고였고, "경고를 없애려면 표준표를 적재분에 맞춰 잘라라" 로 읽혔다. 표준 체계를 데이터에 맞춰 자르면 **새 데이터가 들어왔을 때 조용히 못 알아본다** — 그래서 자르지 않고 `status: pending` 으로 선언한다. 현재 `--check` 는 **errors 0 · warnings 9건**이고 9건 전부 `V1p`(선언된 부재)다 — 신용등급 6(`BB+`·`B0`·`CCC`·`CC0`·`C`·`D`) + 통화 3(`USD`·`JPY`·`EUR`). 1차 데이터엔 있었거나 표준표에만 있는 값들이고, 3차에 다시 들어오면 **선언은 그대로 두고 값 사전만 갱신되면 된다.**

**한계**: V4 는 `ontology/codebooks/`(csv 14개)만 순회하는데 채권 코드북 `credit_grade_scale.csv` 는 `data/external/lookups/` 에 있다. 파일 자체는 규정의 뜻을 지키지만(행마다 `source_url`·`as_of` 2026-08-20 ≤ 기준일), V4 는 컬럼 이름을 `source` 로 찾아서 경로를 고쳐도 그 폴더 7개가 전부 걸린다(§6.3 열린 항목 ⑭).

### 2.3 어떤 검색 방법론을 선택했고 왜 그렇게 설계했는가

#### 2.3.1 왜 SQL 생성인가 — 문제가 검색이 아니다

원천이 관계형 마스터 한 장이고, 사용자 질문의 답은 대부분 **SQL 한 문장**이다. "판매 가능한 원화채권 중 AA- 이상"은 유사한 문서를 찾는 문제가 아니라 **조건 세 개를 정확히 조립하는 문제**다. 그래서 채택한 것과 하지 않은 것이 갈린다.

| 하지 않음 | 왜 |
| :-- | :-- |
| 벡터 DB·임베딩 검색 | 답이 SQL 한 문장인데 "유사한 것"을 끌어오면 그 자체가 환각 경로다. 등급 `AA-`와 `A-`는 임베딩상 가깝지만 답으로는 정반대다 |
| 그래프 탐색·추론, edge 종류 확장 | 관계형 KG 에서 탐색 ≪ 질의 생성. KG 는 **값 접지 사전**으로 쓰고 탐색 대상으로 쓰지 않는다 |
| 0행 자동 재시도 · `LIKE` 완화 | 거절이 정답인 문항에서 조건을 풀면 없는 답을 만든다. 0행은 재생성 대상이 아니다 |
| 파생 컬럼(`nm_*`) 생성 | 값을 고치면 "왜 없는지"를 답할 근거가 사라진다. 이름 규약은 조건식으로 푼다 |
| 컬럼 프루닝(스키마 링킹) | 병목이 아니다. 라우팅은 재현율 우선 union |

#### 2.3.2 온톨로지가 개입하는 네 지점

파이프라인은 **Route → Ground → Gate → Plan → Guard → Execute → Answer** 다. 온톨로지는 네 곳에서 개입한다.

| 지점 | 무엇을 하나 | 채권 실물 | LLM 호출 |
| :-- | :-- | :-- | :-: |
| ① **Route / Ground — 값 접지** | 질문의 낱말을 KG 개체로 매핑하고, 그 개체의 실제 컬럼 값으로 바꾼다 | `'AA-' → CG_AAm → crd_grd='AA-'` · `'원화' → Curr_KRW → curr_cd='KRW'` | 0 |
| ② **Gate — 생성 전 기각** | 물어본 것이 애초에 데이터에 없는 축이면 SQL 을 만들지 않는다 | ABSENT 4 · 등급 표준표 4분기 · `range_by_table` 0~6 · 상수 컬럼 `curr_cd` | **0** |
| ③ **Plan — 규칙 주입** | 개체 매핑 + 도메인 규칙 + 되묻기·답변불가 규칙 + 스키마를 근거문서로 조립해 넘긴다 | 채권 근거문서 22,594자 (09-03 서버 실측 · 09-04 `text`/`evidence` 분리 뒤 `planner_context` 는 18,056자) | 1 (SQL만) |
| ④ **검증·조립** | SELECT 단일문 · 테이블 화이트리스트 · LIMIT · **WHERE 값 사전 대조** → 통과하면 실행, 답변 문장은 기계 조립 | 결정층 가드 23 · 값 검사기 · 재생성 1회(예산 12초) | 0 (문장) |

**②가 이 설계의 특징이다.** 답을 못 찾아서 "없습니다"가 아니라, **온톨로지에 그 속성이 선언돼 있지 않아서** 생성 단계에 가기 전에 끝난다. r15 239문항 중 게이트 기각 10건은 전부 HCX 0회다.

#### 2.3.3 판정이 프롬프트에 실려야 행동이 된다

컬럼 판정이 **문서에 있다**와 **챗봇이 그대로 행동한다**는 다른 문제다. 런타임(`loader.py`)이 yaml 에서 실제로 읽는 슬롯을 실측했다.

| yaml 슬롯 | 어디로 가나 | 채권 분량 |
| :-- | :-- | --: |
| `query_rules` 41 (그중 24는 `text`/`evidence` 분리) | 플래너(SQL 생성) `planner_context` — **지시만** 싣고 근거(사고 이력·실측 수치) 3,826자는 뺀다 | **18,056자** (분리 전 20,824자) |
| `answer_rules` 21 | 답변 생성기 `answer_context` | 3,390자 |
| `clarify` · `synonyms` · `normalization` | 플래너 · 되묻기 | 1,207 · 487 · 727자 |
| `gate_constants` · `absent_properties` | 게이트(HCX 0회 기각) | 425 · 163자 |
| `*.vocab.yaml` (12컬럼) | 값 사전(리터럴 검사) | 3,389자 |
| **`columns:` 23,456자** | **읽지 않는다** — 딱 하나 `crd_grd.value_semantics`(등급 화이트리스트)만 | — |

즉 `missing_reason`·`answer_policy`·`trap` 은 **사람이 읽는 판정문**이고, 행동이 되려면 규칙 슬롯으로 한 번 더 옮겨져야 한다. 대부분은 옮겨져 있었지만 결측·함정 판정 40컬럼 중 **9컬럼이 어느 슬롯에도 없었다** — 예컨대 `bdbns_abl_chnl_nm` 은 yaml 에 답변 문장까지 써 두고("판매 조건이 있는 634건은 전부 온·오프 겸용") 챗봇은 볼 수 없는 상태였다. 09-04 에 `answer_rules` 한 줄로 7컬럼을 회수했고(판매정보 13컬럼의 **모수 고지** 634/21,882 포함), `cov`·`ndy_cov` 2컬럼은 무해 판정으로 남겼다.

**이건 채권만의 일이 아니었다.** 같은 날 ETF 담당이 같은 부류를 고쳤다 — `ru_mkt_price` 가 이름과 달리 실시간이 아니라 종가 복사본(국내 1,774/1,780 동일)이라는 판정이 `columns` 메타에만 있어 프롬프트에 안 실렸고, 답변기가 8/21 종가를 실시간 시세로 팔 수 있었다. 두 도메인이 독립적으로 같은 구멍을 밟았다.

#### 2.3.4 되묻기와 답변불가도 정답 형태다

채권은 4도메인 중 **유일하게 결정층 되묻기를 갖는다.** "위험한 채권"이 데이터 안에서 세 축으로 갈리고 둘이 정반대이기 때문이다.

- **되묻기** — 축 단서(위험등급·신용등급·수익률·듀레이션·부도 …)가 없는 "가장/제일 위험한" 질의는 HCX 호출 전에 되묻고, 축별 규모는 DB 실측으로 채운다(1등급 1,394종목 · C0 103종목). '싸다'(가격 낮음 / 수익률 높음)도 같은 층이다.
- **답변불가** — 세 종류가 각각 다른 층에서 끝난다: 존재하지 않는 enum 값은 게이트에서 HCX 0회(0.3초), 매칭 없는 개체는 0집계 기계 조립, 부분일치만 있는 상품명은 유사 후보 되묻기.

### 4.2 실례 — 공식 예시 #1

**질의** *"현재 판매 가능한 원화채권 중 AA- 이상 종목 알려줘"* (`OFFICIAL-001`)
**실측** 서버 프로브 09-03 r15 · HTTP 200 · **2.4초** · HCX 호출 **1회**(SQL 생성만, 답변 조립은 기계)

| 단계 | 이 질의에서 일어난 일 | 읽는 온톨로지 요소 |
| :-- | :-- | :-- |
| Route | "채권" 머리명사 → `domestic_bonds` 단일 테이블 · 값 `['AA-']` | 라우팅 어휘(`kg_alias` raw + 범주값) |
| Ground | `'AA-' → CG_AAm (CreditGrade) → crd_grd='AA-'` · `'원화' → Curr_KRW → curr_cd='KRW'` | 1층 CreditGrade·Currency alias |
| Gate | 등급 토큰 `AA-` = 표준표 `ok` → 통과 | 3층 등급 표준표 4분기 |
| Plan | 근거문서 22,594자 = KG 개체 매핑 + 규칙(`구매가능`·`등급서열`·`등급정규화`·`대표행` …) + 되묻기·답변불가 + 스키마 | 2층 `query_rules`·`clarify` |
| Guard | **등급 서열 확장** — 단일 등급 비교를 `TRIM(crd_grd) IN (서열 목록)` 으로 | 3층 서열 확장 가드 |
| Verify | SELECT 단일문 · 화이트리스트 · LIMIT · **WHERE 값 사전 대조** 통과 | 3층 값 검사기 |
| Answer | 30행 조회 → 목록 **기계 조립, HCX 0회** — 전체 종목 수·기준일 머리줄 | `answer_rules` |

**생성된 SQL**

```sql
SELECT DISTINCT pd_no, pd_nm, crd_grd FROM domestic_bonds
WHERE TRIM(crd_grd) IN ('AAA', 'AA+', 'AA0', 'AA-')
  AND curr_cd = 'KRW' AND mat_dt >= 20260824
LIMIT 30
```

**응답 첫 줄** — *"조건에 해당하는 채권은 전체 15,792종목이며, 그중 30개는 다음과 같습니다 (기준일 2026-08-24)."*

전체 종목 수 15,792 는 `COUNT(DISTINCT pd_no)` 로 **별도 집계한 값**이라 `LIMIT 30` 과 무관하다(규칙 `대표행`·`개수질문`). 등급 결측 4,020행은 모수 밖이며 "AA- 미만" 이 아니다.

### 4.3 가드가 하는 일 — "안 지키면 이렇게 된다"

| 결함 | 안 지켰을 때 실제로 난 오답 | 지금 막는 층 |
| :-- | :-- | :-- |
| 등급 서열 | "A등급 이상 회사채" 가 `crd_grd='A-'` 로 나가 모수 599종목 중 49행만 조회, 상위 금리 전부 누락 | 가드 `expand_grade_comparison` |
| 날짜 REAL | "3년 안에 만기" 가 `mat_dt <= 2029-08-22`(무따옴표) → SQLite 뺄셈 `1999` → 만기일 미수록 0값 4행만 통과 | 규칙 `날짜표기` + `normalize_date_literals` |
| NULL 논리식 | 추천에서 `NOT(a OR b)` 가 등급 NULL 국공채 2,840행을 통째로 탈락 | 규칙 `고위험제외` COALESCE 확정식 |
| 고정폭 패딩 | 무TRIM `bd_knd IN` = 16행 vs TRIM 2,031행 | 규칙 `문자열비교` + `ensure_trimmed_compare` |
| 되묻기 부재 | "가장 위험한 채권" 에 1등급+수익률 내림차순으로 단정해 신보 유동화 후순위 5종목(최고 728.5%)을 답함 | `clarify` + `risk_ambiguity_clarify` |
| 목록 전사 | 정렬 결과의 2·4·5·6·7위만 나열해 1위 3.986%가 증발 (값이 전부 실제 행이라 환각 검사에 안 걸리는 **선별 누락**) | 기계 조립 + `ensure_top_row_cited` |

### 5.2 현업 적용 지점

- **설명의무.** 결측 등급을 "미부여(국공채) / 미수록(회사채·특수채)" 으로 구분해 답하는 것이 그대로 설명의무 관점의 가치다. "등급 없음 = 위험" 이라는 오해를 시스템이 만들지 않는다.
- **컴플라이언스가 직접 고친다.** 규제 문구가 코드가 아니라 `answer_rules` 에 있다 — 원금 주의 문구, 사모·1등급 제외 고지, 모수 고지가 전부 yaml 한 줄이다.
- **고객 적합성 확인.** 위험 축이 셋으로 갈리는 질문에 단정하지 않고 되묻는 것이 현장 접점의 실제 동작과 같다.

### 5.3 확장성 — 기준은 "코드를 안 고쳐도 되는가"

확장성은 "yaml 이 있다" 로 증명되지 않는다. **데이터나 상품군이 바뀔 때 코드를 고쳐야 하면 그건 확장이 아니라 재작업이다.** 09-04 과적합 점검에서 코드에 남아 있던 판정 4건을 찾아 선언으로 옮겼다.

| 옮긴 것 | 전 (코드) | 후 (선언) | 데이터가 바뀌면 |
| :-- | :-- | :-- | :-- |
| **신용등급 서열** | `pipeline._GRADE_SCALE` — 2차 실재 15종을 적은 상수 | **표준표 rank ∩ 값 사전**(`loader.grade_scale`). 순서·경계는 코드북이, 실재 여부는 `value_semantics` 가 판정 | 새 등급이 값 사전에 들어오면 서열이 **코드 수정 없이** 늘어난다 |
| **데이터 범위·기준일** | `gate.DATA_CUTOFF` 등 날짜 상수 3개 + "외화채는 없다" 를 박은 규칙 | `shared/dataset.yaml dates` · `enums.scope.currency`/`issuer_country` | 외화채가 적재되면 `scope` 한 줄 — 게이트가 스스로 "상수 컬럼인가" 를 다시 판정한다(`gate_constants.scope_key`) |
| **상품 종류 확정식** | `pipeline._KIND_FILTERS` 15개 + 서술형 9개 | `enums.kind_filters.tokens`/`paraphrases` | 전단채·CP 같은 새 종류는 선언 한 줄 |
| **"이 종류에 6등급이 있나"** | `_SAFE16_KINDS` 8종 열거 | 종류 확정식으로 DB 에 1회 질의(캐시) | 열거가 늙지 않는다 |

옛 상수들은 지워지지 않고 **`_FALLBACK` 으로 강등**됐다 — 선언이 없을 때만 쓰이고, 평소엔 아무도 읽지 않는다. 같은 원칙의 앞선 사례가 위험등급 `range_by_table`(코드 상수 → 상품군별 선언)이고, 이번에 신용등급·기준일·종류·안전등급까지 같은 자리로 모았다.

**표준 체계를 데이터에 맞춰 자르지 않는다.** 같은 날 빌드 검증에 `V1p`(선언된 부재)를 신설한 것이 이 원칙의 짝이다 — `CCC`·`D`·`USD` 처럼 표준표엔 있고 이 적재분엔 없는 값은 **지우는 대신 `status: pending` 으로 선언**한다. 지우면 다음 데이터에서 조용히 못 알아본다.

| 확장 | 무엇을 하면 되나 | 근거 |
| :-- | :-- | :-- |
| **평가사·등급 체계 교체** | 코드북 CSV 한 장 교체 + 빌드 1회. rank·밴드·closure·게이트 표준표·서열 확장 가드가 전부 그 파일에서 다시 생성된다 | **등급 관련 코드 상수 0** (09-04 `_GRADE_SCALE` 해소 — 폴백으로만 남음) |
| **3차 데이터 반입** | 같은 조건식을 다시 돌려 유형표를 갱신한다. 1→2차에서 이미 해봤고 유형 ④가 소멸하는 것까지 확인됐다. 새로 생긴 값은 값 사전만 갱신하면 서열·게이트가 따라온다 | `gen_proposal_numbers.py` 에 '결측 블록' 검증식(`동시 NULL = 하나라도 NULL`) 편입 · `V1p` pending 선언 9건 |
| **다른 상품군** | 같은 3층 틀을 그대로 쓴다 — 컬럼 판정 → `missing_reason`/`answer_policy` → 규칙 슬롯 승격 → 빌드 검증 | ETF·펀드가 같은 틀로 이미 동작(`range_by_table` 은 테이블별 선언) |
| **축 추가** | `maturityClass`(단·중·장기 경계) · `collateralType` · `issuerCategory` 를 `axis_derivation.pending_workshop` 에 골격만 두었다 | 경계값이 도메인 합의 사항이라 임의로 정하지 않았다 |

**곁가지 효과 — 프롬프트가 줄었다.** 규칙을 `{text: 지시, evidence: 근거}` 로 쪼개 채권 41개 중 **24개**에 적용했고, 사고 이력·옛 실측 수치 3,826자를 근거 칸으로 옮겼다. `planner_context` 가 20,824 → **18,056자**(−13%)로 줄었고, 더 중요하게는 **모델이 옛 종목명·수치를 현재 사실로 오인할 자리가 사라졌다.**
