## §2. 결함 5부류 — 자리와 실측 크기

### D1 [그라운딩] 종목 지시자가 근거문서에 실리지 않는다 · **P0**

`_ground_entities`(pipeline.py:9429)는 KG 노드 레이블만 찾는다. 채권 20,497종목에는 **노드가 없다**
(`shared/security_auto.yaml` 의 `Sec_*` 는 ETF·펀드 편입종목이고 `한국전력공사채권` 은 0건). 그래서
"한국전력공사채권1184" 에서 발행사 노드 하나만 잡히고 **회차 1184 는 근거에서 사라진다.**

남은 숫자를 HCX 가 메꾼다 — `pd_no = 1184`. `pd_no` 는 12자리 ISIN 문자열이라 **어떤 값과도 안 맞는다**
(#98). #99 에서는 대신 `bd_knd='국고채권'` 을 얹었고(D4), #100 에서는 아예 버려 발행사 전체를 셌다.

같은 병이 세 문항에서 세 가지 다른 오답으로 나왔다 — **오답 형태가 아니라 이 결손이 부류다.**

> 실측 근거: 이름 `한국전력공사채권1184` 는 DB 에 완전일치로 존재한다. 즉 **답에 필요한 값은 다 있었고
> 조건을 쓸 방법만 없었다.**

### D2 [되묻기] 전제를 실측하지 않고 사실을 단정한다 · **P0**

`_issuer_clarify_text`(10323)는 *"발행사 리터럴이 DB 에 없을 때"* 를 전제로 쓰였는데, 호출부(13187)는
**그 전제를 재지 않는다.** 0행이면 발행사 등호 리터럴만 보고 곧장 문장을 만든다:

> 발행사 '한국전력공사(주)' 의 채권은 기준일 2026-08-24 국내채권 데이터에 없습니다.

**403행이 있는데 없다고 말했다.** 0행의 원인은 발행사가 아니라 옆 절(`pd_no=1184`·`bd_knd='국고채권'`)이었다.

전수 실측 — 발행사 1,818곳 중 **1,392곳(76.6%)** 이 같은 문장을 만들어낸다. 그 발행사로 던진 어떤
질의든 다른 조건 때문에 0행이 되면 거짓 단정이 나간다. 특정 종목의 사고가 아니라 **발행사 축 전체의 사고**다.

같은 함수를 부르는 자리가 6곳(10584·13106·13113·13128·13187)이라 값위반 경로도 같은 성질을 공유한다.

더 나쁜 것은 **이미 맞는 답을 옆에서 계산하고 있었다는 점**이다. `guard.diagnose_zero_rows` 는 같은 SQL 에
대해 이렇게 답한다:

```
조건별 단독 조회: TRIM(pd_pbcm) = '한국전력공사(주)' → 403건 / pd_no = 1184 → 0건.
                 값 자체가 없는 조건: pd_no = 1184.
```

되묻기가 켜지면 이 진단을 **덮는다**(13193 `cand = ["issuer"]`). 두 층이 같은 사실을 다르게 말했고,
사용자에게 나간 것은 틀린 쪽이었다.

### D3 [조립] 개수를 묻지 않은 질문에 개수로 답한다 · **P1**

`_bond_count_answer`(10457)의 발동 조건은 **SQL 모양뿐**이다(단일 COUNT·1행·값>0). 질문이 개수를
물었는지는 보지 않는다. 주어를 못 읽으면 `"조건에 해당하는 채권"` 으로 때운다 — #100 이 정확히 그 경로다:

> 한국전력공사채권1184 지금 살 수 있어? → **조건에 해당하는 채권은 총 385종목입니다.**

주어 읽기 실패(fallback)는 *"이 질문은 'X 는 몇 종목' 꼴이 아니다"* 라는 **정지 신호인데 무시된다.**

단, fallback 자체를 정지 신호로 쓰면 안 된다 — eval 실측에서 개수 어휘를 가진 21문항 중 **11문항**이
주어 정규식에 걸리지 않는다("통안채 몇 개 있어?"·"부동산투자회사채 몇 종목이야?"). 이들은 지금도
일반 주어로 옳게 답한다. **경계는 주어 정규식이 아니라 질문의 개수 의도다.**

### D4 [가드] 질문에 종류 신호가 0인데 종류 등호 절이 살아남는다 · **P1**

`restore_kind_breadth`(8237)는 **질문에 종류 낱말이 있을 때만** 돈다. #99 의 질문에는 종류 낱말이
하나도 없어 `bd_knd='국고채권'` 은 아무 검사도 받지 않고 실행됐다.

같은 부류의 가드는 이미 여럿 있다 — `strip_fabricated_risk_filter`(위험 어휘 없으면 위험등급 절 제거) ·
`drop_unquestioned_numeric_clause`(질문에 없는 숫자 절) · `drop_unasked_count_having` ·
`_unquestioned_name_needles`(질문 밖 이름 조각). **종류 축만 구멍이다.**

판정 근거는 이미 선언에 있다 — `_question_kind_filters(question)` 이 낱말·서술형(`은행이 발행한` 류)까지
포함해 질문의 종류 신호를 돌려준다. 채권 eval 54문항 중 **40문항이 종류 신호 0** 이고, 그 40문항에
`bd_knd` 등호가 붙는 것은 어느 경우든 날조다(영구채·코코본드·녹색채권은 종류가 아니라 구조/ESG 축이라
`pd_nm`·판정식으로 푼다 — 종류 컬럼을 건드리지 않는다).

### D5 [선언] 발행사 통칭 축이 어휘에도 확정식에도 없다 · **P1**

"산금채" 는 라우터가 못 알아봤고(`[Route] 미특정 → Intent 채택`), `kind_filters` 에도 없다. HCX 는
`bd_knd='산업금융채권'` 을 썼고 값 검사가 잡아냈으며, **재생성이 우연히** `pd_pbcm='한국산업은행'` 을 골라
값이 맞았다. 같은 질문을 다시 던지면 같은 답이 나온다는 보장이 없다.

| :-- | :-- | --: |
| 산금채(산업금융채권) | 한국산업은행 | 503 |
| 중금채(중소기업금융채권) | (주)중소기업은행 | 398 |
| 수은채(수출입금융채권) | 한국수출입은행 | 221 |

규칙 원문(`query_rules.종류필터` ②)은 *"특수은행채(산금채 등) 포함"* 이라고 **이미 말하고 있다.**
선언만 있고 어휘·확정식이 없어 안 지켜진 자리다.

## §3. 수리 계획

원칙: ① 새 기계를 만들지 않고 **기존 부류에 항목을 얹는다** ② 판정은 DB 실측 ③ 항목마다 회귀 · 형제 문항 ·
오폭 실측을 붙인다 ④ 사례가 아니라 규칙을 고친다.

### P0-1 · 채권 종목 지시자 그라운딩 (D1)

**자리** `_ground_entities` 뒤, 대상 테이블이 `domestic_bonds` 일 때 도는 결정층 조회 한 번
(KG 가 아니라 SQLite — 종목 20,497개를 KG 노드로 만들지 않는다. 온톨로지 구조를 건드리지 않는 이유다).

**판정** 질문을 공백 제거해 정규화하고, `pd_nm` 정규화 사전에서 **최장 일치** 하나를 찾는다.

**불개입 조건(측정으로 고정)**
- 숫자를 포함하지 않는 후보는 버린다 — 채권 종목명 **20,497개 전부가 숫자를 포함**한다. 순 한글 낱말은
  구조적으로 오탐이 될 수 없다.
- 길이 5자 미만 버림(4자는 '서흥26' 1건뿐).
- 앞이 숫자면 불일치.
- 🔴 **뒤가 숫자이거나 단위(년·년도·월·일·개·종목·억·만·원·%·퍼센트·프로)면 불일치** — 1차 설계에는
  없었고 실측에서 오탐이 잡혔다. `한글+2자리숫자` 꼴 종목명이 **109개** 있어 연도 표현과 충돌한다:
  "삼천리24년 만기 채권" 이 종목 `삼천리24` 로, "경남개발공사27년 만기" 가 `경남개발공사27` 로 걸렸다.
  단위 경계 검사를 넣으면 셋 다 불개입이고 `풍산109`·`DGB금융지주 24` 같은 진짜 지목은 그대로 적중한다.
- 채권으로 라우팅된 질의에서만.

**효과** 근거문서에 `TRIM(pd_nm) = '한국전력공사채권1184'` 한 줄이 실린다. #98·#99·#100 이 전부
1행 조회가 되고, D2·D3·D4 를 타지 않는다.

**오폭 실측** (단위 경계 검사 포함한 최종 판정식으로) eval 195문항 **오탐 0건**. 형제 12문형 —
지목형 5건 적중 / 연도·발행사·종류 문형 7건 전부 불개입:

```
✔ 한국전력공사채권1184 표면금리랑 수익률 / 발행잔액 / 지금 살 수 있어  → 한국전력공사채권1184
✔ 풍산109 수익률 알려줘 → 풍산109        ✔ DGB금융지주24 신용등급 → DGB금융지주 24
· 삼천리24년 만기 채권 / 서흥26년에 만기되는 채권 / 경남개발공사27년 만기 → 불개입(단위 경계)
· 한국전력공사 채권 알려줘 / 산금채는 몇 종목이야? / 2027년에 만기되는 채권 / 국고채 몇 종목이야 → 불개입
```

**회귀** `tests/test_round35_bond_item_ground.py` — 적중 3 · 불개입 9 · 이름 사전 숫자 포함 100% 불변식.

### P0-2 · 되묻기 전제 실측 (D2)

**자리** `_issuer_clarify_text` **안**. 호출부 6곳을 고치지 않고 함수 하나로 닫는다.

**판정** 후보를 만들기 전에 `SELECT COUNT(*) FROM domestic_bonds WHERE TRIM(pd_pbcm) = ?` 를 실행해
**0 일 때만** 문장을 만든다. 0 이 아니면 빈 문자열을 돌려주고, 흐름은 이미 옳은 답을 갖고 있는
`guard.diagnose_zero_rows` 로 떨어진다.

값위반 경로(13106·13113·13128)는 값 검사가 이미 부재를 증명했으므로 이 검사도 0 을 돌려준다 — 불변.

**한 줄 원칙** — 되묻기 문장이 **주장하는 사실은 실측한 뒤에만 말한다.** 이 원칙은 발행사에만 있는 게
아니다. 같은 꼴의 단정을 하는 자리를 전수로 훑어 같은 검사를 붙인다(`_suggest_similar_products` 는
"요청하신 상품은 제공된 데이터에 없습니다" 를 같은 방식으로 단정한다).

**회귀** 한전+`pd_no=1184` → 거짓 문장 없음 · 진단 문장 노출 · 실재하지 않는 발행사('삼성전자')는
종전 되묻기 그대로. 발행사 1,818곳 전수로 "실재하는데 없다고 말하는" 건수 **1,392 → 0**.

### P0-3 · 0행 진단이 어느 조건 때문인지 말한다 (D2 후속)

`ZeroRowDiagnosis.user_text()` 의 '값 자체가 없는 조건' 갈래가 지금은 *"조건 중 일부는 … 없습니다"* 로
뭉갠다. 진단은 이미 컬럼과 리터럴을 알고 있으므로 스키마 한글명으로 **어느 조건인지 적는다** — 다른
갈래(`발행기관이 '…'인 상품 403건 …`)는 이미 그렇게 하고 있다. 갈래 간 표기 통일이다.

### P1-4 · 개수를 묻지 않았으면 SQL 을 고친다 (D3) — 🔄 1차 설계 폐기

**1차 설계는 틀렸다.** 처음에는 *"개수 의도가 없으면 `_bond_count_answer` 가 `None` 을 돌려 산문 조립으로
넘긴다"* 로 썼는데, 이는 **이 코드베이스가 선언한 원칙과 정면으로 어긋난다** — `_distribution_answer` ·
`_bond_avg_answer` 주석이 반복해 못박은 *"집계 해석은 LLM 에 맡기지 않는다"*. 조립기를 물리면 COUNT
한 줄이 그대로 HCX 로 가고, 그건 #52(국고채 295 를 국공채라 옮겨 적은 사고)가 났던 바로 그 경로다.
**결함은 조립기가 아니라 SQL 이 질문과 어긋난 것이므로, 상류에서 SQL 을 고친다.**

**자리** 결정층 SQL 교정, `ensure_bond_select_columns` 옆(같은 부류 — SELECT 모양을 조립기가 다룰 수
있는 형태로 되돌리는 가드).

**판정** ① 질문에 개수 의도(`몇`·`개수`·`건수`·`종목 수`·`얼마나 많/되/있`)가 없고 ② WHERE 에 P0-1 이
실은 종목명 등호가 있으며 ③ SELECT 가 COUNT 하나면 → SELECT 를 표준 컬럼 목록으로 바꾼다.
1행 속성 조회가 되어 기존 목록·속성 조립기가 받는다. **개수 문장은 애초에 만들어지지 않는다.**

**불개입** 개수 의도가 있으면 전부 지금 그대로. 종목명 등호가 없으면(발행사·조건 검색) 불개입 —
"조건에 해당하는 채권은 총 N종목입니다" 는 그 문형에서 옳은 답이다.

**오폭 실측** eval 195문항 — 개수 어휘 21문항 전부 통과(주어 정규식에 안 걸리는 11문항 포함),
개수 어휘 없이 주어 정규식만 맞는 문항 **0건**. 종목명 등호 조건까지 요구하므로 실제 발동면은 더 좁다.

**짝** 지목된 단일 종목의 구매가능 여부는 결정층이 조립한다(`결론 → 이유 → 대안`, `wording.py` 어투):
"가능합니다 — 원화 표시, 만기 2052-04-21 로 기준일 2026-08-24 현재 구매가능 모수입니다. 다만 당사
판매 조건(매수수익률·매매단가)은 이 종목에 수록돼 있지 않습니다." 규칙 `구매가능`·`판매행` 을 그대로 옮긴다.

### P1-5 · 질문에 종류 신호가 0이면 종류 등호 절을 걷는다 (D4)

**자리** `strip_fabricated_risk_filter` 옆 — 같은 부류의 형제 가드로.

**판정** `_question_kind_filters(question)` 이 공집합이고, WHERE 최상위 AND 절이 종류 컬럼
(`bd_knd`·`std_pd_mcls_nm`·`std_pd_scls_nm`) 등호/IN 하나로만 이뤄져 있으며, 그 리터럴이 질문 문언에
없으면 **그 절만** 걷는다.

**불개입** OR 결합 · 부정 연산 · 다른 컬럼이 섞인 절 · 리터럴이 질문에 있는 절 · 구조/ESG 판정식
(`pd_nm` 축이라 애초에 대상 아님) · 질문에 종류 신호가 하나라도 있으면 전부 `restore_kind_breadth` 몫.

**🔴 0행 한정은 선택지가 아니라 확정이다 — 반례를 찾았다.**

*"질문에 종류 신호가 0이면 종류 절은 날조"* 라는 1차 전제는 **거짓이다.** 채권 eval 54문항 중 종류 신호
0 인 40문항을 전수로 훑어 반례가 나왔다:

| qid | 질문 | gold SQL 이 쓰는 종류 조건 |
| :-- | :-- | :-- |
| BND-D-026 | 정부가 **책임지는** 채권 중에서 수익률 높은 순으로 5개 | `TRIM(std_pd_mcls_nm)='국공채'` |
| BND-D-014 | 정부가 **보증하는** 채권 알려줘 | 같은 조건(신용보강 CASE 안) |

선언된 서술형은 `정부가 **발행**` 까지만 잡는다(`kind_filters.paraphrases`). '보증·책임' 은 신용보강 부류라
종류 낱말 없이 **정당하게 종류 축을 쓴다.** 지금은 두 gold 모두 그 조건이 OR 그룹 안에 있어 내 불개입
조건(OR 결합·복합 절)에 걸려 우연히 살아남지만, HCX 가 같은 뜻을 `AND TRIM(std_pd_mcls_nm)='국공채'`
단독 절로 쓰면 **상시 가드는 정답 조건을 걷어낸다.**

→ **0행 한정으로 고정한다.** 정답 조건이면 정의상 0행이 아니므로 이 반례를 구조적으로 못 건드린다.
날조 절이 우연히 행을 내는 경우는 못 잡지만, 그건 상시화의 이유가 아니라 다음 라운드의 실측 대상이다.

**나머지 39문항** 은 종류 등호가 필요 없다 — 영구채·코코본드·전환사채는 구조 판정식, 녹색채권은 ESG
이름축, 단기채·하이일드는 잔존일수·등급축, "채권 종류별로"(BND-A-015)는 `GROUP BY` 라 등호가 아니다.

### P1-6 · 발행사 통칭 5종 선언 (D5)

두 자리에 **같은 어휘**를 등록한다(라우터·규칙·게이트가 같은 낱말을 보게 하는 기존 원칙,
`domestic_bonds.yaml:1055` 주석 그대로).

1. `synonyms` — `산금채: 특수은행채` 꼴 라우팅 대표값 (국민주택채권 1051행과 같은 형식)
2. `kind_filters.tokens` — 확정식

```yaml
- {token: 산금채, sql: "TRIM(bd_knd)='특수은행채' AND TRIM(pd_pbcm)='한국산업은행'"}
- {token: 중금채, sql: "TRIM(bd_knd)='특수은행채' AND TRIM(pd_pbcm)='(주)중소기업은행'"}
- {token: 수은채, sql: "TRIM(bd_knd)='특수은행채' AND TRIM(pd_pbcm)='한국수출입은행'"}
- {token: 농금채, sql: "TRIM(bd_knd)='특수은행채' AND TRIM(pd_pbcm)='농협은행'"}
- {token: 수협채, sql: "TRIM(bd_knd)='특수은행채' AND TRIM(pd_pbcm)='수협은행'"}
```

종류 컬럼을 절 안에 남기는 이유: 종류 가드들이 이 절을 **종류 절로 알아보게** 하기 위해서다. 발행사
등호만 쓰면 `_kind_clause_signature` 가 이름 가지로 읽어 다른 가드와 어긋난다. 두 식은 실측상 같다
(한국산업은행 503종목 전부 특수은행채).

**⚠ 미검증 — 구현 전 회귀부터 쓴다.** 주입 자체는 안전하다(`_append_exclusions` 는 최상위 AND 로 이어
붙여 기존 OR 그룹을 안 깬다). 문제는 그 뒤다: 괄호 없이 넣으면 `A AND B` 가 **최상위 절 둘**로 쪼개져
`restore_kind_breadth` ②가 `bd_knd` 절만 보고 F 와 다르다고 판정해 교체를 시도한다. → 선언 문자열을
`(TRIM(bd_knd)='특수은행채' AND TRIM(pd_pbcm)='한국산업은행')` 처럼 **괄호로 묶어 한 절로 유지**하고,
`ensure_kind_filter` → `restore_kind_breadth` → `ensure_trimmed_compare` 를 연달아 통과시키는 회귀를
**코드보다 먼저** 쓴다. 이 항목만은 실측으로 닫히지 않았다.

**고지** 종류 낱말을 발행사 축으로 판정했다는 사실을 답변에 한 줄 적는다 — `domain_caveats` 에
"산금채는 한국산업은행이 발행한 특수은행채로 집계했습니다". **축 대체는 밝히는 것이 규칙**이다(#66·#79 부류).

채권 이름이 다른 상품군 질의를 가로챌 수 없다.

### ④ 과적합인가 — 아니다. 같은 병이 다른 상품군에도 있다

P0-2 를 채권 밖에서 재봤더니 **ETF·펀드에 같은 결함이 있고 더 나쁘다**:

```
SELECT … FROM domestic_etfs WHERE TRIM(pd_abrv_nm)='KODEX 200' AND ttl_exp_rate < 0.0   → 0행
되묻기 후보 → ['KODEX 200', 'KODEX 200TR', 'KODEX 200타겟위클리커버드콜', …]
```

순자산 1위 ETF 를 두고 *"요청하신 상품은 제공된 데이터에 없습니다"* 라 말하면서 **자기 자신을 대안으로
제시한다**(발행사판은 `pd_pbcm <> ?` 로 자기를 빼는데 상품판은 그마저 없다). 펀드도 같다.

→ 채권 한 곳을 기우는 게 아니라 **"되묻기가 주장하는 부재는 실측한 뒤에만 말한다"** 는 원칙을
세 상품군의 되묻기 자리에 같이 건다. 사례가 아니라 부류라는 증거가 이것이다.
