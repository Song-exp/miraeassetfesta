## 3. 전수 조사 결과 — 무엇이 문제였고 어떻게 됐나

챗봇이 질문을 처리하는 순서에서 보면 문제가 어디 있는지 보인다:

```
질문 ─▶ ① 상품군 정하기 ─▶ ② 이름→DB값 매핑 ─▶ ③ 규칙 안내판 ─▶ HCX 가 SQL ─▶ 실행 ─▶ HCX 가 문장
           F                E                 A·C·D              B                     G·H
```
**HCX 는 yaml 을 직접 읽지 않는다.** 코드가 yaml 의 `query_rules` 만 뽑아 ③ 안내판을 만들고, HCX 는 그것만 보고 SQL 을 쓴다. 그래서 "안내판에 없는 규칙" 은 없는 규칙이다.

## 7. E·F 라우팅 설계 — "채권" 글자가 있다고 채권이 아니다

세 겹, 어느 겹에도 사람이 쓴 단어 목록 없음:
1. **문장 구조** — 마지막 상품 명사가 주인공("채권형 **ETF**" → ETF), 접속사로 이어지면 둘 다("채권**과** ETF"), 앞의 국내/해외로 ETF 를 가름. 상품 명사 4개는 주최 파일 라벨에서.
2. **온톨로지 값** — 상품 명사가 없으면 질문에 어느 테이블의 값(발행사·지수·ETF 이름·채권종류)이 나오는지. 어휘는 DB 에서 자동 생성(1,998 · 3,017 · 8,399 · 2,546). 경계식·3자 이상.
3. **동의어는 yaml** — 통안채→통화안정채권, 영구채→신종 … 코드가 아니라 온톨로지가 소유.
4. 그래도 모르면 4테이블 → HCX 가 FROM 으로 정함.
5. (E) 정해진 상품군 **안의** 값만 매핑에 씀.

시제품 `scripts/route_prototype.py`: 채권·ETF·펀드·교차 36문항 **36/36** (현행 게이트 13건 미특정·오라우팅). 1판은 점수만으로 해 "LH 채권" 이 ETF 로 가는 등 실패 → 머리 명사 규칙을 앞세운 2판에서 해결.

## 10. 이틀의 교훈 (같은 실수 반복 금지)

| 무엇 | 왜 |
| :-- | :-- |
| **`NOT (a OR b)` 를 결측 컬럼에 쓰지 말 것** | 국공채 2,840행이 NULL 로 증발. `COALESCE + AND`. 검사 스크립트에서도 같은 함정에 두 번 걸렸다 |
| **내 어제 판정도 재점검 대상** | 전수조사에서 가장 큰 결함은 내가 전날 넣은 규칙이었다 |
| **규칙 파일 ↔ 팀 문서가 어긋나면 주최 공지 원문을 먼저 묻는다** | 7/11 로 확정했다가 다음 날 8/24 로 철회 |
| **단어 목록으로 판정하지 않는다** | 표기 하나 늘 때마다 놓친다. 컬럼·문장 구조·온톨로지 값으로 |
| **"안내판에 없는 규칙은 없는 규칙"** | yaml 컬럼 설명에 있어도 `query_rules` 에 없으면 HCX 는 모른다 |
| **거부된 명령도 부분 실행됐을 수 있다** | §9 가 두 번 붙었다. 재개 때 상태부터 확인 |
