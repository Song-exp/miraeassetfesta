### 1-1. 챗봇 가동 — 비어 있던 건 `Planner` 하나였다

파이프라인은 이미 완성돼 있었고 `Plan`·`Answer` 두 지점만 인터페이스 뒤에 비어 있었다. 그걸 채웠다.

  SQL 예산 512 / 답변 1024. 병목이 rate limit 이라 토큰이 곧 처리량이다.
- `pipeline.build_grounding()` — 근거문서 = **KG 매핑 + 도메인 규칙(yaml) + 교차질의 조인 키 + 스키마**
  🔴 **yaml 을 고치면 프롬프트가 바뀐다.** 판정을 문서가 아니라 yaml 에 적어야 하는 이유가 여기서 실증됐다.
- `loader` — `schema_metadata` 280컬럼 + `ext_*` PRAGMA 적재, `schema_text()`
- `src/chat.py` — 실험용 CLI (`-q` / `-f` / 대화형 / `--no-hcx`), `logs/chat-*.jsonl` 기록
- `api` — planner 싱글턴 · `/reload`(토큰) · `/health` 에 planner 상태

**실측 4문항을 흘려서 잡은 버그 5건** — 전부 회귀 테스트로 고정했다. 가짜 플래너 단위 테스트는 이걸 하나도 못 잡았다.

| 증상 | 원인 |
| :-- | :-- |
| "미래에셋자산운용이 운용하는 국내 ETF" → 0행 | Ground 가 대상 테이블을 안 보고 **채권 발행사 노드**를 골랐다 |
