## 0. 이 블록이 무슨 작업인가 (쉬운 말)

챗봇에게 "이 데이터는 이런 뜻이야" 를 적어 준 설명서(`public_funds.yaml`)를 갖고 있고, 챗봇은 그걸 보고 SQL 을 만든다. 데이터가 1차 → 2차로 바뀌면서 설명서가 어긋난 곳을 팀이 자동으로 뽑아 놨고, 그중 **공모펀드 몫**을 사람이 하나씩 판정하는 게 이 작업이다.

**식별자 계열**은 펀드·클래스·기관을 가리키는 코드 컬럼 묶음이다. 성격이 같아 한 블록으로 본다.

```
자동 검사가 "여기 숫자 안 맞는데요" 하고 찍어 줌
        ↓
DB 를 직접 조회해서 왜 안 맞는지 알아냄  ← 이번 회차 (실측 완료 · YAML 규칙 그대로 재현)
        ↓
✅ 괜찮음 / ⚠️ 더 봐야 함 / ❌ 진짜 틀림  판정  ← 지금 여기, 승인 대기
        ↓
승인되면 표에 적고, ❌ 는 설명서(yaml)·생성기를 고침
```

| 판정 | 쉬운 뜻 |
| :-: | :-- |
| ✅ | 설명서가 맞다. 자동 검사가 다른 걸 세고 있었다 |
| ⚠️ | 지금 내가 확정 못 한다. 리드가 정할 규약·구조에 걸린다 |
| ❌ | 설명서·구현이 틀렸다. 고쳐야 한다 |

### 🔴 이 블록에서 반드시 알아야 할 것 — "결측" 의 정의가 컬럼마다 다르다

식별 코드는 **물리 NULL 만 세면 틀린다.** `000000000000` · `KR0000000000` · `00000000000000000000`(20자리 0) 같은 **더미가 진짜 결측의 대부분**이다. YAML 은 이 더미를 잡는 규칙을 `normalization.dummy_as_missing` 에 SQL 4갈래로 정의해 놨다.

```sql
-- YAML normalization.dummy_as_missing.sql  (이 규칙을 그대로 써야 수치가 맞는다)
(C IS NULL                                                    -- ① 물리 NULL
 OR trim(C)=''                                                -- ② 공백/빈 문자열
 OR replace(replace(trim(C),'KR',''),'0','')=''               -- ③ KR·0 만 남으면 빈값 (000..., KR000...)
 OR (length(trim(C))>1
     AND replace(trim(C), substr(trim(C),1,1), '')=''))       -- ④ 첫 글자가 전부 반복 (0000, 1111, 20자리 0 반복)
```

- 패턴 2개: `^(KR)?0+$` · `^(.)\1+$`
- 적용 컬럼(화이트리스트): `fss_itm_no` · `kofia_fd_ccd` · `rptt_ksd_itm_no` · `mtco_itm_no` · `ksd_itm_no` · `std_itm_no`
- 🔴 **화이트리스트 밖에 걸면 안 된다** — `fd_estb_ctry_cd '000'`(23,055행) · `pfiv_sale_cntl_tcd '00'`(22,263행) · `fd_set_pcd '00'`(1,967행)은 **정상값**이다. 더미 규칙을 여기 걸면 통째로 오배제된다.

## 3. 피처별 상세 보고 (YAML 규칙 기준 실측)

### 3.1 `itm_no` (종목번호) → ✅
- **무엇인가**: 판매 단위인 펀드 클래스 1개를 가리키는 행 PK. 예: `OS559003001M`.
- **실측**: `count(*)=count(distinct itm_no)=23,676`. NULL 0 · 더미 0.
- **값 의미**: ISIN 유사 12자리. 앞 4자리(`KR51`·`KR50`·`KR55`·`KR52`·`OS…`)로 상품군 판별.
- **"미판정" 의 뜻**: `gen_data_dictionary.py` 는 `public_funds.yaml` 의 `columns:` 블록에 그 컬럼 항목이 **있는지로만** 판정 여부를 표시한다. `itm_no` 는 `columns:` 에 항목이 없어 `🔲 미판정` 으로 뜨지만, `missing_profile.결측없음_컬럼` 목록에는 들어 있다. 즉 **데이터 문제가 아니라 "컬럼별 상세 판정 항목이 비어 있다"** 는 형식상 표시다.
- **조치** (`public_funds.yaml` `columns:` 에 신규 항목):
  ```yaml
  itm_no:
    korean_name: 종목번호
    missing_reason: none
    note: "식별 기준 키 · 행 PK(23,676 완전 유일). 개수·조인·식별은 이 컬럼으로."
  ```
  (현재 `columns:` 에 `itm_no` 항목 자체가 없어 데이터 사전이 `🔲 미판정` 으로 표시 → 항목 신설로 B-1-60 닫힘.)

> 📌 **이 블록의 교훈** — "숫자가 안 맞는다" 고 말하기 전에 **그 숫자를 만든 규칙(YAML)을 먼저 읽고 그대로 실행**한다. 어림한 정규화로 "불일치" 를 주장하면, 실제로는 내 규칙이 틀린 것이다. 초판의 ❌·⚠️ 상당수가 이 오류였고, YAML 규칙으로 재현하니 **대부분 ✅ 로 정정**됐다.
