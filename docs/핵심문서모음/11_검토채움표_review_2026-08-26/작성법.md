## 0. 한 항목을 채우는 데 3단계

```
① 자동 수집 근거를 읽는다   →  ② 판정 한 글자를 고른다  →  ③ 조치를 적고 원본을 고친다
   (표에 이미 채워져 있음)        ✅ / ⚠️ / ❌                yaml 을 고쳐야 반영된다
```

표는 이런 모양입니다. **왼쪽 넷은 이미 채워져 있고, 오른쪽 둘만 씁니다.**

| ID | 대상 | 확인할 것 | 자동 수집 근거 | 판정 | 근거·조치 |
| :-: | :-- | :-- | :-- | :-: | :-- |
| A-1-02 | 채권 `exg_close_price` | `answerable_n` 이 도메인 조건 포함 모수인지, 단순 non-null 인지 | 기재 **1,270** vs 실측 non-null **17,746** | ☐ |  |

한 항목에 **2~5분**이면 됩니다. 오래 걸리면 판정을 미루지 말고 `⚠️` 로 두고 왜 막혔는지를 적으세요 — 막힌 이유가 곧 회의 안건입니다.

## 1. 판정 세 글자

| 판정 | 뜻 | 그다음 |
| :-: | :-- | :-- |
| **✅** | 지금 상태가 맞다 | `근거·조치` 에 **왜 맞는지** 한 줄. 근거 없는 ✅ 는 검토를 안 한 것과 같다 |
| **⚠️** | 더 봐야 안다 | 무엇을 더 봐야 하는지, 누구에게 물어야 하는지 |
| **❌** | 틀렸다 | **고칠 파일과 위치**를 적고 실제로 고친다 |

> `☐` 를 그대로 두면 미판정입니다. 진행률은 `☐` 개수로 셉니다 (§5).

## 2. 채운 예시 — 네 가지 결

### 예시 ① 판정이 낡은 경우 (A절)

| ID | 자동 수집 근거 | 판정 | 근거·조치 |
| :-: | :-- | :-: | :-- |
| A-1-02 | 기재 **1,270** vs 실측 non-null **17,746** | **✅** | `answerable_n=1270` 은 non-null 이 아니라 **장내 한정 모수**다(`pd_exg_mkt='장내'`). `answer_policy` 에 이미 "장내 1,270행만 유효" 라고 적혀 있음. 필드 뜻이 두 가지로 쓰이는 게 문제지 이 값이 틀린 건 아님 → **B-4 로 승격**: `answerable_n` 정의를 yaml 규약에 명시할 것 |

**요령** — 어긋난 두 수치를 보고 *어느 쪽이 틀렸나* 가 아니라 ***둘이 서로 다른 것을 재고 있는가*** 를 먼저 봅니다.

### 예시 ② 진짜 결함인 경우 (A절)

| ID | 자동 수집 근거 | 판정 | 근거·조치 |
| :-: | :-- | :-: | :-- |
| A-1-25 | 판정 `none`(결측 없음)인데 실측 결측 **13,079**행 | **❌** | 펀드 `thco_sale_yn`(당사판매여부) 결측 55%. 1차엔 결측이 없었고 2차에서 생겼다. `missing_reason: none` → **`mixed`** 로 바꾸고 `missing_semantics` 에 사모/공모별 분해를 적음 (사모 1,993 · 공모 419). `public_funds.yaml` 수정 완료 |

### 예시 ③ 값의 뜻을 가르는 경우 (C절)

| ID | 자동 수집 근거 | 판정 | 근거·조치 |
| :-: | :-- | :-: | :-- |
| C-1-01 | 국내ETF `cu_lev_fector` 결측 182/1,780 · 값 0 이 0 | **❌** | 결측 182 = **ETN 전량**(구조상 배수 개념 없음) → `not_applicable`. 값 `1.0` 은 "레버리지 없음"(실제값), `2.0`·`0.5` 는 배수. **음수(인버스)는 2차에서 부호가 소실**됐으므로 방향은 `derivation_rules.inverse_direction`(상품명) 으로 판정. `missing_semantics: {null: not_applicable}` 추가 + `trap` 에 부호 소실 명시 |

**요령** — `mixed` 는 "행마다 다름" 이라는 **선언일 뿐** 답변 규칙이 아닙니다. NULL·0·특정값 각각에 뜻을 붙여야 답변 문장이 정해집니다.

### 예시 ④ 개체를 합칠지 나눌지 (E절)

| ID | 자동 수집 근거 | 판정 | 근거·조치 |
| :-: | :-- | :-: | :-- |
| E-2-03 | `Organization` · `국민은행` — **3노드** · 별칭 3 — `Org_issuer_c2c9c36b8f`, `Org_trustee_00020004`, `Org_trustee_00160005` | **❌** | 같은 법인이 **역할별로 3노드**(발행사 1 + 수탁사 2)로 갈렸다. 수탁사 코드 2개는 지점/계정 단위로 보임. 한 노드로 합치고 역할은 **관계로** 표현해야 함(`issuedBy` / `custodiedBy`). `shared/organization.yaml` 에 통합 노드 + alias 3종으로 재작성 |

**요령** — KG 탐색기(`build/kg.html`)에서 이름을 검색해 **이웃 모드**로 펼치면, 각 노드에 붙은 별칭 원시값이 그대로 나옵니다. 같은 실체인지는 대개 별칭을 보면 판가름납니다.

## 3. 고치는 곳 — 문서가 아니라 yaml

**판정을 문서에만 적으면 답변은 그대로입니다.** `loader.planner_context()` 가 yaml 의 `query_rules`·`normalization` 을 **플래너 프롬프트로 그대로 넘기기** 때문에, yaml 을 고쳐야 챗봇 동작이 바뀝니다.

| 고치려는 것 | 고칠 파일 | 위치 |
| :-- | :-- | :-- |
| 컬럼의 결측 사유·단위·답변 정책·함정 | `ontology/enums/<도메인>.yaml` | `columns.<컬럼>` |
| 값별 의미 분해 | 〃 | `columns.<컬럼>.missing_semantics` |
| 0 을 배제할지 | 〃 | `columns.<컬럼>.zero_is_value` · `normalization.zero_*` |
| 질의에 항상 걸 조건 | 〃 | `query_rules` |
| 파생 축(인버스·총보수·재간접) | 〃 | `derivation_rules` |
| 개체·별칭·계층·부재 선언 | `ontology/shared/<개체>.yaml` | `nodes` · `aliases` · `parent` · `absent_in` |
| 코드↔이름 대응 | `ontology/codebooks/*.csv` | — |
| 컬럼 한글명·타입 | **못 고침** — 주최 원본(`*_schema.xlsx`) | — |

> ⚠️ yaml 은 **중복 키를 조용히 삼킵니다.** 항목을 덧붙일 때 같은 키가 이미 있는지 보세요.
> 실제로 이것 때문에 검수 결론 하나가 옛 지침에 덮여 사라져 있었습니다.

## 6. 순서와 요령

**A → B·C → D → E** 순입니다. A(정합성)가 먼저인 이유는 수치가 틀리면 아래 판정이 잘못된 근거 위에 세워지기 때문입니다.
**E 안에서는 라벨·동일성(E-1·E-2)이 관계(E-4)보다 먼저**입니다 — 노드가 틀리면 관계 검토가 무의미합니다.

| 상황 | 이렇게 |
| :-- | :-- |
| 같은 원인이 여러 항목에 걸침 | 대표 항목 하나에 상세히 적고 나머지는 `❌ A-1-25 와 동일 원인` 으로 참조 |
| 판정이 도메인 지식을 넘어감 | `⚠️` + 누구에게 물을지 적기. 회의 안건이 된다 |
| 항목 자체가 잘못 잡힘 | `✅` 로 닫지 말고 `⚠️ 항목 부적절 — 이유` 로 남기기. 다음 생성 때 규칙을 고친다 |
| 고치면 파급이 큼 (예: `kg_*` 전체 재생성) | 고치지 말고 `❌` + **영향 범위**를 적고 리드와 상의 |
| 근거가 더 필요함 | 온톨로지 도해에서 컬럼 상세·값 전체 목록, KG 탐색기에서 개체 이웃 확인 |
